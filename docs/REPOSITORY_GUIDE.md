# 文件归属与长期维护规范

[文档索引](README.md) · [代码导览](PROJECT.md) · [协作约定](../AGENTS.md)

本文规定文件放置、文档职责、图片与历史资料的维护方式。适用于新增与整理文件；目录归属不是删除许可。功能事实以当前源码和相应验证为准，任务范围以用户当前授权为准。

## 目录与文件归属

| 位置 | 放什么 | 维护规则 |
| --- | --- | --- |
| 根目录 | README 中英版、AGENTS、LICENSE、包和构建配置、两个 Windows 启动入口 | 保持入口稳定；新增报告、截图、临时脚本不散落根目录 |
| `src/main/` | Electron 宿主、服务、持久化、pi RPC | 按能力定位；移动前核对 import、测试与构建入口 |
| `src/preload/`、`src/shared/` | 桥接与共享协议、纯逻辑 | 跨进程契约成对维护，避免复制定义 |
| `src/renderer/src/` | React 组件、状态、样式、语言与界面资产 | 保持现有功能分组；不因整理文档重排代码 |
| `resources/pi-extensions/`、`resources/yan-cli/` | 随包薄层适配和本机 CLI 源码 | 与打包复制规则一起检查 |
| `scripts/` | 可重复运行的启动、检查、构建工具 | 延续已有脚本入口；通用辅助放 `lib/`，数据放 `fixtures/`，探针放 `probe/`，设计维护放 `design/`，审计放 `audit/` |
| `docs/` | 使用、贡献、架构、源码导航、品牌与维护规范 | 新增公开文档须从文档索引可达；不要复制计划或验收流水 |
| `docs/dev/RELEASING.md` | 发布、包内容和用户数据边界 | 此目录仅此文件公开；不能因为目录名相同就公开其他内部文件 |
| `docs/assets/inkstone/` | 精选公开品牌图片及演示截图 | 维护用途、来源、真实性说明；检查中文及英文引用 |
| `build/` | 受控图标、安装侧栏及构建辅助产物 | 以 Git 跟踪清单区分受控资源与生成物，禁止整目录清理 |
| `docs/plan/`、`docs/design/`、`docs/archive/`、其余 `docs/dev/` | 既有本地计划、设计参考、历史证据 | 原位保留，Git 忽略；只在任务需要时读取；不作为公开构建的依赖 |
| `.local-docs/` | 新的本地报告、归档清单、整理备份 | 按主题与时间分目录；可能含私人路径，禁止直接公开 |
| `.tmp/` | 新的一次性脚本与短期中间文件 | 使用任务子目录；结果需保留时转入本地报告并记录来源 |
| `out/`、`dist/`、`resources/pi-runtime/` | 编译产物或内置运行时 | 按构建流程生成；不能手改来代替源码修复 |
| `release/` | 发行包、解包目录及可能混存的真实数据 | 先区分产物与数据；`release/砚数据/` 只读，不能当作缓存 |
| `node_modules/`、`.git/`、`.pi/`、`.yan-tmp/`、`.backup/` | 依赖、Git、本机配置、请求回执、备份 | 不参与常规文档搬迁；不能仅凭文件名或年龄判定可删 |

已有脚本可能仍将截图输出到 `docs/design/preview/`，保留兼容。新任务优先使用 `.local-docs/evidence/<日期>-<主题>/`，可配置输出路径时再指定新位置。

## 文档各自负责什么

| 文档 | 唯一职责 | 何时同步 |
| --- | --- | --- |
| 根 README 中英版 | 产品介绍、快速开始与公共入口 | 用户可见功能、启动方式、主页素材或导航变更 |
| 根 AGENTS | 每次协作都必须遵守的授权、边界和最低检查 | 工作规则变更；细节链接到本文，不复制长清单 |
| 文档索引 | 按目的导航公开文档 | 新增、改名、归档公开文档 |
| GETTING_STARTED 中英版 | 安装、模型接入、使用与备份 | 用户操作或数据位置变更 |
| CONTRIBUTING | 开发环境、命令与贡献检查 | 脚本入口、环境要求、检查方法变更 |
| PROJECT | 目录和关键能力的源码入口 | 新增能力、文件迁移或职责变化 |
| ARCHITECTURE | 进程、协议与数据边界 | 边界或事件流变化 |
| RELEASING | 包、运行时、升级和真实数据 | 发布配置、产物及验证流程变更 |
| BRAND | 品牌名、图标源和公开图片说明 | 品牌资产或其来源变化 |
| 本文 | 文件生命周期与资料管理 | 文件归属、归档与审核方法变更 |

命令事实以 `package.json` 为准，打包事实以 `electron-builder.yml` 和实际包内容为准。旧 HANDOFF、计划和截图只描述当时状态；不得仅因旧资料标注“已完成”而宣称当前版本通过验收。

## 命名、更新与归档

1. 公开文件用稳定用途名，沿用现有命名风格；不将日期、实施编号或“最终版”塞入长期入口文件名。
2. 本地报告使用 `<日期>-<主题>/`，证据文件增加时间或序号。报告写明日期、范围、输入、结论、验证与限制；未验证项直接注明。
3. 更新长期文档时改写现行规则，不无限追加相互矛盾的“本轮说明”。旧记录需要保留时先做本地快照，再更新入口。
4. 计划从活动转入历史须有完成、搁置或被替代的依据；不能只凭修改时间自动归档。遗留项保留归属与证据，不能借归档宣称完成。
5. 移动文件前检查代码、脚本、配置、文档相对链接与本地引用。写出旧路径、新路径和理由；检查目标未被占用，移动后核对大小与 SHA-256。涉及相对路径的脚本即使未被引用也可能仍有用途，归档后明确标记不可直接重跑。
6. 名称、哈希相同仅是复核线索。图标源、渲染端副本和打包副本可能都需要保留；不自动去重。历史截图、备份和原文不覆盖、不删除。
7. 旧索引冲突时修订入口并链接现行规范；保留历史正文，不对全部历史记录批量替换术语或规则。

## 图片与细碎文件

- 公开图片必须有明确的文档或产品用途。记录源文件、生成/编辑方式、许可或来源信息；截图注明真实会话还是合成演示，隐去凭证与私人内容。
- 图标沿用 [品牌规范](BRAND.md) 的源与生成入口，设计维护用预览留在 `scripts/design/`。不能把同名文件视为可互换。
- 批量视觉证据留在本地。文件名表达日期、场景、主题与窗口条件；尺寸或哈希检查不替代肉眼验收。
- 日志、请求 JSON、审计 JSON、临时脚本与缓存按用途登记。活跃回执、系统保留名文件和未知用途文件先原位保留；不执行旧脚本来“确认用途”。
- 不新增全局扩展名忽略规则来隐藏未分类文件；先判定用途，再使用窄范围目录规则。字体和第三方许可沿用实际分发要求。

## 低消耗检查与交付

先用本地工具清点和筛选，仅阅读相关摘要与冲突片段；无必要不重扫全文、不启动模型或应用。大型清单可以交给用户授权的低成本代理读取，由负责 agent 核验结论。

```powershell
node scripts/audit/workspace.mjs
node scripts/audit/workspace.mjs --report
git diff --check
```

第一条检查公开 Markdown 的本地文件链接和公开目标边界，失败时非零退出。第二条另外在 `.local-docs/workspace-audits/` 创建独立时间戳目录，包含 `INDEX.md` 和 `catalog.json`：列出项目维护范围内文件、分类、Git 状态、文档标题、图片哈希与 PNG 尺寸，以及相同内容组。无须安装额外依赖，也不修改被清点文件。

清点不展开依赖、Git、构建输出、发行包、本机配置、回执、`.backup/` 与既有 `workspace-audits/` 报告，不跟随符号链接；`.local-docs/` 的其他文件只列元数据，不读取正文；报告列出全部跳过边界与读取错误。它不是全盘内容审查。链接检查不验证外部网址、标题锚点、自然语言准确性或代码示例；未跟踪且未忽略的新文件按“待公开文件”检查，不代表已提交。

纯文档整理执行上述检查及相关引用复核即可。改动可执行脚本时先检查语法并运行对应入口；移动路径有消费方时再运行消费方检查。只有实际改到应用行为才扩大到构建、单元或 live 测试。最终分别报告文件变更、机器检查、人工检查和未验证项。

提交前逐项核对本次文件及暂存列表；新克隆不能依赖本机内部资料。提交、推送、打包、重启和删除仍遵循用户授权。内部清单留在本地，公开提交不带完整私人路径或历史任务材料。
