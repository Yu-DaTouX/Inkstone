### 协议与安全模型

```
模型 ──bash──▶ yan operations status --id X
                    │ POST http://127.0.0.1:<随机端口>/rpc
                    │ Authorization: Bearer <一次性 token>
                    │ { apiVersion, command, params, sessionId, projectId }
                    ▼
             宿主：token 校验 → 身份比对 → 执行 → 结果落文件
                    ▼
        { ok, operationId, summary, resultFile, resultBytes }   ← 只有这段进上下文
```

- **只监听 `127.0.0.1`**，端口随机；
- token **每实例一份**，只经 pi 子进程环境变量传递（不落盘、不进日志、不进渲染端）；
- token 与 `(sessionId, projectId)` **绑定**，比对用的是 `timingSafeEqual`；
- `stop()` 后 token 立即作废，端点不再服务；
- 未登记命令直接拒（`unknown_command`），不是「未知命令当成万能入口」。

### 证据（自动检查）

`npm run test:unit` 新增 **17 项**，全部通过（总计 2293/2293）：

| 断言 | 覆盖的失败模式 |
|---|---|
| 合法请求返回 ok | 管道基本可用 |
| 大结果落文件并回路径 | 结果没落盘 → 模型拿到几 MB stdout |
| 响应只回摘要，不回完整数据 | 摘要与数据一起回 → 省 token 的设计落空 |
| **伪造 projectId 被拒**（403） | **S2 出口的硬指标** |
| 伪造 sessionId 同样被拒 | 只校验一半身份 |
| 错误 token 被拒（401） | 鉴权形同虚设 |
| 未登记命令被拒 | 端点变成万能执行器 |
| 未实现命令走完整管道后如实报错 | 静默成功（比报错更糟） |
| 协议版本不一致被拒 | 旧 CLI 打新宿主 |
| stop 后端点不再服务 | token 泄漏后仍可用 |
| 启动器：纯 Node 模式 / 指向随包 CLI / 用应用自带运行时 | 依赖用户机器上的 node |
| 找不到 CLI 时返回 null | 静默生成坏启动器，模型看到「不是内部或外部命令」 |

## S3 · 提示与上下文组织

### 实现位置

[resources/pi-extensions/capability-guide.js](../../resources/pi-extensions/capability-guide.js)
—— 在 `before_agent_start` 把一段**短说明**追加到系统提示末尾。

它只回答两件事（多一句都不写）：

1. 有这个入口、怎么按需查用法（`yan --help`）；
2. **输出是摘要 + 结果文件**，用文件工具只取需要的片段，别整份读进上下文。

外加能力选择顺序：本机工具 / 脚本 → Skill → 发布方 CLI / API → 确实需要的 MCP。

**为什么走钩子而不是 `--append-system-prompt`**：后者是进程启动时固定的，
改一次就要重建 pi 实例（掐掉后台会话、界面短暂失去历史）。静态文本追加在
提示末尾，落在缓存前缀之后，不破缓存。
