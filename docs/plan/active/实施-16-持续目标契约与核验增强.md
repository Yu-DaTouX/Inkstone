## 1. 边界

- 模型报告完成 ≠ 宿主核验通过；两者分字段、分展示，文本 evidence 不自动提升为核验事实。
- 首期 verifier 只做明确白名单内的宿主只读检查（先沿用 `exists`；是否扩到 `nonempty_file` 需单独验收），**不执行**模型拼出的 shell / 脚本 / 网络请求，不把 URL 可访问性当事实。
- 目标事实、状态转换与核验结果由宿主持有；`resources/pi-extensions/` 只做宿主无法经 CLI/RPC 表达的生命周期桥接，不新增模型工具 / pi 命令 / 第二个任务服务。
- 不改任务面板、预算机制、续接次数、模型工具集、项目知识和历史会话 JSONL。
- G-4（计划审阅关口）是独立可选项，不阻塞核验闭环；是否默认开启在实施前单独确定，现不加入当前执行优先级。

### 冻结的边界（G-1 起必须遵守）

1. **写入通道唯一**：目标的一切写入仍只有 `yan goal` CLI 一条路（`GoalStore`）；渲染端保持只读（`yan:getGoal`）。新增字段不得开第二写入口。
2. **字段分层**：目标级核验（`verification`）与链接级核验（`GoalLink.check`）分字段，展示层可并列但不得合并成一个“已核验”布尔。
3. **版本与迁移**：`GoalDocument.version` 维持 1；新字段按可选读取，缺省即默认值；不做一次性写回迁移（避免旧目标被后台改写）。
4. **并发**：沿用 `GoalState.revision` 乐观版本与 `transitionId` / `reportId` 幂等；核验由宿主在报告落盘后写，不接受模型提交的核验结论。
5. **不动的东西**：`READY_FIELDS` 五项、任务面板、预算机制（`checkGoalBudget`）、续接次数（`AUTONOMOUS_CONTINUE_LIMIT`）、模型工具集、`resources/pi-extensions/` 的桥接范围。
6. **迁移面**：本轮工作树里未提交的 11 个文档改动（归档交接 + 计划导航）保留，不在本主题内提交或回退。
