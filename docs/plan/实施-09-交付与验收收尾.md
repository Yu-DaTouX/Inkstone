  ⚠️ 必须真写文件：`resolvePi` 对 `YAN_PI_BIN` 只做 `existsSync`，路径不存在会被**静默忽略**
  并回落到内置 pi（刻意的降级：坏设置不该让应用打不开）—— 拿编出来的路径测，测的就不是这一态。

  `mode` 写死成 `save` → `exitinterrupt` 的 mode 断言红。

  在探针里不可达 —— probe 替身不 `await` 对话框，那条路径只能靠代码审阅；「中断退出真的掐断正在跑的回合」

### S3 的口径（2026-09-18 定）

**不新建状态真源。** 会话文件是唯一真源，`lastSessionId` 会造成**双写一致性问题**。

- 只在会话文件里补 **`lastOpenedAt`**（单调序号或显式时间戳）；
- 启动 / 切回项目时**扫描目录推导**「最近的会话」；
- **不要**依赖文件 `mtime` —— 复制、恢复备份、系统时钟变化都会污染排序；
- 草稿不丢仍靠「切走 / 回收前强制落盘」，`lastOpenedAt` 只解决**恢复哪一个**的问题。

**落地时的偏离（2026-09-19，如实记录）**：`lastOpenedAt` **没有写进会话文件**，而是落在
**已有的** `YAN_DIR/session-layout.json` 条目里（那个文件本来就在记归属与移动历史）。
原因是 pi 的 JSONL 里没有宿主可安全写入的元数据位：`custom` **entry** 会被 pi 的运行时装进
聊天（`renderSessionEntries` → 自定义渲染器）、`role: 'custom'` 的 **message** 会进模型上下文、
`session_info` 由 pi 独占（拿它塞宿主字段等于改人家的格式）。
口径的实质要求是**不新增第二份真源** —— 那条守住了：索引按 `sessionId` 存，**没有**
`project → sessionId` 映射，索引整份删掉也只是「先选哪个」退回按活动时间排，
识别会话、读内容、判定归属全都仍只看会话文件。

**排序语义（别改回去）**：有 `lastOpenedAt` 的会话**整类**排在只有活动记录的之前，
同类内再各自比时间。两个时间戳不能直接混比 —— `lastActivityAt` 会被后台续行、
子代理写回、另一个窗口发消息刷新，混比会让「项目最后一个会话」变成「最近被模型碰过的会话」。
