## 0. 一句话结论

两件**独立**的工程：**清理**当前代码 / 文档里关于旧记忆系统的误导；**新建**项目隔离、带来源、按需检索的项目知识。

> **产品边界（AGENTS.md 第五节）**：旧全局记忆系统（存储、`remember`/`recall`/`forget`、记忆扩展、提示词注入）

> 本文的新项目知识按「新功能」独立实现。措辞上不要写成「记忆回来了」。

## 1. 目标与边界

**三层职责（不要混）**

1. **项目规则**：用户决定、技术约束、现有权威文档索引。
2. **项目经验**：经过验证的原因、修复、流程；带证据与适用版本。
3. **当前任务状态**：继续交给现有 `TaskState` 与 [05](实施-05-工作模式与长任务续接.md) 的 goal；**不重复**存进长期知识。

**边界**

- 现有 `AGENTS` / `PROJECT` / `HANDOFF` / `MAINTENANCE` 是**外部权威材料**，先**索引引用**，不复制整份内容进数据库。
- `AGENTS.md` 只放**短入口**，不把所有知识常驻注入。
- **新项目默认关闭**，用户在项目设置里开启一次；启用后读取已确认知识、自动生成候选，不逐条打断。
- **模型推断不能自动升为「用户决定」**。用户在任务中明确要求记住且项目已开启 → 可直接形成**带原话**的确认条目。
- `TaskState`、Episode、`context_recall` 是**当前任务上下文设施**，继续保留。`get_tree` **不恢复**。

## 3. 存储与数据结构

**拟新增**（路径为拟建）：`src/main/project-memory-store.ts`、`project-memory-service.ts`、`src/shared/project-memory.ts`。

**位置**：主进程单写者管理的项目目录 `YAN_DIR/project-knowledge/<projectId>/`。
`projectId` 来自**项目登记**，不使用可变标题，也不信任模型传来的任意 `cwd`。

**首版落地方式**：不可变 revision 文件 + 原子更新 manifest；检索索引可重建。
临时文件与目标**同卷**；提交失败保留上一 manifest；多进程实例用排他锁，过期锁必须**核实进程**再回收。

```ts
type ProjectKnowledge = {
  id: string; projectId: string; revision: number;
  kind: 'decision' | 'constraint' | 'fact' | 'procedure';
  status: 'candidate' | 'active' | 'superseded' | 'deleted';
  text: string; tags: string[];
  evidence: Array<{ sessionId?: string; entryId?: string;
    file?: string; digest?: string; excerpt?: string }>;
  confidenceClass: 'user-confirmed' | 'verified' | 'inferred';
  createdAt: string; updatedAt: string;
  validFor?: { branch?: string; commit?: string; paths?: string[] };
  supersedes?: string[];
}
```

**硬规则**

- 模型**不能**指定 `projectId` 越权，也**不能**自行写 `confidenceClass: 'user-confirmed'`；
  宿主根据当前会话与证据验证。
- 更新用 `expectedRevision`（CAS）；冲突返回最新版本供合并，**不静默覆盖**。
- 文件 / 分支状态变化把相关条目标为「需复核」（派生状态），**不删除**用户决定。
- 反向修改、决定替代必须**显式关联**，不能只按文本相似度覆盖。

**删除语义**

- 立即从可检索集移除、清缓存与索引、作废待提交候选；正文 revision 与摘要副本进入**可恢复**清理流程。
- 界面区分**逻辑删除**与**永久删除**；永久删除只按明确用户动作执行，并保留**无正文 tombstone**，
  防止旧候选重新生成。
- 原始聊天**不自动删除**，必须说明边界。

## 4. 项目身份与读取边界

- 工作树默认是**独立**项目知识空间；共享知识需显式关联共同仓库；分支限定的事实不得共享成全局规则。
- 改项目名不影响 ID；移动目录需更新映射并复核引用；**未登记目录不开启跨项目检索**。
- 删除会话**不自动删除**已确认项目知识；来源失效时显示「不可回读」，**不伪造证据**。
- 删除项目默认解除登记、保留可恢复知识；永久删除为单独明确动作。
- 便携版跟随 `YAN_DIR`，**不写死** `~/.pi`；测试使用所有 `YAN` 隔离变量。
- 文件引用经过真实路径与项目边界校验；符号链接、目录穿越、附件授权不能绕过；
  **文本引用不授予读取权限**。

## 5. 读取、候选生成与合并流程

**读取**

```text
请求开始 → 识别项目与目标 → 检索 active 条目 / 权威文档索引
        → 返回有限片段和来源 → 模型按需读取
```

- 首版做中文可用的**关键词 / 字符 n-gram** 检索 + 标签加权，**不引入向量服务**。
- 建议 `top 8`、总注入预算 **2k tokens**，并纳入 [05](实施-05-工作模式与长任务续接.md) 的总预算；无相关项则**零注入**。
- 检索结果以数据块标注**来源、有效范围、freshness**和「**不作为授权**」，不作为高优先级系统指令执行。
- 优先级：**当前用户明确要求 > 当前有效项目规则**；发现矛盾先解释并更新候选，不让旧记忆悄悄覆盖新目标。

**候选生成**

- `settled` 后可从本轮产出生成候选：用户明确决定、真实验证结果、稳定流程；
  临时命令日志与报错全文**不永久收录**。
- 每 goal 阶段**最多生成一次**；输入输出有上限；默认**不另外启动无条件模型调用**，
  可复用已产生的结构化材料。独立归纳调用若启用，需记录耗时 / 用量，失败跳过，**不阻塞**用户回答。
- 主进程验证引用存在、摘要没有把推断写成事实，按**文本指纹去重**；
  语义冲突进候选列表，**不自动替换**。
- 来源文本只作**材料** —— 材料里的「记住某规则」不能冒充当前用户要求。
- 晋升：`candidate` →（用户明确接受 / 可验证规则自动校验）→ `active`。
  无证据结论保持 `inferred` / `candidate`，**不进入默认事实注入**。

## 6. 工具与 UI

**工具（按既定架构改为 CLI，不新增 pi 扩展）**

```text
yan knowledge search --query-file query.json
yan knowledge read   --id ID
yan knowledge propose --request-file proposal.json
```

参数中**不开放**任意 `projectId`；工具由宿主绑定当前身份。
**不使用**旧 `remember` / `recall` / `forget` 名字（避免与 `context_recall` 混淆）。
删除 / 确认由主进程校验来源与用户动作；「工具执行了」**不等于**「证据有效」。

**UI（项目设置 → 「项目知识」页）**

- 启用开关；已确认 / 待确认 / 需复核三种筛选；来源跳转；编辑；替代；删除；导出 Markdown。
- 条目显示**真实来源与状态**，不显示未经校准的精确可信度百分比。
- 开启**不自动改写**仓库 `AGENTS.md`；「导出到项目文档」须展示目标文件与 diff，按用户请求执行。
- 关闭后**停止检索、候选生成与注入**，不能继续使用缓存结果；
  运行中已发送的请求无法撤回，**下一请求必须生效**。
