## 当前方案的关系

**实施计划（接下来一次会话做什么）→ HANDOFF（现在是什么样）→ 工程清单（验到什么程度）→ 实施方案（架构怎么做）→ PROJECT / CODE-MAP（改哪里）。**

- N12 会话运行是项目切换、定向队列、语言、命令及子代理生命周期的基础。
- L02 与 N19 共用文件引用语义；N18 与 N19 共用输入补全和项目切换竞态验收。
- 功能完成后统一进入发布门槛（见[实施-09](plan/active/实施-09-交付与验收收尾.md)），不能用历史包结果替代最终源码验收。
- 日期快照（STATUS / WORK-PLAN / AUDIT / 审阅报告 / 功能清单 / 旧排期）已归档到 [archive](archive/)；文件带日期不代表内容全部作废，工程清单的验收条件仍有效。
- 方案、完成正文、验收证据和外部原文各自只有一份正文，分别位于 `plan/active/`、`archive/plan/`、`archive/evidence/` 和 `archive/reference/`；不要在其他目录重新复制。
- 上下文管理有**两份**核心输入：[方案-上下文工具内的自动压缩](design/active/方案-上下文工具内的自动压缩-2026-09-15.md)（砚自己的设计 + 阶段落地记录 + §12 阶段 4 契约 + §13 对外部参考方案的对齐结论）与
  [参考-长上下文状态化压缩（外部方案·原文）](archive/reference/参考-长上下文状态化压缩（外部方案·原文）.md)（用户提供，**逐字归档、不在本仓改写**）。
  两者关系与取舍只看前者的 §13；剩余任务见[实施-06 上下文管理收尾](plan/active/实施-06-上下文管理收尾.md)。
  外部评审的**原文存档**另有四份（都是外部意见，不是本项目的决定）：
  [上下文管理外部评审（ChatGPT·原文）](archive/reference/参考-上下文管理外部评审（ChatGPT·原文）-2026-09-17.md)、
  [同题 Codex](archive/reference/参考-上下文管理外部评审（Codex·原文）-2026-09-17.md)、

  每份都在活动方案 §16/§17 里有对应的「核查 + 采纳/不采纳」小节，**以方案为准**。

## 维护规则

1. README 保持短入口；不要加入排障经过、测试数量和完整文件树。
2. 未完成项只改[实施计划](plan/README.md)；当前状态与证据只改 HANDOFF；工程清单只改需求、验收条件与证据链接。
3. 实施方案描述目标，PROJECT 描述已有实现，两者不可混称“已完成”。
4. 测试结果带日期和适用范围；完整日志、截图归验证报告，不复制到每份文档。
5. 历史记录不作当前指令；保留截图、原始证据和仍被引用的路径。
6. 自动生成的 [CSS 令牌清单](design/CSS-令牌清单.md) 与 [样式归属表](design/CSS-归属表.md) 不手工精简；设计令牌先改 DESIGN 再同步代码。

新会话可使用 [NEXT-SESSION](dev/NEXT-SESSION.md) 的简短开场说明。AI 必须遵守的工作区规则集中在根目录 [AGENTS.md](../AGENTS.md)。
