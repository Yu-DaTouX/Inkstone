### 2.1 复用边界

## 3. 产品结构与界面

### 3.1 环境菜单

会话头部保留项目胶囊，将其变成菜单入口。旁边按空间显示分支、文件数与增删统计；点击变更摘要直接打开审查。非 Git 项目显示“未使用 Git”，仍允许文件来源等功能。

| 菜单项 | 展示 | 行为 |
|---|---|---|
| 变更 | 文件数、文本增删统计 | 打开工作区全部改动 |
| 本地 / 本地工作树 | 实际执行环境 | 打开“继续至”子菜单及路径信息 |
| 当前分支 | 分支名、detached 或尚无提交 | 搜索、切换、新建分支 |
| 提交或推送 | 暂存数、未推送提交数 | 打开明确的操作面板 |
| PR 状态 | 编号、状态、检查或不可用原因 | 打开详情/托管网页 |
| 比较分支 | 基准与目标 | 在 Yan 内比较或打开托管网页 |
| 来源 | 附件与网页摘要 | 打开来源详情与全部来源 |

菜单上的“+”必须有具体文字提示和键盘可访问名称，例如“添加来源”“添加工作目录”；不能用一个图标承载多个不明动作。

### 3.2 审查布局

- 顶部：范围、基准/目标、统计、刷新、统一/并排显示、提交/推送。
- 左侧主体：连续排列的文件差异，逐文件折叠，可定位到指定行。
- 右侧：只含变更的文件树，文件名与状态筛选，已查看进度。
- 宽窗口支持聊天与审查并排；审查可扩大占据主内容区。
- 窄窗口将文件树改为抽屉或切换页，diff 自动使用统一显示。
- 关闭审查恢复聊天滚动位置、输入草稿及此前视图。

建议引入统一的详情视图状态，例如 `none / browser / file / subagent / review`，另保留工具栏是否展开的状态。审查显示时正确隐藏原生 WebContentsView，恢复时校验浏览器仍存在且此前确实可见。

## 4. 审查的数据语义

### 4.1 范围定义

| 范围 | 比较语义 |
|---|---|
| 工作区全部改动 | 当前工作区最终内容相对 HEAD 的变化，另含未跟踪文件；暂存/未暂存状态单列 |
| 未暂存 | 工作区相对 index；未跟踪文件单列 |
| 已暂存 | index 相对 HEAD；无首提交时相对空树 |
| 分支改动 | 共同祖先到目标分支 HEAD 的变化 |
| 两端比较 | 指定两个提交最终树的直接差异 |

工作区总览不能简单把已暂存与未暂存行数相加，否则同一段内容可能重复计算。文件在 index 中有改动、工作区又恢复为 HEAD 时，总览仍应保留状态提示，允许展开两部分审查。

分支范围不静默混入未提交内容，界面单独提示。若共同祖先不存在，明确说明并允许用户主动改用两端比较。远程跟踪分支展示最近获取时间；刷新本地 diff 与获取远程更新分开。

### 4.2 文件类型与展示

- 文本：统一/并排 diff、增删行号、语法高亮、展开上下文、复制路径和定位文件。
- 新增/删除：允许单侧内容，不伪造缺失的一侧。
- 重命名：记录旧路径和新路径，单独显示内容变化。
- 冲突：标明 unmerged，首版以冲突状态和各版本读取为主，不伪装成普通可提交文件。
- 图片：新增显示新图，删除显示旧图，修改并排显示前后图；支持适配/原尺寸、尺寸与字节信息。
- 二进制、LFS 指针、超大文件、子模块：明确类型和限制，不能显示误导性的 `+0 -0` 或成功加载状态。
- SVG/HTML 不以不受控的可执行文档方式嵌入；图片预览采用受限资源通道或安全转换。

旧图片从 Git 对象读取；另一侧按范围从工作区、index 或指定提交读取。资源返回类型、大小和稳定标识，避免将完整大图反复塞进全局 IPC 快照。

### 4.3 已查看与刷新

已查看由用户主动标记，可一键标记当前文件；滚动经过不自动算已查看。

持久化键至少包含：仓库身份、工作树身份、范围、旧/新路径、两侧内容指纹。diff 发生变化即失效，其他文件的标记保留。分支切换或基准变化后重新匹配，不沿用仅以路径为键的旧标记。

轻量监听与防抖刷新结合：面板打开、应用重新获焦、已知工具任务结束和 Git 操作结束时刷新；不递归监听整个依赖目录，也不持续全量生成 patch。状态清单先返回，正文按文件懒加载。

## 5. Git 操作

### 5.1 分支

展示本地、远程跟踪、当前分支及被其他工作树占用的状态。新建时明确起点和是否切换，校验名称。切换前检查该工作目录的运行任务；有写入任务时阻止切换并说明。

脏工作区不等于一律不能切换，但必须保留用户改动并让 Git 的实际检查决定是否可切换。拒绝时显示原因，不自动 stash、reset、clean 或覆盖。无 Git、无首提交、detached HEAD 都有独立状态。

### 5.2 暂存与提交

第一版按文件暂存/取消暂存，第二版再增加按块或按行。文件同时含暂存和未暂存部分时分别展示；新增文件取消暂存也要兼容无首提交仓库。

提交面板以真实 index 为最终预览来源，显示仓库、分支、文件与提交说明。点击提交前复核 index/HEAD，发生变化则刷新预览，不提交用户尚未审阅的新增内容。执行真实 commit，显示身份未配置、hook/签名失败等原因，不静默跳过 hook。

### 5.3 推送

保留统一入口，但动作分为“提交”“推送”“提交并推送”。后者作为两个有结果记录的步骤：提交成功、推送失败时保留提交，重试只推送。

显示 remote、远程分支、upstream 与待推送提交；首次推送明确设置 upstream。默认不提供强制推送、自动 rebase、自动冲突解决。认证依赖系统 Git 凭证机制，日志不记录凭证。

### 5.4 一致性与并发

写操作按仓库协调，涉及当前分支、index 和工作目录的操作按工作树绑定。操作记录包含 projectId、repoId、worktreeId 和预期版本；执行前检查实际状态。外部进程不受 Yan 的锁控制，需检测变化与 Git lock 错误，不能声称内部锁消除了所有竞争。

超时或取消后重新查询实际状态；尤其提交/推送可能已完成，禁止无条件重试造成重复操作。

## 6. “继续至”与本地工作树

### 6.1 本地

显示当前实际工作目录，支持打开文件夹、复制路径和返回当前环境。环境选择与聊天会话身份分离：切环境不允许只修改一个 cwd 字段后继续使用旧 pi 实例。

### 6.2 新建本地工作树

分两步交付：先支持“创建并打开独立工作树”，再支持“带会话继续”。

创建流程：选择起点 → 输入新分支名 → 选择由 Yan 管理的目标目录 → 展示将携带的内容 → 创建成功后登记为可独立打开的项目/环境。

默认从已提交状态创建，明确提示“未提交改动不会自动带入”。可选“携带当前未提交改动”作为后续能力：分别捕获已暂存、未暂存及用户选择的未跟踪文件，保留二进制与文件状态，在目标验证应用；源工作区及 index 保持不变。无法准确迁移的冲突、子模块等情况阻止迁移并解释，不退化成全目录复制。

用户工作树有独立生命周期：保存路径、分支、所属仓库、关联任务；关闭窗口不删除。删除前检查未提交与未推送内容，不复用子代理的强制清理函数。

### 6.3 带会话继续

前置条件是源任务停止并完成落盘。创建新的目标会话/运行实例，记录来源关系，按现有 JSONL 历史机制展示继承内容，不把压缩后的 `get_messages` 当完整历史。

必须重绑定项目权限、相对文件路径、附件授权与上下文派生状态；旧进程继续留在源目录或已停止，不能静默换 cwd。第一版若无法正确完成这些重绑定，只开放“在新工作树开始新会话”，不显示“无缝继续”。

### 6.4 外部网页任务与云端

截图中的“关联 Codex Web”属于外部产品集成参考，不能推断 Yan 已有官方交接接口。首版可规划通用“关联外部任务链接”：保存用户提供的 URL 与标题并打开网页，文案明确只是关联，不宣称上传代码、同步会话或远程执行。

云端执行暂列外部依赖：需要服务端执行器、身份认证、仓库权限、数据同步和计费方案。没有可工作的后端时不展示可执行入口，也不伪造登录/同步状态。当前 Android 远程控制 API 不等于云端执行环境。

### 6.5 剩余用量

复用现有用量展示和 provider 能力，区分当前会话 token、上下文占用、费用估算与账户配额。只有供应商权威接口返回的额度才能显示“剩余用量”和重置时间；缺字段时显示不可用及原因，不用上下文剩余量推算账户额度。

## 7. PR 与远程比较

第一阶段支持 GitHub，通过独立 hosting adapter 隔离平台差异。可先采用 GitHub CLI 结构化输出，未安装/未认证时保留本地 Git 能力并提示；后续再评估直接 API 和其他平台。

状态区分：无关联 PR、查询中、草稿、打开、已合并、已关闭、检查中/通过/失败、认证错误、网络失败、不支持的 remote。关联依据仓库与实际 head/base 信息，处理多个 remote 和 fork，不能仅按同名分支猜测。

比较分支同时提供 Yan 内部比较与托管网页比较。创建 PR 是单独后续动作，不与读取状态混合；本阶段不自动合并 PR。

## 8. 来源与附件菜单

菜单展示当前会话实际关联的图片缩略图、文件名称、网页标题；截图中的剪贴板附件属于此类数据。

来源模型建议包括：sourceId、sessionId、kind、标题、原始定位信息、持久化资源引用、添加时间、获取状态、内容指纹以及可选的消息关联。粘贴图片复用现有附件存储链，核查其是否持久化；不能只保存会被清理的临时路径。

交互：

- 添加来源：选择文件、粘贴图片或网址；目录仅授予可浏览范围，不自动注入全部文件。
- 查看全部：筛选图片、文件、网页；打开原文、定位关联消息、移除会话引用。
- 移除引用不删除用户原文件，也不改写已发送的历史消息。
- 明确区分“已关联”“已读取”“本轮已参与上下文”；证据不足时不显示后一状态。
- 网页搜索只有在已发现兼容搜索能力时启用；浏览器能导航不等于存在搜索服务。
- 来源按会话/项目隔离，切换后忽略迟到响应；获取失败可以重试并保留原因。

## 9. pi 插件目录与管理

接入官方 [Package Catalog](https://pi.dev/packages)，产品称“pi 插件目录”，分别标明包作者和维护来源，收录不代表官方维护或审核。

P1：设置增加目录入口和已加载资源列表；确认目录有稳定数据接口后再做原生搜索。详情区分扩展、技能、提示模板和主题，标注 Yan/RPC 兼容性。终端主题不直接应用到 React 界面。

P2：新增安装指定版本、启用/禁用、更新、卸载、加载结果。包管理使用 Yan 实际 PI_AGENT_DIR 和项目作用域，不直接修改生成的 pi-runtime。安装成功、加载成功、当前会话可用分别记录；任务运行中安排安全的生效时机。

本轮读取的内置 pi 版本为 0.85.1，官方在线文档为 latest；实施前核对当前实际版本和命令能力。扩展具有执行代码能力，详情页说明来源与实际影响，不宣称沙箱隔离。兼容性验证在隔离环境进行，涵盖与内置语言、浏览器和上下文扩展的冲突。

## 10. 颜色与字体重构

### 10.1 颜色

保留已有深浅主题基础，目标是统一语义而非整体换肤。建立应用背景、侧栏、卡片、输入框、悬停、选中、焦点的用途令牌；文字分正文、次要、辅助、禁用。diff 新增/删除和语法色保持独立用途。

逐个清点硬编码颜色及引用，处理过期注释和命名，例如已移除记忆模块留下的 `--fact` 用途说明。先核查引用再调整，不批量删除旧名样式。新审查面板优先使用统一令牌。

### 10.2 字体

当前 DESIGN 仍强调全部等宽，chat.css 已采用正文无衬线、代码等宽，应先统一规范。建议分 `font-ui / font-body / font-mono`：界面与正文使用适合中文阅读的字体栈，代码/diff/终端保留 Maple Mono CN。

候选字号供真实对照：UI 13px、正文 14px、代码 12.5–13px、辅助信息 11–12px。它们不是已定值，需与当前版在深浅主题、长中文、混合英文、文件路径、表格和缩放场景比较。正文和输入框风格协调；字体大小与布局密度分离。

先更新 DESIGN，再同步 tokens；以真实 Electron 视觉证据确定最终值，旧截图不覆盖。等宽栅格的测量结论不直接外推为所有 UI 字号的唯一约束。

## 11. 技术拆分与数据边界

以下为拟新增模块，不表示文件已存在：

| 模块 | 职责 |
|---|---|
| `src/main/git-service.ts` | 仓库发现、身份、状态、分支、查询与调度 |
| `src/main/git-diff.ts` | 清单、统计、文本 patch、版本内容与二进制元数据 |
| `src/main/git-actions.ts` | 分支、暂存、提交、获取远程、推送 |
| `src/main/git-worktrees.ts` | 用户工作树登记、创建与生命周期 |
| `src/main/git-hosting.ts` | remote、PR、托管网页地址 |
| Git 共享协议及 preload 接口 | 明确类型、能力、身份、请求版本和错误 |
| `EnvironmentMenu` / `ReviewPanel` | 环境入口、布局与范围选择 |
| `ChangedFileTree` / `DiffViewer` / `ImageDiff` | 变更导航与内容呈现 |
| `BranchPicker` / `CommitPanel` / `WorktreeDialog` | 写操作的具体可审阅界面 |
| 来源状态与视图 | 附件/网页记录和会话级展示 |

Git 使用 execFile 参数数组，不拼接 shell 命令。结构化清单采用 NUL 分隔解析，正确处理中文、空格、制表符等路径。禁止渲染端传任意 Git 命令；主进程按已登记项目解析目录并验证 IPC 来源、路径边界与 ref。

查询关闭 external diff 和 textconv；读取路径使用明确的字面路径语义。只读状态查询尽可能避免可选 index 刷新写入。历史文件预览同样进行内容类型和大小检查。

每个响应绑定 projectId、repoId、worktreeId、范围与请求版本。用户切项目后丢弃迟到结果。缓存按文件版本索引，统计与正文发现状态已变化时重查或显示已过期，不拼接不同时间点的结果冒充一致快照。

### 13.1 自动与真实行为验证

使用临时 Git 仓库、本地 bare remote 和隔离的 Yan 数据目录，不在真实项目造测试改动。

- 内容呈现：旧/新图片确为不同版本；大文件截断可见；已查看在内容变化后失效。
- 写操作：脏目录切分支、分支占用、hook 失败、锁冲突、外部并发、提交成功/推送失败、无 upstream、非快进拒绝。

- 来源：临时附件转持久化、切会话隔离、原文件不存在、网页获取失败、移除引用保留原文件。
- 插件：隔离安装、加载、实际调用、禁用/卸载、版本不兼容与加载失败。

本地 bare remote 的推送成功不能替代真实平台认证和 PR 查询验收；后者需要具备权限的测试仓库并单独记录结果。

### 16.4 与方案的偏差（以及为什么）

| 方案原文 | 落地形态 | 理由 |

| §3.2「审查可扩大占据主内容区」＋「宽窗口支持聊天与审查并排」 | 审查是**右栏的详情视图**，打开时右栏走宽档位 `clamp(420px, 46vw, 900px)` | 占主内容区要把聊天整块卸载，滚动位置与输入草稿都得手工保存/恢复（两处都是真实的状态，容易丢）；而「边聊边看改动」本来就是审查时的常见需求。Codex 的参考界面也是并排 |
