## 5. 状态语义与优先级（按批注 03/06）

### 5.1 五态定义

| 状态 | 数据源 | 视觉 | 所在维度 |
|---|---|---|---|
| **hover** | CSS `:hover` | `--bg-3` 底 + `--r-sm` 圆角 | 指针 |
| **focus** | `focusPath`（键盘游走） | hover 视觉 + 1px `--accent-line` 内描边（`outline-offset:-1px`） | 键盘 |
| **current（预览中）** | `store.filePreview.path` | `--bg-3` 底 + 左侧 2px `--accent` 竖条 | 选中语义 |
| **in-context（已加入）** | `store.fileRefs` 含该绝对路径 | 名称右侧一个小圆点（`--accent` 40% 透明），**不占额外宽度** | 标记 |
| **expanded（目录展开）** | `open` Set | chevron 旋转 90° + `folder-open` | 结构，不参与上述优先级 |

### 5.2 优先级与叠加规则

```
current  >  focus  >  hover          （底色/竖条只由 current 与 hover/focus 决定）
in-context 独立叠加（只加一个点，不改底色）
expanded 独立（只改 chevron 与图标）
```

- current 与 focus 同时成立时：底色取 current，内描边取 focus（两条信息都要保留，且不冲突）。
- **不使用 `aria-selected`**（未实现 tree 选择模型），改用 `aria-current="true"`；目录继续用 `aria-expanded`。
- 术语统一为 **current / previewed**，文档与代码里不再出现 `selected`。

### 5.3 窄栏与 trailing 槽位（按批注 07）

根因不是"两个元素同时出现"，而是 `.rp-fs-size` 用 `display:none ↔ inline` 切换 —— **显隐本身改变文本可用宽度**，所以 hover 时文件名会跳。

规格：行内右侧固定一个 trailing 槽（`44px` 体积 + `22px` 按钮 = `66px`，右对齐），两个子元素始终占位、只用 `opacity`/`visibility` 切换；名称区 `min-width:0` + `text-overflow:ellipsis`，hover 前后**字符宽度不变**。

### 5.4 计数：完全不显示（用户定稿 2026-09-15）

懒加载下不存在可信 total；而“根目录 N 项”的信息价值也偏低，容易被误读成项目规模。
右栏窄态只有约 210px，项目头只承担**项目身份 + 展开/折叠**。因此：

- 项目头**不显示任何计数** —— 就是 `▾ 📁 pi-desktop`。
- **同时去掉分区头部原有的计数**（它是“所有已加载层的条目数之和”，口径同样不成立）。
- **不新增** `rp.fsRootCount` 之类的 i18n 键。
- 隐藏项（`node_modules` 等）继续走现有的「已隐藏：…」行。

## 6. 「显示更多」的精确定义（按批注 09）

```
作用对象：当前已加载的可见行（不新增目录读取、不递归展开）
默认上限：50 行
点击一次：+50 行（visibleLimit: 50 → 100 → 150 …）
按钮文案：「显示更多（还有 n 项已加载）」，n 归零即隐藏
重置时机：切 cwd / 换 generation / 换 projectId / 关闭搜索
不做什么：不改 expanded 集合、不预读子目录、不一次渲染全部
```

**语义强调（用户定稿）**：50 是 **UI 展示批次，不是文件系统加载批次**。点十次「显示更多」也不会多读一个目录。

实现约束：`visibleLimit` 同时约束**渲染行数**与**键盘游走的可见顺序**（两者必须一致，否则方向键会走到没渲染出来的行）。

与内部滚动的关系（补 v1 缺失的事实）：树本来就是 `max-height:280px` 内部滚动，因此「显示更多」控制的是**行数**，滚动控制的是**可视高度**，两者叠加时按钮固定在列表末尾（随内容滚动，不做吸底），避免与右栏滚动竞争。

> **批注 01｜样式归属：** `.rp-fs-*` 同时散落在 `tools.css` 和 `redesign.css`。这次既然会改 hover / focus / current 等交互态，建议顺手明确唯一 owner，至少不要继续在两个文件里叠加同名选择器，否则 specificity 覆盖会让后续视觉回归很难定位。

> **批注 05｜项目头的实现方式：** 项目头应当**替换现有 root row 的视觉呈现**，而不是在 root 上方再插入一层。数据仍复用 root node，但渲染上直接把它升级为 project header，否则会形成“项目头 pi-desktop → 根目录 pi-desktop → src”的重复层级，键盘 tree 语义也会多一个无意义节点。

> **批注 06｜“当前项”语义：** 建议明确成 `previewed/current`，不要直接等同于 `selected`。后续如果支持多选、上下文勾选或批量操作，`selected` 会产生语义债。DOM 上的 `aria-selected` 也只有在容器真正采用 `role=tree` / `treeitem` 的选择模型时才合适；目录折叠则应有 `aria-expanded`。

> **批注 07｜窄栏布局：** 210px 宽度下，文件体积和“加入上下文”按钮同时出现很容易挤压文件名。建议给 trailing action 预留固定槽位，或者让动作区绝对定位叠在右侧渐隐层上，避免 hover 前后文本宽度跳动。

> **批注 09｜最需要改的是“展开显示”：** 不建议“超过 50 项后一次展开全部”。这会和现有懒加载边界打架，尤其大型 monorepo 下可能一次性制造大量 DOM，甚至触发不必要的目录读取。更稳妥的定义是：**默认最多渲染 50 个已加载可见项，点击后再增加 50；不递归展开目录，也不读取未展开目录。** 如果本意只是限制根目录子项，则应明确写成“根目录直接子项 > 50”。

> **批注 10｜实现项建议调整：** `FileTree.tsx` 里的①建议改成“将 root row 渲染为项目头”，③不要用 `expandedAll: boolean`，更适合用 `visibleLimit` / `showMoreLoaded` 之类只控制渲染量的状态，避免把“展示更多”和 tree expansion 混在一起。

> **批注 11｜测试应偏行为而不是死锁像素：** `--r-sm` 以后如果改 token，探针不应仅因为 token 调整就误报功能回归。可以验证 computed style 等于当前 CSS 变量的计算值；同时补行为断言：项目折叠后的焦点落点、重新展开后的 active row 恢复、`Alt+Enter` / `A`、方向键、搜索取消均保持原行为。

> **批注 12｜再补三组边界：** ① 超长文件名 + 210px 窄栏 + hover action 同时出现；② 当前预览文件位于折叠目录内时，折叠父级后的 current/focus 状态；③ 搜索模式下是否还显示项目头与“显示更多”，以及“显示更多”究竟作用于搜索结果还是原文件树。
