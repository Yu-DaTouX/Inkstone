## 1. 设计意图

将砚设计成以内容为中心的“墨色工作空间”：安静、清楚、精致。主对话是第一视觉重心，
输入区是下一步操作的稳定锚点，执行过程、状态和诊断按摘要到详情分层。

界面与正文使用适合中文阅读的无衬线字体；代码、diff、终端和技术标识继续使用等宽字体。
品牌识别使用唯一的提示砚源图形，功能按钮仍使用语义化线性图标。

对外英文产品名为 **Inkstone**，中文名为 **砚**（2026-09-24）。命名、主页 slogan、字标组合与可换色素材见 [品牌与项目主页](BRAND.md)；本页继续维护 UI 令牌与组件规范。

### 三条不可动摇的原则

| # | 原则 | 含义 |
|---|---|---|
| 1 | **内容优先** | 正文、产出和输入操作优先于工具元数据；执行过程默认显示摘要，详情按需展开 |
| 2 | **字体分工** | UI 与正文使用无衬线，代码、diff、终端与路径使用 `--font-code` 等宽字体 |
| 3 | **克制层级** | 通过留白、暖中性色和少量边界表达分区，不用重复徽章、装饰线或持续发光争夺注意力 |
| 4 | **单一强调** | 交互强调使用靛蓝；成功、警告、错误保留独立语义色，品牌色不承担状态含义 |

## 2. 设计令牌

### 2.1 字体

```css
/* 内嵌，不依赖用户已装字体 —— 见 docs/design/font-test/README.md */
@font-face {
  font-family: "Maple Mono CN";
  src: url("../assets/fonts/MapleMono-CN-Regular.woff2") format("woff2");
  font-weight: 400; font-display: block;
}

--font-mono: "Maple Mono CN", ui-monospace, Consolas, monospace;
--font-code: var(--font-mono);   /* --font-mono 的别名 */
--font-ui:   "Segoe UI", "Microsoft YaHei UI", system-ui, sans-serif; /* 导航、按钮、标题 */
--font-body: var(--font-ui); /* 对话正文与多行输入 */
```

#### 字族的分工（2026-09-21）

| 令牌 | 用在哪 | 为什么 |
|---|---|---|
| `--font-ui` | 按钮、导航、列表、树、状态、标题栏 | 中文控件与阅读文本保持一致，减少界面碎片感 |
| `--font-body` | 消息正文（`.md`）、问题面板和主输入 | 中文长段落的行长与行高更舒适 |
| `--font-mono` / `--font-code` | 代码块、行内代码、diff、终端、工具参数 | 栅格对齐是硬需求（§2.2 的整数像素论证只对它们成立） |

> **两条约定**：
> 1. 新增样式**不要**再写裸字体名 —— 一律取上面某个令牌（历史上 `.md` 与
>    `.qpanel-editor` 各硬编码过一次，改字体要满仓找）。
> 2. `--font-code` 曾经**只被引用、从未定义**（chat.css / tools.css 各一处），
>    那两条声明一直在静默失效。现在它显式等于 `--font-mono`。

> 本轮已确认 UI 13px、正文 14px、代码 12.5px。等宽栅格只用于技术内容，
> 不再用“所有界面文字必须落在等宽整数栅格”限制中文 UI 的可读性。

> **实施状态（已落地）**：不再自带字体文件。改为 npm 依赖
> [`@mogeko/maple-mono-cn`](https://www.npmjs.com/package/@mogeko/maple-mono-cn)
> （Maple Mono CN 的 `cn-font-split` 重打包：239 个 woff2 分片 + `unicode-range`，
> 共 9.7MB，而**实际只加载当前用到的几个分片**）。
> 字号与栅格指标与原全量 TTF **完全一致**（12.5px 下汉字格 15.000px、
> 拉丁列 7.500px、比值 2.000，有 `npm run shot` 与 live 场景验证）。
> `npm install` 会安装字体依赖，无需额外复制本地字体文件。
> 授权：字体 SIL OFL 1.1，打包 MIT，均可随软件分发。

**必须内嵌字体，不能靠系统回退。** 原因：

终端风格 UI 的命门是**栅格对齐** —— 一个汉字必须正好占两个 ASCII 字符宽，
否则表格、边框、diff 标记全部错位。而常见英文字体的 ASCII 宽**不是 0.5em**，
永远凑不出整数比：

| 字体 | ASCII 宽 | 汉字宽 | 比值 |
|---|---|---|---|
| Cascadia Code | 0.586em | 1.000em | **1.707** ✗ |
| Consolas | 0.550em | 1.000em | **1.819** ✗ |
| Microsoft YaHei | 0.977em | 1.000em | **1.023** ✗ |
| **Maple Mono CN** | **0.600em** | **1.200em** | **2.000** ✓ |

所以要凑 2.000，中文字体得是 1.172em 宽 —— **不存在这种字体**。
唯一的出路是选一个**拉丁部分本身就是整数倍步进**的字体。

#### Maple Mono CN 的两个特性

1. **列宽 0.6em，汉字 1.2em**（严格 1:2）。
   注意：列宽 0.6em 比 Cascadia 的 0.586em 宽一点，所以**同一个列宽下 Maple 的字号要小一档**。
2. **自带连字**（`-->` `!=` `<=` 会变成合并字形）。连字**不改变字符宽度**，
   所以不影响对齐，纯风格问题。约定：

```css
/* UI 文字关掉连字，代码/ diff 打开 */
button, .label, .tab, .rail-item { font-variant-ligatures: none; }
.code, .diff, .tool-pre         { font-variant-ligatures: contextual; }
```

### 2.2 字号

**UI 基准 13px、正文 14px、代码 12.5px。** 字号服务于阅读层级；DPR、系统回退和缩放
仍需通过真实窗口检查，不能只凭字号或截图文件名宣称清晰：

| 字号 | 拉丁列宽 | 汉字格宽 | 汉字整数像素 | 栅格最大偏差 | 780px 可容列数 |
|---|---|---|---|---|---|
| 11px | 6.600px | 13.200px | ✗ | — | 118 |
| 11.5px | 6.900px | 13.800px | ✗ | — | 113 |
| 12px | 7.200px | 14.400px | ✗ | 0.234px | 108 |
| **12.5px** | **7.500px** | **15.000px** | **✓** | **0.000px** | **104** |
| 13px | 7.800px | 15.600px | ✗ | — | 100 |

只有 12.5px 的汉字格是整数（15.00px）。DPR 1 下 15px 落回整数像素栅格，
汉字笔画不发虚、字与字之间没有细微分差；DPR 2 下 15px 是 30 物理像素，同样对齐。
12px 的 14.4px 无法落在整数栅格上，差量被逐字累积成 **0.234px 的抖动**。

对比图：[`preview/fontsize-compare.png`](./preview/fontsize-compare.png)
（`fontsize-a-12px.png` / `fontsize-b-125px.png` 为整页对照）

代价是每行少 4 列（108 → 104）。换来的是等宽栅格真正对齐 ——
这是选 Maple 的全部意义所在，值得。

| 令牌 | 值 | 用途 |
|---|---|---|
| `--fs-xs` | 11px | 角标、次级元数据、树节点、diff 行号 |
| `--fs-sm` | 12px | 会话项、键值、按钮 |
| `--fs-code` | **12.5px** | 代码块、diff、终端 |
| `--fs-base` | **13px** | 界面基准 |
| `--fs-body` | **14px** | 消息正文与主输入 |
| `--fs-lg` | 15px | 面板标题 |
| `--lh-tight` | **1.45**（旧 1.35） | 紧凑行 |
| `--lh-base` | **1.65**（旧 1.6） | 正文 |

> 行高上调是因为 Maple 的汉字字面框就是 **1.2em**，比常见字体高。
> `1.35` 下的中文行会贴得过紧。
>
> 复核方法（零成本，改动字号后必跑）：在 `docs/design/` 下放一个临时 HTML
> （**必须与字体同目录**，见下），用 `document.createElement` + `getBoundingClientRect()`
> 量「国」×50 与「M」×50 的宽度，检查比值恒为 2.0000 且汉字宽是整数。

> ⚠️ `@font-face` 的相对路径**是相对于 HTML 文件所在目录**的。
> 临时测试页必须放在 `docs/design/` 下，不能放到 `preview/` 子目录，
> 否则字体静默加载失败 —— 页面会掉到系统回退字体，尺寸变小但不报错。

### 2.5 尺寸

```css
--h-titlebar:   40px;
--w-rail:       248px;   /* 左：会话列表 + 任务（实际由 layout.css 按用户值/窗口宽度分档夹取） */
--w-stream:     800px;   /* 中：内容列上限（关键，防止宽屏行长失控） */
```

> **2026-09-23（V-1）**：`--w-status` 与 `--tree-indent` 已从 `tokens.css` 删除 —— 右栏
> 搬进设置后没有使用点（`var()` 与 `getPropertyValue` 都没有）；本文下方提到
> 的 `.tnode[data-d]` 文件树也不再是当前实现。

> **2026-09-23 新决定，实施入口 V-2a**：默认只显示最新一句/正在形成的末句，一行尾端可见，不改写原文。一次点击在当前聊天位置展开全文，限高 `min(70vh, 620px)`，折叠头可达；上滚阅读不被流式更新抢回。旧 `--reason-max-h` 多行裁剪是迁移前源码状态，已从令牌与样式中删除，不再作为设计目标。默认无内部滚动条；全文主动展开允许内部滚动。实现证据见 HANDOFF。
>
> 「尾端可见」由两层保证：`.reason-peek` 外层 `dir="rtl"` 把溢出挤到左侧（省略号在左、尾端贴右），内层 `dir="ltr"` 隔离 bidi 以免中英混排被重排；展示层 `peekText` 再按字素只保留尾段做兜底。不要用 `unicode-bidi:plaintext`——它会把方向反回去、变回截尾（2026-09-23 截图实测）；截断只作用于预览，正文仍是模型原文。

三栏比例 **248 : 1fr : 320**，中栏内部再套 `max-width:800px` 居中。

> ⚠️ `--w-stream` 是必须的。中栏是 `1fr`，1920px 下会到 1400px+，
> 没有上限的话 diff 和正文将无法阅读。

> ⚠️ **不要用 `calc(var(--d) * var(--tree-indent))` 做树缩进。**
> `data-d="2"` 这类 HTML 属性**不会**生成同名的自定义属性，`var(--d)` 会求值为空，
> 整条 `padding` 声明失效 —— 而且不报错，树只是「没有缩进」而已。
> 正确写法是属性选择器：`.tnode[data-d="2"]{padding-left:calc(var(--tree-indent)*2 + 4px)}`。
>
> 历史注：`--tree-indent` 与 `.tnode` 已随旧右栏文件树一并移除（2026-09-23 V-1），
> 但这条陷阱对任何「想用同名自定义属性接数据属性」的写法仍然成立。

### 2.6 控件状态：禁用与键盘焦点（V-1，2026-09-23）

这两个状态以前各自散在各模块里，同一个意图有很多种写法（实测禁用不透明度 9 个值、
焦点环 4 种组合）。现在只有一个来源：

| 令牌 | 值 | 用途 |
|---|---|---|
| `--ctl-disabled-opacity` | 0.5 | 所有 `:disabled` 控件的不透明度 |
| `--focus-ring-color` | `var(--accent)` | 键盘焦点环颜色 |
| `--focus-ring-w` | 1px | 默认焦点环宽度 |
| `--focus-ring-offset` | 1px | 默认焦点环偏移 |
| `--focus-ring-w-strong` | 2px | 小目标 / 浮层里空间紧张时 |

- 全局 `:focus-visible`（`tokens.css`）用默认档；**. 不要另写焦点环颜色**。
- 结构性把手（`.resizer` / `.grip` / `.browser-splitter` / `.rp-vgrip`）用 `outline:none`
  加自身 `::after` / 背景高亮表达焦点 —— 这是有意例外，不是遗漏。
- 输入框沿用边框变色（`.set-input:focus-visible` → `--accent-line`），不叠外圈。
- 比 0.5 更低的 0.25~0.4 不透明度属于「半失效 / 过期」语义
  （`.ub-item.dim`、`.tok.dim`、`.tl-dot.off`），不是控件禁用。

标题栏最左的 `sidebar-left` 图标钮折叠左栏，最右的 `sidebar-right` 钮折叠右栏。
宽度**拖拽**（`248` ↔ `320` 之间自由调整）保留用户偏好，设计稿只表达可折叠。

左栏文字与内部导引线必须保持至少 12px 的间距；导引线只表达层级，不得穿过项目名、会话名或图标。
工作区入口只切换“编码 / 日常”工作区，不映射到输入区的 AgentMode（标准 / 澄清 / 自主）。

### 2.5.1 视觉重做（历史对照，2026-09-11）

本节记录上一版卡片 / 终端式视觉的迁移背景，不覆盖上面的 v0.3 当前令牌。

设计稿 v0.2 的令牌偏保守，实际跑起来「三栏糊成一片黑 + 空会话一片死寂」。
以下改动**只在应用侧**（`styles/tokens.css` + `styles/redesign.css`），
设计稿 `prototype.html` 保持原样作为历史基准。

| 项 | 旧 | 新 | 为什么 |
|---|---|---|---|
| 色阶 | `bg-0 #0b0b0d` → `bg-1 #121215`（差 7） | `#0a0a0c` → `#111114` → `#1a1a20` → `#24242d` → `#2f2f3a`（每级差 ~8–10） | 三栏几乎同色，看不出「卡片浮在面板上」 |
| 边框 | `--border` / `--border-str` 两级 | 加 `--border-soft`（分隔线）与 `--edge`（卡片顶部 1px 高光） | 用内描边代替投影，守住 DESIGN §4 |
| 圆角 | 4 / 8 / 12 / 14 | 4 / 6 / 10 / 14 / 18 + `--r-full` | 4px 是「开发工具」的观感，不是产品 |
| 正文前景 | `#d6d6dd` | `#e4e4ec` | 长文更轻松 |
| 空状态 | 一行 12.5px 小字 | 符号 + 一句编码任务方向的话 + 当前项目路径 + 3 条可点建议 + 斜杠命令提示 | 空会话时三栏全空，最大的「难看」来源 |
| 「新对话」 | `dashed 0.8px --border-str` | 实心次要按钮（底 + 实线边 + 图标） | 虚线细边框看着像「坏掉的样式」 |
| 分区标题 | 10px | 11px + 加强对比 | 太淡，读不出结构 |

**唯一允许的 `box-shadow`**：`inset 0 1px 0 var(--edge)`
—— 它是**内描边高光**，不是投影；层级仍由背景色阶表达。

#### ⚠️ 为什么设计稿要把图标**内联**进 HTML

`<use href="external.svg#id">` 在 `file://` 下会被 Chromium 拦截（跨文档引用被拒），
而设计稿的要求是「双击就能打开」。全量 sprite 239 KB 又会把设计稿撑到 280 KB，
所以走**构建期内联子集**：`embed-icons.mjs` 扫 HTML 里的 `<use href="#i-*">`
加上运行时才决定的图标（`RUNTIME_ICONS`：folder / folder-open / sun / moon），
只把那几十个 symbol 贴进 `<!-- ICON-SPRITE-START -->` 标记之间。
**改完设计稿要重跑这个脚本**，否则新引用的图标是空的。

实现阶段（打包后的应用）没有这个限制，直接用整份 sprite 或按需 import 即可。

#### 用法

```html
<svg class="ico"><use href="#i-folder"/></svg>       <!-- Outline，默认 -->
<svg class="ico"><use href="#i-folder-f"/></svg>     <!-- Filled -->
```

```css
.ico { width:16px; height:16px; fill:none; color:var(--fg-dim); flex:none }
```

尺寸只用 **12 / 14 / 16 / 20**，不出现奇数尺寸。

#### 风格约束

| 规则 | 理由 |
|---|---|
| 默认用 **Outline** | 1.5px 描边与细边框、紧凑行高同一量级 |
| **Filled 只用于选中态与状态点** | 两套权重混用会乱，必须有明确分工 |

### 3.1 工具卡智能展开

pi 的工具输出长短差异极大（`read` 可能 5 行也可能 500 行），全展开会让消息流
被输出淹没，全折叠又会让报错藏在两层点击之后。所以按**信息价值**给默认态：

| 情况 | 默认 | 理由 |
|---|---|---|
| 失败（非 0 退出 / 报错） | **展开** | 报错必须第一眼看到 |
| 含 diff（edit / write） | **展开** | diff 是审阅对象，不是日志 |
| 进行中 | **展开** | 让用户看到正在干什么 |
| 成功的长输出（read / bash） | **折叠** | 噪声，需要时再看 |
| 成功的短输出 | 折叠 | 同上 |

两条实现约定：

1. **手动状态优先，且是永久的。** 卡片一旦被点过就置 `data-manual="1"`，
   之后再也不被自动规则切换 —— 否则「用户刚展开，流式更新又把它折回去」。
2. **折叠不等于隐身。** 折叠态在头部下方留一行 `--fg-mute` 的摘要
   （`已读取 42 行 · 点击展开` / `10 passed (2 files) · 点击展开`），
   否则卡片会变成信息黑洞，用户不知道该不该点开。

实现上是每条 `.tool` 标 `data-default="open|closed"`（由数据决定），
没有该属性时才走行数启发式（`>8 行` 折叠）。

### 3.2 常驻汇总条

pi **无权限弹窗、写入立即落盘**（`docs/usage.md:309`），所以不存在「接受/拒绝」。
我们把「改动」做成一个显式的审阅对象：

```
⚠ 3 处改动待确认        改动已写入磁盘，接受是隐式的   [↺ 全部回滚] [▤ 查看汇总 diff]
```

| 约定 | 说明 |
|---|---|
| 位置 | 输入区**上方**常驻，不随消息流滚动 |
| 底色 | `--warn-soft` + 橙色上边框 —— 语义是「待确认的改动」，不是错误 |
| 计数为 0 时 | 整条**隐藏**（不应长期占据一条带色的横条） |
| 「接受」 | 隐式：刷新/离开/继续对话即视为接受。文案里要写清，否则用户以为在等一个按钮 |
| 「全部回滚」 | 从 session JSONL 逐条取 `oldText` 还原 |
| 单条回滚 | 每条 edit 卡的操作栏也有「回滚此改动」，只还原该次编辑 |

### 3.3 状态面板结构与排序（v0.2 定稿）

> **当前视觉收敛（2026-09-21）**：右栏沿用下面的功能分区，但外层采用
> “固定标题 + 单一滚动内容区 + 可折叠分组行”的上下文面板结构，参考 ChatGPT
> 侧栏与 IDE Inspector。它不是一组互相争夺高度的 Dashboard 卡片；层级靠缩进、
> 字号和色阶表达。当前实现的标题行为 44px，分组行 40px；排序把手只占 12px，
> 箭头槽 14px、箭头与标题之间保持 2px，分组内容左缩进 12px；文件树再由自身的
> 4px / 14px 层级规则处理目录关系，避免普通内容被分组缩进重复推远；
> 标题行右侧保留一个 26px 的工作区工具启动器，不额外占一整行。
> 只有 `.rp-body` 负责右栏主滚动；文件树 / 日志仍可保留用户主动调整后的内部高度，
> 以维持既有拖拽能力。

分区顺序默认如下，**且用户可自行拖拽调整**（持久化）：

顺序按**重要性**排列，计费沉底：

```
1. 会话        目录（右对齐可换行）/ 分支 / 模型 / 思考
2. 上下文窗口   进度条 + 「287,431 / 1,000,000」+ 百分比
3. 工作区       改动文件（M/A/D + 路径 + 增删定宽列）
                ─ 虚线分隔 ─
                检查状态（✓ / ✗ / ◐ + 命令 + 耗时）
                ─ 虚线分隔 ─
                增删合计
4. 文件树       目录可折叠 + 改动文件带 +N/−N（见 §3.4）
5. 任务        ✓ 完成（删除线）/ ◐ 进行中 / ○ 未开始
6. 计费        ● 谷时/峰时 + 倒计时 + 用量 + 提供方时段
```

> **设计决策（经评审修正）**：早期版本把「用量 / 花费 / 计费时段」放在上半部分，
> 读起来像"账单后台"而非编码工具。已下沉到底部，上半部分让位给代码上下文
> （改动文件、检查状态、文件树）。这是"工作台"与"聊天记录"的分界线。

#### 排序交互

| 方式 | 实现 |
|---|---|
| 鼠标 | 分区标题左侧的把手（`⠿`）按住拖动；也可从工具库拖出/放回 |
| 键盘 | 把手可聚焦：`Alt+↑` / `Alt+↓` 排序，`Alt+←` 移出为浮动，`Alt+→` 放回工具页 |
| 浮动 | 磁贴可停在工具页、浮在应用内容区、或收进工具库；一个 id 只有一份实例 |
| 持久化 | `AppSettings.toolLayout`（version 2 + `revision`）—— 见文末「可移动工具磁贴契约」 |
| 重置 | 工具库里的「恢复默认布局」（只重置布局，不动业务数据） |

三个细节：

1. **把手默认隐身。** 常显的拖拽把手会让安静的侧栏变吵；`opacity:0` →
   `:hover` / `:focus-visible` 时 `.75`。键盘用户靠 `focus-visible` 也能发现它。
2. **落点指示用 2px 色条**（`::before` / `::after` + `--accent`），不用投影 ——
   与 §4 禁止项一致。
3. **`localStorage` 在 `file://` 下会被拒**（opaque origin）。
   所以读写都包 `try/catch`，失败时降级为「仅本次会话有效」，页面不报错。
   加载顺序时也要**容错**：认不出的 id 丢掉、缺失的按默认顺序补到末尾，
   这样后续版本增删卡片不会把用户的顺序清空。

#### 额度色阶（2026-09-21）

额度分区（`[data-testid="rp-quota"]`）里「已用百分比」与进度条共用一套三档色阶，
唯一真源是 [`src/shared/quota-tone.ts`](../../src/shared/quota-tone.ts) 的 `quotaTone()`：

| 已用 | 色调 | 令牌 |
|---|---|---|
| < 70% | 绿 | `--ok` |
| 70% – 95% | 黄 | `--warn` |
| ≥ 95% | 红 | `--err` |

- 两个边界都算进**更严**的一档：70 起黄、95 起红（用的是 `>=`，不是 `>`）。
- 供应商自己报 `exceeded` 时**恒红**，与百分比无关（权威字段优先于推算）。
- 三档必须**真的落类名**（`.rp-v.ok` / `.rp-v.warn` / `.rp-v.err`，进度条同理：
  `.rp-meter.ok/.warn/.err`）。⚠️ 别把 `ok` 档写成空类名 —— 那会让「低用量」落回
  默认前景色（灰），看上去像没有分级（2026-09-21 修过一次，是视觉矩阵的
  「计算色必须等于设计令牌」断言抓出来的）。
- 主值（本月已用）与各窗口共用这套阈值；拿不到 `used/total` 的口径
  （例如余额型的 DeepSeek）不着色。
- ⚠️ 与上下文水位的 85% / 95% **不是一套**：那套是压缩策略阈值（见 `ctx.tip`），
  与「额度还能用多久」是两件事，各自演进。

### 3.4 文件树

放在右栏中下部（工作区与任务之间），用来回答「这仓库里还有什么、哪些被改过」。

| 元素 | 约定 |
|---|---|
| 目录 | `chevron-right` 旋转 90° 表示展开；`folder-open` / `folder` 图标跟随切换 |
| 叶节点 | `file-text`；测试文件用 `file-check`；代码用 `code-file` |
| 选中 | `--accent-soft` 底 + `--accent` 图标与文件名（与消息流当前编辑的文件联动） |
| 改动标记 | 右侧 `+N −N`，新增 `--ok`、删除 `--err`、修改 `--warn` |
| 缩进 | 每级 13px，靠 `[data-d]` 属性选择器（**不要用 `var(--d)`**，见 §2.5 警告） |
| 折叠 | 点击目录名切换；可见性由「所有祖先目录是否展开」**整体重算**，不做增量增删 |

> 折叠逻辑要重算而不是逐节点 `add/remove` hidden：嵌套折叠时增量写法会残留
> 错误状态（展开外层时把内层已折叠的子节点也放出来）。
> 正确做法是遍历一次，维护「当前处于哪个折叠子树之下」的深度，一次算完。

> 左栏的「可折叠」与右栏的「文件树」是两件事，别混：
> **左栏 = 会话列表（按时间折叠分组）+ 选中会话内嵌的可折叠任务列表；
> 右栏中下部 = 文件树。**

### 3.5 折叠与展开的高度约定

三处「收起 / 展开」共用一套量（用户 2026-09-18 一次报的三条都落在这里）：

| 位置 | 收起 | 展开 | 为什么 |
|---|---|---|---|
| 左栏 | **0 宽**（`--w-rail-collapsed: 0px`）+ 容器 `display: none` | 用户拖出来的宽度 | 「不要留下一个边框」：48px 的紧凑图标轨在深色主题下就是消息区左边一条颜色不同的竖条。展开入口只剩标题栏那个开关 |
| 项目下的会话 | 前 **5** 条（`SESSION_PREVIEW`） | 「更多会话（N）」→ 全部 | 左栏是导航不是列表；**当前会话**落在折叠段里时自动多展开到它那一行（不能把自己藏起来） |
| 工具**组**展开后的列表 | 折叠（一次调用都不渲染） | **约 25 行**（`min(625px, 80vh)`；行步进实测约 25px）+ 内部滚动 | 用户原话：「主动展开调用工具/命令栏的时候，**给展开的条目一个显示范围，而不是铺开到整个界面**」—— 一次 `npm run check` 能产生一百多条调用，不限高就把整段对话顶走。**列表的单位是“条”，所以上限也按条数（25 条）定，不跟着 vh 走**。组头（「调用了 N 次工具/命令」）在 body 外面，限高后始终留在上方 |
| 工具**详情** / 推理全文 | 默认折叠（工具）/ 最新一句（推理，V-2a） | `min(70vh, 620px)` + 内部滚动 | 「展开时应该有一个固定的范围，或者在最上方显示折叠回去的按钮」：卡住高度后行头 / 胶囊留在上方，它们本身就是那个按钮，不必另加 |

⚠️ 两条例外，改选择器前先看：

- 命令类详情是**终端窗口**（自带高度与缩放手柄，尺寸记在 `localStorage`），详情上限的选择器写成 `.trow-body > :not(.term)` —— 套上它会出现「终端外面还有一层滚动条」。
- 推理的**默认态**只显示最新一句、不用滚动条；一次点击打开固定范围全文，用户主动上滚时保留阅读位置。

### 3.6 环境菜单与审查面板（方案 G1，2026-09-18）

**环境菜单**（会话头部的项目胶囊即入口）

| 项 | 右侧显示 | 行为 |
|---|---|---|
| 变更 | 变更文件数（`--warn`）+ 未跟踪数（`--fg-mute`） | 打开审查面板（工作区范围） |
| 本地 | 工作目录（`~` 缩写）+ 「打开」「复制」 | 位置是**信息行**，不是导航项 —— 名字必须与实际动作对得上 |
| `<分支名>` | `↑n ↓m`（`--magenta`） | 与该分支比较（只读） |
| Pull Request | 「无法获取 Pull Request 状态」 | 拿不到就说拿不到，**不伪造**「检查中」 |
| 比较分支 | `origin/main → main` | 打开两端比较 |

约定：

- 宽度 `320–420px`：要能一行放下「Pull Request · 无法获取 Pull Request 状态」，
  它是「不伪造状态」这句承诺的全部信息量。截断时必须有 `title` 兜底。
- 菜单项**只放已经能用的动作**。提交 / 推送 / 切换分支属于 G2，这里不摆按钮 ——
  一个按下去说「还没做」的入口比不摆更糟。
- 图标沿用 §2.7 的语义映射：变更 `history`、本地 `folder`、分支 `layers`、
  PR `globe`、比较 `search`。reicon 没有专用的 diff / 复制图标，所以「打开 / 复制」
  用**文字**按钮 —— 不复用别的图标来承担第二层含义。

**审查面板**（右栏详情视图，优先级最高）

```
┌ 范围▾   9 个文件 +905 -31 2 个二进制        ✓ ⟳ ≡ ┐
├ 说明行（可选）                                      │
├──────────────────────────────┬─────────────────────┤
│ ▸ M path/a.ts            +42 -8  [已查看]           │  变更树（220px）
│   ↕ 70 行未修改（可点，点了真展开）                  │  ├ 筛选框
│   @@ -10,8 +10,9 @@ export function …              │  ├ 全部/文本/图片/其它
│   10 10   const x = 1                               │  ├ 进度条 n/N
│   11  -   const files = …                           │  └ 目录 / 文件（带状态字母）
│   11  +   const files = snapshot?.files ?? []       │
└──────────────────────────────┴─────────────────────┘
```

| 约定 | 值 / 做法 | 为什么 |
|---|---|---|
| 宽度 | `clamp(420px, 46vw, 900px)`，**不给拖** | 审查的列宽由内容决定（两列行号 + 代码），不是个人偏好；不改用户的 `--w-panel-user`，退出后原样回来 |
| diff 的增删表达 | **只**用底色（`--ok-soft` / `--err-soft`）+ 符号 + 两列行号 | 一屏上千行时，图标或左右边框都会变成噪声 |
| 行号 | 两列（旧 / 新），`tabular-nums`，空侧留白不补 0 | 只有一列会让「新增」与「删除」的行号含义错位 |
| 长行 | **不折行**，横向滚动 | 折行会让行高不一致、行号对不上，代码结构也看不清 |
| 未修改区 | 「N 行未修改」折叠条，**点击真的展开**（上限 300 行，超出提示剩余） | 一个点了没反应的控件比没有这个控件更糟 |
| 图片 | 前后两张并排 + 适配 / 原尺寸；透明底用棋盘格 | 透明 PNG 在白底上看起来像"图片坏了" |
| 二进制 / 子模块 / LFS / 超大 | 各自一句明确的说明，**不给空 diff** | 空 diff 与 `+0 -0` 都是在说「没改动」，而实际是「看不到内容」 |
| 已查看 | 用户主动点；键含两侧内容指纹 | 内容一变自动失效，滚动经过**不算**已查看 |
| 空态 | 「这个范围里没有改动」/「未使用 Git —— 这个目录不在 Git 仓库里」 | 两种空是不同的事实，不能都说「没有改动」 |

**Codex 风格的右栏工具入口与窗口标签（当前实现）**

右栏使用一条共同的窗口标签栏。工具栏、审查、浏览器、文件是同级窗口表面：
当前只显示一个活动表面，窗口栏左侧显示活动 / 已打开的标签，右侧的 `＋` 打开审查、
终端、浏览器和文件入口菜单。标签使用与审查页相同的圆角胶囊、图标、关闭按钮和激活底色，
不再把浏览器、文件预览或审查内容塞进工具栏的附加行。

工具栏窗口的第二行才是唯一滚动的分区区；审查窗口直接显示范围、差异列与变更树；浏览器
窗口把原生 `WebContentsView` 放在标签栏下面，右栏收起时隐藏标签栏并让网页占满整列；文件
窗口在同一表面内按状态显示文件树或只读文件预览。这样原生网页与 DOM 表面不会争用同一坐标，
点击文件树、切换审查或打开浏览器时也不会出现标题栏 / 代码预览重叠。

菜单项使用 `16px / minmax(0, 1fr) / auto` 三列：语义图标、名称、可选的快捷键胶囊；行高约
34px，弹层贴窗口标签栏右侧。**只有真接了全局快捷键的项才画胶囊** —— 2026-09-24 删掉了审查 /
终端 / 浏览器 / 文件上那四个从未接线的提示（其中 `Ctrl+P` 还被「下一模型」占着），
屏幕上写着组合键却按不动，比不写更坏。终端现在是工作窗口的一类资源（H-11，宿主 node-pty）。

⚠️ 窗口标签栏必须能在**窄右栏**里活下来（2026-09-24 补）：标签是可变数量的（审查 / 浏览器 /
每个文件 / 每个终端各一个），而右栏在窄窗口下只有 190px（≤980px）/ 170px（≤900px）的
设计宽度，装不下两个固定宽胶囊。规定：标签宽度由内容决定、上限 220px，**空间不够时收缩并
截断文字**（`flex: 0 1 auto` + `min-width: 0`），图标与关闭按钮不参与收缩，右侧 `＋` 不被顶出。
容器仍保留横向滚动作兜底，但**不能只靠它**：滚动条是隐藏的，用户看不出右边还有标签
（940×620 实测第二个标签被挤到可视区外，看上去就像被裁掉）。1440×900 下不触发收缩，
外观与旧图一致。

⚠️ 与其它右栏视图的关系：切换窗口时非活动表面**整块不渲染**（不是藏起来）。
实测教训 —— 藏起来时 `.rp-top` / `.rp-body` 仍然参与 flex 分配，截图上审查只剩顶上一条，
下面全是任务 / 上下文 / 额度分区。

⚠️ 原生的 `WebContentsView`（内置浏览器）永远盖在 DOM 之上：打开审查必须让主进程
`browser.setVisible(false)`，否则审查面板会被浏览器整块压住（看起来像"没打开"）。

### 3.7 写操作区（暂存 / 提交 / 分支 / 推送，方案 G2）

**位置与层级**：提交区固定在审查面板**底部**（不弹窗）—— 提交前要核对的东西
（改了哪些文件、说明写得对不对）就是上面的 diff，弹窗会把它们挡住。默认只占
一行输入框，要写长说明自己长高（最多 5 行），不抢 diff 的地方。

**符号而不是图标**：暂存 / 取消暂存用文本 `+` / `−`（`.stage-glyph`）——
sprite（reicon）里没有 minus，硬塞一个语义不符的图标比用符号更糟；
两者都是等宽一格，宽度对齐。位置在「已查看」**左边**：会改仓库状态的动作
离右边缘远一点，不容易误点。

**忙碌与禁用**：写操作进行中，所有相关按钮 `disabled`（含菜单里的分支 /
拉取 / 推送）。**预期版本还没拿到时也禁用**（而不是点了才报错）——
`git state` 还没回来的那一瞬间点下去，正是最容易撞上「状态已变化」的时刻。

**失败提示**（`.gwrite-fail`）：一行分类 + 一句可执行的下一步 + 默认折叠的
**git 原始输出**（等宽、可横向滚动 —— 保留 `! [rejected]        main -> main`
这种靠空白对齐的信息）。用 `--danger` 的 8% 底色 + 30% 边框，不用纯红块：
它要一眼看到，但不该像「应用崩了」。

**成功提示**（`.gwrite-ok`）是一行摘要（「已暂存 a.txt」「已推送到 origin」），
不弹 toast —— 结果是可核对的事实，用户可能马上要去看。

**环境菜单的分支区**（`.env-branches`）：内联展开（不弹二级选单）；当前分支
带「当前」标记且**不可点**（它本来就是当前状态）；被其它工作树占用的分支
同时禁用 + 标注原因。新建分支的输入框与「创建并切换」按钮同一行。

**不做**：没有「丢弃工作区改动」按钮。它是整个 Git 集成里唯一不可恢复的操作，
方案 §5.1 明确要求不覆盖用户改动；要加它必须先有「哪些文件会被覆盖」的完整
预览与二次确认设计。

### 3.8 工作树区（方案 §6.2，W1）

挂在环境菜单里、与分支区同一种内联展开。一行一个工作树：**等宽**的分支名 +
标记（「主工作树」/「砚创建」）+ 「移除」。**主工作树没有「移除」按钮** ——
不是禁用，是根本不渲染：一个永远点不动的按钮比没有更让人困惑。

「同时删分支」是复选框（默认不勾）：删目录不等于删分支，这两件事分开让用户决定。
「新分支名」与「目标目录」分成两行（后者更长，且常常留空用默认），
创建按钮与分支名同一行。被拦下时用与写操作失败同一种块（`.gwrite-fail`）
逐条列出原因与计数 —— 同一种信息在界面上只该有一种长相。

**携带未提交改动**（W2a）在同一个区里，三项分开勾（已暂存 / 未暂存 / 未跟踪），
默认**全不勾** —— 「默认从已提交状态创建」是方案 §6.2 的原话。未跟踪清单自己滚
（`max-height`），菜单高度不该由文件数决定；长路径省略结尾（路径太长，省略中间反而
看不出是哪个文件），完整路径在 title 里。

工作树行**允许换行**：分支名 + 标记 + 两个按钮挤一行时名字会被压成 `feat/git-re...`，
而分支名是这个区里最需要看全的东西（要拿它去终端里敲），所以给名字保底 96px。

### 3.9 关联外部任务（方案 §6.4）

一行一条：标题占满剩余宽度并省略结尾（长标题不该把「移除」挤出可视区）、原始地址在
title 里。两个输入（地址 3 : 标题 2）与「关联」按钮同一行 —— 标题常常留空。

下面那行小字是**产品边界**，不是提示：「只是记下地址并在内置浏览器里打开：不会上传
代码、不会同步会话、不会远程执行」。它属于界面的**必读部分**（有 live 断言在读它），
不要为了整洁删掉。

「在网上比较」只在认得出托管站时出现：给一个打不开的链接比不给更糟。

### 3.10 插件（方案 §9）

⚠️ `.set-row` 是 **grid**（标签 + 控件两列）。要让一行变成纵向堆叠的区块，
**必须显式写 `display: flex`** —— 只写 `flex-direction: column` 是无效的，
内容会被留在第二列、整块跑到右半边（这一条是视觉矩阵的截图抓出来的）。

列表项：包名等宽靠左、版本次之、作用域标签用 accent 描边区分「项目级」；
「磁盘上找不到」用 `--warn` 标出来 —— 那是**异常状态**（settings 里登记着但
磁盘上没有），不是正常情况。按钮（详情 / 更新 / 卸载）统一靠右。

详情里那句「会执行代码、不做沙箱隔离」属于界面的**必读部分**（有 live 断言在读它），
不要为了整洁删掉或改成暗示性的措辞。

### 3.11 来源（方案 §8 的 S1）

每一行必须是**同一套骨架**：`[缩略图 36×36] [标题 + 状态标签] [操作按钮]`。
缺一块行高就会参差；缩略图没读出来时用**同样大小**的占位（行高不跳）。
这三件是第一次忘记写样式时截图上直接看出来的：标题与「已关联」粘在一起、
缩略图占不到位置。

筛选是四个胶囊（全部 / 图片 / 文件 / 网页），数量为 0 的**禁用**（点了也没内容）；
数量全为 0 时整行不渲染 —— 空列表上摆四个禁用的按钮只是噪声。

「文件不在了（被删除或改名）」用 `--warn`：那是**异常状态**，不是正常情况。
底部那行小字是产品边界（移除不删原文件、不改写历史、不上传代码），有 live 断言在读它。

### 3.12 PR 状态（方案 §7）

一行里给三样东西：**状态 · 检查 · 本地是否领先**（例如「已合并 · 检查通过 · 本地有
未推送的提交」）。分隔符统一用 `·`，只有一档时不显示多余的分隔符。

失败要说清是**哪一种**查不到（需要授权 / 限流 / 连不上 / 远端不支持 / 仓库不存在），
而不是笼统的「无法获取」—— 用户接下来该做什么完全取决于哪一种。

⚠️ 文案必须是显式分支，不能拼模板字符串去查 i18n：`t()` 的键是**字面量联合类型**，
拼出来的字符串过不了类型检查 —— 而这正是不该拼的原因（拼错的键在编译期发现不了）。

### 3.13 项目知识页（实施-03 S5）

顺序就是用户要回答的三个问题：**开不开 → 有哪些 → 怎么处置**。骨架固定为
「开关行（带默认关的标签）→ 项目 id + 三个筛选（带计数）→ 条目卡列表 → 导出」，
四段都用 `.set-row.col`，不另造布局体系。

⚠️ **正文只出现一次**：标题行放「类型 · 条目 id」，正文单独一行。
首版把同一条文字同时放在标题与正文位，截图里看着像**两条不同的条目** ——
这类“数据没错、层次错乱”的毛病只能靠看图发现。

状态用文字类别而不是分数（§6 明令不许显示未经校准的可信度百分比）：
`已确认` / `待确认` / `已被替代` 用 `--ok` / `--warn` / `--fg-mute` 描边胶囊；
置信类（用户确认 / 已验证 / 模型推断）与状态**分开两个标签** ——
它们是两个轴（“这一步走到哪” vs “凭什么信它”）。

来源不可回读时，链接**置灰不可点**并紧跟「不可回读」字样，
不伪装成能点、也不把来源 id 抹掉（§4：不伪造证据）。
「需复核」用 `--warn` 行内提示，理由用文字（分支已变 / 引用路径已不存在 /
来源会话不可回读），它同时出现在「已确认」与「需复核」两个筛选里 ——
把带警告的已确认条目从「已确认」里藏起来，用户就找不到了。

永久删除**不是逻辑删除的开关**，而是另一个动作（不同的文案、不同的回执），
界面当前只提供逻辑删除；导出只写用户在选择框里点的地方，**不自动改写仓库文档**。

窄窗口（实测 900×520）下筛选与操作按钮必须能换行：`.kn-filter` 与
`.kn-item .set-ctl` 都显式 `flex-wrap: wrap`（`.seg` 默认不换行，三个中文标签
加计数比右侧参数列宽时会直接溢出 —— 和 `.seg-scale` 是同一个坑）。

## 4. 禁止项

| 禁止 | 原因 |
|---|---|
| `box-shadow` 投影 | 层级用背景色阶表达。**唯一例外**：峰谷状态点的 `0 0 0 3px` 光晕 |
| `linear-gradient` / `radial-gradient` | 终端调性是平色。**唯一例外见下** |
| 大圆角药丸按钮（>14px） | 除滚动条 / 进度条 |
| 大面积彩色填充 | 彩色只做小面积语义标记 |
| 弹跳 / 弹性动画 | 只做 120ms 淡入；尊重 `prefers-reduced-motion` |

`check.mjs` 会自动检查这五条。

### 4.1 修订（2026-09-14）：运行状态允许低对比度扫光

方案《Yan-功能升级与UI优化方案》要求「运行中的流动光效」。为了既满足它
又不把界面变成发光边框，规范修订为：

> **静态界面继续不使用装饰渐变；只有「正在运行」的状态行允许一道低对比度扫光。**

具体要求：

- 只用于**运行中**的行（工具调用 `[data-state="running"]`），结束后立即停止；
- 渐变两端必须是透明的（`transparent → var(--accent-soft) → transparent`），
  不使用第二种彩色，也不套在容器外框上；
- 扫光**不能是唯一的状态信息** —— 同行必须有图标 / 动词 / spinner 在表达“在跑”；
- `prefers-reduced-motion: reduce` 下直接不渲染它。

`check.mjs` 的白名单需要包含 `.trow-head::after`（实现见 `styles/chat.css`）。

### 4.2 修订（2026-09-21）：自主模式的克制状态边界

> 2026-09-19（实施-05 S2）补充：「自主」不再是底栏上的一个开关，而是**会话级工作模式**
> （标准 / 澄清 / 自主）的第三档 —— 底栏那个位置现在是**模式菜单**（原位写当前档位名 +
> 一句说明，`Tab` 可快切）。下面这篇规范的**触发条件**因此改为「当前会话处于自主档」。

「自主模式开着」需要一个**常驻但低干扰**的信号。新 UI 将它收敛为固定位置的
靛蓝边界与可读的模式名称：

- 不改变输入区尺寸、发送位置或键盘语义；
- 不使用持续旋转、双光带或大面积发光；
- 减少动态效果后，模式仍由文字与静态边界可识别；
- `prefers-reduced-motion` 下不产生额外动画。

旧版双光带实现保留在历史 diff 中，不再作为当前设计要求。

## 5. 动效

```css
--dur: 120ms;
--ease: cubic-bezier(.2, 0, .2, 1);
```

只有几处动效：悬停背景、折叠三角旋转、流式光标闪烁、工作状态框的 80ms 帧、
自主模式的静态状态边界（§4.2）、长文模式切换的 200ms 高度过渡（只在切换那一瞬间接上——
拖动与打字时不能有，否则高度跟不上手）。
`@media (prefers-reduced-motion: reduce)` 下全部关闭（状态仍由文字与静态边界表达）。

**主题切换是唯一一处整屏动效**（View Transition + `clip-path: circle()`，760ms）：
切到深色时新层从中心向外晕开，切到浅色时**旧层**从外缘向中心收拢
（露出压在下面的浅色层）。两个方向都**只让一层动** —— 两层同时动会糊成一团，
看不出是谁在长、谁在退。比常规控件动效慢得多是有意的：整屏换色快了像闪屏。
方向由 `<html data-theme-dir>`（`out` / `in`）驱动，在 `startViewTransition` 之前写。

**圆心是“触发它的那个按钮”**（`--theme-origin-x/y`，App 按按钮中心写入；量不到才回退屏幕中心）——
这样「我点的那一下让主题从这儿铺开 / 收拢」才读得出来；固定在屏幕中心会让
设置面板里的小按钮与全屏动画之间没有因果关系。

**圆心必须写成“相对视口的百分比”而非 px，并且把 root 组的盒子钉回视口**
（2026-09-23 用户现场：在设置里点「深色」，圆却从屏幕另一处展开）：
`clip-path` 里的长度基准是**过渡伪元素自己的 border box**，而这个盒子由 Chromium
用行内 style 给出（`width/height` + `transform`）。只要新旧两帧快照尺寸不一致
（页面缩放、滚动条、布局抖动都会），这层就会带一个**非单位 transform**，
写进去的 px 到屏幕上就不是那个位置了。两道保险：

1. `shell.css` 把 `::view-transition-group(root)` 钉成 `fixed / inset:0 /
transform:none !important`（行内样式只能用 `!important` 盖），只在
   `html[data-theme-dir]` 有效的那一瞬间生效，元素级过渡不受影响；
2. App 写的是 `(按钮中心 / 视口尺寸)` 的百分比 —— 盒子被缩放时百分比跟着走，
   正常时与 px 完全等价。

### 规则

| 规则 | 说明 |
|---|---|
| 回退链 | 当前语言 → `en-US` → key 原文（并向 console 发 warning） |
| 类型安全 | 从 `zh-CN.json` 生成 TS 类型 → **漏翻译编译报错** |

| 切换 | 设置项 + 「跟随系统」，持久化 |

### ⚠️ 边界：内容不可翻译

壳是双语的，**内容不是**。以下原样透传：

模型回复 / 工具输出（bash、read、grep）/ pi 内置错误 / 扩展的 `notify`。

`prototype.html` 内的 `LOCALES` 对象即为 `locales/*.json` 的雏形，

### 零成本的额外校验（改完也顺手做）

|---|---|

## 2026-09-23 导航柄与图标补充契约

会话导航轨固定在会话可用区域左边缘的独立槽内，视觉边距建议 4–8 CSS px；命中区与正文交互元素不得相交。预览卡不得出可用区，键盘焦点与鼠标同等可用。V-2b 持有实现与验收，不改标题栏左栏开关。

> **实现机制（2026-09-23 收口）**：槽位是 `.outline` 上的常量 `--outline-slot-inset/w/gap`（4 / 44 / 8px）。正文的避让槽用 `--outline-avoid` —— ConversationOutline.tsx 量出内容列在**不加避让**时的左缘，差额才写进变量（宽窗正文离得远，值为 0），CSS 把它加在 `.stream-inner` / `.stream-row` 的左内边距上。纵向不走 CSS：absolute 子项的 grid area containing block 在当前 Chromium 下实测没生效（`grid-row` 解析成 3，`bottom` 仍取会话区 padding box，轨道会压住输入区），改由 tsx 跟随 `.stream` 的矩形。长轨在轨道内受限滚动（键盘 Tab 到末项时浏览器自动滚入）。

语义图标继承 currentColor 与主题 token，深浅各态必须可辨；动效用于 hover/focus/press/展开和真实运行状态，建议 120–180ms，reduced-motion 去除持续旋转和位移。既有 Icon/sprite/Orb 是复用基础，新增规范不表示过去完全没有主题或动画支持。H-8a/b 持有实际触点盘点与验收。

> **实现机制（2026-09-23 收口）**：图标颜色一律来自 `currentColor`（sprite 无硬编码色），状态色由所属控件给；跨模块只补 `.ico` 的 `color` 过渡（`icon-state.css`，reduced-motion 压到 1ms）。artifact / 图片进度 / 子代理内联卡原先引用不存在的 `--text / --panel / --line / --muted`，已分别映射到 `--fg / --bg-2 / --border〔`--border-soft`〕/ --fg-mute（更次）与 --fg-dim`，状态色保持 `--accent / --ok / --err`。进行态旋转只挂在真实 running 条件上（`.image-progress.running`、`ub-live`、`.spin` 仅在 compacting/loggingIn 下）。

## 2026-09-23 可移动工具磁贴契约（实施-12 U-4 / U-5）

设计规格唯一来源仍为 [方案-侧栏工作台与子代理交互 §5](active/方案-侧栏工作台与子代理交互-2026-09-23.md)；这里只回填**已经生效的实现参数**，避免同一件事在设计与代码里各写一套。

### 布局真源

- 唯一真源：`AppSettings.toolLayout`（[`src/shared/tool-layout.ts`](../../src/shared/tool-layout.ts)），
  形态 `{ version: 2, tiles: [{ id, placement, order, rect?, collapsed? }], revision }`。
- `placement` 三选一：`docked`（工具页）/ `floating`（应用内容区）/ `library`（工具库）。
- `revision` 单调递增；写入仲裁 `commitTileLayout` 丢弃 revision 不大于当前的写入
  —— 连续拖动的晚返回不会覆盖新位置。重置布局也必须递增 revision。
- 旧 `toolOrder` / `toolHidden` 只在读盘时一次性迁移；界面侧不再写入（旧字段成为只读遗留）。

### 几何

| 项 | 值 |
|---|---|
| 归一化坐标 | `rect.x/y/w/h` 均 0–1，相对 `.workspace` 内容区（U-0 冻结契约） |
| 默认宽 | 目标 300px（`TILE_DEFAULT_W`） |
| 最窄 / 最宽 | 240 / 420px（`TILE_MIN_W` / `TILE_MAX_W`） |
| 磁贴头 | 32px（`TILE_HEAD_H`），折叠后整体只剩这一条 |
| 内容最大高 | `min(360px, 50vh)`；长内容在磁贴内部滚动 |
| 夹取 | `clampFloatPixels` / `clampRectToBounds`：缩窗、缩放后磁贴完整留在可用区 |
| 网页避让 | `avoidFloatObstacle`：与原生网页矩形相交时吸附到最近可用 DOM 区；无处可放则退回工具页并就地说明（不永久遮住网页） |

### 交互

- 可浮动 registry 排除 `todo`（保持工具页原布局）与 `files`（完整文件树留在文件页）；
  它们仍可停靠 / 排序 / 收进库。
- 拖动状态机：按下头部 → 位移 ≥6 CSS px 才进入 dragging → 放开 commit；正文选字与按钮不触发拖动。
- 拖动期间领取 H-9a 的 overlay blocker（原生网页暂隐），只 commit 时写盘；Esc / pointercancel /
  失焦 / 切会话取消并释放捕获。
- 一个磁贴 id 只有一个主实例：工具页只留「已浮动 · 定位」轻量占位，不挂第二份订阅。
- 工具库是工具页内的稳定面板，列出全部 id 与三处位置，按钮完成移出 / 定位 / 放回 / 收进库 /
  上移下移 / 恢复默认；键盘与按钮共用同一组 `setTilePlacement` / `moveTile` 命令。
