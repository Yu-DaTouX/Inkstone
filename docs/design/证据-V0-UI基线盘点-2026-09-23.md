## 3. 可排序清单

### D1 · 样式顺序真源漂移（**已修**，V-0）

- **区域**：`docs/design/CSS-令牌清单.md` 与 `CSS-归属表.md` 的生成器
- **复现**：`node scripts/css-inventory.mjs --md`，看第 1 节表格的文件数
- **实际**：两个生成器各自硬编码 **16** 个文件的 ORDER，且 `dialog.css` 的位置与
  真实 import 不同 —— 2026-09 分模块拆分后新增的 `review.css`、`icon-state.css`
  根本不在表里。顺序决定「谁覆盖谁」，顺序错了「最终值 / 覆盖热力」就不可信。
- **期望**：顺序只有一个来源，且与运行时一致
- **影响**：所有基于这两份清单的迁移判断（P0-1 样式收敛、令牌反查）都可能指错文件
- **处置**：新增 `scripts/lib/css-order.mjs`，从 `App.tsx` 解析导入顺序；两个生成器
  改为调用它；重新生成后为 **18** 个文件、14800 行、1960 个唯一选择器。
- **归属**：V-0（已完成）

### D2 · 散落值规模与分布（V-1 输入）

- **区域**：全部 18 个样式文件
- **复现**：`npm run measure:css`（→ `docs/design/CSS-散落值清单.md`）
- **实际**：声明里直接写死的有 **颜色 76 处、`px` 1395 处、时长 48 处**；
  其中**同值可映射到已有令牌的 816 处**，**无对应令牌的 119 种**（多为 2/5/10/26px
  这类尺寸与 `rgba(0,0,0,1)` 阴影色）。
- **硬编码颜色最多的文件**：`chat.css`(30) > `redesign.css`(10) > `motion.css`(7)
  > `composer.css`/`tools.css`(各 6) > `layout.css`/`review.css`(各 4)。
- **期望**：UI 语义色与间距尽量只从令牌来；新语义（如密度档位）补 token 而不是写值
- **影响**：换主题/改密度时容易漏改，正是 L3 那批「未定义变量回退成固定浅字深底」的同类根因
- **注意**：`可映射` 只说明**同值**，不代表语义相同 —— 替换前要确认含义（清单里已写明）
- **归属**：V-1（迁移）、V-2/V-4（各表面）

### D3 · 定义了但没人用的令牌（V-1）

- **复现**：`npm run measure:css`，第 3 节（扫 `var(--x)` 与 JS 的 `getPropertyValue('--x')`）
- **实际**：`--tree-indent`（13px）、`--w-status`（320px）无任何引用
- **期望**：要么用上，要么删掉；留着会让「真源」表变宽
- **影响**：低（不影响渲染），但会误导「改这个就能调树缩进/状态栏宽度」
- **归属**：V-1

### D4 · 视觉矩阵覆盖缺口 23 条（V-6 / 状态 owner）

- **复现**：`out/matrix-v0-20260923.log` 里 grep `缺 [`
- **实际**：123 条采样里有 **23 条**没渲染出自己声明的关键元素，集中在这几个钩子：
  `subagent-zone-right`(4)、`env-source-menu`(4)、`goal-panel`(3)、
  `workspace-changes`/`subagent-preview`/`rail-waiting`/`env-worktree-list`/`env-branches`(各 2)。
- **期望**：状态脚本真的把目标元素注入出来，或把断言改成它真正覆盖的东西
- **影响**：这些状态看着「已覆盖」，实际没有 —— 视觉验收会被高估
- **说明**：这是**采样脚本**的缺口，不是产品缺陷（抽看 `matrix-subagentinline-*.png` 等
  确认渲染出来的是普通会话，元素确实不在）
- **归属**：V-6/U-6（收口矩阵时一并处理）

### D5 · 横向溢出基线（无须改动）

- **复现**：同上日志，任一行 `溢出=Npx`
- **实际**：123/123 为 `0px`
- **期望**：保持；后续切片引入的改动不得让它非 0
- **归属**：无需改动；列为回归红线

### D6 · 动效令牌两套并存（V-1 建议）

- **复现**：`docs/design/CSS-令牌清单.md` 里同时有 `--dur: 120ms` 与 `--mo-base: 170ms`
- **实际**：`tokens.css` 的 `--dur/--ease` 与 `motion.css` 的 `--mo-*` 都在用
- **期望**：明确哪个是控件过渡、哪个是位移/入场；不要出现「同一类过渡两个时长来源」
- **影响**：中低 —— 视觉上目前不冲突，但改一处不会改变全部
- **归属**：V-1（**建议**，未验收截图支持，先不动）
