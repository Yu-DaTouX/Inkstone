## 1. 三个正交维度（不要让它们互相污染）

```text
pairing（身份）      unpaired ──► pairing ──► paired ──► (revoked) ──┐
                        ▲                                            │
                        └──────────────── PAIR_START ◄───────────────┘

auth（授权）         unauthorized ──► authorizing ──► authorized
                          ▲                │              │
                          │                ▼              ▼
                          └── expired ◄────┘           revoked

transport（通道）    idle ──► opening ──► open ──► closing ──► closed
                        （抽象三段：传输就绪 → 握手 → 订阅）
```

三条铁的分离规则：

1. **配对 ≠ 授权。** 配对一次得到耐久设备身份；授权可以多次失效、多次重来。
   授权过期**不需要**重新配对；配对被撤销**必须**重新配对。
2. **已连接 ≠ 已授权。** `transport = open` 且握手成功时，`auth` 仍可能是
   `unauthorized` / `expired`。此时手机能看到"电脑在线，但需要重新授权"，
   并且**重新授权不需要重连**。
3. **断线 ≠ 失权。** `DROP` 只把连接态打到离线，**不改变授权轴**。反过来
   `AUTH_REJECTED` 也不把连接态打回离线。

这三个维度是**抽象状态**：词表里没有任何一格需要知道"token 是手填的还是扫码换来的"。

## 2. 连接态词表（六态）

| 状态 | 机器名 | 判据（可判定，不是感觉） | 数据新鲜度 |
|---|---|---|---|
| 未配置 | `unconfigured` | 本机**没有**任何电脑连接目标记录 | 无数据 |
| 已配置 | `configured` | 有目标记录，但**没有**已建立的通道 | 仅缓存 |
| 连接中 | `connecting` | 存在一次进行中的连接尝试（`attemptId` + `epoch`） | 仅缓存 |
| 在线 | `online` | 传输就绪 **且** 协议握手成功（版本兼容 + 能力清单可读） | 实时 |
| 离线 | `offline` | 已有目标记录，**尝试过**且当前无可用通道（或曾在线后断开） | 缓存 + `stale` 标记 |
| 被撤销 | `revoked` | 该设备的授权被明确撤销（任一侧发起）；本机身份与凭据已清除 | 缓存已清 |

容易混淆的两组，先说清：

- **`configured` vs `offline`**：`configured` 是"还没试"（刚添加完电脑 / 用户主动断开订阅）；
  `offline` 是"试过，现在不通"。两者界面文案不同：前者"尚未连接"，后者"电脑不可达 · 上次更新 …"。
- **`offline` vs `revoked`**：`offline` 随时可以自动重连；`revoked` **不排重连定时器**，
  只提供"重新配对"入口。**撤销是安全动作，不是网络故障。**

被撤销后**清除该设备的会话缓存与草稿**（决定，非待定）：撤销的语义是"这台手机不再被信任"，
保留可读缓存与撤销冲突，且会让用户误以为撤销没生效。

状态之外还有一个**不参与迁移**的诊断字段：

```text
offlineReason: 'transport' | 'handshake' | 'protocol' | 'service-stopped' | 'network' | 'background'
```

它只用于文案与诊断。**不得**把 `network`（超时 / DNS / 连不上）说成"电脑关机" ——
电脑关机、桌面退出、Wi-Fi 断了在客户端无法区分（[UI 方案 §4.5](ANDROID-UI-PLAN-2026-09-18.md)）。

## 3. 事件词表（21 个，抽象的）

| 编号 | 事件 | 抽象含义（不绑实现） |
|---|---|---|
| E01 | `TARGET_KNOWN` | 本机写入了一台电脑的连接目标（标识，不含凭证） |
| E02 | `PAIR_START` | 用户发起配对 |
| E03 | `PAIR_OK` | 配对阶段成功，得到耐久设备身份 |
| E04 | `PAIR_FAIL` | 配对失败（校验不符 / 超时 / 用户取消） |
| E05 | `CREDENTIAL_CLEAR` | 本机凭据材料被清除（用户操作或系统密钥库失效） |
| E06 | `CONNECT` | 请求建立或恢复连接（首次 / 前台回归 / 用户手动） |
| E07 | `TRANSPORT_OPEN` | 传输层就绪（**尚未**握手） |
| E08 | `HANDSHAKE_OK` | 协议版本兼容且能力清单可读 |
| E09 | `HANDSHAKE_FAIL` | 传输就绪但握手失败 |
| E10 | `PROTOCOL_INCOMPATIBLE` | 协议版本不兼容 |
| E11 | `AUTH_REQUIRED` | 服务端要求授权 |
| E12 | `AUTH_ACCEPTED` | 授权通过 |
| E13 | `AUTH_REJECTED` | 凭证无效 / 已过期（401 类） |
| E14 | `PERMISSION_CHANGED` | 该设备的权限集发生变化 |
| E15 | `REVOKE` | 授权被**明确撤销**（电脑侧或手机侧发起） |
| E16 | `DROP` | 已建立的连接丢失 |
| E17 | `RETRY_DUE` | 重连定时器到点 |
| E18 | `DISCONNECT` | 用户主动断开本机订阅 |
| E19 | `BACKGROUND` | 应用进入后台 |
| E20 | `FOREGROUND` | 应用回到前台 |
| E21 | `TIME_PASSED` | 已加载数据超过保鲜窗口 |

每个事件都携带三个信封字段（实现要求，S1 落地）：

```text
{ eventId, at, epoch }            // epoch = 产生该事件的连接尝试代次
```

`eventId` 用于去重；`epoch` 用于丢弃迟到事件（§8.5）。

| **E18** `DISCONNECT` | `＝(i)` | `＝(i)` | `→C` 取消尝试，`epoch+1` | `→C` 关订阅；**不撤销、不停电脑任务** | `→C` 停自动重连、清退避 | `＝(i)` |
| **E19** `BACKGROUND` | `＝` | `＝` | `＝` 已有尝试允许在绝对超时内完成 | `＝` 连接态不变；允许系统回收传输 | `＝` 仅**暂停**退避计时 | `＝` |
| **E20** `FOREGROUND` | `＝` | `→G` **条件**：存在凭据且授权轴∈{authorized, expired} | `＝` | `＝` 触发重取快照 + 续订 + 重新鉴权 | `→G` 立即重连，退避重置 | `＝` 只显示重新配对入口 |
| **E21** `TIME_PASSED` | `—` 无数据 | `—` 无数据 | `—` 尚无数据 | `＝` 标 `stale` 标记 | `＝` 同上 | `—` 撤销即清缓存 |

**E17 在 `F` 上的条件**（四者同时成立才 `→G`，否则 `＝` 并转"手动重连"）：

1. 用户/产品策略允许自动重连（前台，且未关闭自动重连）；
2. 未超过自动重试上限；
3. 最近一次失败的错误类**可自动重试**（见 §9.2）；
4. `offlineReason` 不是 `protocol`（协议不兼容重试无意义）。

**E20 在 `C` 上的条件**：`configured` 是"用户主动断开订阅"或"刚添加电脑"的落点。
只有**存在凭据**且授权轴不是 `unauthorized`/`revoked` 时才自动连接；否则保持 `C`。

### 4.1 必须单列的三条"保护性不迁移"

| 场景 | 禁止的迁移 | 原因 |
|---|---|---|
| 传输就绪（E07） | `G → O` | 传输就绪 ≠ 协议兼容；在线判据必须包含握手 |
| 断线（E16） | `O → F` **且** 授权轴被重置 | 断线不是失权；否则用户断网一次就得重新授权 |
| 撤销后重连（E06/E17） | `R → G` | 撤销必须由人重新配对；自动重连会把撤销变成"临时故障" |

## 5. 非法迁移、可重入与幂等

### 5.1 非法迁移：处理规则（不抛异常、不部分写入）

`✘` 的格子很多，但处理规则只有四条，按顺序判定：

1. **迟到 / 旁路事件**（`epoch` 与当前尝试不符，或该态下本不该出现传输类事件）：
   静默丢弃 + 计数器 + 脱敏诊断日志。**不得改变任何状态**。典型是 `C`/`F` 上的 E07/E08、
   `R` 上的全部传输事件。
2. **互斥窗口冲突**（`G` 上改目标/配对、`O` 上改目标/配对/重连）：
   拒绝 + 给用户一句可读提示 + 建议动作（"先断开连接" / "添加为新的电脑"）。
3. **恢复路径错误**（`R` 上任何非 `PAIR_START` 的连接意图）：
   拒绝 + 只提供"重新配对"入口。不得静默重连。
4. **未配置态的用户意图**（`U` 上的 `CONNECT` / `PAIR_*`）：拒绝 + 指向"添加电脑"。

所有 `✘` 分支的统一约束：**归约函数不得抛出**、不得写入半个状态、
不得发起网络副作用（副作用统一由 effect 队列在归约之后执行，见 §5.2）。

规则与格子的对应（每一格都有归属，实现与单测按这张表判）：

| 规则 | 覆盖的格子 |
|---|---|
| 1 迟到 / 旁路 | `C` 上 E07–E14；`F` 上 E07, E08, E11–E14（`F` 上的 E09/E10 是 `＝(i)`，只允许刷新 `offlineReason`，不改变状态） |
| 2 互斥窗口 | `G` 上 E01–E04；`O` 上 E01–E04；`F` 上 E01, E02 |
| 3 恢复路径 | `R` 上 E01, E03, E04, E06, E07–E14（`R` 只接受 E02、幂等的 E05/E15/E16/E18 与 E19/E20） |
| 4 未配置意图 | `U` 上 E02, E03, E04, E06（`U` 只接受 E01 与幂等事件） |

可验证的两个不变量（S1 写单测时直接断言）：

- 对全部 `6 × 21 = 126` 个 `(状态, 事件)` 组合调用归约函数，**不抛异常**，
  且返回的状态始终落在六态内；
- 所有 `✘` 组合返回的状态与输入状态**完全相同**（并产生一条诊断，不产生 effect）。

### 5.2 可重入要求

1. **归约不可重入。** 归约函数是纯函数，事件处理期间**不得同步派发新事件**（会递归）。
   需要产生的副作用（发起连接、排定时器、清理缓存、发请求）进 **effect 队列**，
   等本轮归约**返回之后**按顺序执行。
2. **单尝试。** 同一时刻最多一个 `connecting` 尝试。`CONNECT` 在 `G` 上是**合并**语义，
   不是新建；能产生第二条并发尝试的实现都算缺陷。同理最多一个打开的订阅。
3. **代次 `epoch`。** 进入与离开 `G` 都 `epoch+1`。所有异步回调（传输、握手、授权、超时）
   在创建时捕获当时的 `epoch`，回调时 `epoch !== current` → 丢弃。
   **这是防「迟到响应」的唯一机制**，不靠"发送方不会迟到"。
4. **定时器归属。** 每个重连定时器带 owner `epoch`；离开 `G`/`F`、`DISCONNECT`、`REVOKE`
   必须按 `epoch` 取消全部未决定时器。取消不彻底会表现为"已撤销却仍在自动重连"。
5. **两条通道独立。** 订阅（事件流）与命令是两条独立链路：一条失败不得写另一条的状态。
   订阅断开不改授权轴；命令得到 `401` 不改连接态。
6. **撤销的最高优先级。** `REVOKE` 处理中**先**使 `epoch` 失效，**再**执行清理；
   这样清理期间到达的任何回调都已经过期。
7. **冷启动不假定在线。** 进程被回收 / 应用重启后，连接态一律从
   `configured` / `offline` 重新推导并走正常 `CONNECT`；
   不得从本地缓存的"上次在线"恢复出 `online`。

### 5.3 幂等要求

| 对象 | 幂等键 | 重复时的必须行为 |
|---|---|---|
| 事件 | `eventId`（或 `(sessionId, messageId, revision)`） | 归约层 no-op：**不得二次追加消息或工具卡** |
| 写命令 | `clientRequestId` | 服务端返回**同一结果**（不重复执行）；客户端重复点击必须复用同一 id，而不是发新的 |
| 用户意图 | 事件类型本身 | `CONNECT` / `DISCONNECT` / `CREDENTIAL_CLEAR` / `REVOKE` / `PAIR_OK` / `AUTH_ACCEPTED` 重复投递不改变状态（迁移表已逐格标 `(i)`） |
| 快照 | `snapshotAt` 水位 | 比当前水位旧的快照不得覆盖新状态 |

三条硬规则：

1. **去重在归约层完成**，不依赖"发送方不会重复"；
2. **幂等记录必须跨重连与电脑端进程重启有效** —— 语义是冻结的，
   落盘位置与保留期是 S1 的决定（本文不定）；
3. **不得把幂等实现成"算了不发了"**：用户显式重试时，
   服务端要么返回上一次的结果，要么明确告知这是一次新请求。

## 6. 授权轴（与连接态正交）

### 6.1 授权态词表

| 授权态 | 机器名 | 判据 |
|---|---|---|
| 未授权 | `unauthorized` | 无凭据材料，或从未授权 |
| 授权中 | `authorizing` | 正在交换 / 校验凭据 |
| 已授权 | `authorized` | 凭据被接受，**且已知权限集** |
| 已失效 | `expired` | 凭据被拒（无效 / 过期 / 被替换）——可**重新授权**恢复 |
| 已撤销 | `revoked` | 授权被明确撤销——**只能重新配对**恢复 |

`expired` 与 `revoked` 的区别必须保留：前者是"凭证到期，再授权一次"，
后者是"这台设备被踢出去了，要走配对流程"。

### 6.2 授权轴可用性矩阵

能力按其**授权前置等级**分四档（定义见 §7.1）：

| 授权态 \ 前置等级 | A0 无需授权 | A1 只读 | A2 控制 | A3 管理 |
|---|---|---|---|---|
| `unauthorized` | ✔ | ✘ | ✘ | ✘ |
| `authorizing` | ✔ | ◐ 结果未定时不给数据，只显示进度 | ✘ | ✘ |
| `authorized` | ✔ | ✔ 若权限集含 `read` | ✔ 若含 `control` | ✔ 若含 `admin` |
| `expired` | ✔（含"重新授权"入口） | ✘ | ✘ | ✘ |
| `revoked` | ✔（仅本机设置 + "重新配对"） | ✘ | ✘ | ✘ |

`A0` 只包含**纯本机设置**（主题、字号、缓存大小、删除本机设备记录）。
会话缓存读取虽不联网，但属于该设备的数据，**撤销时已清除**，
所以 `revoked` 下不提供（这也是 §2 清除决定的直接推论）。

### 6.3 权限集（`permission` 是集合，不是等级数字）

```text
permissionSet ⊇ { 'read', 'control', 'admin' }   // 可能再细分，但实现不得只用一个布尔
```

- `read`：能力清单、会话列表、历史、工具详情、事件订阅；
- `control`：发送、新建、选择、重命名、定向停止；
- `admin`：电脑端设置（当前协议未提供，见 §7.2 的 C10）。

**只读永远不包含 `select`**：查看另一个会话**不得**抢走电脑当前视图
（[UI 方案 §5](ANDROID-UI-PLAN-2026-09-18.md)）。`select` 属于 `control`。

## 7. 能力可用性矩阵

### 7.1 前置条件模型（可求值，不是散文）

每个能力声明一份前置条件，界面可用性由它**推导**出来，
而不是每个页面各写一套 `if`：

```text
requires = {
  transport:  'any' | 'configured' | 'online',
  auth:       'none' | 'valid',
  permission: 'none' | 'read' | 'control' | 'admin',
  target:     'none' | 'deviceId' | 'sessionId' | 'runId',
  freshness:  'live' | 'cached'              // cached 允许在离线时降级
}
```

求值顺序（**第一条不满足即返回，不再往下判** —— 这保证界面只给一个原因）：

```text
1) transport 前置不满足                 → ✘ 「连接态」
2) auth = valid 且 authState ≠ authorized
     ├ freshness = cached 且存在缓存    → ◐ 「缓存 / 可能过期」
     └ 否则                             → ✘ 「授权态」
3) permission ∉ permissionSet           → ✘ 「权限」
4) target 未定向                        → ✘ 「目标未定向」
5) 全部满足                             → ✔
```

**原因优先级（唯一真源，文案与测试共用）**：

```text
revoked  >  未配置  >  offline/protocol  >  authn(expired)  >  permission  >  target  >  freshness
```

矩阵是本节的**结论**；`requires` 是它的机器可读形式。两者必须一致 ——
不一致以 `requires` 为准并按 `RC-SM` 变更规则改本文（S1 应有一条"矩阵由 `requires` 推导"的单测）。

### 7.2 矩阵（连接态 × 能力）

图例：`✔` 可用　`◐` 降级（括注）　`✘` 不可用（括注原因）　`—` 不适用（括注理由）

| 能力 | 前置 | U | C | G | O | F | R |
|---|---|---|---|---|---|---|---|
| **C1** 本机设置（主题/字号/缓存/删设备） | A0 | `✔` | `✔` | `✔` | `✔` | `✔` | `✔` 另给"重新配对" |

### 7.3 可见性规则（原型与实现都适用）

1. 前置不满足的能力**默认隐藏**，不要摆出按钮再让用户点失败。
2. 无法隐藏的（已在屏幕上的输入框）**禁用并给一句原因**，原因取 §7.1 的优先级结果。
3. 唯一允许的"保留可操作但需确认"是**结果待确认**（§8.3 的 `uncertain`），
   且它只能"刷新核对"，**不得**提供自动重发。
4. 降级（`◐`）必须**显式标注**（"缓存 · 上次更新 12 分钟前"），不得让用户以为是实时数据。
5. 手机上的任何操作**不得**乐观覆盖电脑终态（UI 方案 §9.C）。

## 8. 断线语义

### 8.1 重连

- **触发**：`RETRY_DUE`（退避到点）、`FOREGROUND`、用户手动重连、授权通过后。
- **退避形状**（数值是实现选择，形状是冻结语义）：指数 + 抖动 + 上限。
  默认 `1s → 2s → 4s → 8s → 16s → 30s`（上限 30s），抖动 ±20%，自动重试上限 **N=6** 次；
  超限后停止自动重连，连接态停在 `offline`，界面转"手动重连"。
- **退避重置**：只有 `CONNECT`（用户手动）、`FOREGROUND`、`PAIR_OK`、`AUTH_ACCEPTED` 重置退避。
  `DROP` **不**重置退避 —— 否则连接抖动会变成高频重试。
- **后台**：进入后台**暂停**退避计时（`BACKGROUND` 在 `offline` 上 `＝`）；
  不承诺后台常驻连接（[UI 方案 §8](ANDROID-UI-PLAN-2026-09-18.md)）。
  回前台**重新鉴权并刷新**，不假定订阅仍在线。
- **不重连的情况**：`revoked`、`protocol`（版本不兼容）、`authn`（凭证失效，先重新授权）。
- **并发上限**：任意时刻最多 **1** 个进行中的连接尝试、最多 **1** 个打开的订阅。

### 8.2 进行中操作（三类，处理方式不同）

| 类别 | 例子 | 断线时 |
|---|---|---|
| 幂等读 | 能力清单、会话列表、历史、工具详情 | 可安全重发（重连后自动或按需刷新），**不提示用户** |
| 非幂等写 | 发送消息、新建会话、重命名 | **绝不自动重发**，进入 `uncertain`（见 §8.3） |
| 订阅 | 事件流 | 重连后先取快照，再从快照水位继续；**重连本身不补历史** |

电脑端的任务**不因手机断线而停止**；"断开连接"只断开手机的订阅。

### 8.3 结果未知（`uncertain`）—— 消息状态机的第四态

手机侧每条写操作的结果状态：

```text
发送中 ──► 已接收 ──► (run 终态由事件给出，不属于本条的状态)
   │
   └─► uncertain「结果待确认」   // 请求已发出但没拿到响应（超时 / 断线）
   └─► failed「明确失败」         // 服务端明确拒绝，带错误类
```

冻结规则：

1. `uncertain` **只能**通过**显式刷新核对**（回执查询，或重读会话历史）转成"已接收"或"未接收"。
2. **不得**提供"自动重发"；重发必须由用户重新确认，且必须复用同一个
   `clientRequestId`（否则服务端会当成两次执行，工具可能被跑两遍）。
3. 服务端**必须**按 `clientRequestId` 去重，并在重复请求时**返回同一结果**
   （而不是再执行一次）。这是 S1 的硬要求，不是优化。
4. `uncertain` 的气泡不得伪装成"已发送"（UI 方案 §5）。

### 8.4 重复投递

| 对象 | 去重键 | 重复时的行为 |
|---|---|---|
| 事件（`msg-add` / `tool` / `todos` …） | `(deviceId, eventId)` 或 `(sessionId, messageId, revision)` | 归约层 no-op；**不得二次追加消息或工具卡** |
| 写命令 | `clientRequestId` | 服务端返回同一结果，不重复执行 |
| 用户意图 | 事件类型本身 | `CONNECT` / `DISCONNECT` / `CREDENTIAL_CLEAR` / `REVOKE` / `PAIR_*` 全部幂等 |

降低重复的通用规则：**归约层按键去重，不靠"发送方不会重复"**。

### 8.5 迟到响应

迟到响应（订阅已重连、页面已离开、操作已被取代之后才到）按**绑定的目标身份**路由，
**不按"当前页面"**（UI 方案 §7.2 的原话口径）：

```text
响应/事件携带：  { deviceId, sessionId?, runId?, epoch, at, watermark? }
```

1. **`epoch` 不是当前值** → 丢弃（这是最常见的迟到）。
2. **目标是别的 `sessionId`** → 应用到该会话自己的线程状态；**不得**投到当前阅读的会话。
3. **目标已被删除 / 设备已撤销** → 丢弃并（会话级）提示"目标已不存在"，**不把草稿投到别的会话**。
4. **水位规则**：快照带 `snapshotAt`；只接受 `at >= watermark` 的事件，
   比当前快照更旧的响应**不得**覆盖新状态。
5. 迟到响应**永远不改变授权轴与连接态**。

## 9. 协议兼容、错误分类与重试性

### 9.1 版本与握手

握手 = 传输就绪 **且** 读到能力清单 **且** 协议版本兼容。
版本不兼容 → `PROTOCOL_INCOMPATIBLE` → `offline(reason=protocol)`，停止自动重连，
文案"客户端与电脑端版本不兼容"，给"查看两端版本"的动作。

### 9.2 错误分类表

| 类 | 机器名 | 判定信号 | 可重试性 | 对连接态 | 对授权态 | 文案原则 |
|---|---|---|---|---|---|---|
| 网络 | `network` | `ECONNREFUSED` / `ETIMEDOUT` / `ENETUNREACH` / DNS / TLS 失败 / 心跳超时 | **自动可重试**（仅幂等读与订阅）；退避重连 | 尝试中→`F` | 不变 | "电脑不可达 / 网络不可用"；**不得**写成"电脑关机" |
| 认证 | `authn` | `401` | **不自动重试**；需重新授权 | 保持 | →`expired` | "授权已失效，请重新授权"（不要求重新配对） |
| 授权 | `authz` | `403` / 权限不足 | **不靠重试**；需权限变更或提升授权 | 保持 | 保持 `authorized`，权限集更新 | 该操作按钮应据权限**禁用**，正常路径下不应出现 |
| 服务端异常 | `server` | `500` / `502` / `504` | 幂等读可自动重试；写操作先核对回执 | 连续失败→`F` | 不变 | "电脑端服务异常" |
| 服务端未就绪 | `not-ready` | `503`（pi 未运行 / 桌面未就绪） | **不重试**，等状态事件；提供手动重试 | 保持 `O` | 不变 | "电脑端尚未就绪"，与网络故障区分 |
| 客户端 | `client` | `400` / `409` / `413` / `422` | **不重试**，必须改输入或目标 | 不变 | 不变 | 显示具体原因，允许编辑后重试 |
| 协议 | `protocol` | 版本不兼容 / 能力清单缺失 | **不重试**，需一端升级 | →`F`，停退避 | 不变 | "版本不兼容" |
| 未知 | `unknown` | 其它 | 保守：仅幂等读自动重试一次 | 不变 | 不变 | 记录 + 通用提示，不外泄内部细节 |

错误对象统一形状（脱敏，不含凭证与绝对路径）：

```text
{ class, retryable, at, status?, operationId?, clientRequestId?, detail }
```

配套硬规则：

- **`401` 与 `403` 必须分开**：前者是"你是谁不确认"，后者是"你是谁确认了但你不许"。
  两者混用会让用户被反复要求重新授权。
- **`503`（未就绪）与 `network` 分开**：前者电脑是活的，重试网络没有意义。
- 所有 `detail` 走脱敏；错误里**不得**出现凭证、绝对路径、完整会话文件内容。
