建议把砚推进为“**对话 + 工作窗口**”：左侧管理项目与会话，中间阅读、输入，右侧承载文件、网页、工具和子代理详情。移植 Harness 最有价值的部分，是清晰的入口、统一的资源窗口，以及过程信息退出正文后的阅读秩序。

延续砚当前 [DESIGN.md](../DESIGN.md) 的“墨色工作空间”：中文无衬线正文、暖中性色、单一靛蓝交互强调、代码等宽。参考图用于确定信息层级与行为，不原样照搬字体、比例与插件架构。

## 3. 文件链接与文档窗口

### 3.1 视觉与点击

正文中的文件引用显示为“小文件图标 + 蓝色短路径”，例如 `docs/PROJECT.md`。普通代码仍使用代码样式；不把所有行内代码自动染蓝。悬停/键盘聚焦显示完整路径与行号，点击区域包含图标和文字。

1. 单击文件：打开或激活它的文档标签；目录树选中该文件并展开父目录。
2. 单击目录：打开文件窗口并展开该目录，不尝试按文本读目录。
3. 行号链接：打开源码视图并定位、高亮该行；如果是 Markdown，带行号时优先源码视图。
4. 预览头：文件名、面包屑、阅读/源码切换、复制路径、在资源管理器显示、外部打开。
5. 文件缺失：保留标签、显示原路径和“重试 / 定位父目录”，不伪造内容。

同一资源重复点击复用标签并更新定位；不同文件可以并存。身份取 `projectId + workspaceRoot + canonicalPath`，不是仅凭文件名；不同工作树中的同名文件不能混为一个标签。

### 3.2 路径与渲染边界

- 兼容现有 `path:42`，新增 `path#L42`、`path#L42-L60`，正确处理 Windows 盘符、中文、空格与百分号编码。范围链接可标高亮范围，但不能把范围当文件名。
- 在相应消息/文档的路径上下文解析相对路径；文档内 `../` 链接相对当前文档目录，聊天引用相对所属会话工作目录。历史来自工作树或会话链时保留来源根目录，不能一律套当前 cwd。
- 用 Markdown AST 与导航上下文接入，不对原始流式字符串做全局正则替换。只将完整的显式链接设为可交互；未来若支持裸路径识别，另列功能开关与误判测试。
- `classifyLink` 只分类，主进程仍需判断实际文件、目录、项目边界与读取权限。不要把“蓝色可点”当作跨目录授权。
- Markdown 阅读模式禁用原始 HTML 执行，图片与相对资源经现有受控读取路径；代码块保持复制与换行能力。HTML 运行预览不随此项开启。
- 超过 2000 行的定位需要窗口化加载或围绕目标行读取，不能只估算滚动到不存在的 DOM 行。大文件仍显示截断/分页状态。
- 文件变化提示“内容已更新 · 重新加载”，不自动打断阅读位置。

### 3.3 移植取舍

借鉴 Harness 的 `parseFileLink`、Markdown 导航委托、文件资源身份、查看器切换与变更提示；保留砚 `window.yan.readPreview/revealPath/openPath` 的宿主边界。不要直接引入整套 Cordis、slots、资源服务容器。

## 4. 助手消息与底部信息

### 4.1 新的阅读顺序

```text
模型的过程说明（确实有时才显示）
  工作过程 ▸                         ← 默认紧凑，可展开推理/工具
  子任务：项目目录只读查阅 · 已完成    ← 短入口，归属本轮

最终回答正文……
参考文件：▱ docs/PROJECT.md           ← 蓝色文件链接

复制   用时 42 秒   20:42   ⋯         ← 整轮只出现一次
```

取消助手顶部“砚 / N 步 / 标准”与相应空占位。无工具、无推理的普通回答直接从正文开始。保留用户消息与助手正文的区别，但不靠每条重复品牌名区分。

“工作模式”（标准/澄清/自主）、“回复详细度”（简短/标准/详细）、“工作区模式”（编码/日常）仍各司其职；本次只移除助手消息上的详细度徽章，不联动修改它们的实际值。

底部默认仅“复制、用时、完成时刻、更多”。截图中的 token 用量适合放进“更多 → 本轮统计”，也可在偏好里打开常显。若常显，应明确是本轮还是会话累计，不复制“498K”这类示例数值。无点赞、点踩、评价入口。

### 4.2 整轮计时口径

**本方案默认：本次请求被执行器接纳开始运行 → 本轮最终稳定结束的墙钟时间。** 不含请求还在发送队列中的等待，也不含用户提交下一条请求前的空闲。

| 情况 | 计时行为 |
|---|---|
| 首 token 等待、模型思考、工具执行、重试等待、自动压缩 | 都属于本轮用时 |
| 等待用户授权或补充回答，但仍在同一运行中 | 总用时继续；统计详情另列“等待用户”，运行态显示等待状态 |
| 并行工具或子代理 | 算真实经过时间，不把各分支时长相加 |
| 父回答已结束，后台子代理继续 | 父回答用时冻结，子代理独立计时 |
| 停止或失败 | 冻结当时用时并显示“已停止 / 失败”，不装作成功完成 |
| 同一请求自动继续、跨会话链交接 | 使用稳定 logicalTurnId 归属，不能每次 agent_end 都冻结成新回合；定义 settled 与 continuation 的最终边界 |
| 崩溃/退出时仍运行 | 恢复为中断或状态待确认，不能把应用关闭期间当作一直生成 |
| 旧历史没有整轮起止记录 | 隐藏用时或显示“未记录”；不得用最后一条 elapsedMs 伪装 |

实现建议：主进程建立独立 `TurnTiming` 记录，含 `logicalTurnId / sessionId / userEntryId / runId / startedAt / endedAt / terminalReason / waitSpans`，关联助手消息 ID。运行态以单调计时为准，持久化保存起止与累计值，避免系统时钟调整得到负数。

使用宿主侧的版本化元数据日志保存时间与用量索引；恢复消息仍读 pi 会话 JSONL，元数据只装饰已有消息，不生成一套平行历史。落盘位置按现有 `YAN_DATA_DIR` 规范定义，考虑会话链、分叉、删除与工作树重绑定。

**用量必须先校验协议语义。** 当前 `turns.ts` 注释称 usage 为累计值并取最后一条；Harness 的统计模型则聚合独立 provider bucket。本轮没有核验砚所有 provider 的真实 usage，后续需区分“同一请求的流式累计更新”与“不同 API 请求的独立使用量”。以请求/消息 ID 去重后再聚合，未知不显示，不能简单取末条或盲加每个 delta。

## 5. 右侧工作窗口

### 5.1 开始页

没有打开的资源时显示“开始”。核心入口竖排：

```text
开始                                      ＋  放大  收起

                 工作区文件
                 浏览器
                 工具

              审查变更 · 新建终端
```

首期三个主入口保持轻量；终端真正完成后提升到主入口，不在首页放永久灰色占位按钮。审查仍保留项目环境菜单入口，开始页给次要快捷入口即可。

点击入口替换空“开始”标签；`＋` 打开一个新的开始页或入口菜单。关闭最后一个普通标签返回开始页；点击“收起右栏”仅改变布局，保留已开资源与活动标签。

### 5.2 工具窗口

工具从固定主面板变成名为“工具”的普通标签。保留当前上下文、任务、队列、扩展、日志、操作分区的排序/折叠/隐藏设置；**不改任务面板布局与任务来源**。

文件以独立文件窗口作为主要入口。已有工具窗口内文件树首期保留兼容，避免旧工具布局丢失；后续可由用户隐藏这个重复分区，不能迁移时悄悄删掉。

### 5.3 真正的窗口状态

建议增加内部 `WorkbenchState`，按会话（稳定的会话链身份）保存标签和布局：

```ts
type WorkbenchTab =
  | { id: string; kind: 'start' | 'tools' | 'files' | 'review' }
  | { id: string; kind: 'document'; resourceKey: string; path: string; line?: number }
  | { id: string; kind: 'browser'; browserTabId: string }
  | { id: string; kind: 'subagent'; runId: string }
  | { id: string; kind: 'terminal'; terminalId: string }

// 每会话 tabs / activeTabId / width / expanded / version；
// 各资源内容、进程和 DOM 是否挂载，分别由资源所有者管理。
```

这是示意契约，最终字段需与现有 session-layout、浏览器和会话链身份衔接。首期只有一个活动内容区，但可保留多个已打开标签；不同时引入多列 docking、拖出独立 OS 窗口、复杂分屏树。

| 操作 | 规定的生命周期 |
|---|---|
| 从网页切到工具或文件 | 隐藏原生网页视图，保留网页会话和标签 |
| 收起右栏 | 所有资源仍存在；取消可见原生区域，不改变任务状态 |
| 关闭一个文档 | 释放该查看器，其他文档不受影响 |
| 关闭一个网页标签 | 仅释放对应砚内置网页；Chrome 连接与用户浏览器生命周期分别处理 |
| 关闭子代理详情 | 只关闭查看窗口，任务继续；“停止”是明确的独立操作 |
| 关闭终端标签 | 有运行进程时明确“结束终端”或“保留后台”；不可因切页杀进程 |
| A/B 会话切换 | 还原各自活动页与滚动；旧请求不能写进新会话窗口 |

当前 `RightPanel.switchWindow('tools')` 会调用 `closeBrowser()`，而 `BrowserManager.close()` 会关闭内部所有网页并断开外部 Chrome；这正是本次要改掉的行为。表面标签存在不等于资源可保留。

原生视图的显隐集中在一个协调器：只有当前会话、当前活动网页、右栏可见、且没有覆盖弹窗时才能显示。切文件、设置、菜单、子代理弹层时统一处理，避免每个组件各自“关闭后恢复浏览器”。同步 bounds 继续乘窗口 zoomFactor。

### 5.4 尺寸建议

右栏常规目标宽 360–480px，文档/网页可以放大；聊天区优先维持可阅读宽度。标签行约 36px，路径/导航行约 36px，常规图标 14–16px；这些是候选尺寸，必须经真实窗口验证后才写入 DESIGN 令牌。

在窄窗中，用单面板切换或扩大右侧工作窗口查看详情；不要把聊天和文档硬挤成两条窄列。已有推理默认限高、主动展开范围、折叠入口保持原规则。

## 6. 浏览器：移植交互，保留砚的能力

| 比较点 | 判断与方案 |
|---|---|
| 页面承载 | Harness 当前右栏 Body 是 iframe；砚使用原生 WebContentsView。保留砚，避免引入 iframe 的嵌入限制和地址可观测性约束 |
| 标签组织 | 将砚现有网页标签映射到工作窗口标签，避免“工作窗口浏览器标签 + 网页标签”双层重复；browserTabId 仍由 BrowserManager 管理 |
| 导航状态 | 借鉴 Harness `request.revision`、加载/失败分离；砚以 did-navigate / did-navigate-in-page 等真实事件为已提交 URL 真源，旧导航结果不得覆盖新地址 |
| 地址栏 | 前进、后退、刷新/停止、地址、更多；编辑草稿与已提交地址分离，后台导航不应清掉正在输入的内容 |
| 错误 | 在导航栏下显示“打不开该页面 / 重试 / 在外部浏览器打开”；错误标签仍保留原 URL |
| Chrome | 保留明确的 Chrome 来源标识、接入/断开与已有受控同步能力；点击普通网页不自动复制登录信息 |
| Agent 控制 | 保留用户接管与恢复 Agent，显式展示正在操作的页面；后台标签不得偷偷夺取用户当前阅读页 |
| 下载与权限 | 保留已有下载与按 origin 权限管理，收进更多菜单/状态区域；不复制 iframe 的“关闭 sandbox”按钮到原生浏览器 |
| 模型调用 | 保留 `yan browser …` CLI → 宿主能力服务 → BrowserManager/CDP；不因参考项目有 browser-use 包就重新注册 pi 工具 |

本轮只比较了 Harness 右栏浏览器与相关源码。其 experimental 下存在多个 browser-use provider，文件存在不证明本机可用，不据此承诺它们优于砚，也不批量引入。

## 13. 补充：用户消息时间与图标

### 13.1 用户消息时间

用户消息气泡下方显示 `20:42`，与气泡文本边缘对齐，弱化到辅助文字，但保持可读对比度。悬停时间或键盘聚焦时显示例如 `2026年9月21日 20:42:08 · Australia/Sydney（UTC+10:00）`；实际偏移必须按该时间的时区规则计算，不固定写 +10，也不从文件修改时间猜发送时间。

已有 `UIMessage.timestamp?: number`，`normalize.ts` 已转交消息 timestamp，优先使用这个字段。缺失则不显示伪造时间。DOM 使用 `<time datetime="…">`；完整时间在可访问标签/提示中可读，触屏点击可展开，不能只有鼠标悬停才看得到。

发送队列中的消息仍标“待发送”；正式进入会话后使用持久化消息时间。若希望展示点击发送的时刻，应单列 submittedAt，不与 pi 消息落盘时间混用。复制/分叉/历史恢复保留原消息时间语义，不能用组件挂载时刻。

助手底部完成时刻采用同样的完整时间提示。日期格式与界面语言一致；精确值统一由共享 formatter 产生，避免消息区和子代理列表两套格式。

### 13.2 图标风格

建议采用 **Lucide 式单色线性图标**：简洁、均匀描边、圆角端点，与终端符号和砚的墨色工作空间协调。选择一套完整 glyph 来源，继续通过砚现有 `Icon` / SVG sprite 统一渲染，不在每个组件添加另一套图标运行库。

| 含义 | 建议图形 |
|---|---|
| 工作区文件 / 文档 | folder-open / file-text；Markdown 文件加轻量 MD 类型标识 |
| 工具 | panels-top-left 或 sliders-horizontal；全应用同一语义使用同一图形 |
| 终端 | terminal（`>_`） |
| 浏览器 | globe；Chrome 通道用文字来源标识 |
| 子代理 | network；运行/完成/失败另加状态符号 |
| 用时 / 消息时间 | timer / clock；用户短时间旁可省图标以保持克制 |
| 复制 / 目录定位 | copy / folder-search |
| 审查 / 展开 / 收起 | git-compare-arrows / maximize-2 / panel-right-close |

主操作图标 16px，次级 14px，小标签 12px；统一视觉重量，候选描边 1.75px，实施前在 100%/125%/150% 下检查清晰度。点击命中区独立于图形尺寸，提供中文 aria-label。成功/错误不能只靠颜色。

保留砚自有品牌图形作为应用身份，不用通用图标替换品牌。开始页可用低对比小罗盘，不使用彩色 emoji 文件夹、混用实心/线性图标或不同来源的按钮风格。

## 14. 补充：1M 上下文的审阅结论

详细证据与候选参数见 [上下文压缩审阅与大窗口策略](./审阅-上下文压缩频率与1M模型策略-2026-09-21.md)。

结论：**当前默认策略对 1M 窗口偏早，应增加按模型生效的大窗口策略；最近样本不足以断言持续高频压缩。** 默认工作集封顶 240K，实读六份最近会话有两次压缩，发生在 240,846 / 242,459 tokens。工具清扫、状态摘要与整轮压缩必须分别设计，不能仅修改一个工作集数值。

建议给确认有效窗口约 1M、且本次输出预算允许的模型试行 **600K 整轮软压缩线**，700K 作为可选更长档，硬上限仍受真实窗口、输出预留和误差余量限制。600K/700K 是待验证参数，不是模型最佳点的实测结论；本轮没有修改用户设置。

增加独立切片 **C1 上下文策略与观测**，可与 S2 窗口工作分开实施：统一宿主/扩展策略解析、请求预算、阶段门槛、摘要触发原因、压缩前后占用与增量防抖；更新上下文窗口里的“实际占用 / 整理线 / 压缩线 / 策略来源”。保持现有任务面板不动。
