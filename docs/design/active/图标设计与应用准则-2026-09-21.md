# 砚 · 提示砚图标设计与应用准则

> **状态：设计提案，尚未实施。**
>
> 日期：2026-09-21
> 适用项目：砚（Yan / pi-desktop）桌面客户端。
> 参考输入：用户提供的《砚-全新 UI 设计方案与设计规则-2026-09-21》。
>
> 本文件只定义图标方向、品牌图标的使用边界和验收规则。它不替代
> [`docs/design/DESIGN.md`](../DESIGN.md) 的当前设计令牌真源，也不代表整套新 UI
> 已经实施或通过真实窗口、视觉、打包验收。方向确认后，才把需要生效的内容回填到
> `DESIGN.md`、样式令牌和组件实现。

## 1. 这次要解决什么

新的 UI 参考把产品气质定为“墨色工作空间”：安静、清楚、精致，减少装饰线、提示符、
重复徽章和多种高亮竞争。图标应服务于这个方向，而不是再增加一套抢注意力的装饰语言。

本提案采用两层图标体系：

| 层级 | 统一对象 | 作用 | 允许出现的位置 |
|---|---|---|---|
| 品牌层 | `01-prompt-stone.svg` 的“提示砚” | 识别产品、应用和安装包 | 应用图标、任务栏、开始菜单、安装器、关于页、品牌空状态 |
| 语义层 | 现有 reicon 线性图标集 | 表示动作、对象和状态 | 搜索、文件、设置、浏览器、审查、发送、停止等功能控件 |

“全部使用这个图标”在本方案中解释为：**所有品牌触点统一使用提示砚**；不把品牌标记
强行替换成所有功能按钮的图标。功能按钮必须保留语义图标，否则“打开文件”“搜索”
“停止运行”等动作会失去可理解性，也会违背参考方案 §11.5 的“同一动作使用相同图标”
和“图标只承担一层含义”规则。

## 2. 品牌图标原型

### 2.1 唯一源图形

唯一品牌源图形是用户提供的 100×100 SVG：

```text
01-prompt-stone.svg
```

当前工作树中用于生成资源的副本应保持为：

```text
build/prompt-stone.svg
```

这个副本只能作为源文件保存；`build/icon.png`、`build/icon.ico`、
`build/installer-sidebar-generated.png` 和 `build/installerSidebar.bmp` 都是生成物，
不得反向编辑生成物来改变图形。

### 2.2 几何含义

图形由两部分组成：

- **石框**：一个留有右上开口的方形框，表达砚、容器和工作空间边界；
- **提示符**：右向折线与短横线，表达输入、提示、命令和模型工作的入口。

图形的识别重点是“开口方框 + 提示符”的组合，而不是某一个单独的角或横线。任何缩放、
裁切或重绘都必须保证两部分仍然同时可见。

### 2.3 不改变的属性

在没有新的品牌评审前，以下属性固定：

- `viewBox="0 0 100 100"` 不改；
- 保持原始路径比例、开口位置和端点形状；
- 保持单色 `currentColor` 语义；
- 不在 SVG 源文件中加入渐变、阴影、纹理、文字或产品名；
- 不把图标改成四角星、闪光符号、汉字“砚”或 emoji；
- 不通过倾斜、拉伸、压扁、旋转来制造“动感”版本。

## 3. 图标变体

### 3.1 源图标：透明底单色版

用于网页、关于页、设计稿和需要由容器提供背景的地方。

- 前景使用 `currentColor`；
- 背景由父容器负责；
- 不能假定永远在深色背景上，浅色背景必须单独检查对比度；
- 不在源 SVG 内写死 `#22d3ee`，避免浅色主题或外部文档无法复用。

### 3.2 应用图标：深色方形底版

用于 Windows 应用图标、任务栏、开始菜单和快捷方式。

- 外层可以使用深色方形底和极细边界；
- 只允许一枚居中的提示砚，不叠加旧四角星；
- 前景可使用项目强调青色，候选值为 `#22d3ee`；
- 16px 预览必须仍能看出右向提示符，不得为了保留细节而塞入文字；
- 透明区域、圆角半径和外层背景属于应用资源包装，不得改变源图形比例。

### 3.3 安装器侧栏版

用于 NSIS 欢迎页和完成页侧栏。安装器侧栏是品牌展示位，不是功能面板。

- 最终尺寸固定为 164×314；
- 以完整提示砚为主视觉，允许在下方放一枚低透明度的同图形水印；
- 不使用旧的四角星、随机曲线或与品牌源图形无关的装饰；
- 不在图片内重复写“砚”“Yan”或版本号，安装器文字由安装器页面负责；
- 导出为 24-bit BGR BMP，避免透明通道在 NSIS 中被错误解释；
- 深色底使用稳定的纯色或非常克制的明暗层次，不使用持续发光或玻璃模糊。

### 3.4 单色反白版

用于黑白打印、故障回退、低对比度背景或系统不支持彩色资源的场景。

- 只改变 `currentColor`；
- 不增加实心填充；
- 前景与背景的对比度必须通过实际测量确认；
- 单色反白不是新的品牌图形，不单独发展形状变体。

## 4. 使用位置与尺寸

尺寸是候选规则，最终需要在深浅主题、DPI 1 / 1.25 / 1.5 / 2 和真实 Windows 外壳中
复核。尺寸本身不能替代视觉验收。

| 位置 | 推荐视觉尺寸 | 资源形式 | 规则 |
|---|---:|---|---|
| 应用图标源 | 100×100 viewBox | SVG | 只存源图形，不带背景 |
| 应用/快捷方式 | 16 / 32 / 48 / 64 / 128 / 256px | ICO 多尺寸 | 使用同一源图形生成，不分别绘制 |
| 应用 PNG | 512×512px | PNG | 用于构建、文档和不能读 ICO 的平台 |
| 关于页 / 品牌空状态 | 48–96px | SVG 或 PNG | 只做一个视觉重心，不加重复徽章 |
| 标题栏品牌入口 | 20–24px | SVG | 与文字间距 8px，不能挤压窗口操作 |
| 安装器侧栏 | 164×314px | 24-bit BMP | 预留安全边距，不裁切主图形 |
| 通知 / 外部快捷方式 | 32–64px | ICO / PNG | 仍使用应用图标版，不使用功能图标冒充品牌 |

### 4.1 小尺寸检查

16px 与 20px 是最容易失败的尺寸。每次生成资源后必须检查：

1. 方框开口是否仍然可见；
2. 折线与短横是否粘连成一块；
3. 细边界是否比主体更抢眼；
4. 深浅背景上是否都能辨认；
5. Windows 任务栏缩略预览是否不会误认成普通终端符号。

如果小尺寸确实不可辨认，应先调整导出抗锯齿和包装背景；不能直接修改源图形来“补像素”。

## 5. 各产品触点的应用准则

### 5.1 桌面应用外壳

- 左侧品牌入口可以使用提示砚，产品名“砚”作为旁边文字，不把文字塞入图标；
- 标题栏的折叠、置顶、浏览器、辅助区和窗口控制仍使用语义化功能图标；
- 品牌图标不参与运行、成功、警告、失败等状态染色；
- 运行状态应使用文字、小型状态标记和现有状态语义，不把提示砚变成旋转 loading 图标；
- 同一页面只保留一个主要品牌图形，避免左栏、空状态、输入区同时出现大图标。

### 5.2 会话与空状态

- 空会话可使用 48–64px 提示砚作为主视觉；
- 主视觉下方应有一句说明和可执行建议，图标不能独立承担“现在该做什么”；
- 普通助手消息只保留轻量角色标识，不为每条消息重复显示大图标；
- 用户消息、工具调用、文件、任务和错误使用各自的语义表达，不用提示砚代替角色或状态。

### 5.3 设置与档案

- “关于 / 版本 / 品牌”使用提示砚；
- 头像自定义可以提供提示砚作为默认品牌选项，但不能把用户选择的其他头像强制覆盖；
- 设置页的模型、外观、上下文、项目知识、扩展包等入口继续使用语义图标；
- 图标按钮必须有可访问名称、键盘焦点和必要的 tooltip，不能只让用户“猜图”。

### 5.4 安装包与更新

- NSIS、便携版、ZIP 中的应用图标全部来自同一批 `icon.ico` / `icon.png`；
- 安装器侧栏使用同一源图形的专用排版，不再使用与应用图标不同的旧四角星；
- 安装包文件名、版本号和安装器文案由打包配置负责，不写进图标位图；
- 重新生成图标后必须重建所有 Windows 产物，旧 `release/` 文件存在不等于本次打包已换图标。

## 6. 颜色与对比度

### 6.1 品牌色候选

应用图标的深色包装版可以使用：

| 部分 | 候选值 | 说明 |
|---|---|---|
| 图标背景 | `#0b0d0e` | 与当前深色应用图标包装一致的候选值 |
| 图标边界 | `#22303a` | 只做极轻边界，不能抢主体 |
| 提示砚前景 | `#22d3ee` | 仅用于品牌图标候选，不代表运行状态 |

这些值是图标包装候选，不自动成为全局 UI 令牌。新 UI 参考提出的温和中性色与单一靛蓝
强调方向确认后，应用图标前景是否继续使用青色需要单独看深浅主题和 Windows 外壳效果。

### 6.2 禁止混淆品牌色与状态色

- 青色品牌图标不表示“正在运行”；
- 绿色不用于品牌成功版；
- 红色不用于“失败版品牌图标”；
- 不制作一组“成功提示砚 / 警告提示砚 / 失败提示砚”来代替状态组件；
- 状态必须同时有文字或形状信息，不能只靠图标颜色传达。

## 7. 与新 UI 设计规则的对应

| 新 UI 参考原则 | 图标落地解释 |
|---|---|
| 主对话是第一注意力 | 品牌图标只做轻量锚点，不在消息区反复占据视觉中心 |
| 减少提示符、装饰线和徽章 | 提示砚只在品牌触点出现；功能操作不叠加品牌符号 |
| 单一强调色 | 品牌图标采用单色版本；功能图标跟随语义色，不另造颜色 |
| 图标与文字间距 8px | 品牌入口和带文字按钮统一使用 8px 间距，必要时做光学微调并记录原因 |
| 图标视觉尺寸与点击区域分开 | 图标本身 14–24px，按钮命中区按可用性要求扩大 |
| 不使用 emoji 作为功能图标 | 不再用 `✦` 等字符承担品牌或功能图标职责 |
| 深浅主题分别检查 | 源 SVG 允许由容器提供颜色，不能只截图深色主题就宣布完成 |
| 设计提案不能替代运行证据 | 资源生成、真实窗口、包内落位、Windows 安装器视觉分别验收 |

## 8. 实现边界与文件职责

### 8.1 源文件与生成文件

| 文件 | 职责 | 是否手工编辑 |
|---|---|---|
| `build/prompt-stone.svg` | 提示砚唯一品牌源图形 | 只在品牌确认时改 |
| `scripts/build-icon.mjs` | 由源图形生成 ICO / PNG | 可以维护生成逻辑 |
| `build/icon.ico` | Windows 应用多尺寸图标 | 不手工编辑 |
| `build/icon.png` | 512px 应用图标 | 不手工编辑 |
| `scripts/build-installer-sidebar.mjs` | 生成安装器侧栏 PNG | 可以维护排版逻辑 |
| `build/installer-sidebar-generated.png` | 侧栏中间生成物 | 不手工编辑 |
| `build/installerSidebar.bmp` | NSIS 最终侧栏资源 | 不手工编辑 |
| `electron-builder.yml` | 应用图标和 NSIS 资源落位 | 可以维护打包配置 |
| `docs/design/icons/` | reicon 功能图标集 | 不混入品牌图标 |

### 8.2 不越过现有架构边界

图标替换不应：

- 让 renderer 直接读取用户任意路径的 SVG；
- 把品牌 SVG 当成 pi 扩展或能力工具；
- 改变会话、任务、模型、凭证、远程 API 或默认 pi 行为；
- 为了视觉统一而删除现有功能图标的可访问名称；
- 用图片内容伪造登录、同步、运行成功或模型状态。

## 9. 验收清单

本提案获得确认并进入实现后，至少分开登记以下六类证据：

### 实现

- [ ] 所有品牌触点引用同一份提示砚源图形；
- [ ] 应用图标和安装器侧栏不再引用旧四角星；
- [ ] 功能控件仍使用语义化线性图标；
- [ ] 资源生成链可以从源文件重复产出。

### 自动检查

- [ ] SVG 可以解析，viewBox 和路径完整；
- [ ] ICO 含 16 / 32 / 48 / 64 / 128 / 256px 资源；
- [ ] PNG 与 BMP 尺寸、像素格式符合打包配置；
- [ ] `typecheck`、设计测量和图标相关检查通过；
- [ ] 未把品牌图标误接到功能状态或 emoji 回退路径。

### 真实运行

- [ ] 开发态窗口标题栏 / 左栏品牌入口显示正确；
- [ ] 深色、浅色、窄窗口和高 DPI 下品牌入口不变形；
- [ ] 任务栏、开始菜单、快捷方式实际读取新 ICO；
- [ ] 安装器欢迎页和完成页实际显示新侧栏；
- [ ] 旧用户头像和设置数据没有被覆盖。

### 视觉验收

- [ ] 16px、20px、24px、48px、96px 样张已看图；
- [ ] 深色 / 浅色背景对比度分别确认；
- [ ] 安装器 164×314 侧栏无裁切、拉伸和奇怪的透明黑块；
- [ ] 品牌图标不是页面唯一信息，文字和操作入口仍然清楚；
- [ ] 截图记录真实窗口尺寸、CSS 视口和缩放值。

### 应用与包

- [ ] `npm run dist` 生成的新三种 Windows 产物都包含新应用图标；
- [ ] `test:packaged` 解包、便携和 NSIS 安装态都通过启动探针；
- [ ] 安装目录中 `resources/app.asar` 与品牌资源落位正确；
- [ ] 旧用户数据升级读取验证逐字节不变；
- [ ] 产物哈希在本次构建后重新生成。

### 剩余限制

- [ ] 明确 Windows 外壳缓存旧图标时的刷新方式；
- [ ] 明确是否要为 Android 远程客户端复用同一 SVG（Android 按当前计划放最后）；
- [ ] 明确是否保留青色包装，或随新 UI 方向改成靛蓝包装；
- [ ] 明确关于页、空状态和用户头像默认项是否都采用提示砚。

## 10. 推荐实施顺序

1. 先确认本文件中的品牌范围：确认“全部使用”指品牌触点统一，而不是功能按钮全部同图。
2. 确认颜色包装：透明源图形、深色应用图标、浅色回退版和 NSIS 侧栏版。
3. 运行资源生成脚本，检查小尺寸和安装器侧栏视觉结果。
4. 在一个独立的视觉变更片中接入标题栏 / 空状态 / 关于页，保留功能图标与产品行为不变。
5. 通过深浅主题、窄窗口、DPI、真实安装和打包六栏验收后，再更新 `DESIGN.md` 的当前真源。

在方案确认前，不应把整套新 UI 设计、字体体系、色板或布局候选值直接写回当前产品规则。
