# Inkstone 设计规范 v0.5

[文档索引](README.md) · [品牌规范](BRAND.md) · [代码地图](CODE_MAP.md)

本文是砚（Inkstone）界面的**唯一公开设计规范**：设计意图、令牌、控件、版面、信息层级、动效、手机端、安装与引导界面，以及以后升级规范的流程。实现以源码为准，本文说明「为什么这样、以后怎么改」。

## Agent 原生上下文

上下文区采用紧凑操作布局：标题旁显示用量，内容只保留自动压缩开关、手动压缩操作及正在压缩/用量未知等必要状态。管理归属、token 阈值和历史资料政策不作为常驻说明。上下文设置页同样只显示操作；没有会话时显示简短原因。

手机端生活助手对话与桌面配对入口可独立进入，模型配置返回原页面，Android 返回键与界面返回按钮语义一致。页面切换保留本次会话与草稿；请求在离开页面时取消并保留可重试记录。未配置模型时显示配置入口，不生成演示回答。没有实际持久化与调度能力时，不展示「已设置提醒」或未生效的记忆开关；附件能力未接入时不放占位按钮。等待模型响应与真实内容分别显示，不用逐字动画模拟模型输出。

砚把 Agent 的运行过程投影成界面。上下文的内容、压缩、恢复与技能加载由 Agent 管理；界面不再提供砚的工作集预算、材料固定、自动整理、摘要注入或自动交接续跑。

右侧上下文区显示当前模型的物理窗口用量及 Agent 报告的压缩状态；未知用量显示未知，不把历史日志长度当作模型用量。设置页与右侧工具区的「自动压缩」「立即压缩」直接调用原生 pi，正在执行或压缩时禁止重复发起手动压缩。项目知识页保留资料查看、维护与主动发送，移除砚的自动检索注入开关。旧资料与原始会话记录保留。

原生 codemode 的子工具保留父调用身份，并归属同一条助手消息。MCP、工具搜索和 codemode 优先使用 pi 原生实现；砚继续承担窗口、文件展示、共享浏览器/终端和必要的宿主授权。其他 CLI Agent 的上下文状态来自它自己的协议或终端，不套用 pi 的压缩控件。

能力页在 pi 实际提供 `/mcp` 命令时显示原生服务器状态入口，点击后交由原生命令响应。既有宿主 MCP 列表标明兼容用途，不自动迁移配置或凭证。自动压缩开关具有可见标签；资料管理标题不再暗示自动注入开关仍然存在。

能力与插件页提供「Codemode」开关，采用 SettingRow 与 Switch，默认开启。说明只表达批量调用工具与整理结果，以及下一轮对话生效；不增加独立工作区模式。开启保留普通工具直接调用，关闭同时限制工具声明与实际执行；计划模式、只读子代理及活动档案限制优先。偏好只属于砚，不改写用户的 pi settings.json；旧 pi 或显式停用原生 Codemode 扩展时不伪造工具。

插件安装区的「仅本项目」只选择新安装的作用域。已安装条目的卸载按该条目显示的用户级／项目级执行，更新按该作用域解析本地来源路径；二者不受安装区勾选状态影响。同一来源在两级均有登记时分别显示，详情只展开所点的条目。更新沿用原生 pi 按来源匹配的语义，同一包身份跨两级登记时可能同时更新。

## Agent Hub 工作台

### 可移动工作区

主会话、任务、日志、文件、浏览器和 Agent 使用同一个应用内磁贴工作区。右侧只是工具首次打开的默认位置；主会话可以移到中间，内容区支持左右分列、上下分区，不设置固定列数上限。主会话保持独立，不可隐藏或合入工具标签。

每个磁贴是一张圆角卡片（`--r-lg`、`--bg-1` 底、柔和描边），卡片之间与工作区边缘留 8px 缝隙，缝隙本身就是分隔线，悬停或聚焦时显示强调色细线。工具磁贴只有一行 28px 标题（标签与按钮 22px）：左侧为标签（资源可新建时标签后跟 `+`），右侧只有一个「收起」；不另放移动图标，拖动从标签或标题留白开始，双击标题留白放大/还原。面板菜单（移动到左右上下、合组、放大、资源自身操作如新建或结束终端、收起）在标签或标题上右键打开，键盘用菜单键或 Shift+F10。可关闭的资源（终端）在标签上带 ×：选中标签常显，其余悬停或聚焦时显示，点 × 结束该资源而非仅收起。终端标签按顺序命名为「终端 1」「终端 2」，不带图标，shell 与目录放在悬停提示里，参照 Claude 桌面端的内置终端面板。主会话卡片没有标签行，顶部中央是一条拖动把手，悬停加深，键盘聚焦后 Enter 打开移动菜单；会话头（标题、地图/概览、项目与环境、目标、会话菜单）不在卡片内，与应用主栏合为一条，位于标题栏品牌之后，参照 Claude 桌面端。项目与环境菜单顶部是项目卡（文件夹图标块、项目名、等宽完整路径一行省略，右侧「打开」「复制」），其下按组以细线分隔：变更（十格方点表示改动量，已跟踪为警示色、未跟踪半亮）与分支｜拉取、推送并排一行（推送只写 `↑n`，完整说明在悬停提示）｜工作树、Pull Request、网页比较｜来源。行标题用无衬线，分支名、路径、数字用等宽；菜单从触发器下方落下，各组依次落位。来源区的副本目录只在有图片时出现，「移除」说明只在有条目时出现。磁贴正文不再重复资源标题行，只保留状态提示与内容自有工具条；文件磁贴的标签就是文件名，标签上的 × 关闭文件，标题右侧的 × 只收起磁贴，正文头只放阅读/源码与文件操作，路径行只给所在目录。打开工具和调整排列的入口位于应用标题栏右侧，菜单统一使用 `<Menu>`，贴着触发按钮弹出。

标题栏高 40px（`--h-titlebar`），窗口按钮与它同高，会话头并入其中段；会话标题退一档（medium 字重、`--fg-dim`），与品牌之间隔一条细竖线，避免品牌与标题并列成两个主角；左栏收起时，指针停在标题栏开关上约 140ms，左栏以浮层滑出（不推挤中栏，宽度沿用用户拖出的值），离开开关与浮层约 260ms 后收回，点击开关才固定展开；对话区顶部有一小段（16px、起点 35% 不透明）轻渐隐，滚动到标题栏下的消息淡出而不是被切断。输入框静止高度 64px（两行，参照 Claude），超过三行自动进入长文模式。会话切换器（Ctrl+K）是居中的模态小窗：顶部输入，下方结果列表（标题、项目 · 时间，正文命中另带一行片段），方向键选择、回车打开、Esc 关闭，没输入时列最近的会话；用户消息下方的「回退代码」只在存过检查点时出现，确认框先列出将修改、删除、恢复的文件，做完提供「撤销这次回退」。

主会话是主要内容，不画卡片：它的磁贴没有底色和描边，与工作区背景融为一体，只保留顶部拖动把手；工具磁贴仍是卡片。默认工作区只有主会话，没有检查器，也没有标题栏右栏开关。原检查器按用途拆开：上下文与额度见下；「任务」磁贴放目标、任务清单与待投递队列，「日志」磁贴放扩展状态与日志，二者从“打开工作区工具”菜单按需打开，状态栏的“打开任务”直接打开任务磁贴；导出、克隆、在文件夹中显示与自动重试收进会话头右侧的「⋯」会话菜单。旧布局里保存的检查器引用不再显示。

上下文占用由输入框右下的圆环 `<MiniRing>` 显示百分比（≥85% 黄、≥95% 红）。点开为「上下文窗口」浮层：首行左侧标题、右侧 `已用 / 窗口 (百分比)`；下面一条 6px 分段条，按类别着色，剩余部分为底色；再下是图例行（色块 · 类别 · token · 百分比，数字右对齐等宽）。类别为系统提示与工具（含压缩摘要，取总量减去消息估算）、用户消息、回复、思考、工具调用与结果、剩余空间；pi 只报告总量，分类按当前消息文本估算并在底部注明「分类为估算」，总量缺失时只显示总条。图例下是上次压缩、自动压缩开关与「压缩」按钮。额度在状态栏右侧显示各窗口百分比与迷你条；点开浮层的首行为标题、供应商与刷新图标，每个窗口一行“标签 … 百分比”（百分比用大号等宽字），下接 4px 进度条和一行暗色“已用 / 总额 · 重置时间”，窗口之间留白而不画分隔线，底部一行暗色“更新于”。两处浮层使用 `.ui-detail-popover`，从触发处向上弹出，Esc 或点外部关闭。 状态栏最右「本会话 $x」是本会话累计花费：pi 没有报价的模型（订阅制、自写服务，如 Command Code 上的 DeepSeek / Kimi / GLM）按随包模型目录的公开 API 价估算，数字前带 ≈，详情浮层另列「其中估算部分」；目录里也没有标价的模型仍记 0，不猜。

状态栏的额度只回答「当前模型还剩多少」；「账号额度」磁贴回答「我所有账号各剩多少」，从“打开工作区工具”菜单打开。正文是账号列表，每个账号一块，块与块之间留白不画框：首行为供应商字母标识、名称（有备注显示备注，否则显示邮箱或供应商名）、`使用中` 徽标（强调色，只给正在被砚使用的 ChatGPT 账号）与行尾操作；第二行暗色写邮箱 · 套餐 · 来源（来源只在非砚账号上出现，如「Codex CLI」）。其下沿用额度浮层的窗口语言：每个窗口一行“标签 … 百分比”，4px 进度条，一行暗色重置时间；余额类账号只写一行“标签 … 金额”。备注用行尾铅笔按钮就地编辑（单行输入框，回车保存、Esc 取消，清空即恢复默认名）。砚的 ChatGPT 账号可切换：非当前账号的行尾有「切换」按钮，切换在当前回合结束后生效，不另做确认框；「移除」只在编辑备注时出现在输入框旁（危险按钮，点后系统确认框）。列表底部一行是「添加 ChatGPT 账号」次要按钮，登录进行中显示等待与取消。本机 CLI 账号（Codex CLI、Claude Code、Gemini CLI）是可选来源，默认关闭，开关收在列表末尾的「本机 CLI 账号」折叠项里，用 `<Switch>`；这些账号只读，不提供切换，令牌过期时写一句暗色提示说明去哪个 CLI 刷新。查询失败就地显示一行错误，保留上次成功的数字并注明时间。磁贴标题行不放额外按钮，刷新在正文顶部一行「更新于 … · 刷新图标」。

「Agent 协作」磁贴是协作总览：顶部一行选择项目；其下「命令行 Agent」卡片每行一个 CLI（字母标识 · 名称 · 版本或未安装及包名），已安装的行尾是「打开终端」，一键在所选项目中启动交互终端并在侧边打开；未安装的行尾是「安装」，在一个普通终端磁贴里运行 `npm install -g <包名>`，用户可见全过程，终端结束后自动重新检测，标题行另有手动「重新检测」。再下是「带任务启动」卡片：分段控件选执行方式（交互终端 / 派出子任务 / pi 只读），Agent 选择片（未安装置灰），任务输入框与主按钮。运行列表按「进行中」「需要处理」「已结束」分组，每行为 Agent 标识、标题、方式与相对时间、状态点，点击在侧边打开该运行。没有运行时显示简短空状态。单个运行磁贴的顶部是一行状态条（状态、Agent、协作与审批入口），其下是终端或过程对话。

受管运行的磁贴是对话视图：第一条是派活指令（右对齐浅底气泡，标注来源「你」或「来自 砚主会话」，带上的未提交改动与附件以徽标、文件片显示）；其后按时间排列 Agent 叙述（复用主会话 Markdown）、工具行（可折叠，运行中展开，显示完成/失败）、改动卡片（文件名、+/− 行数、红删绿加 diff）、交接包（左侧强调色竖线，「来自 砚主会话 · 交接包」与投递徽标）、发回主会话的回报（虚线框「回报给 砚主会话」）；待答复的审批固定在末尾，黄色卡片就地批准或拒绝，问题类跳到审批与成果。路径一律显示为项目相对路径。底部是补充要求输入框，左侧「＋」添加附件，也可粘贴或拖入，待发送附件显示在输入框上方。交互终端运行仍显示原生终端。总览顶部在项目下方说明主工作区状态：有未提交改动时显示数量与「带上未提交改动」开关，非 Git 项目给出提示；运行结束后状态条提供「清理工作区」。

每条助手回复底部在时间旁提供复制按钮，复制该回合的完整回复正文；工具步骤的展开与收起按钮都固定在列表上方。左侧项目名称按钮单击展开或收起会话列表，进入该项目由会话或项目菜单操作完成。文件磁贴的目录列表使用全部剩余高度，仅在磁贴内部滚动。

思考强度在模型菜单中是分档滑块 `<StepSlider>`，视觉语言是「神经脉冲」：轨道是画布绘制的五行方点阵（5px 间距、2px 方点），已点亮部分沿整条轨道取档位连续色（相邻 `--think-*` 之间插值，无硬切），未点亮为 `--bg-4` 暗点。菜单打开时，填充前沿从最左「充能」到当前档；之后亮脉冲沿点行从左向右跑过，头部最亮、拖尾渐暗，档位越高脉冲越密、越快、拖尾越长，最高两档会分叉到相邻行，「关」没有脉冲。切档时填充前沿以轻微欠阻尼的弹簧追到新档（略冲过再回落），同时从新档位向左回灌一束脉冲。它表达强度预览，不能用于表示模型正在运行。手柄是当前档位色的块光标（10×26，柔光），位置跟随画布的弹簧前沿，静止时按终端光标节拍（1.06s `step-end`）在亮与半暗之间跳四次后常亮（闪烁不超过 5 秒），悬停暂停闪烁并略放大，拖动时放大且上方浮出档位名气泡，键盘聚焦显示同色双环。档位名在轨道下方，当前档为档位色文字加同色浅底。可拖动、点击轨道或档位名跳档，方向键/Home/End 调整。画布只在菜单打开时绘制，页面隐藏时停帧，换主题即重新取色；禁用时点阵静止、不闪烁；减少动态偏好下只画静态点阵，不充能、不脉冲、不闪烁。当前模型只有「关」一档时，思考区不隐藏：头部写「不支持」，下面一句说明原因（模型配置没有声明能思考）；砚管理的自定义服务另给一个「去设置」幽灵按钮。模型菜单从输入框向上弹出，高度取三者最小：触发器上方到标题栏之间（留 8px）、窗口高度的 60%、560px；可用高度不足 480px 时（如 150% 缩放的 1080p 笔记本）进入紧凑排版，两块设置收紧间距，「回复详细程度」的标题与分段并成一行，高度留给模型列表。模型菜单里两项设置的当前值前都有一枚同色小块光标（5×13），与手柄同语言；模型搜索整行就是输入框，聚焦时只亮放大镜与底线；键盘落点行用 `--bg-3` 底，不画描边。

拖动标题留白、标签或主会话把手时实时重排：被拖磁贴保持原尺寸与抓取点，整张卡片（含内容）浮起跟随指针，带阴影与顶部把手条；其余磁贴按当前落点以约 200ms 过渡让出位置，松手后的落点显示为强调色虚线占位框；放到另一块磁贴的左右时其余磁贴实时让位，放到上方或下方时其余磁贴不动，只用强调色边框标出新磁贴将占的那一半；被拖磁贴可跟随指针移出画布，超出部分裁掉，不撑大滚动区；落下时保留它被拖起时的尺寸；松手或取消后卡片滑入落点或原位。落点判定基于“拿掉被拖面板后”的排列且整个拖动期间不变，避免磁贴移动后目标来回跳动。边缘形成分区，中央合入工具标签组。预览不写入保存的布局，松手到有效位置才提交，Esc、失焦或无效位置恢复原排列；拖动期间隐藏分隔线，终端在尺寸稳定后才调整 PTY 行列。标签可以拆分；同一资源只挂载一次，移动、合组、放大或隐藏不新建 PTY、网页或 Agent。隐藏与停止分开，停止仍由内容组件明确提供。

工作区宽高变化（左栏展开收起、窗口缩放）时，主会话旁的工具磁贴保持用户最后一次排列时的像素宽高，只有主会话伸缩；主会话到最小宽度后工具磁贴才让出空间。布局记录排列时的画布尺寸（`basis`），每次拖动、调整分隔线、打开或移动磁贴都以屏幕上的当前排列为新基准；工具与工具之间仍按比例分配。

分隔线可拖动调宽高，也可聚焦后用方向键调整；移动菜单提供左右上下移动及合组选项。布局按稳定会话保存，仅保存资源引用、组、分区比例、活动标签和隐藏/放大状态。旧右栏排列迁移为主会话加右侧工具组。恢复默认排列只改变摆放，不清空资源。窄窗以可滚动的工作区保留最小阅读尺寸，放大当前面板可专注操作；窗口恢复后继续使用原比例。

布局调整与菜单使用现有原生浏览器遮挡协调器；浏览器坐标持续同步，PTY 按可见尺寸调整。子代理只复用主会话的消息、Markdown、过程折叠与工具呈现，不提供主会话分支、输入、追问或续跑操作。任务卡默认突出短标题、状态和打开入口，模型、范围与耗时作为第二行；完整任务和调用用量在详情里查看。

子 Agent 与外部 CLI 使用同一个「Agent 协作」入口。子任务是父会话/父运行的派活关系，不是另一套工作台。对话中的任务卡可打开侧边同一运行详情；旧任务保留原身份、转录、停止和补丁审阅，界面只做投影，不复制运行状态。终端运行使用一行标签栏，结构化运行展示真实过程，不模拟终端。补充要求与协作记录按需打开，正常电脑输入不常驻显示输入端。

协作关联由当前会话明确建立，同项目不等于已关联。主 Agent 可查询和联系自己的协作运行，外部运行可向其父任务或关联主会话回报；消息记录来源、目标运行及投递状态，旧运行消息不得投到新的执行尝试。终端协作消息先排队，由持有输入权的用户核对输入行后发送，不能自动粘贴并回车覆盖人工输入。协议接收与已写入终端均不表示模型已处理。成果验收与应用补丁使用不同操作。

检视器中的入口使用带 Agent 图标与进入箭头的整行按钮，与工具区对齐。工作台默认展示内嵌的真实 CLI 终端，通过统一分段切换终端/任务；「新增 Agent」展开表单，默认交互终端模式，创建后在有窗口位置时自动打开。重新进入时展示现有运行中的终端；关闭窗口只隐藏显示，不停止运行。模板和模型等可选设置按需展开，任务列表把标题与 Agent/状态分行，避免整页按钮和说明堆叠。窄栏保持单列，所有控件可用键盘操作。

普通终端与多 Agent 终端共用渲染配置：解析后的代码字体、13px 字号、1.15 行高、零额外字距。字体加载后才建立字符网格，避免 Canvas 测量与 DOM 字体不一致；窗口尺寸仍同步给真实 PTY，主题随深浅色切换。

终端优先使用 WebGL 与连续块字符/框线绘制；GPU 不可用或上下文丢失时回退默认渲染器。提供可访问的终端文本树，屏幕阅读与运行验收不依赖画布像素反推。

终端工作窗默认用标签切换 CLI，每个标签可隐藏、重新打开；「并排」显示多个终端。终端占据剩余高度，正文不受普通按钮的固定高度约束。参照用户提供的 Claude 工作窗方向，保持紧凑页头与原生终端内容。

新增交互 Agent 只需选择项目和 CLI，初始指令可留空，直接进入原生 CLI。砚不追加受管任务说明；交互终端默认不设任务时长上限，显式指定的时限仍有效。受管执行继续要求任务内容并保留其范围与超时约束。

交互终端最多四个同时运行，与受管任务的执行槽分别计数。隐藏标签保留进程，「停止」明确结束运行并释放执行槽。

桌面右侧工具区提供「多 Agent」入口，进入任务列表、派活表单与运行详情。用户选择现有项目、Agent、受管执行或交互终端以及模型；编码任务从明确的 HEAD 基线创建独立工作区，审查任务选择已冻结的交付成果。任务完成执行后显示「待审阅」，由用户验收；不自动合并。结构化执行和交互终端分别展示覆盖范围，终端静默、退出不表示任务完成。

任务详情在当前报告之后提供「运行历史」：每次运行按时间显示状态、模型、运行身份、外部会话和成果摘要，报告默认收起，由用户按需展开。恢复后的新运行保留旧运行记录；手机复用同一组事实，路径仅在桌面展示。历史内容是审阅依据，不能用旧批准直接执行新运行。

派活表单提供用户模板选择、名称、保存和删除。模板仅填写任务内容、Agent、模式与模型偏好；使用模板后仍由用户选择当前项目、核对任务并点击派活，不自动执行，也不携带旧成果、运行、输入权或批准。手机仅在新派活表单显示模板控件。

工作台提供「全部任务／待处理」筛选；待处理来自待答复、待审阅、失败与结果待核实的宿主事实。已开启手机待回答提醒时，Hub 待处理事项沿用现有提醒服务，锁屏只显示数量，不展示任务或批准内容；点击进入多 Agent 页面。未开启提醒不自动启用。

Agent 之间可互发**交接包**：交接包只携带参考资料（来源任务、基线、成果 SHA/ tree、摘要与请求），不授予新权限、不自动合并或推送。投递按目标能力降级——受管运行注入成新回合输入，交互终端写入 PTY（bracketed paste）；能力不适用时明确报失败，不假装成功。任务详情按**时间线**显示交接的对象、时间与投递结果（已注入／已写入终端／排队／失败）。同一项目内的活跃任务才可投递；受管运行只能把交接包发给它派出的运行，用户在电脑端可发给同项目任意活跃运行。

工作台提供「窗口」视图：用户可**自行增加 agent 窗口**，每个窗口一个运行（终端任务显真实画面，受管任务显说明与状态），窗口按自适应网格并排，可随时关闭；同一时刻只有一个窗口持有终端输入权，窗口头部标注当前输入端，不在「任务列表」里。

两端共用同一套任务、时间线与投递结果，**各自按屏幕布局**：桌面端窗口用自适应网格并排；手机端窗口**纵向堆叠**，每张卡片一行头部（名称 · agent · 状态）加内容（终端或说明），最多 3 个。手机端的「窗口」与「任务」用页内切换，不新增底部导航。时间线在两端都按时间倒序，显示来源、时间与投递结果（已注入／已写入终端／排队／失败），长文可展开、可复制。受管执行没有终端画面的运行卡片要直接说明，不留空白。

Agent 的执行过程以**对话**呈现（Chat View），不把终端原样缩小。对话流由四类条目组成：叙述（agent 的人话）、工具（Shell／文件／Patch；Patch 显示红删绿加的 diff，可折叠）、审批（就地批准或回答）、交接包（标注来自哪个运行）。受管运行用宿主的结构化事件；纯终端运行显示真实终端画面，不做逐帧解析。对话流底部是对话输入，可发消息或交接包。手机端任务列表用分组卡片（工作中／待处理／已完成），卡片显示标题、你发的指令、agent 与时间。

审批显示所属任务、动作与目标摘要、截止时间；答复已发送与对端已确认分别显示。资源争用显示等待，未知结果显示「待核实」，不能自动重试。桌面和 Android 复用任务事实，手机提供派活、审批、取消、报告与终端输入；终端输入和尺寸由同一控制端持有，接管后拒绝旧端迟到输入。高危 pi 确认沿用电脑确认边界。手机完整控制要求已配对且使用 Tailscale 加密通道或 HTTPS。

所有按钮、输入框、下拉框沿用统一控件；任务详情可展开，错误就地显示。布局在窄窗上下排列，不新增资源锁设置管理台。手机采用同样的信息顺序，长报告和终端输出可滚动，输入操作必须显示当前控制端。

手机选择任务后收起新任务表单并回到详情顶部，以「新派活」恢复表单。文本终端输入提供明确的「发送」按钮；Enter、Ctrl+C 等快捷键单独作用于终端，不承担输入框的发送语义。

## 1. 设计意图

砚是**墨色工作空间**：安静、清楚、克制。对话与成果是主角，输入区是下一步操作的锚点，执行过程、用量和诊断从摘要到详情分层展开。

v0.5 在此之上加入现代终端的气质：等宽骨架、提示符语言、命令块、状态栏、方点阵与块光标。终端气质服务于「看清发生了什么」，不做仿古绿屏、扫描线或发光。

四条原则：

1. **内容优先。** 正文、产出和输入高于工具元数据；元数据默认淡显，悬停、聚焦或展开时才完整出现。
2. **一种意图一种长相。** 同一个意图（主要操作、次要操作、互斥选项、状态标签）在所有页面只有一种外观，由 `ui.css` 统一提供；手机端用同样的语义与配色，尺寸按触控放大。
3. **克制层级。** 用背景色阶、留白和细分隔线表达层级；不用重复徽章、装饰渐变或持续发光争夺注意力。
4. **单一强调。** 靛蓝只表达选中、主要操作、链接和键盘焦点；成功、警告、错误保留独立语义色，品牌色不承担状态。

## 2. 令牌

### 2.1 颜色

深浅两套主题定义同名令牌（`html[data-theme]`），组件只引用令牌，不写色值。

| 令牌 | 用途 |
| --- | --- |
| `--bg-0` | 窗口底、中栏、分段容器底、设置内容区 |
| `--bg-1` | 左栏、右栏、会话头、状态栏、卡片、弹层 |
| `--bg-2` | 次要按钮、输入框、用户消息块 |
| `--bg-3` | 悬停、分段选中项、导航与列表选中项 |
| `--bg-4` | 按下、滚动条 |
| `--border-soft` / `--border` / `--border-str` | 分隔线 / 控件描边 / 悬停描边（半透明，适配任何底色） |
| `--fg` / `--fg-dim` / `--fg-mute` | 正文 / 次要（分区标题、说明） / 三级（元数据、诊断） |
| `--accent` · `--accent-soft` · `--accent-line` | 强调实色 / 浅底 / 描边 |
| `--on-accent` | 强调实底上的文字 |
| `--ok` `--warn` `--err`（各带 `-soft`） | 成功与新增 / 警告与待确认 / 失败与删除 |

规则：

- 强调色保持靛蓝（深色 `#93a4f4`、浅色 `#4b5dbf`）。原型里比较过的青绿、紫两档不采用：青绿与 `--ok` 太近，紫与思考档位色冲突。
- 绿色只表达成功或新增，不用来装饰「好的数字」；用量、缓存率等诊断值用 `--fg-mute` / `--fg-dim`。
- 新增颜色前先确认文本对比度 ≥ 4.5:1，并同时给出深浅两套值。强调色、状态色与思考档位色都会作文字用，在 `--bg-1`、`--bg-2`、`--bg-3` 与各自淡底上都要达标。
- 已删除的旧名（`--fg-0…4`、`--line`、`--line-1`、`--border-strong`）不再使用；`npm run check:motion` 会报告未定义的令牌引用。

### 2.2 字体与字号

界面汉字由系统微软雅黑 UI 排版，代码与纯命令保留等宽字形：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--font-mono` | Maple Mono CN（随包内嵌，拉丁 : 汉字 = 1 : 2） | 字体真源 |
| `--font-ui` | CJK 区段用本机微软雅黑 UI，其余回退 Maple Mono CN | 导航、列表行、元数据、工具行、按钮、分段、状态栏；含中文的路径也用它 |
| `--font-code` | `var(--font-mono)` | 代码、diff、终端 |
| `--font-sans` | Segoe UI + 微软雅黑 UI | 字体真源 |
| `--font-body` | `var(--font-sans)` | 对话正文（用户与助手）、页标题、设置说明等两行以上的中文段落 |
| `--fs-xs` 11 · `--fs-sm` 12 · `--fs-code` 12.5 · `--fs-base` 13 · `--fs-body` 14 · `--fs-lg` 15 | | |
| 页标题 | 18px / `--fw-strong` / `--font-body` | 设置页标题、引导标题 |

- 判断依据是**内容**：界面汉字与正文用无衬线，代码、diff、终端和纯命令用 `--font-code`。不要为了对齐而把中文路径塞进等宽字体。带中文的控件文字（按钮、分段、菜单项、徽标、折叠行标题）走 `--font-body`，等宽留给路径、文件名、代码、数字与快捷键，避免同一个标签里拉丁与汉字取自两套字体。
- 数字列（用量、计时、行号、计数）一律 `font-variant-numeric: tabular-nums`。
- 字重只用三档：`--fw-regular` 400、`--fw-medium` 500（按钮、行标题、选中项）、`--fw-strong` 600（分区标题、页标题）。不写裸数字字重。


### 2.3 间距、圆角、尺寸

- 间距 4 的倍数：`--sp-1…6` = 4 / 8 / 12 / 16 / 24 / 32。
- 圆角：`--r-xs` 4（分段内的项、行内代码、徽标） · `--r-sm` 6（按钮、输入框、分段容器、导航项） · `--r-md` 8（菜单、消息块） · `--r-lg`/`--r-xl` 12（卡片、对话框、输入区容器）。
- 全圆角（`--r-full`）只给滚动条、进度条、开关、头像、计数点和悬浮圆按钮；按钮与分段不用胶囊形。
- 控件高度三档：`--ctl-h-sm` 24 · `--ctl-h` 28（默认） · `--ctl-h-lg` 32。按钮、分段、输入框只用这三档。
- 状态栏高 24px（`--statusbar-h`）。

### 2.4 投影

界面内部的层级靠色阶，不靠投影。唯一的投影是弹出层（对话框、设置、引导、菜单、命令菜单）的 `--shadow-pop`，它表达「浮在内容之上」。

## 3. 控件

外观全部来自 `styles/ui.css`。模块 CSS 只写控件在自己版面里的**位置**（`margin`、`flex`、`align-self`、宽度），不重写底色、描边、字号、高度或悬停色。

### 3.1 按钮

| 写法 | 组件 | 用途 |
| --- | --- | --- |
| `.btn` | `<Button>` | 次要操作（默认）：对话框的取消、卡片操作、设置行操作 |
| `.btn.primary` | `variant="primary"` | 一个区域里唯一的主要操作（开始使用、提交、打开） |
| `.btn.ghost` | `variant="ghost"` | 行内低频操作、取消暂存、「不管了」 |
| `.btn.danger` | `variant="danger"` | 删除、移除、覆盖 |
| `.btn.icon` | `<IconButton label=…>` | 只有图标的按钮；必须给 `label`（用作 title 与无障碍名称） |
| `.btn.sm` / `.btn.lg` | `size` | 24 / 32px；默认 28px |
| `.btn.on` / `aria-pressed="true"` | `active` | 切换按钮的「已开启」 |

一个区域最多一个主要按钮。按钮文字写动作（「打开」「提交」），不写「确定」。图标在文字前；导航去别处的按钮可在文字后放 `chevron-right`。

### 3.2 分段控件

`.seg` > `.seg-btn`（`.sel` 或 `aria-pressed`），组件 `<Segmented>`。二到五个互斥选项：主题、语言、视图切换、筛选、档位。选中项用 `--bg-3` 底 + 正文色 + 中等字重，图标变强调色；**不用强调色实底**。`.seg.sm` 用于面板内部与筛选。选中底块切换时沿横向滑动到新位置，不跳变（`<Segmented>` 自动带 `.sliding`；手写 `.seg` 的地方在迁到组件后获得）。

同一外观的变体：会话头视图切换（`.shead-view`）、右栏队列模式（`.rp-switch`）、模型菜单档位条（`.mt-stops`）。新增互斥选项时直接用 `.seg`，不再新建变体。

### 3.3 其他

- **开关** `.switch-pill` / `<Switch>`（带 `.on`）：布尔设置；开启为强调色实底。
- **徽标** `.ui-badge`（`accent` / `ok` / `warn` / `err`）：状态标签与计数。浅底 + 同色描边 + 同色文字，不用实底。
- **空状态** `.ui-empty` / `<EmptyState>`：一句事实 + 可选的下一步操作。不画插图，不写「暂无数据」式空话；「没有改动」与「不在 Git 仓库里」这类不同事实用不同文案。
- **分区标题** `.ui-section-title` / `<SectionTitle>`：12px / 600 / `--fg-dim`，图标 `--fg-mute`。
- **键位** `.ui-kbd`：只给真正接了快捷键的动作画键位。
- **输入框** `.ui-input` / `<Input>` `<Textarea>` `<Select>`：`--bg-2` 底、`--border` 描边，悬停 `--border-str`，聚焦 `--accent` 实色描边（半透明 `--accent-line` 在浅色底上不足 3:1，不作焦点指示）。默认 240px 宽、左对齐；数值用 `.num`（96px、等宽数字、右对齐）。要撑满时模块只写 `width` / `flex`。
- **字段** `.ui-field` / `<Field>`：表单里的一项，标签（12px 中等字重）+ 控件 + 说明，整项包在 `<label>` 里。
- **设置行** `.ui-row` / `<SettingRow>`：「名称 + 说明｜控件」两列，行间一条细线，行本身不响应悬停；`col` 为上下排布。分组容器 `.ui-rows`。
- **设置分组** `<SettingGroup>`：分组标题和说明统一排版；同组设置行由 `.ui-rows` 承载。
- **渐进展开** `<Disclosure>`：把低频、诊断与高级选项收在明确标题下，默认收起；使用原生 `details` / `summary` 表达展开状态。
- **页签** `.ui-tabs` > `.ui-tab` / `<Tabs>` `<Tab>`：`role="tab"` + `aria-selected`，方向键移动焦点。选中项与分段同一语言（`--bg-3` 底 + 强调色图标），不画下划线。`.vertical` 用于设置导航；`.doc` 是可关闭的文档页签（右栏窗口栏、浏览器），关闭钮 `.ui-tab-close` 用 `close` 图标。互斥的视图切换用分段，不用页签。
- **菜单** `.ui-menu` > `.ui-menu-item` / `<Menu>` `<MenuItem>`：右键菜单、行菜单与下拉共用。`--bg-2` 底、`--r-md`、`--shadow-pop`；项 28px 高，悬停 / 键盘聚焦 / 选中为 `--bg-3`，键盘聚焦另加 1px 强调色内描边，`.danger` 只染文字，分隔 `.ui-menu-sep`，小标题 `.ui-menu-title`。定位由调用方负责（`ContextMenuSurface` 负责 fixed 与夹取）。
- **检查器分区** `.ui-inspector-section` / `<InspectorSection>`：标题 12px 半粗 + 右侧摘要，分区之间一条细线。
- **列表行** `.ui-list-row` / `<ListRow>`：可点的一行，图标或状态点 · 主文字截断 · 右侧元数据；选中 `--bg-3` 底。
- 模块不自建 `*-btn` / `*-chip` / `*-tab` 类：`npm run check:css-budget` 统计模块 CSS 里的这类选择器，只许为 0。
- **选中项**（列表、导航、菜单）：`--bg-3` 底；菜单与命令菜单的选中行首加强调色 `›`，左栏会话行用状态圆点。**不用 inset 边线**：圆角会把它弯成一道蓝弧。
- **进行中**：同一画面全局只显示一个方点阵 `<Spinner>`（`.ui-spin`，见第 6 节），放在运行主位置；工具行、任务、列表等局部运行状态用静态 `<RunDot>`（`.ui-run-dot`）。不用旋转图标、盲文字符或其它动画小球。

### 3.4 图标「砚线」

图标语义写在 `scripts/design/icons/catalog.json`，一个图标只承担一个语义；桌面与手机共用同一份生成物。图标是自绘的「砚线」，母题是品牌标志「提示砚」：开口石框 + 方头斜接的 `>_`。几何真源 `scripts/design/icons/inkline.json`，与编目一一对应。

几何规则：

1. **16 网格，12 活动区**，四周留 2px，对齐 12 / 14 / 16 三档尺寸。
2. **描边恒定 1.25px**（`vector-effect: non-scaling-stroke`），三档尺寸一样粗；手机端 1.5dp（见第 7 节）。
3. **方头 · 斜接**：`stroke-linecap: square; stroke-linejoin: miter`，统一直角。
4. **开口角**：文件、目录、终端、外链等容器类图标右上角留缺口。
5. **直线与整圆为主**：0° / 45° / 90°，不画插画式隐喻。
6. **进行中不用图标**：用方点阵；状态点、勾选框由 CSS 绘制。

可读性规则（描边取 1.25px 而不取 1.5px 的原因：1.5px 在 12px 下会把推子、清单这类多笔画图标糊成一块；1px 配 `--fg-mute` 在浅色主题下发虚）：

- **笔画间距**：平行笔画之间的净空在 16 网格中不少于 2 个单位（12px 下 1.5px）。达不到的图标在 12px 使用简化几何，或该位置改用 14px。
- **颜色**：单独出现的图标（图标按钮、无文字的状态标记）至少用 `--fg-dim`；`--fg-mute` 只给紧挨文字、只作辅助的图标。
- **可辨认**：同一区域并列的图标轮廓必须能区分（例如文件与复制、目录与项目），靠外形而不是细节区分。
- **验收**：新增或修改几何时，截取深浅主题 × Windows 100% / 125% / 150% 缩放下 12px 与 14px 的对照图。

尺寸只用 12 / 14 / 16（手机 16 / 20 / 24dp）。界面里不用 `✓ ○ ◐ ✕` 这类文字符号当图标。改图标：改编目与 `inkline.json` → `npm run icons` → `npm run check:icons`。

语义调整：`sparkles` → 星号 `*`；`agent` → `>>`；`settings` → 两道推子（三道在 12px 下会糊，按笔画间距规则简化）；`alert-circle` / `check-circle` → 方框内 `!` / 勾；`terminal` 即标志图形。`running`、`activity` 仍有几何，但进行中的状态改用方点阵（§6），这两个语义只留给静态计数。

### 3.5 提示符语言

| 位置 | 形式 |
| --- | --- |
| 用户消息 | 左侧 `›` 提示符 + 正文的块，`--bg-2` 底 + `--border-soft` 细边（浅色主题下白底与页面底接近，靠细边分块），与助手正文同列；时间与「分支」淡显于块下方 |
| 工具调用 | 细边框命令块表：静态状态点 · 工具名 · 目标 · 右侧耗时或 `+n −m`；`bash` 目标前加强调色 `$`。连续步骤在同一表中，七步及以上折叠较早步骤，保留最近四步 |
| 写入 / 编辑 | 命令块内联 diff 预览，行号 + `+` 标记，新增行 `--ok-soft` 底 |
| 输入区 | 左侧 `›` 提示符（`!` 开头的直执行命令是 `$`）；顶边为运行条（方点阵 · 阶段文字 · 计时），只在运行时长出来（压缩上下文也算运行，写「压缩中 · 原因」，不被「仍在运行」顶掉）；中止在右下角的发送键上，不在运行条里重复。压缩收尾给一条通知（完成 / 失败原因）。用户消息里 pi 展开的 `/skill:名字` 技能全文只展示为用户敲的那一行，模型仍收到全文；pi 终端内置命令在桌面端有对应动作的直接执行（`/settings` `/thinking` `/export` `/copy` `/name` `/session` `/clone`），其余登记为兼容项并说明桌面端入口，不会当消息发给模型 |
| 命令菜单 | 见 3.6 |

提示符 `›` 用 `--accent`、等宽字体；正文仍用 `--font-body`。

Codemode 等组合工具的子调用**嵌套在父调用之内**，读起来是同一步：父行之下是一段缩进的子调用区，左侧一条 `--border-soft` 细引导线对准父行状态点，子行之间不画横向分隔线、行高 26px；更深一级在子调用区里再嵌一段（最多四级，更深的平铺在第四级）。父行目标在有子调用时写「工具名 ×次数」（如 `read ×6`），还没有子调用时写脚本首行；点开父行看脚本原文与输出。折叠较早步骤时父调用连同子调用算一步；子调用区超过六条时只留最近四条已完成的，较早的收在区内「前面 N 个调用」。运行中或失败的子调用始终可见，连同父调用一起保留。历史只能恢复 pi 保存的调用摘要，成功子调用没有完整输出时不补造内容；保留现有键盘展开与窄屏布局。

### 3.6 命令菜单

不新增 `Ctrl K` 命令面板。输入框里现有的 `/` 命令菜单（以及 `@` 文件菜单）是唯一的命令入口，外观改为：

- 顶部 `›` 输入行回显当前查询；结果按类别分组，组标题用分区标题样式；
- 选中行 `--bg-3` 底 + 行首强调色 `›`；右侧淡显快捷键或参数提示；
- 底部一行键位提示（`↑↓` 选择 · `Enter` 执行 · `Esc` 关闭）；
- 入场 `--mo-slow`、退场 `--mo-fast`；方向键、Enter、Esc 与 Tab 行为保持现状。

## 4. 版面与信息层级

本轮交互收敛：能力列表只显示短说明，全文按需查看；工具区常显执行中与失败项，成功历史默认折叠。普通提问嵌入输入框上方的扩展区，沿用同一边框与宽度；运行中发送普通消息默认排队，问题回答直接交给对应请求。状态栏点击展开详情。检查器名称统一，栏宽允许按窗口空间自由调整并保存；排序与浮出控件必须定位在所属分区内。设备连接首屏优先呈现开关、状态和配对，网络参数与帮助折叠。语音首屏呈现就绪状态、模型和识别语言，硬件与路径收进高级项；优先使用实际可用的 GPU 后端，程序与模型都经过运行确认才显示可用。

会话地图围绕当前会话及其分支，以问答轮次为节点，提供追问、分叉、子树折叠和完整内容；会话日志与真实分叉记录为事实来源，布局偏好不替代会话状态。模型身份为 Inkstone（砚）内的助手，pi 仅为执行内核；内置能力说明只声明实际可调用的入口。界面淡化 pi：日常界面称「Agent 内核」或只写状态，pi 这个名字只出现在设置的诊断信息、插件与原生功能说明，以及 Agent 协作里区分 Agent 来源的地方。切换项目或会话时内核换进程属于正常过程，不打断界面：连接条在启动超过 1.5 秒后才出现，写「正在准备会话…」；失败时写「Agent 内核未连接」，详情里保留原始诊断输出。

```
│ 新对话 + 搜索 │ 对话流（内容列上限 --w-stream）                  │ 任务          │
│ 置顶 / 最近    │                                                    │ 上下文 · 额度 │
│ 项目 → 会话    │ 输入区（运行状态嵌在顶边）                          │ 文件 · 队列   │
├ 待我处理 · 用户 ┴────────────────────────────────────────────────┴──────────────┤

```

- **品牌只出现一次**（标题栏）。左栏顶部是「新对话 + 搜索」。
- **分屏**（参考 Claude Code 的多会话布局，最多 5 块）：在左栏按住 Ctrl 点击会话，或会话菜单「在旁边分屏打开」，新会话作为一列追加到最右。每一列是一条会话自己的工作区：会话加它旁边的工具（终端、文件预览、子代理等），排布按这条会话保存，与单会话时看到的同一份；工具只能在自己那一列里挪动，不能拖到别的会话。各列等宽，每列至少是自己的会话加工具所需的宽度（会话至少 340px），放不下时整排横向滚动，不压扁。已满 5 块时再打开会挤掉离落点最近、没有焦点的一块。磁贴按从左到右的顺序各绑一条会话，位置固定、不随焦点交换。分屏时会话头从窗口标题栏移到各自磁贴上方：焦点一块是完整会话头（标题、视图切换、项目胶囊），其余是同位置的标题（`--fg-dim`、medium）加项目标签，每块右端都有关闭这一块；标题栏只留品牌与窗口控件。每一块都是完整的会话外观：正文加同样高度的输入框，焦点切换时版面不跳。焦点那一块是活动会话，输入框可用；其余各块的输入框显示这条会话的草稿或占位文字（运行中 / 等你回答写在底栏），外观与真输入框同尺寸。非焦点的块盖一层淡遮罩（`--split-dim`，深浅各一值，会话头不盖），悬停时变浅；遮罩不拦指针，照样能滚动、拖选文字。在非焦点块上单击（没有拖出选区）切焦点并把光标放进输入框，这一下不交给里面的按钮；焦点换块时遮罩立即换位、不做淡入淡出（两块一淡一显叠在一起像闪烁），只有悬停变浅有过渡。焦点切换时，失焦的那块继续显示它刚才的内容与滚动位置，新焦点那块先用已显示的内容铺上，不出现空白或旧会话内容。非焦点那块与焦点时版面一致：同样有导航轨（正文让位量相同，不横移），内容取它在焦点时屏幕上的那份（含只推给活动会话的成果卡片），失焦后又跑过才改用运行缓存。从左栏单击会话（单会话或分屏）后同样把光标放进输入框。从左栏点别的会话替换焦点那一块。关掉焦点那一块时焦点先去右邻（没有就左邻）；关到只剩一块回到单会话。终端与文件预览属于开出它的那条会话（`state/resource-owners.ts`，没登记过的归给当时正在看的会话），只显示在它那一列；单会话时切到别的会话也不跟过去。读当前会话的工具（任务、日志、账号额度、文件树）和唯一的内置浏览器只在焦点那一列显示；非焦点列的工具同样盖淡遮罩，点它先切焦点，这一下照常交给工具（光标留在工具里）。打开工具、整理排布的请求只由焦点那一列响应。每两列之间是一道 2px 的分隔条（`--border-str`，`.ui-splitter`，两侧各外扩 4px 好抓）：拖它只在相邻两列之间分宽度（每列不窄于 340px），左右方向键每次 24px，双击回到等宽；宽度按份额记，窗口变化时各列按比例跟着变。列与窗口右缘只留 2px，列与列之间两侧各 4px。左栏里分屏打开着的会话行铺 `--bg-2` 底色，焦点那条照常是选中行（`--bg-3`）。**从左栏拖会话**进工作区时，每块磁贴盖上左、右两个落点，指针所在的那一个高亮，松手插到那里：落在第 i 块的左半 = 插到它前面，右半 = 插到它后面；没分屏时主会话的左、右半就是最左、最右；拖的会话已在分屏里则挪到落点而不是重复开，焦点跟着会话走。长会话（虚拟列表）搬到新磁贴时，原来停在底部的仍停在底部，列表若挂载后一格都没画出来会自动重挂一次。状态在 `state/split-view.ts`（`tiles` + `live`，纯函数 `placeInSplit` / `removeSplitTile`），每列是一个 `Workspace`（`fit`），会话窗格 id 都是 `chat`，列上标 `data-split-column`（从 0 起，左起）；各列刚显示的内容与滚动位置在 `state/split-snapshots.ts`。
- **左栏首次打开默认收起**，由标题栏开关显式展开。展开、收起时立即保存选择，下次启动恢复退出时的状态；已有保存状态优先于默认值。
- **左栏视图**（参考 Claude Code 的侧栏筛选菜单）：搜索框右侧一个「视图」按钮，菜单分两组单选——分组方式（按项目 / 按状态 / 按日期 / 不分组）与排序（最近活动 / 名称 / 创建时间）。默认「按项目 · 最近活动」即原有的项目树；偏离默认时按钮点亮。「按状态」依次分为等你回答、出错、运行中、其余，空分区不显示；「按日期」分今天、昨天、本周、更早（按本地零点算）。非项目视图下会话平铺、不缩进，仍保留置顶区，隐藏「最近」区与已归档项目入口；分叉会话在平铺视图里是普通行（带分支编号）。排序同时作用于项目内的会话顺序，项目本身的顺序仍由拖拽或活动时间决定。视图菜单还有第三组「显示」：进行中的会话 / 已归档的会话，默认前者。**归档**是会话菜单里的一个动作（可取消），只在会话索引里记一个时间，不动对话文件、不停运行实例；归档后会话离开默认列表、置顶区和「最近」，在「已归档」视图里原样列出并能取消归档。置顶同样存在会话索引里（手机端与多窗口共用），旧版本存在本机的置顶在第一次启动时一次性搬过去。设置·工作区里有「自动归档闲置会话」（从不 / 7 / 14 / 30 天）：超过天数没有动静、没置顶、没有运行实例的会话在列会话时被打上归档标记，随时可在「已归档」里找回。视图选择是本机偏好，存在 `yan.sidebar.view`；分区与排序的计算在 `src/shared/rail-view.ts`，自动归档的选择规则在 `src/shared/session-archive.ts`，渲染只画结果。左栏的拖拽在 `rail/useRailDrag.ts`，按项目视图的数据整理在 `rail/useRailProjects.ts`。
- **右栏是检查器，不是仪表盘。** 分区之间只有一条细分隔线，标题 12px 半粗，右侧可放摘要：主值用前景色、次值用 `--fg-mute`，后跟 56px 迷你用量条（`<MiniMeter>`，正常档强调色、黄 / 红档随压力变色，不在条里写字）。上下文展开体按工作集画进度条，清理 / 折叠 / 压缩刻度名收在刻度左下，放不下时退成右对齐一排；额度每个窗口两行（标签 · 条 · 百分比；已用 / 总额 · 重置），正常档不用绿色。分区可拖动排序、折叠或浮出为磁贴。
- **运行状态的主位置是输入区顶边**（唯一方点阵 + 一句状态文字 + 计时；中止在发送键上）。思考档位色只留在边线和方点阵上，文字用 `--fg-dim`。工具行和任务列表用静态 RunDot 标自己的状态，不重复播报整体进度。
- **状态栏**（`shell/StatusBar.tsx`）：窗口底部 24px 横贯全宽，`--bg-1` 底，顶部一条 `--border-soft`，11px 等宽、`--fg-mute`、表格数字。
  - 左段是**全局状态**：模式色块 `RUN / IDLE / WAIT`（宽度固定，颜色 240ms 过渡、文字交叉淡变；RUN 为强调色实底，WAIT 为警告色浅底，IDLE 为 `--bg-3`）· 分支与改动数 · 内核连接（状态点 + 状态词，不写 pi；点开的详情里才说明内核是 pi）· 手机配对。
  - 右段是**本轮用量**：常驻速度 · 缓存命中率 · 本会话花费，输入与输出在悬停或聚焦用量段时展开，点开详情始终可见全部（宿主只有会话级统计，没有跨会话的当日汇总，不编造「今日」）。规则沿用原用量条：流式期间不编造速度，显示「生成中」；有请求没报用量时值前标 `≥`；悬停显示缓存读写明细。
  - 输入区下方的用量条随之移除，状态栏是用量的唯一常驻位置。
  - 不重复别处已有的信息：模型与思考档位留在输入框内，上下文占用是输入框右下模型左侧的小圆环，额度在底部状态栏。
  - 用量只显示数值，不写 `tok` 单位；缓存只显示命中率。没有用量时隐藏该段，不铺一排占位符。窄窗时从右往左按优先级隐藏（容器查询）：先花费（≤1100px），再手机与内核连接（≤980px）；用量段可从右端截断，不压到左段。每一段可聚焦，可点击的段是 `role="button"` 并带 `aria-expanded`，悬停或聚焦给出完整说明。
- **诊断信息常驻但退后**：状态栏整体用 `--fg-mute`；需要细节时展开或悬停。
- **消息元数据按需出现**：时间与「分支」合并在用户消息块下方一行，平时用 `--fg-mute` 退后（不叠透明度），悬停与聚焦不改变它。回合页脚（步数、用时、时间）只在回合末出现一次。
- **编码与日常共用同一骨架**：差异体现在默认展示的内容（编码突出改动、终端、文件；日常突出资料、成果、学习），不是另一套界面。
- 空入口不渲染：没有归档项目时不显示「已归档项目 · 0」；计数为 0 的筛选档不画。
- 窄窗口（900×520、940×620）下所有标题、按钮和筛选不能换成竖排或溢出；grid 弹性列一律 `minmax(0, 1fr)`（`npm run lint:css` 检查）。输入区工具条不换行，发送规则提示先省略；长文模式的输入框高度不超过窗口高度的 35%，不把工具条和状态栏挤出窗口。

## 5. 弹出层：设置、对话框、引导

- 遮罩：深色 `rgba(0,0,0,.5)`、浅色 `rgba(20,20,18,.28)`，2px 模糊。
- 面板：`--r-xl`，`--border` 描边，`--shadow-pop`。
- **设置**：左导航 `--bg-1`，内容区 `--bg-0`（深浅主题层级方向一致）。六页依次为模型、外观与输入（含提醒）、工作区与上下文（含项目知识）、能力与插件、语音与设备（含手机、其他电脑）、关于；旧入口映射到对应合并页。导航项 32px 高，选中为 `--bg-3` 底 + 强调色图标，不画框。内容区顶部有 18px 页标题；用 `<SettingGroup>` 组织同类设置，以 `<Disclosure>` 收纳低频与诊断项。布尔项用 `<Switch>`，说明压到一句。语音与设备页的配对二维码与可复制链接指向同一临时地址和配对码。打开时焦点落在当前页的导航项上。
- **首次引导**：清单而不是向导。每项是「状态标记（完成为绿色浅底圆 + 对勾；待办为警告色空心环）· 标题 + 说明 · 操作」，操作按钮并排、可换行，主操作只有一个。
- Esc 只关闭最上层；焦点圈定只在最上层生效；关闭后焦点回到打开它的元素。

## 6. 动效

关键帧只在 `styles/motion.css` 定义（`npm run check:motion` 拦截模块里的 `@keyframes`、裸时长和裸曲线）。v0.5 收敛为「一条曲线、三档时长、一个节拍」：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--mo-fast` | 110ms | 退场、按压、悬停、菜单 |
| `--mo-base` | 170ms | 淡入、浮层入场、图标切换、tab 内容淡入 |
| `--mo-slow` | 240ms | 展开、滑块、色阶变化、对话框与设置入场 |
| `--mo-ease` | `cubic-bezier(.22,1,.36,1)` | 所有入场与位移：快进慢停 |
| `--mo-ease-out` | `cubic-bezier(.4,0,1,1)` | 退场：干脆 |
| `--mo-loop` | `cubic-bezier(.45,0,.55,1)` | 只给运行中的循环（呼吸、脉冲） |
| `--dur` / `--ease` | 120ms / 标准曲线 | 悬停、颜色、边框过渡 |
| 错峰 | 60–70ms | 列表、diff 行 |
| 字符节奏 | 输入 30ms/字 · 流式正文 20ms/字 | 只用于演示与引导，不人为拖慢真实输出 |

规则：

- 入场与退场成对（`usePresence` 延迟卸载），退场更快、位移更小。
- 位移不超过 4px（`--mo-shift`，v0.4 为 6px），缩放不小于 0.965；不做弹跳或弹性动画。
- 按钮、分段、图标按钮按下时有 `mo-press` 反馈。
- 状态循环动画只挂在**真实运行**上（方点阵、运行条、运行中的工具行、环绕流光），结束立即停止，且不能是唯一的状态信息。思考滑块在菜单打开时的脉冲与块光标闪烁是强度预览例外，与运行状态动画分开。
- 整屏动效只有两处：主题切换（View Transition，圆心为触发按钮）与启动画面（§3.4.1）。
- `prefers-reduced-motion: reduce` 下时长压到 1ms、只播一次（保留终态，不删除动画，以免延迟卸载出现空窗）；全局规则在 `tokens.css`。

基础件，关键帧与类在 `motion.css`（`.ui-grow` / `.ui-spin` / `.ui-caret` / `.ui-orbit` / `.seg.sliding`），组件在 `components/ui`（`Grow` / `Spinner` / `Caret` / `Segmented`）：

- **展开** `grow`：新块 `grid-template-rows: 0fr → 1fr` 同步透明度，旧内容被连续推开，不跳。
- **方点阵** `spin`：10×10px、3×3 方点，亮点沿外圈转、带一格尾迹，0.8s 一圈；同屏只保留一个。其余运行项用静态 RunDot。
- **光标** `caret`：2px 宽、1.2em 高；输入时常亮，停下后 1.06s `step-end` 闪烁。
- **环绕流光** `orbit`：`@property --ang` + `conic-gradient` 边框，经 mask 只露 1px 边，2.4s 一圈。**只在一次运行持续超过 3 秒后**随 240ms 淡入，运行结束淡出；短回合不出现，避免频繁闪动。
- **分段滑块**：选中底块 `translateX` 滑动。
- **状态交叉淡变**：状态栏模式色块颜色 240ms 过渡，文字叠放交叉淡变，宽度固定（随状态栏在 P5 落地）。

**同一时钟原则**：运行中的各面板（输入区运行条、工具行、任务、上下文、改动、终端、状态栏）都从同一条运行事件流推导状态，不各自计时，因此动效始终同拍。

## 7. 手机端（Android）

手机端（`mobile/`，React Native）是同一产品的另一个入口，不是另一套设计。它与桌面共享语义、配色和图标，差异只在触控尺寸、字号和导航方式。

- **令牌同源**：`mobile/src/theme.ts` 的色值与 `tokens.css` 同名同值（`bg0` ↔ `--bg-0` 等）。修改颜色时两边一起改；P1 起由检查脚本比对，不一致即失败。
- **尺寸**：触控目标不小于 44dp；按钮 44dp、紧凑按钮 36dp；字号 12 / 13 / 15 / 16 / 18 / 22；间距与圆角沿用桌面刻度。
- **字体**：界面汉字与正文使用系统无衬线；Android 上不强制嵌入微软雅黑。地址、配对码、代码和纯命令用系统 `monospace`，不在 APK 内嵌 Maple Mono CN。字重只用 400 / 500 / 600（`weight`）。
- **图标**：使用同一份 `catalog.json` 生成物与语义名；尺寸只用 `icon.sm/md/lg` = 16 / 20 / 24dp（随文字 16、按钮与行首 20、页面级 24），描边 1.5dp（手机像素密度高、户外阅读，取较粗一档）。系统通知的小图标是砚标志的单色简化字形（`ic_stat_inkstone`，为 24dp 重画），标题着浅色强调色。
- **应用图标**：与桌面同一块砖形图标（§3.4.1）——启动器普通、圆形与自适应图标，以及首页品牌角标，都是 `#151515` 底 + 浅色开口石框 + 强调色 `>_`，不另加竖笔或其它装饰。`mobile` 下 `npm run icons:launcher` 生成密度位图，APK 构建时同步生成。
- **状态表达**：没有底部状态栏；运行、待回答、断线在会话页输入区上方的运行条（`RunBar`）与首页列表的状态点表达，用词与桌面状态栏一致（运行中 / 等你回答 / 已连接 / 重新连接中，`STATUS_TEXT`），系统通知同样用这组词。同屏只有主运行位置用方点阵，其他运行项用静态 RunDot。
- **动效**：沿用 `--mo-fast/base/slow` 与 `--mo-ease` 的数值，位移不超过 4dp；遵循系统「减少动画」。`Spinner` 是桌面方点阵的同一个节拍（3×3 方点、0.8s 一圈），减少动画时停在第一帧。
- **控件**：`mobile/src/ui.tsx` 的 `Button`（含 36dp 紧凑档）/ `IconButton` / `Badge` / `EmptyState` / `Header`（标题 + 等宽副标题）/ `SectionTitle` / `Meta` / `Input` / `RunBar` / `StatusDot` 与桌面同名同义，`Spinner` 在 `motion.tsx`；页面不自建按钮、输入框、徽标或状态行外观。
- **提示符语言**：会话里的用户消息与桌面一致，是 `›` 提示符 + 正文的块（`bg2` 底 + `borderSoft` 细边），与助手正文同列靠左；工具步骤用同一细边框命令块表显示，较早步骤按桌面阈值折叠。
- 深浅主题跟随系统；宽屏与折叠屏双栏时，列表与详情的层级与桌面左栏 / 中栏一致。

## 9. 可访问性与键盘

- 所有控件可 Tab 到达；全局 `:focus-visible` 为 1px 强调色环，小目标用 2px（`--focus-ring-w-strong`）。
- 禁用统一 `--ctl-disabled-opacity`（0.5）；更低的透明度只表示「过期 / 半失效」。例外：发送键的禁用态用中性底（`--bg-3` + `--fg-mute`），不用透明度，免得浅色主题里与可发送态难分。
- 图标按钮必须有无障碍名称；分段项用 `aria-pressed`，tab 用 `role="tab"` + `aria-selected`。
- 元数据淡显不能让信息只在悬停时可得：聚焦同样让它完全显现。状态栏各段同理。
- 手机端控件提供 `accessibilityLabel` 与 `accessibilityRole`，不只靠颜色或图标传达状态。

## 10. 升级规范的流程

1. **先改规范再改代码。** 新令牌或控件变体先在本文写清用途与边界，再改 `tokens.css` / `ui.css`（手机端同步 `theme.ts` / `ui.tsx`）。
2. **新增控件先问能否复用。** 能用 `.btn` / `.seg` / `.ui-badge` / `.ui-empty` 表达的，不新建类；需要新变体时加在 `ui.css`，并补到第 3 节。
3. **模块 CSS 只管版面。** 发现模块里重写控件外观时，改成 `className="btn …"` 或组件，再删掉旧规则。
   新样式文件在 `styles/index.css` 登记并放进所属的层：后面的层整体压过前面的层，与特异性无关；`!important` 反过来，前层优先。间距、圆角、字号、字重有同值令牌时写令牌，不写裸值（`npm run check:css-budget` 只许散落值下降）。
4. **检查。** `npm run typecheck`（含 CSS 布局检查）→ `npm run check:motion` → `npm run check:icons` → `npm run check:css-budget` → `npm run check:mobile-tokens` → `npm run measure:css` 更新 CSS 清单 → 结构性改动再用 `YAN_STYLE_DUMP=1` 跑视觉矩阵，`node scripts/css-computed-diff.mjs` 比较前后逐元素计算样式 → 视觉矩阵截图（深浅主题 × 1440×900 / 940×620 / 900×520）核对；手机端 `mobile/` 下 `npm run typecheck` 与实机截图。视觉结论以截图为准。
5. **记录取舍。** 推翻本文某条规则时，在对应章节写明新规则与理由；不保留两套并行的说法。
