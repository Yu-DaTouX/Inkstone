# Inkstone 设计规范 v0.5

[文档索引](README.md) · [品牌规范](BRAND.md) · [代码地图](CODE_MAP.md)

本文是砚（Inkstone）界面的**唯一公开设计规范**：设计意图、令牌、控件、版面、信息层级、动效、手机端、安装与引导界面，以及以后升级规范的流程。实现以源码为准，本文说明「为什么这样、以后怎么改」。

v0.5（终端风格、底部状态栏、动效体系与「砚线」图标）已于 2026-09-28 定案，按[界面重构计划](UI_REDESIGN.md)分阶段落地。标注 **〔v0.5 · Pn〕** 的条目是已定案的目标，在对应阶段完成前源码仍保持 v0.4 行为；阶段完成后删去标注。

## 1. 设计意图

砚是**墨色工作空间**：安静、清楚、克制。对话与成果是主角，输入区是下一步操作的锚点，执行过程、用量和诊断从摘要到详情分层展开。

v0.5 在此之上加入现代终端的气质：等宽骨架、提示符语言、命令块、状态栏、方点阵与块光标。终端气质服务于「看清发生了什么」，不做仿古绿屏、扫描线或发光。

四条原则：

1. **内容优先。** 正文、产出和输入高于工具元数据；元数据默认淡显，悬停、聚焦或展开时才完整出现。
2. **一种意图一种长相。** 同一个意图（主要操作、次要操作、互斥选项、状态标签）在所有页面只有一种外观，由 `ui.css` 统一提供；手机端用同样的语义与配色，尺寸按触控放大。
3. **克制层级。** 用背景色阶、留白和细分隔线表达层级；不用重复徽章、装饰渐变或持续发光争夺注意力。
4. **单一强调。** 靛蓝只表达选中、主要操作、链接和键盘焦点；成功、警告、错误保留独立语义色，品牌色不承担状态。

## 2. 令牌

### 2.1 颜色

深浅两套主题定义同名令牌（`html[data-theme]`），组件只引用令牌，不写色值。

| 令牌 | 用途 |
| --- | --- |
| `--bg-0` | 窗口底、中栏、分段容器底、设置内容区 |
| `--bg-1` | 左栏、右栏、会话头、状态栏、卡片、弹层 |
| `--bg-2` | 次要按钮、输入框、用户消息块 |
| `--bg-3` | 悬停、分段选中项、导航与列表选中项 |
| `--bg-4` | 按下、滚动条 |
| `--border-soft` / `--border` / `--border-str` | 分隔线 / 控件描边 / 悬停描边（半透明，适配任何底色） |
| `--fg` / `--fg-dim` / `--fg-mute` | 正文 / 次要（分区标题、说明） / 三级（元数据、诊断） |
| `--accent` · `--accent-soft` · `--accent-line` | 强调实色 / 浅底 / 描边 |
| `--on-accent` | 强调实底上的文字 |
| `--ok` `--warn` `--err`（各带 `-soft`） | 成功与新增 / 警告与待确认 / 失败与删除 |

规则：

- 强调色保持靛蓝（深色 `#93a4f4`、浅色 `#5264c8`）。原型里比较过的青绿、紫两档不采用：青绿与 `--ok` 太近，紫与思考档位色冲突。
- 绿色只表达成功或新增，不用来装饰「好的数字」；用量、缓存率等诊断值用 `--fg-mute` / `--fg-dim`。
- 新增颜色前先确认文本对比度 ≥ 4.5:1，并同时给出深浅两套值。
- 已删除的旧名（`--fg-0…4`、`--line`、`--line-1`、`--border-strong`）不再使用；`npm run check:motion` 会报告未定义的令牌引用。

### 2.2 字体与字号

v0.5 按「骨架等宽、正文无衬线」分工〔v0.5 · P5〕：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--font-mono` | Maple Mono CN（随包内嵌，拉丁 : 汉字 = 1 : 2） | 字体真源 |
| `--font-ui` | `var(--font-mono)` | 界面骨架：导航、列表行、元数据、路径、工具行、按钮、分段、状态栏、快捷键 |
| `--font-code` | `var(--font-mono)` | 代码、diff、终端 |
| `--font-sans` | Segoe UI + 微软雅黑 UI | 字体真源 |
| `--font-body` | `var(--font-sans)` | 对话正文（用户与助手）、页标题、设置说明等两行以上的中文段落 |
| `--fs-xs` 11 · `--fs-sm` 12 · `--fs-code` 12.5 · `--fs-base` 13 · `--fs-body` 14 · `--fs-lg` 15 | | |
| 页标题 | 18px / `--fw-strong` / `--font-body` | 设置页标题、引导标题 |

- 判断依据是**阅读方式**：逐项扫读的骨架用等宽，连续阅读的段落用无衬线。长段中文用等宽会显著变慢，所以正文不用等宽。
- 数字列（用量、计时、行号、计数）一律 `font-variant-numeric: tabular-nums`。
- 字重只用三档：`--fw-regular` 400、`--fw-medium` 500（按钮、行标题、选中项）、`--fw-strong` 600（分区标题、页标题）。不写裸数字字重。

v0.4 的 `--font-ui` 指向 Segoe UI；P5 改指向等宽之前，界面仍以无衬线呈现。

### 2.3 间距、圆角、尺寸

- 间距 4 的倍数：`--sp-1…6` = 4 / 8 / 12 / 16 / 24 / 32。
- 圆角：`--r-xs` 4（分段内的项、行内代码、徽标） · `--r-sm` 6（按钮、输入框、分段容器、导航项） · `--r-md` 8（菜单、消息块） · `--r-lg`/`--r-xl` 12（卡片、对话框、输入区容器）。
- 全圆角（`--r-full`）只给滚动条、进度条、开关、头像、计数点和悬浮圆按钮；按钮与分段不用胶囊形。
- 控件高度三档：`--ctl-h-sm` 24 · `--ctl-h` 28（默认） · `--ctl-h-lg` 32。按钮、分段、输入框只用这三档。
- 状态栏高 24px（`--statusbar-h`）〔v0.5 · P5〕。

### 2.4 投影

界面内部的层级靠色阶，不靠投影。唯一的投影是弹出层（对话框、设置、引导、菜单、命令菜单）的 `--shadow-pop`，它表达「浮在内容之上」。

## 3. 控件

外观全部来自 `styles/ui.css`。模块 CSS 只写控件在自己版面里的**位置**（`margin`、`flex`、`align-self`、宽度），不重写底色、描边、字号、高度或悬停色。

### 3.1 按钮

| 写法 | 组件 | 用途 |
| --- | --- | --- |
| `.btn` | `<Button>` | 次要操作（默认）：对话框的取消、卡片操作、设置行操作 |
| `.btn.primary` | `variant="primary"` | 一个区域里唯一的主要操作（开始使用、提交、打开） |
| `.btn.ghost` | `variant="ghost"` | 行内低频操作、取消暂存、「不管了」 |
| `.btn.danger` | `variant="danger"` | 删除、移除、覆盖 |
| `.btn.icon` | `<IconButton label=…>` | 只有图标的按钮；必须给 `label`（用作 title 与无障碍名称） |
| `.btn.sm` / `.btn.lg` | `size` | 24 / 32px；默认 28px |
| `.btn.on` / `aria-pressed="true"` | `active` | 切换按钮的「已开启」 |

一个区域最多一个主要按钮。按钮文字写动作（「打开」「提交」），不写「确定」。图标在文字前；导航去别处的按钮可在文字后放 `chevron-right`。

### 3.2 分段控件

`.seg` > `.seg-btn`（`.sel` 或 `aria-pressed`），组件 `<Segmented>`。二到五个互斥选项：主题、语言、视图切换、筛选、档位。选中项用 `--bg-3` 底 + 正文色 + 中等字重，图标变强调色；**不用强调色实底**。`.seg.sm` 用于面板内部与筛选。选中底块切换时沿横向滑动到新位置，不跳变〔v0.5 · P3〕。

同一外观的变体：会话头视图切换（`.shead-view`）、右栏队列模式（`.rp-switch`）、模型菜单档位条（`.mt-stops`）。新增互斥选项时直接用 `.seg`，不再新建变体。

### 3.3 其他

- **开关** `.switch-pill`（带 `.on`）：布尔设置；开启为强调色实底。
- **徽标** `.ui-badge`（`accent` / `ok` / `warn` / `err`）：状态标签与计数。浅底 + 同色描边 + 同色文字，不用实底。
- **空状态** `.ui-empty` / `<EmptyState>`：一句事实 + 可选的下一步操作。不画插图，不写「暂无数据」式空话；「没有改动」与「不在 Git 仓库里」这类不同事实用不同文案。
- **分区标题** `.ui-section-title` / `<SectionTitle>`：12px / 600 / `--fg-dim`，图标 `--fg-mute`。
- **键位** `.ui-kbd`：只给真正接了快捷键的动作画键位。
- **选中项**（列表、导航、菜单）：`--bg-3` 底；菜单与命令菜单的选中行首加强调色 `›`，左栏会话行用状态圆点。**不用 inset 边线**：圆角会把它弯成一道蓝弧〔v0.5 · P5〕。
- **进行中**：方点阵（`.spin`，见第 6 节），不用 `loader-circle` 图标或盲文字符〔v0.5 · P3〕。

### 3.4 图标「砚线」

图标语义写在 `scripts/design/icons/catalog.json`，一个图标只承担一个语义；桌面与手机共用同一份生成物。图标是自绘的「砚线」，母题是品牌标志「提示砚」：开口石框 + 方头斜接的 `>_`。几何真源 `scripts/design/icons/inkline.json`，与编目一一对应。

几何规则：

1. **16 网格，12 活动区**，四周留 2px，对齐 12 / 14 / 16 三档尺寸。
2. **描边恒定 1.25px**（`vector-effect: non-scaling-stroke`），三档尺寸一样粗；手机端 1.5dp（见第 7 节）。
3. **方头 · 斜接**：`stroke-linecap: square; stroke-linejoin: miter`，统一直角。
4. **开口角**：文件、目录、终端、外链等容器类图标右上角留缺口。
5. **直线与整圆为主**：0° / 45° / 90°，不画插画式隐喻。
6. **进行中不用图标**：用方点阵；状态点、勾选框由 CSS 绘制。

可读性规则（描边取 1.25px 而不取 1.5px 的原因：1.5px 在 12px 下会把推子、清单这类多笔画图标糊成一块；1px 配 `--fg-mute` 在浅色主题下发虚）：

- **笔画间距**：平行笔画之间的净空在 16 网格中不少于 2 个单位（12px 下 1.5px）。达不到的图标在 12px 使用简化几何，或该位置改用 14px。
- **颜色**：单独出现的图标（图标按钮、无文字的状态标记）至少用 `--fg-dim`；`--fg-mute` 只给紧挨文字、只作辅助的图标。
- **可辨认**：同一区域并列的图标轮廓必须能区分（例如文件与复制、目录与项目），靠外形而不是细节区分。
- **验收**：新增或修改几何时，截取深浅主题 × Windows 100% / 125% / 150% 缩放下 12px 与 14px 的对照图。

尺寸只用 12 / 14 / 16（手机 16 / 20 / 24dp）。界面里不用 `✓ ○ ◐ ✕` 这类文字符号当图标。改图标：改编目与 `inkline.json` → `npm run icons` → `npm run check:icons`。

语义调整：`sparkles` → 星号 `*`；`agent` → `>>`；`settings` → 两道推子（三道在 12px 下会糊，按笔画间距规则简化）；`alert-circle` / `check-circle` → 方框内 `!` / 勾；`terminal` 即标志图形。`running`、`activity` 仍有几何，但进行中的状态改用方点阵（§6），这两个语义只留给静态计数。

### 3.5 提示符语言〔v0.5 · P5〕

| 位置 | 形式 |
| --- | --- |
| 用户消息 | 左侧 `›` 提示符 + 正文的块，`--bg-2` 底，与助手正文同列；时间与「分支」淡显于块下方 |
| 工具调用 | 命令块：状态（方点阵 / 成功点 / 失败点）· 工具名 · 目标 · 右侧耗时或 `+n −m`；`bash` 目标前加强调色 `$` |
| 写入 / 编辑 | 命令块内联 diff 预览，行号 + `+` 标记，新增行 `--ok-soft` 底 |
| 输入区 | `›` + 2px 块光标；顶边为运行条（方点阵 · 阶段文字 · 计时 · 中止） |
| 命令菜单 | 见 3.6 |

提示符 `›` 用 `--accent`、等宽字体；正文仍用 `--font-body`。

### 3.6 命令菜单〔v0.5 · P5〕

不新增 `Ctrl K` 命令面板。输入框里现有的 `/` 命令菜单（以及 `@` 文件菜单）是唯一的命令入口，外观改为：

- 顶部 `›` 输入行回显当前查询；结果按类别分组，组标题用分区标题样式；
- 选中行 `--bg-3` 底 + 行首强调色 `›`；右侧淡显快捷键或参数提示；
- 底部一行键位提示（`↑↓` 选择 · `Enter` 执行 · `Esc` 关闭）；
- 入场 `--mo-slow`、退场 `--mo-fast`；方向键、Enter、Esc 与 Tab 行为保持现状。

## 4. 版面与信息层级

```
┌ 标题栏：左栏开关 · 品牌（只此一处） ······ 固定 · 浏览器 · 右栏开关 · 窗口控制 ┐
├ 左栏 ┬ 会话头：标题 · 视图切换 · 项目胶囊 · 目标 ───────────┬ 右栏（检查器）┤
│ 新对话 + 搜索 │ 对话流（内容列上限 --w-stream）                  │ 任务          │
│ 置顶 / 最近    │                                                    │ 上下文 · 额度 │
│ 项目 → 会话    │ 输入区（运行状态嵌在顶边）                          │ 文件 · 队列   │
├ 待我处理 · 用户 ┴────────────────────────────────────────────────┴──────────────┤
└ 状态栏：RUN/IDLE · 分支与改动 · pi 连接 · 手机 ··········· 本轮用量 · 今日花费 ┘
```

- **品牌只出现一次**（标题栏）。左栏顶部是「新对话 + 搜索」。
- **右栏是检查器，不是仪表盘。** 分区之间只有一条细分隔线，标题 12px 半粗，右侧可放摘要（环形 + 数字）。分区可拖动排序、折叠或浮出为磁贴。
- **运行状态的主位置是输入区顶边**（方点阵 + 一句状态文字 + 计时 + 中止）。思考档位色只留在边线和方点阵上，文字用 `--fg-dim`。工具行和任务列表只标自己的状态，不重复播报整体进度。
- **状态栏**〔v0.5 · P5〕：窗口底部 24px 横贯全宽，`--bg-1` 底，顶部一条 `--border-soft`，11px 等宽、`--fg-mute`、表格数字。
  - 左段是**全局状态**：模式色块 `RUN / IDLE / WAIT`（宽度固定，颜色 240ms 过渡、文字交叉淡变；RUN 为强调色实底，WAIT 为警告色浅底，IDLE 为 `--bg-3`）· 分支与改动数 · pi 连接 · 手机配对。
  - 右段是**本轮用量**：速度 · 输入 · 输出 · 缓存命中率 · 今日花费。规则沿用原用量条：流式期间不编造速度，显示「生成中」；有请求没报用量时值前标 `≥`；悬停显示缓存读写明细。
  - 输入区下方的用量条随之移除，状态栏是用量的唯一常驻位置。
  - 不重复别处已有的信息：模型与思考档位留在输入框内，上下文占用留在右栏检查器。
  - 窄窗时从右往左按优先级隐藏：先今日花费，再手机与 pi；模式、分支与本轮用量始终保留。每一段可聚焦，悬停或聚焦给出完整说明。
- **诊断信息常驻但退后**：状态栏整体用 `--fg-mute`；需要细节时展开或悬停。
- **消息元数据按需出现**：时间与「分支」合并在用户消息块下方一行，平时 55% 不透明度，悬停或聚焦时完全显现。回合页脚（步数、用时、时间）只在回合末出现一次。
- **编码与日常共用同一骨架**：差异体现在默认展示的内容（编码突出改动、终端、文件；日常突出资料、成果、学习），不是另一套界面。
- 空入口不渲染：没有归档项目时不显示「已归档项目 · 0」；计数为 0 的筛选档不画。
- 窄窗口（900×520、940×620）下所有标题、按钮和筛选不能换成竖排或溢出；grid 弹性列一律 `minmax(0, 1fr)`（`npm run lint:css` 检查）。

## 5. 弹出层：设置、对话框、引导

- 遮罩：深色 `rgba(0,0,0,.5)`、浅色 `rgba(20,20,18,.28)`，2px 模糊。
- 面板：`--r-xl`，`--border` 描边，`--shadow-pop`。
- **设置**：左导航 `--bg-1`，内容区 `--bg-0`（深浅主题层级方向一致）。导航项 32px 高，选中为 `--bg-3` 底 + 强调色图标，不画框。内容区顶部有 18px 页标题；设置行是「标签 + 说明｜控件」两列，行之间一条细线，行本身不响应悬停（它不可点击）。打开时焦点落在当前页的导航项上。
- **首次引导**：清单而不是向导。每项是「状态标记（完成为绿色浅底圆 + 对勾；待办为警告色空心环）· 标题 + 说明 · 操作」，操作按钮并排、可换行，主操作只有一个。
- Esc 只关闭最上层；焦点圈定只在最上层生效；关闭后焦点回到打开它的元素。

## 6. 动效

关键帧只在 `styles/motion.css` 定义（`npm run check:motion` 拦截模块里的 `@keyframes`、裸时长和裸曲线）。v0.5 收敛为「一条曲线、三档时长、一个节拍」：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--mo-fast` | 110ms | 退场、按压、悬停、菜单 |
| `--mo-base` | 170ms | 淡入、浮层入场、图标切换、tab 内容淡入 |
| `--mo-slow` | 240ms | 展开、滑块、色阶变化、对话框与设置入场 |
| `--mo-ease` | `cubic-bezier(.22,1,.36,1)` | 所有入场与位移：快进慢停 |
| `--mo-ease-out` | `cubic-bezier(.4,0,1,1)` | 退场：干脆 |
| `--mo-loop` | `cubic-bezier(.45,0,.55,1)` | 只给运行中的循环〔v0.5 · P3〕 |
| `--dur` / `--ease` | 120ms / 标准曲线 | 悬停、颜色、边框过渡 |
| 错峰 | 60–70ms | 列表、diff 行 |
| 字符节奏 | 输入 30ms/字 · 流式正文 20ms/字 | 只用于演示与引导，不人为拖慢真实输出 |

规则：

- 入场与退场成对（`usePresence` 延迟卸载），退场更快、位移更小。
- 位移不超过 4px（`--mo-shift`，v0.4 为 6px〔v0.5 · P3〕），缩放不小于 0.965；不做弹跳或弹性动画。
- 按钮、分段、图标按钮按下时有 `mo-press` 反馈。
- 循环动画只挂在**真实运行**的状态上（方点阵、运行条、运行中的工具行、环绕流光），结束立即停止，且不能是唯一的状态信息。
- 主题切换是唯一的整屏动效（View Transition，圆心为触发按钮）。
- `prefers-reduced-motion: reduce` 下时长压到 1ms（保留终态，不删除动画，以免延迟卸载出现空窗）。

基础件〔v0.5 · P3〕，实现迁入 `motion.css` 与 `components/ui`：

- **展开** `grow`：新块 `grid-template-rows: 0fr → 1fr` 同步透明度，旧内容被连续推开，不跳。
- **方点阵** `spin`：10×10px、3×3 方点，亮点沿外圈转、带一格尾迹，0.8s 一圈，取代 spinner 图标与盲文字符。
- **光标** `caret`：2px 宽、1.2em 高；输入时常亮，停下后 1.06s `step-end` 闪烁。
- **环绕流光** `orbit`：`@property --ang` + `conic-gradient` 边框，经 mask 只露 1px 边，2.4s 一圈。**只在一次运行持续超过 3 秒后**随 240ms 淡入，运行结束淡出；短回合不出现，避免频繁闪动。
- **分段滑块**：选中底块 `translateX` 滑动。
- **状态交叉淡变**：状态栏模式色块颜色 240ms 过渡，文字叠放交叉淡变，宽度固定。

**同一时钟原则**：运行中的各面板（输入区运行条、工具行、任务、上下文、改动、终端、状态栏）都从同一条运行事件流推导状态，不各自计时，因此动效始终同拍。

## 7. 手机端（Android）

手机端（`mobile/`，React Native）是同一产品的另一个入口，不是另一套设计。它与桌面共享语义、配色和图标，差异只在触控尺寸、字号和导航方式。

- **令牌同源**：`mobile/src/theme.ts` 的色值与 `tokens.css` 同名同值（`bg0` ↔ `--bg-0` 等）。修改颜色时两边一起改；P1 起由检查脚本比对，不一致即失败。
- **尺寸**：触控目标不小于 44dp；按钮 44dp、紧凑按钮 36dp；字号 12 / 13 / 15 / 16 / 18 / 22；间距与圆角沿用桌面刻度。
- **字体**：骨架等宽、正文无衬线的分工与桌面一致。桌面的 Maple Mono CN 是 Web 子集包，手机端暂用系统 `monospace`；是否在 APK 内嵌子集字体见重构计划第 8 节。
- **图标**：使用同一份 `catalog.json` 生成物与语义名；尺寸 16 / 20 / 24dp，描边 1.5dp（手机像素密度高、户外阅读，取较粗一档）。
- **状态表达**：没有底部状态栏；运行、待回答、断线在会话页输入区上方的运行条与首页列表的状态点表达，用词与桌面状态栏一致（运行中 / 等你回答 / 已连接 / 重新连接中）。
- **动效**：沿用 `--mo-fast/base/slow` 与 `--mo-ease` 的数值，位移不超过 4dp；遵循系统「减少动画」。
- **控件**：`mobile/src/ui.tsx` 的 `Button` / `IconButton` / `Badge` / `EmptyState` / `Header` / `SectionTitle` 与桌面同名同义；页面不自建按钮或徽标外观。
- 深浅主题跟随系统；宽屏与折叠屏双栏时，列表与详情的层级与桌面左栏 / 中栏一致。

## 9. 可访问性与键盘

- 所有控件可 Tab 到达；全局 `:focus-visible` 为 1px 强调色环，小目标用 2px（`--focus-ring-w-strong`）。
- 禁用统一 `--ctl-disabled-opacity`（0.5）；更低的透明度只表示「过期 / 半失效」。
- 图标按钮必须有无障碍名称；分段项用 `aria-pressed`，tab 用 `role="tab"` + `aria-selected`。
- 元数据淡显不能让信息只在悬停时可得：聚焦同样让它完全显现。状态栏各段同理。
- 手机端控件提供 `accessibilityLabel` 与 `accessibilityRole`，不只靠颜色或图标传达状态。

## 10. 升级规范的流程

1. **先改规范再改代码。** 新令牌或控件变体先在本文写清用途与边界，再改 `tokens.css` / `ui.css`（手机端同步 `theme.ts` / `ui.tsx`）。
2. **新增控件先问能否复用。** 能用 `.btn` / `.seg` / `.ui-badge` / `.ui-empty` 表达的，不新建类；需要新变体时加在 `ui.css`，并补到第 3 节。
3. **模块 CSS 只管版面。** 发现模块里重写控件外观时，改成 `className="btn …"` 或组件，再删掉旧规则。
   新样式文件在 `styles/index.css` 登记并放进所属的层：后面的层整体压过前面的层，与特异性无关；`!important` 反过来，前层优先。间距、圆角、字号、字重有同值令牌时写令牌，不写裸值（`npm run check:css-budget` 只许散落值下降）。
4. **检查。** `npm run typecheck`（含 CSS 布局检查）→ `npm run check:motion` → `npm run check:icons` → `npm run check:css-budget` → `npm run check:mobile-tokens` → `npm run measure:css` 更新 CSS 清单 → 结构性改动再用 `YAN_STYLE_DUMP=1` 跑视觉矩阵，`node scripts/css-computed-diff.mjs` 比较前后逐元素计算样式 → 视觉矩阵截图（深浅主题 × 1440×900 / 940×620 / 900×520）核对；手机端 `mobile/` 下 `npm run typecheck` 与实机截图。视觉结论以截图为准。
5. **记录取舍。** 推翻本文某条规则时，在对应章节写明新规则与理由；不保留两套并行的说法。
