# Inkstone 设计规范

[文档索引](README.md) · [品牌规范](BRAND.md) · [代码地图](CODE_MAP.md)

本文是砚（Inkstone）界面的**唯一公开设计规范**：设计意图、令牌、控件、版面、信息层级、动效、手机端、安装与引导界面，以及以后升级规范的流程。实现以源码为准，本文说明「为什么这样、以后怎么改」。

现行方向是 2026-10-10 定的**方向 E**（终端风格的控制中心）。2026-10-13 起按**方向 F「双声部」**修订字体、圆角与动效（各节标注「方向 F」；与旧写法冲突时以 F 为准）：界面分人声与机声，人声用系统比例字体、机声用 Maple Mono CN，圆角放大一档，浮层从触发点长出。同日本文按章节重排：各节只写现行规则；已退出默认界面的模块（Agent Hub 工作台、文件任务页、手机生活助手、会话地图、右栏检查器）的规则移到文末[附录](#附录历史与退役界面)，只供维护旧实现时查阅。v0.5 的分阶段记录见[界面重构计划](UI_REDESIGN.md)（历史）。

## 1. 设计意图

砚是**墨色工作空间**：安静、清楚、克制。对话与成果是主角，输入区是下一步操作的锚点，执行过程、用量和诊断从摘要到详情分层展开。

方向 E 的风格：简洁、规整、专业；终端味加控制中心；元素有规律；信息默认简洁，可展开到全面。终端气质服务于「看清发生了什么」，不做仿古绿屏、扫描线或发光。

四条原则：

1. **内容优先。** 正文、产出和输入高于工具元数据；元数据默认淡显，悬停、聚焦或展开时才完整出现。
2. **一种意图一种长相。** 同一个意图（主要操作、次要操作、互斥选项、状态标签）在所有页面只有一种外观，由 `ui.css` 统一提供；手机端用同样的语义与配色，尺寸按触控放大。
3. **克制层级。** 用背景色阶、留白和细分隔线表达层级；不用重复徽章、装饰渐变或持续发光争夺注意力。
4. **单一强调。** 终端蓝只表达选中、主要操作、链接和键盘焦点；成功、警告、错误保留独立语义色，品牌色不承担状态。

## 2. 令牌

### 2.1 颜色

深浅两套主题定义同名令牌（`html[data-theme]`），组件只引用令牌，不写色值。冷中性三层背景加终端蓝强调。

| 令牌 | 用途 |
| --- | --- |
| `--bg-0` | 窗口底、正文底、分段容器底、设置内容区 |
| `--bg-1` | 左栏、状态栏、工具磁贴、弹层 |
| `--bg-2` | 抬起的输入框与卡片、次要按钮、输入控件 |
| `--bg-3` | 悬停、分段选中项、导航与列表选中项 |
| `--bg-4` | 按下、滚动条 |
| `--border-soft` / `--border` / `--border-str` | 分隔线 / 控件描边 / 悬停描边（半透明，适配任何底色） |
| `--fg` / `--fg-dim` / `--fg-mute` | 正文 / 次要（分区标题、说明） / 三级（元数据、诊断） |
| `--accent` · `--accent-soft` · `--accent-line` | 强调实色 / 浅底 / 描边 |
| `--on-accent` | 强调实底上的文字 |
| `--ok` `--warn` `--err`（各带 `-soft`） | 成功与新增 / 警告与待确认 / 失败与删除 |

规则：

- 强调色为终端蓝，深浅分别校准：深色 `#93a8ff`、浅色 `#4059ad`。青绿与 `--ok` 太近、紫与思考档位色冲突，不采用。
- `--ok` / `--warn` / `--err` 降饱和以便作文字。绿色只表达成功或新增，不用来装饰「好的数字」；用量、缓存率等诊断值用 `--fg-mute` / `--fg-dim`。
- 新增颜色前先确认文本对比度 ≥ 4.5:1，并同时给出深浅两套值。强调色、状态色与思考档位色都会作文字用，在 `--bg-1`、`--bg-2`、`--bg-3` 与各自淡底上都要达标。
- 灰度只作设计审查（样板里切换），不做用户设置。
- 已删除的旧名（`--fg-0…4`、`--line`、`--line-1`、`--border-strong`）不再使用；`npm run check:motion` 会报告未定义的令牌引用。

### 2.2 字体与字号

**方向 F「双声部」**：界面里有两种说话者，字体分工按它们划分。

- **人声**（正文、界面标签、按钮、菜单、设置说明）用系统比例字体栈（缺省）：`'Segoe UI Variable Text', 'Segoe UI', 'Microsoft YaHei UI', 'PingFang SC', 'Hiragino Sans GB', 'Noto Sans CJK SC', system-ui, sans-serif`，读写像本地应用。`--font-ui` / `--font-body` / `--font-sans` 都指向它。
- **机声**（`--font-mono` / `--font-code`，随包 **Maple Mono CN**，仅 Regular，拉丁 : 汉字 = 1 : 2）留在真正属于机器的地方：代码块与行内代码、终端、工具行里的命令 / 文件名 / 路径、活动行的状态字符与用时、状态栏数值与花费、模型菜单里的容量（1M / 256K）、`›` 提示符、快捷键提示、diff。`font-synthesis: none`，不造伪粗体。
- 正文里夹的数字与版本号**不**切等宽（混排很碎），只开 `tabular-nums`。
- 字号：元数据 11（`--fs-xs`）· 小字 12（`--fs-sm`）· 代码 12.5（`--fs-code`）· 界面 13（`--fs-base`）· 正文 15（`--fs-body`）· h3 17（`--fs-h3`）· h2 20（`--fs-h2`）· 主数字 22（`--fs-stat`）。h2 / h3 与设置分区标题不带 `## ` 前缀。
- 行高：界面行（列表行、工具行、活动行、文字按钮）24（`--lh-row`）；正文 1.75（`--lh-body`）。正文列宽上限 720px（约 80ch / 40 个汉字，`--w-body`）。
- 字重：`--fw-regular` 400（列表行名称、按钮、导航）；`--fw-medium` 600（h2 / h3、设置分区标题、对话框标题）；`--fw-strong` 700（Markdown 加粗）。微软雅黑无 500 / 600，600 会落到粗体，所以只给标题用；列表行、按钮、导航保持 400，选中靠颜色与底色。选「终端风格」（Maple）时 `--fw-medium` / `--fw-strong` 回到 400（Maple 只有 Regular）。不写裸数字字重。
- 标题 `text-wrap: balance`，正文段落 `text-wrap: pretty`。
- 数字列（用量、计时、行号、计数）一律 `font-variant-numeric: tabular-nums`。
- Windows 不额外打包字体：微软雅黑对小字号有专门调校；随包思源 / Noto 体积大、小字号偏虚。
- 用户在「外观」里改字体（见 2.5）；换成非等宽字体后不再保证 1:2 栅格。

### 2.3 间距、圆角、尺寸

- 间距 4 的倍数：`--sp-1…6` = 4 / 8 / 12 / 16 / 24 / 32。回合间距 `--d-message-gap` 32（随密度变化）。
- 离刻度的间距不新造令牌，也不借用 `--r-*` 圆角令牌，而是用 `--sp-1` 基准等值表达：6 = `calc(var(--sp-1) * 1.5)`、10 = `calc(var(--sp-1) * 2.5)`、14 = `calc(var(--sp-1) * 3.5)`，一个表达式只用一个倍数。圆角令牌只用于 `border-radius`。
- 圆角（方向 F 放大一档）：`--r-xs` 3（分段内的项、行内代码） · `--r-sm` 6（分段容器、导航项、列表行） · `--r-md` 8（按钮、输入控件、菜单、卡片） · `--r-lg` 10（分组块、工具磁贴） · `--r-xl` 14（输入框、浮层、对话框）。
- 全圆角（`--r-full`）只给滚动条、进度条、开关、头像、计数点和悬浮圆按钮；按钮与分段不用胶囊形。
- 控件高度三档：`--ctl-h-sm` 24 · `--ctl-h` 28（默认） · `--ctl-h-lg` 32。按钮、分段、输入框只用这三档。
- 标题栏高 40px（`--h-titlebar`），状态栏高 24px（`--statusbar-h`）。

### 2.4 投影

界面内部的层级靠色阶，不靠投影。弹出层（对话框、设置、引导、菜单、命令菜单、详情浮层）用 `--shadow-pop` 表达「浮在内容之上」，描边取 `--border-soft` 而不是 1px 硬边（方向 F）。方向 F 另外给输入框一层很淡的下投影（`--shadow-soft`），聚焦仍为强调色描边；其余界面内部仍只靠色阶。

### 2.5 外观个性化

设置 → 外观里的字体与字号是对上面缺省值的覆盖：改动只写根元素上的令牌，不改模块 CSS。

- **背景色**：模板一行（深浅各一套色），方向 F 新增**墨灰**（`ink`：深色 `#18191b`、浅色 `#f7f6f3`，排在「石墨」之后，与其他模板一样由底色推出整组层级，只改背景、不改文字灰）；自定义单独一块，深浅主题各存一种底色（`backgroundCustom` / `backgroundCustomLight`，浅色未设时沿用前者），含取色器、`#rrggbb` 输入与五级色阶预览；被夹进可读范围时写明实际使用的颜色。
- **字体**：界面与正文共用一项（**系统无衬线缺省** / 终端风格——Maple Mono CN / 系统衬线 / 自定义字体名），代码与终端另一项（Maple Mono CN / 系统等宽 / 自定义）。自定义只收字体名，后接所选系列的回退栈；能读到本机字体列表时给出候选。旧用户没改过字体时按缺省（系统无衬线）显示，不被当成选了 Maple；「终端风格」会显式落盘并保留。
- **字号**：正文 12–22（缺省 15，标题按 +2 / +5 跟随，正文列宽 = 48 × 正文字号）；界面 11–16（缺省 13，元数据与小字按 −1 / −2 跟随，界面行高随之加高）。整体缩放仍用「界面缩放」。
- **密度**三档同时改界面行高（`--lh-row` 20 / 24 / 28）、正文行距（1.6 / 1.75 / 1.9）、控件高度（−2 / 0 / +2px）、回合间距（16 / 32 / 48）与列表行距，不改字号。

## 3. 控件

外观全部来自 `styles/ui.css`。模块 CSS 只写控件在自己版面里的**位置**（`margin`、`flex`、`align-self`、宽度），不重写底色、描边、字号、高度或悬停色。

### 3.1 按钮

| 写法 | 组件 | 用途 |
| --- | --- | --- |
| `.btn` | `<Button>` | 次要操作（默认）：对话框的取消、卡片操作、设置行操作 |
| `.btn.primary` | `variant="primary"` | 一个区域里唯一的主要操作（开始使用、提交、打开） |
| `.btn.ghost` | `variant="ghost"` | 行内低频操作、取消暂存、「不管了」 |
| `.btn.danger` | `variant="danger"` | 删除、移除、覆盖 |
| `.btn.icon` | `<IconButton label=…>` | 只有图标的按钮；必须给 `label`（用作提示气泡与无障碍名称，组件内部已包 `<Tip>`） |
| `.btn.sm` / `.btn.lg` | `size` | 24 / 32px；默认 28px |
| `.btn.on` / `aria-pressed="true"` | `active` | 切换按钮的「已开启」 |
| `.btn.ui-disclosure-trigger` | `<Button aria-expanded trailingIcon="chevron-right">` | 折叠展开触发：末位 `chevron-right` 默认朝右，`aria-expanded="true"` 时转 90° 朝下（右 → 下）。与菜单、选择复用的 `.ui-choice-trigger`（收起朝下、展开翻转朝上）方向语义不同，两者不可互换 |

一个区域最多一个主要按钮。按钮文字写动作（「打开」「提交」），不写「确定」。图标在文字前；导航去别处的按钮可在文字后放 `chevron-right`。

### 3.2 分段控件

`.seg` > `.seg-btn`（`.sel` 或 `aria-pressed`），组件 `<Segmented>`。二到五个互斥选项：主题、语言、视图切换、筛选、档位。选中项用 `--bg-3` 底 + 正文色，图标变强调色；**不用强调色实底**。`.seg.sm` 用于面板内部与筛选。选中底块切换时沿横向滑动到新位置，不跳变（`<Segmented>` 自动带 `.sliding`）。新增互斥选项时直接用 `.seg`，不再新建变体。

### 3.3 其他控件

- **开关** `.switch-pill` / `<Switch>`（带 `.on`）：布尔设置；开启为强调色实底。轨道不保留原生按钮内边距，圆点按轨道高度居中，设置行的控件格按整行垂直居中，不依赖文字行高。
- **徽标** `.ui-badge`（`accent` / `ok` / `warn` / `err`）：状态标签与计数。方向 F 改为胶囊、无描边：中性底为 `--bg-3`，语义色用同色浅底 + 同色文字，不用实底。
- **空状态** `.ui-empty` / `<EmptyState>`：一句事实 + 可选的下一步操作。不画插图，不写「暂无数据」式空话；「没有改动」与「不在 Git 仓库里」这类不同事实用不同文案。
- **分区标题** `.ui-section-title` / `<SectionTitle>`：12px / `--fg-dim`，图标 `--fg-mute`。
- **键位** `.ui-kbd`：只给真正接了快捷键的动作画键位。
- **提示气泡** `.ui-tip` / `<Tip>`（2026-10-13，合集 10）：替代原生 `title`。纯图标按钮、被截断的触发器统一用它，不再依赖原生 `title` 作为唯一说明。行为：首次鼠标悬停约 400ms 出现，出现过后移到相邻控件用短延迟（0ms）切换；`:focus-visible`（键盘聚焦）立即出现；任何时刻只显示一个，Esc 只关当前这个；指针离开、组件卸载都会清掉待开定时器。外观：`--bg-2` 底、`--r-md`、`--shadow-pop`、界面字号，`role="tooltip"` 且不可交互（`pointer-events: none`），不抢 Tab、不建焦点陷阱；可从触发器所在角长出。目标元素只在气泡可见时带 `aria-describedby`（其余时候不带），`aria-label` 仍是无障碍名称；显示期间租用 `acquireOverlayBlocker`，内置浏览器的原生视图不会穿到气泡上面。可选 `shortcut` 用 `.ui-kbd` 机声键帽显示，键位必须来自 09 的 `KEY_BINDINGS`（同源，不另维护键位表）；没有正式绑定的动作不编造键位。触发元素已带 `title` 字符串说明时，用该字符串作气泡内容；富内容悬浮卡（会话柄预览等）不走它，触摸端不做对应物。
- **输入框** `.ui-input` / `<Input>` `<Textarea>` `<Select>`：`--bg-2` 底、`--border-soft` 描边、`--r-xl`、一层很淡的下投影（`--shadow-soft`），悬停 `--border-str`，聚焦 `--accent` 实色描边（半透明 `--accent-line` 在浅色底上不足 3:1，不作焦点指示）。默认 240px 宽、左对齐；数值用 `.num`（96px、等宽数字、右对齐）。要撑满时模块只写 `width` / `flex`。
- **字段** `.ui-field` / `<Field>`：表单里的一项，标签 + 控件 + 说明，整项包在 `<label>` 里。
- **设置行** `.ui-row` / `<SettingRow>`：「名称 + 说明｜控件」两列；方向 F 起同组行之间不画线，行落在 `--bg-1` 的分组块里（`.ui-rows`），行悬停为 `--bg-2` 圆角底；`col` 为上下排布。分组容器 `.ui-rows`。
- **设置分组** `<SettingGroup>`：分组标题和说明统一排版；同组设置行由 `.ui-rows` 承载。
- **渐进展开** `<Disclosure>`：把低频、诊断与高级选项收在明确标题下，默认收起；使用原生 `details` / `summary` 表达展开状态。
- **页签** `.ui-tabs` > `.ui-tab` / `<Tabs>` `<Tab>`：`role="tab"` + `aria-selected`，方向键移动焦点。选中项与分段同一语言（`--bg-3` 底 + 强调色图标），不画下划线。`.vertical` 用于设置导航；`.doc` 是可关闭的文档页签（文件磁贴、浏览器），关闭钮 `.ui-tab-close` 用 `close` 图标。可关闭的页签是同组的两个同级按钮：切换与关闭分开聚焦，不把关闭按钮嵌进页签按钮。互斥的视图切换用分段，不用页签。
- **菜单** `.ui-menu` > `.ui-menu-item` / `<Menu>` `<MenuItem>`：右键菜单、行菜单与下拉共用。`--bg-2` 底、`--r-md`、`--shadow-pop` + `--border-soft`（方向 F：靠阴影不靠硬描边）；项 28px 高，悬停 / 键盘聚焦 / 选中为 `--bg-3`，键盘聚焦另加 1px 强调色内描边，`.danger` 只染文字，分隔 `.ui-menu-sep`，小标题 `.ui-menu-title`。定位由调用方负责（`ContextMenuSurface` 负责 fixed 与夹取）。供应商、权限等选择复用砚的自绘菜单，不使用系统原生下拉；选中项只用强调色对勾表达，底色与悬停一致，触发器的箭头朝下、展开时翻转。
- **外部链接** `<LinkButton>`（`.ui-link`）：无框文字，显示去掉协议的网址并在 title 给完整地址，悬停/聚焦强调色；设置等模态里的原链接走系统浏览器，避免内置浏览器被模态遮住。
- **检查器分区** `.ui-inspector-section` / `<InspectorSection>`：标题 12px + 右侧摘要，分区之间一条细线。
- **列表行** `.ui-list-row` / `<ListRow>`：可点的一行，图标或状态点 · 主文字截断 · 右侧元数据；选中 `--bg-3` 底。
- 模块不自建 `*-btn` / `*-chip` / `*-tab` 类：`npm run check:css-budget` 统计模块 CSS 里的这类选择器，只许为 0。
- **选中项**（列表、导航、菜单）：`--bg-3` 底；菜单与命令菜单的选中行首加强调色 `›`，左栏会话行用行首字符状态。**不用 inset 边线**：圆角会把它弯成一道蓝弧。
- **运行与加载**：回合活动行的旋转字符是全窗口唯一的主要运行信号（见 4.3）；工具行、任务、列表等局部运行状态用静态 `<RunDot>`（`.ui-run-dot`）；方点阵 `<Spinner>`（`.ui-spin`）只用于加载占位（如设置页按需加载）。不用旋转图标或其它动画小球表示运行。

### 3.4 图标「砚线」

图标语义写在 `scripts/design/icons/catalog.json`，一个图标只承担一个语义；桌面与手机共用同一份生成物。图标是自绘的「砚线」，母题是品牌标志「提示砚」：开口石框 + 方头斜接的 `>_`。几何真源 `scripts/design/icons/inkline.json`，与编目一一对应。

几何规则：

1. **16 网格，12 活动区**，四周留 2px，对齐 12 / 14 / 16 三档尺寸。
2. **描边恒定 1.25px**（`vector-effect: non-scaling-stroke`），三档尺寸一样粗；手机端 1.5dp（见第 7 节）。
3. **方头 · 斜接**：`stroke-linecap: square; stroke-linejoin: miter`，统一直角。
4. **开口角**：文件、目录、终端、外链等容器类图标右上角留缺口。
5. **直线与整圆为主**：0° / 45° / 90°，不画插画式隐喻。
6. **进行中不用图标**：用字符状态或方点阵；状态点、勾选框由 CSS 绘制。

可读性规则（描边取 1.25px 而不取 1.5px 的原因：1.5px 在 12px 下会把推子、清单这类多笔画图标糊成一块；1px 配 `--fg-mute` 在浅色主题下发虚）：

- **笔画间距**：平行笔画之间的净空在 16 网格中不少于 2 个单位（12px 下 1.5px）。达不到的图标在 12px 使用简化几何，或该位置改用 14px。
- **颜色**：单独出现的图标（图标按钮、无文字的状态标记）至少用 `--fg-dim`；`--fg-mute` 只给紧挨文字、只作辅助的图标。
- **可辨认**：同一区域并列的图标轮廓必须能区分（例如文件与复制、目录与项目），靠外形而不是细节区分。
- **验收**：新增或修改几何时，截取深浅主题 × Windows 100% / 125% / 150% 缩放下 12px 与 14px 的对照图。

尺寸只用 12 / 14 / 16（手机 16 / 20 / 24dp）。改图标：改编目与 `inkline.json` → `npm run icons` → `npm run check:icons`。

语义调整：`sparkles` → 星号 `*`；`agent` → `>>`；`settings` → 两道推子（三道在 12px 下会糊，按笔画间距规则简化）；`alert-circle` / `check-circle` → 方框内 `!` / 勾；`terminal` 即标志图形。`running`、`activity` 仍有几何，但进行中改用字符状态，这两个语义只留给静态计数。

### 3.5 提示符语言

| 位置 | 形式 |
| --- | --- |
| 用户消息 | 桌面：靠右、贴内容宽度的浅底气泡（`--bg-2`、`--r-md`，最宽 80% 或 640px），不带 `›`；手机：`›` 提示符 + 正文，无框（第 7 节） |
| 回合活动行 | 每轮助手回复顶部一条，字符状态 + 状态文字 + 计数 + 右侧用时（见 4.3） |
| 过程 | 默认折叠为一行摘要，展开为 `├─ └─` 调用树（见 4.3） |
| 工具行 | 静态状态点 · 工具名 · 目标（优先文件名）· 右侧耗时或真实 `+n −m`；`bash` 目标前加强调色 `$` |
| 输入区 | 左侧 `›` 提示符（`!` 开头的直执行命令是 `$`）；运行时发送位变为「■ 停止 计时」（见 4.4） |
| 命令菜单 | 见 3.6 |

提示符 `›` 用 `--accent`、等宽字体。

用户消息里 pi 展开的 `/skill:名字` 技能全文只展示为用户敲的那一行，模型仍收到全文；pi 终端内置命令在桌面端有对应动作的直接执行（`/settings` `/thinking` `/export` `/copy` `/name` `/session` `/clone`），其余登记为兼容项并说明桌面端入口，不会当消息发给模型。

Codemode 等组合工具的子调用**嵌套在父调用之内**，读起来是同一步：父行之下是一段缩进的子调用区，左侧一条 `--border-soft` 细引导线对准父行状态点，子行之间不画横向分隔线、行高 26px；更深一级在子调用区里再嵌一段（最多四级，更深的平铺在第四级）。父行目标在有子调用时写「工具名 ×次数」（如 `read ×6`），还没有子调用时写脚本首行；点开父行看脚本原文与输出。折叠较早步骤时父调用连同子调用算一步；子调用区超过六条时只留最近四条已完成的，较早的收在区内「前面 N 个调用」。运行中或失败的子调用始终可见，连同父调用一起保留。历史只能恢复 pi 保存的调用摘要，成功子调用没有完整输出时不补造内容；保留现有键盘展开与窄屏布局。

### 3.5.1 消息内 HTML 成果

桌面消息中的 `.html` / `.htm` 成果默认在原有成果卡片里显示网页，不再只铺源码。卡片保留文件名、说明、下载、右侧源码预览、打开位置与复制路径；挂载已有文件时，双击卡片、「打开位置」与「复制路径」都指向**源文件**（受控副本只用于预览与图片展示，源文件已被删除或移动时才回退到副本），生成物本身没有源文件则仍指向副本；HTML 区上方使用统一小号分段控件切换「网页 / 源码」，源码使用现有代码区域。网页占卡片宽度，高度为窗口高度的 55%（260–520px），内容在网页内滚动，不自动把整份页面高度撑进消息流；窄列不额外撑宽。读取失败、文件不可用或超过 5MiB 时明确提示，不能把截断 HTML 当成成功预览。

网页使用无同源权限的 sandbox iframe 和独立受控协议，只加载成果目录内的完整文件快照；允许本地内联脚本与样式以支持生成图表交互，不暴露 preload/IPC，不允许读取其他文件、联网、外链导航、弹窗、表单提交、子网页或权限申请。提示「离线隔离预览，外链与页面导出受限」，原文件仍可下载。此功能只处理受控 HTML 成果附件；普通 Markdown 原始 HTML 和 HTML 代码块继续作为文字，不自动执行。主题由产物自身控制，不覆写第三方页面样式。

网页预览高度固定预留，载入、卸载占位与失败同高；离视口很远时卸载页面、回来重新载入，控制同时存活的页面数量。工具条提供「重新载入」（明确会重置页面内操作）与「展开/收起」（消息内加高，不离开阅读位置）；可重试的失败给重试按钮。提示写明页面内操作不保存，不显示「已保存」。

### 3.5.2 消息内图片成果

同一回合有两张及以上可预览图片时，图片卡片两列并排（`minmax(0, 1fr)`，窄于 640px 回到单列），单张仍占整行；网页、代码等其他成果按原样整行排在图片之后。回合里既有生图结果又有模型用 `yan artifact attach` 挂出的图时，挂出的图视为交付，生图结果视为过程图：交付图并排展示，过程图收进其下的「过程图 N 张」，沿用短进展的折叠样式（›、`--fg-mute`、左侧细线），展开后同样两列。只有生图结果时全部视为交付，不折叠。同一行卡片按各自内容高度顶部对齐，不拉成等高。边长不超过 64px 的小图（像素材质、图标）放大到预览高度并按像素硬边缩放（`image-rendering: pixelated`）。

### 3.6 命令菜单与会话切换器

输入框里的 `/` 命令菜单（以及 `@` 文件菜单）是命令入口：

- 顶部 `›` 输入行回显当前查询；结果按类别分组，组标题用分区标题样式；
- 选中行 `--bg-3` 底 + 行首强调色 `›`；右侧淡显快捷键或参数提示；
- 底部一行键位提示（`↑↓` 选择 · `Enter` 执行 · `Esc` 关闭）；
- 入场 `--mo-slow`、退场 `--mo-fast`；方向键、Enter、Esc 与 Tab 行为保持现状。

**会话切换器**（Ctrl+K）是居中的模态小窗：顶部输入，下方结果列表（标题、项目 · 时间，正文命中另带一行片段），方向键选择、回车打开、Esc 关闭，没输入时列最近的会话。它复用统一 modalLayer 与焦点陷阱，打开期间暂停模型快捷键，关闭恢复原焦点；终端聚焦时 Ctrl+K 让给 shell。正文搜索失败与无匹配分开显示，保留标题结果与重试入口；只允许打开属于当前查询的结果，新的标题匹配即时可用，正文加载状态独立显示。

**动作模式**（2026-10-13，与切换器同一个面板）：输入以 `>` 开头切到动作列表；空输入时最近会话下方给三条常用动作提示（新对话、打开设置、终端），只写一个 `>` 本身即列全部动作。动作有两类来源，不新建注册中心：前端固定宿主动作表（新对话、当前项目新对话、设置各页、两档权限、深浅主题、左栏、工作区工具磁贴、复制上一条回复、停止当前运行）与输入框命令菜单的同一份清单（`command-registry` 清洗结果）。行右侧用 `.ui-kbd` 显示真实键位；不可用的动作（没有项目、没有可复制的回复、不在运行、已是当前档）整行禁用并写明原因，点不动也不假装成功。执行时调用各入口的正式动作：设置复用导航页 ID，工具磁贴走工作区启动入口，斜杠命令走与输入框提交完全相同的分发（本地命令执行、兼容命令给说明、其余按普通输入发送），不新建事件或状态副本，也不把命令填进草稿冒充执行。动作成功后关闭面板；异步动作在切换会话 / runner 后不把结果投给新会话。键盘 `↑↓` 选择、`Enter` 执行、`Esc` 关闭，空列表时索引安全。

## 4. 版面与信息层级

### 4.1 窗口骨架

```
┌ 标题栏：左栏开关 · 品牌 │ 会话头（标题 · 项目与环境 · 会话菜单）······ 工具菜单 · 固定 · 浏览器 · 窗口控制 ┐
├ 左栏 ┬ 工作区：主会话（对话流 + 输入区） + 按需打开的工具磁贴 ─────────────────────────────────┤
│ 新对话 + 搜索 │                                                                                  │
│ 置顶 / 最近    │                                                                                  │
│ 项目 → 会话    │                                                                                  │
└ 状态栏：空闲/运行中/等待批准 · 分支与改动 · 内核连接 · 子 Agent · 手机 ············ 额度 · 本会话花费 ┘
```

- **窗口外框圆角**走系统默认（主进程 `roundedCorners`）：Windows 11 给无边框窗口画系统圆角，最大化与贴边时由系统切回直角，Win10 及更早版本仍是直角；界面内部的控件圆角不受影响。
- **标题栏**高 40px，窗口按钮与它同高，会话头并入其中段；会话标题退一档（`--fg-dim`），与品牌之间隔一条细竖线，避免品牌与标题并列成两个主角。品牌只出现在这里。
- **左栏首次打开默认收起**，由标题栏开关显式展开；展开、收起时立即保存，下次启动恢复。左栏收起时，指针停在标题栏开关上约 140ms，左栏以浮层滑出（不推挤中栏，宽度沿用用户拖出的值），离开开关与浮层约 260ms 后收回，点击开关才固定展开。
- 对话区顶部有一小段（16px、起点 35% 不透明）轻渐隐，滚动到标题栏下的消息淡出而不是被切断。
- 默认工作区只有主会话，没有检查器，也没有标题栏右栏开关。工具（任务、日志、文件、浏览器、终端、账号额度）从「打开工作区工具」菜单按需打开为磁贴（4.6）；导出、克隆、在文件夹中显示与自动重试收进会话头右侧的「⋯」会话菜单。
- 界面淡化 pi：日常界面称「Agent 内核」或只写状态，pi 这个名字只出现在设置的诊断信息、插件与原生功能说明里。模型身份为 Inkstone（砚）内的助手，内置能力说明只声明实际可调用的入口。切换项目或会话时内核换进程属于正常过程，不打断界面：连接条在启动超过 1.5 秒后才出现，写「正在准备会话…」；失败时写「Agent 内核未连接」，详情里保留原始诊断输出。
- 空入口不渲染：没有归档项目时不显示「已归档项目 · 0」；计数为 0 的筛选档不画。
- 窄窗口（900×520、940×620）下所有标题、按钮和筛选不能换成竖排或溢出；grid 弹性列一律 `minmax(0, 1fr)`（`npm run lint:css` 检查）。

### 4.2 左栏

- 顶部是「新对话 + 搜索」。行高 24px，字符状态在行首（运行 `●` 强调色、等待 `◆` 警示、失败 `✕` 错误），选中为 `--bg-3` 底。静止会话行不显示空心点（悬停淡显，位置保留），状态只表达选中、运行、等待、失败、隔离与未读；相对时间随界面语言（「刚刚」）。
- 左侧项目名称按钮单击展开或收起会话列表，进入该项目由会话或项目菜单操作完成。项目菜单提供「更改项目文件夹…」（见第 5 节）。
- **视图**（参考 Claude Code 的侧栏筛选菜单）：搜索框右侧一个「视图」按钮，菜单分两组单选——分组方式（按项目 / 按状态 / 按日期 / 不分组）与排序（最近活动 / 名称 / 创建时间）。默认「按项目 · 最近活动」即原有的项目树；偏离默认时按钮点亮。「按状态」依次分为等你回答、出错、运行中、其余，空分区不显示；「按日期」分今天、昨天、本周、更早（按本地零点算）。非项目视图下会话平铺、不缩进，仍保留置顶区，隐藏「最近」区与已归档项目入口；分叉会话在平铺视图里是普通行（带分支编号）。排序同时作用于项目内的会话顺序，项目本身的顺序仍由拖拽或活动时间决定。视图菜单还有第三组「显示」：进行中的会话 / 已归档的会话，默认前者。
- **归档**是会话菜单里的一个动作（可取消），只在会话索引里记一个时间，不动对话文件、不停运行实例；归档后会话离开默认列表、置顶区和「最近」，在「已归档」视图里原样列出并能取消归档。置顶同样存在会话索引里（手机端与多窗口共用）。设置 · 会话 · 常规里有「自动归档闲置会话」（从不 / 7 / 14 / 30 天）：超过天数没有动静、没置顶、没有运行实例的会话在列会话时被打上归档标记，随时可在「已归档」里找回。
- 视图选择是本机偏好，存在 `yan.sidebar.view`；分区与排序的计算在 `src/shared/rail-view.ts`，自动归档的选择规则在 `src/shared/session-archive.ts`，渲染只画结果。左栏的拖拽在 `rail/useRailDrag.ts`，按项目视图的数据整理在 `rail/useRailProjects.ts`。
- 会变化的都要有过渡：会话行挂载（展开项目、显示更多、置顶移位）轻落位，归档先淡出再移除，重命名框、拖拽插入线、撤销条淡入。

### 4.3 对话流

- **用户消息**：靠右，一块贴内容宽度的浅底气泡（`--bg-2`、`--r-md`、无描边，最宽 80% 或 640px），不带 `›` 提示符；图片与元数据随之靠右。时间、分支、回退在悬停或聚焦时淡入。问题面板的回答整块带强调色左线与底色，回看时能认出不是手打的。用户消息下方的「回退代码」只在存过检查点时出现，确认框先列出将修改、删除、恢复的文件，做完提供「撤销这次回退」。
- **回合活动行**：每轮助手回复顶部一条固定的活动行，原地更新：字符状态（运行 `⠋` 旋转 / 待批准 `◆` / 完成 `✓` / 失败 `✕` / 停止 `■`）+ 状态文字 + 计数（步数、失败数）+ 右侧用时；复制在悬停时出现。运行中的旋转字符是全窗口唯一的主要运行信号；减少动效时改为静态 `●`。
- **结论在前，过程在后**：正文后面是**过程**，默认折叠为一行摘要（`› 过程 · N 步 · 推理 Ns · 1 项失败`），展开为 `├─ └─` 调用树，第一行是推理入口（标注「服务返回的摘要」，点开在原位看全文），失败行用错误色。运行中的调用与失败项在折叠时也会写进摘要。小型工具组直接列出调用，长组（七步及以上）才折叠较早步骤。
- **失败**：回合错误的摘要直接显示在正文里：错误浅底 + 左侧 2px 错误色线。重试的调用各自保留，首次失败的那行不被覆盖。模型错误写明可确认的原因与处理建议，并保留脱敏后的服务商原文；无原文时明确说明未返回原因，不猜测额度、鉴权或审核拦截。额度类错误要分清「额度用尽」与「请求频率限流」：同一句里常同时出现 rate limit 字样（如 Claude 的 `rate limit (five_hour)` 配合 `hit your session limit`），按额度窗口用尽说明，并从原文提取恢复时间一并显示；不把等窗口恢复的问题说成「降低并发」。
- **过程布局**（设置 `processLayout`，缺省 `inline`）：
  - `inline` 阅读优先：过程在正文上方，展开后直接阅读工具详情。
  - `side` 过程并列：正文列宽不变，右侧加一栏 `--w-proc-side`（240px 起，宽窗口取两侧余量的一半，上限 440px）放同一个过程组件，在本回合内 sticky、默认展开，最高不超过对话区可见高度（`--stream-h`），栏内终端与长列表在栏里滚动，正文里的过程摘要行不再出现。
  - 入口两处共用一个设置值：会话头的文字按钮「并列过程」，设置 · 外观「执行过程」分段。对话区宽度放不下「正文 + 过程栏」时自动回到正文所在列（设置值不变）；分屏窄磁贴同样处理。展开/折叠状态两种布局共用。
- **工具详情**：正文内与并列栏复用同一份调用和详情组件，不复制执行状态。过程树、工具组不再叠加固定高度滚动框；单条结果只保留一个纵向内容滚动区，终端保留自己的滚动与尺寸调节。并列栏保留整栏滚动，详情可通过「宽幅查看」进入独立模态阅读区，不受栏宽与原工具行限高约束；窄窗口自动夹在视口内。关闭后返回原工具行焦点，不改变用户手动展开状态。工具行优先显示文件名（完整路径在详情中可选择复制），编辑/写入行在有执行前后真实差异时直接显示 `+新增 −删除`，未知不显示虚假零值。详情将完整路径、结果与原始参数分开：结果优先，参数按需折叠；代码脚本仍按代码显示。diff 逐行红删绿加，保留原始符号；来源没有行号时不编造行号。宽幅查看只展示已记录内容，不把被执行器截断的输出称为完整原文件；缺少快照时明确显示替换片段或写入内容，不把覆盖写入都称作新增。
- **流式呈现**：实时正文保留 Markdown 结构，正在增长的末段暂不做语法高亮或写入历史缓存，完成后恢复完整高亮。界面按真实增量更新，不添加人为逐字播放或完成后的拖尾；历史回合在当前输出时保持稳定。工具过程显示真实工具与状态；宿主不伪造模型发言。流式回复中新出现的顶层块（段落、列表、引用、标题、代码块）整块淡入并上移 3px，块间错峰 60ms、上限 8；已有块与历史 / 恢复 / 压缩重放不重播（见第 6 节）。
- **回合页脚**：每条助手回复底部在时间旁提供复制按钮，复制该回合的完整回复正文；用时与时间只在回合末出现一次。已结束的助手回复段计时保持冻结；宿主子代理结果通知虽不画成用户消息，但须分隔后续助手运行段，不能把通知到达、等待与后续总结重新累计到此前已结束的段上。后续运行独立显示自己的计时，会话累计统计仍累计真实新请求，不复制旧段用量。模型取回合最后一条有值的实际助手消息，不以当前选中的虚拟模型冒充；按该消息的供应商与模型 ID 匹配模型菜单的显示名称，保留名称原有大小写，不能直接把小写 ID 当作已知模型的名称。实时与历史归一化保留 pi 原始 `provider` 与 `model` 的完整身份；目录优先使用菜单的当前模型列表，未就绪项可用菜单收藏名回填。旧记录缺供应商时，仅在同 ID 的全部候选具有一致显示名时使用该名称，不猜供应商；歧义或目录找不到时原样显示记录中的 ID，不猜名称。名称在窄窗截断，完整名称与模型 ID 留在提示与可访问文本中，旧历史缺值不猜。
- **智能界面**（`VisualBlock` / `VisualParts` / `VisualChart` / `WidgetBlock`）：融入正文背景，不加底色、外框与分隔线；标题为元数据字号淡色；指标只靠间距成组，数值比正文大一级；对比卡的推荐项靠名称正文色与「● 推荐」区分；小部件标题行与图表标题同级，生命周期（活跃 / 已暂停）写在标题行，滑块为细轨。小部件换主题只发变量、不重建页面；离视口远时卸载，回来重新载入。小部件标题行有「保存状态」「填入输入框」；仅点击保存时持久化常规表单值和可选 JSON 状态，恢复按会话/段落/代码块身份隔离，不赋予网页文件权限。密码、隐藏域和文件输入不采集。
- **结构化回答块**：回答需要比较数值、推荐几个选项或说明因果流程时，模型在正文里写 `yan-chart` / `yan-cards` / `yan-flow` 等代码块（JSON 数据，格式与校验见 `src/shared/visual-blocks.ts`，写法由随包 `visual-answer` 技能说明），宿主画出来：模型只给数据与文字，比例尺、配色、字号与动效都由宿主决定，历史中仍是文字，换主题即重画。块包含标题与副标题、可选大号数字、图形、数据来源一行（图表必填）、说明与来源标签（域名 + 名称，单击内置浏览器、双击外部浏览器）。图表按容器真实像素绘制，纵轴自动取整（百分比封顶 100），系列色依次为强调色、青、警示色、兰紫，第二、四组柱用浅填充、第二、四条折线为虚线，图例不只靠颜色；「查看数据」展开原值表。流式中块未写完只占同高位置，写完且校验通过才画；完成后仍无效则按原文代码块显示并写明原因，不猜着画。入场：块淡入，柱子从基线长出、折线描出，卡片与流程步骤逐个落位（错开上限 8）。不新增依赖、不执行脚本，链接只放行 http(s)。
  - 块的种类：`yan-chart`（bar / hbar / stacked / line / area / dumbbell / diverging；横向用于长类别名，哑铃恰好两组，偏离以 0 为对称中线、负值用错误色）、`yan-stats`（指标卡：数值、带箭头的涨跌按「哪个方向是好事」着色、小趋势线、进度条 ≥85% 警示 ≥95% 错误）、`yan-cards`（list 一行一个带序号；grid 并排卡片，至多一个「推荐」）、`yan-record`（首字头像、标题、键值字段两列）、`yan-flow`、`yan-steps`（分步演示：步骤页签 + 面板 + 上一步/下一步，可循环，方向键切换）、`mermaid`（离线渲染，严格安全级别，SVG 文本标签，取砚的令牌配色，按自然宽度显示、放不下才缩小）、`yan-widget`（自由 HTML/SVG：放进 HTML 成果同一个隔离协议，宿主注入 `--text` `--surface` `--accent` `--c1…c6` 等主题变量与基础控件样式，高度随内容；页面只能回报高度、打开 http(s) 链接、调用 `askInkstone` 请求追问——追问显示在小部件下方，用户点「填入输入框」后照常由用户发送）。
  - 开关在输入框模型菜单最下方「可视化回答」（设置 `visualAnswers`，缺省开）：关掉后从下一轮起不再向模型说明这些写法，已有历史照常渲染。说明同时写进 pi 的具名分区，只转发结构化部分的 provider（Claude 订阅桥接）也能收到；回复语言、详细程度、提问指引与能力说明同样双写。
- **提问表单**：`yan question ask` 带 `fields`（1–5 项）时，问题面板按字段渲染：单选/多选是带说明与图标的卡片（单选最多 3 项，多选最多 6 项），每个选择题下有一行「或自行撰写回复」；日期、数字、滑块用原生输入，可选项标「可选」；必填项未填就地提示不提交。答案以 JSON 回到同一请求，宿主按字段夹取后交还模型并写一行摘要。宿主提问超时后移除对应面板；其他待答问题保留，迟到提交不再处理。普通提问嵌入输入框上方的扩展区，沿用同一边框与宽度。
- **接入批准**：Agent 申请接入技能时用同一个问题面板，徽标换成盾牌「授权」；正文依次写技能名、用途、来源（仓库 + 提交）、文件数与脚本、审查结果；选项只有「仅本次会话使用」「安装到我的技能」，底部「跳过」即不安装，自写回复也视为不安装并转告 Agent。倒计时 2 分钟，从看到起算、可点加时，到点自动跳过。手机端只能跳过，不能批准。
- **子 Agent 卡片**：聊天任务卡默认只显示短标题、状态和至多一行原因或当前动作；第二行固定按「只读/可写 · 菜单模型名字 · 供应商 · 思考强度 · 上下文使用量 · 运行时间」排列；供应商直接可见，不删掉 CommandCode 等来源，不要求展开详情才能辨认，完整 `provider/id` 留在提示和详情，不再重复「子代理」标签。上下文使用量取 pi 原生上下文快照，显示已用/窗口及百分比，不用累计调用 token 冒充上下文；历史或未报告字段显示「—」，未知思考强度同样不猜测；窄窗允许元数据自然换行。点击标题打开完整过程；过程窗口顶部显示发给子代理的任务原文（brief 与任务拼成的提示词）与字数，默认展开、可收起，运行中推送不会把用户的收起状态重置；「详情」入口同时显示用量与最近调用，默认不展示产出正文。子代理只复用主会话的消息、Markdown、过程折叠与工具呈现，不提供主会话分支、输入、追问或续跑操作。
  - 分组：同一回合启动的子代理是一组；两个及以上时组首一行汇总「并行 N 个 · 运行中 a · 需处理 b · 已完成 c」。运行中与需要处理的（出错、超时、待合并、冲突）始终逐张显示；已完成或已停止且无需处理的默认收进汇总行，点「展开已完成」逐张查看、再点收起。完成后无需处理的卡片只保留第一行，第二行元数据随「详情」一起显示。
  - 常驻区（2026-10-15，修订）：当前会话有运行中或需处理的子代理时，在输入框上方常驻**一行**概览「子代理 · 运行中 a · 需处理 b」加一个查看入口，**不再渲染任何任务卡、也不再在输入区展开第二套列表**（避免与原回合历史卡重复、把输入区撑高）；窄窗这一行允许截断。查看沿现行工作区入口：只有一个任务时派 `inkstone-agent-open`（`subagent:<id>`）打开既有 `SubagentPanel` 的运行详情；多个任务时派 `inkstone-workspace-launch`（`agents`）打开既有面板总览，不在这里复制列表。只投影同一份运行快照，不复制执行状态，也不把历史卡移到最新消息处。已完成且无需处理（`done` 无待审阅、被停止）的自动撤下，原回合历史卡照旧保留、不移动会话记录。只显示**当前显示视图**（peek 优先）的子代理：`parentSessionId` 命中视图即留下；旧记录缺归属字段时，只要挂在这个视图的运行实例下（`parentRunId` 命中）也留下，不漏在跑的任务，其余缺失归属仍不猜当前会话。分屏只出现在焦点那一列；常驻区是输入区的一部分，不另建任务台。
  - 失败任务的退出：已失败且没有待审阅改动的单条任务提供「不再处理」次要操作，点击后移出「需处理」并进入默认折叠的「已完成」区；保留原始失败原因、调用历史与原生会话，不重试、不通知模型、不改写为成功，也不影响其他任务。聊天卡片与子 Agent 总览沿用同一个宿主持久标记；保存失败就地提示，仍留在需处理区。待合并或冲突的 worktree 不能用此操作绕过审阅，仍须明确合并或放弃改动。
  - 运行规则：调用过程随运行快照保存，重启后按原父会话恢复；历史不会自动恢复执行或重发完成通知。连续十分钟未收到模型输出或工具事件进入超时收尾，显示实际停滞原因；75 秒宽限内仍未结束才停止。默认没有总时长或工具调用次数上限；全应用最多同时 24 个子代理。宿主子代理结果通知仅供模型在后台继续任务，实时、历史、导航和排队区均不显示为用户消息。
  - 子 Agent 表单是纵向表单：模型、任务、执行位置、启动按钮，复用 Field/Select/Textarea/Button；显示实际模型和完整执行目录，在提交前说明不支持的组合，不静默改变用户选择。
- **会话柄**（`ConversationOutline`）：刻度 14×3，当前轮加长到 22 且用正文色，悬停那格就地变宽变高（强调色）；失败轮红色。预览卡显示「序号/总数 · 标题 · 三行摘要 · 状态与时间」，书签按会话与用户消息身份保存在本机，写入失败显示错误，不改会话原文。
- **滚动恢复**：普通切换与分屏焦点切换遵循同一规则，首次打开显示最新消息，回来接着原来的阅读位置；是否跟随底部按会话保存。虚拟列表重建期间的初始顶部事件不覆盖已保存的位置。
- **启动页**（空会话）：终端排版、靠上对齐、整体紧凑（参照 CC 客户端的体量），不对称两栏：左侧宽栏 `›`（强调色）+ 问候「{本机用户名}，接下来做什么？」（`--fs-h3`）与一行淡色说明，下面是当前项目（路径 + 强调色「更换」）、从这里开始（图标 + 文字按钮竖排，悬停才着强调色），不列斜杠命令（输入 `/` 时有提示）；右侧窄栏（23rem）比左栏下沉一截，放本机用量：小标题与「概览 / 模型」、「全部 / 30 天 / 7 天」都是文字切换（淡色字，选中为正文色 + 1px 强调色下划线）；概览以 Token 总数为唯一主数字（`--fs-stat`），下面一行三项（会话、消息、活跃天数，界面字号）；热力图为近 20 周固定 10px 小格（一列一周、周一在上、与指标左对齐，空格为正文色 9% 混色，五级强调色）；模型页每个模型一行名称（同名补淡色供应商）· token · 占比，下方 2px 细轨比例条。不加卡片底色、外框与分隔线。数据只来自本机会话文件（主进程增量统计并缓存），没有历史时右栏不显示；对话区窄于 760px 时只留左栏，用量整段隐藏，顶部留白收小。

### 4.4 输入区

- **pi 原生操作**：会话树、模型循环范围与项目信任通过斜杠命令打开轻量操作面板，复用统一控件、浮层阻挡与键盘焦点规则，不恢复退役会话地图。树只投影 pi 持久条目与当前叶子；导航执行原生操作，不改写会话文件。导入与 JSONL/HTML 导出由系统文件选择承接；分享必须先说明会话可能含代码、工具输出及凭证，用户明确确认后才上传，不默认上传。运行期间不允许替换会话或重载运行时。扩展文本组件尊重原生 `aboveEditor` / `belowEditor` 位置，收在输入区对应位置，不冒充 TUI 自定义组件。

- **外观**：单层平面（`--bg-2` 底、`--border` 描边、聚焦时强调色描边），没有渐变光带、环绕流光与顶边运行条。静止高度 64px（两行），超过三行自动进入长文模式；长文模式的输入框高度不超过窗口高度的 35%，不把工具条和状态栏挤出窗口。
- **运行**：运行时发送位变为「■ 停止 计时」；从开始到工具执行、等待与结束始终可停止，消息发送/待投递与停止分别处理。运行中发送普通消息默认排队，问题回答直接交给对应请求。
- **会话统计与用量**：两个紧凑、可键盘聚焦的文字入口「轮数 / 步数 · 输出速度」与「累计 Token · 缓存命中率」，由 `usageUnderInput` 控制（缺省开）。**位置随版面走，两处互斥**：单会话时它们常驻状态栏右段（同一组件，各占满状态栏高，点开向上弹出详情）；主页面切成多会话磁贴（分屏）时回到**焦点磁贴的输入框下方**并居中，状态栏那一段不再显示——分屏里只有焦点磁贴渲染输入框，于是每屏只出现一处。输入框下方那种形态绝对定位在输入框正下方、行底落在输入区预留的下内边距底边上，让它在输入框与状态栏之间视觉居中（上下留白相当），显示与否都不改变输入框的位置与高度；统计行不在输入框下方时该下内边距收成一段呼吸，输入框与状态栏之间不再夹一行数字，窄窗允许摘要换行、行高增加时不挤掉状态栏。点击向上展开与触发器对齐的统一详情浮层：会话统计列出模型用时、工具调用用时、平均首 token 延迟（TTFT）与输出速度（TPS）；Token 用量列出累计总数、缓存命中率、未缓存输入、缓存读取、缓存写入（有值时）和输出。累计调用 Token 不表示上下文占用，既有上下文圆环保持独立。轮数取有模型回答的用户回合，步数取实际模型请求；模型用时取宿主观测的原生 `turn_start`（请求准备）至助手 `message_end`，含请求准备、网络等待与 provider 内部重试，不等于服务端纯推理时间；TTFT 从同一起点至首个实际文本、思考或工具调用内容。新记录用 `generationTiming.startEvent = 'turn_start'` 标明来源；缺标记的旧流内时长仅作模型用时下限（`≥`），其流内首内容延迟不参与真实 TTFT 平均。解码速度仍取首内容至结束，缺失显示「—」，不拿整轮墙钟冒充模型时间。缺报用量时已知累计标 `≥`；会话切换关闭浮层，窄窗允许摘要换行，深浅主题复用统一控件。
- **排队附件**：运行中排队、改为插话、撤回、停止回填及运行实例重载恢复须保留消息原有图片，不得只恢复文字。队列按消息身份归属附件；相同文字与纯图片消息不能互相借用附件。撤回回到当前会话草稿时恢复图片，不能覆盖用户后来添加的附件。队列显示至少提供图片数量，让纯图片消息不呈现为空白行。
- **工具条**：权限与模型用安静的文字按钮。最窄磁贴的工具条保持一行不重叠：模型名先省略，用量环、再到语音按钮依次让位，权限名可省略；发送规则提示先省略。窄会话工具栏可换行，停止/发送始终可点击。
- **权限**：入口位于输入框加号左侧，显示当前档位，菜单明确对所有会话生效。两档为「自动批准」（`danger`，缺省，仍对危险操作请求批准，描述中明确说明）与「不受限制」（`all`，砚不额外拦截）；不恢复标准/计划/自主菜单。
- **批准卡**：宿主要问用户的事（高危操作、写入项目之外、工具同意）统一用输入框上方的内嵌批准卡片，不用原生弹窗。卡片与输入框、排队栈同一栏（`--w-stream` 同宽居中），是这一栏里唯一带完整边框的块（1px、`--r-md`），高危时边框与底色取警示色，不用侧边色条。卡片一次显示最早一条，其余计数排队；卡片没有「点外面关闭」，Esc 等同拒绝。批准卡显示来源会话、子 Agent/模型及目录，可查看已识别的来源；无法识别时明确显示未知，不猜测为当前会话。底栏「等待批准」表示有请求待用户处理，提示其他任务仍可能运行。
- **模型菜单**：主会话与子 Agent 共用可搜索、可收藏、按供应商筛选的连续滚动列表；同供应商、同系列按模型版本从新到旧排列，不将当前模型置顶打乱顺序。筛选不切换实际模型，收藏不关闭菜单。当前模型以行首强调色对勾和浅强调底标记，每个模型一行：左侧模型名称，右侧以「·」分隔的简短信息（更小号淡色）——未按供应商筛选时显示供应商，另有上下文容量与已声明的图像能力；推理能力由下方档位表达，不在行内重复，完整 ID 放在悬停提示中；未就绪/未配置用警示色字。选择与收藏星同在一行、共用整行悬停底，按钮自身不另画底色，未收藏的星只在悬停或键盘落点时出现；筛选行左侧为全部/收藏，右侧为模型计数和供应商菜单。鼠标悬停与键盘共用一个落点，列表里只有落点行与当前模型有底色。名称已含容量（如「1M」）时不再重复容量。收藏页显示全部收藏，不受供应商筛选（筛选菜单此时禁用）。供应商顺序可在供应商菜单里拖动或 Alt+↑/↓ 调整，存为本地设置，菜单与「全部」列表都按此顺序分组。未就绪收藏保留但不能选。模型搜索整行就是输入框，聚焦时只亮放大镜与底线；键盘落点行用 `--bg-3` 底，不画描边。
  - 新会话采用上次成功选择的主模型，旧会话保留自己的模型；子 Agent 独立记住上次选择，首次采用当前主模型，保留明确的跟随选项。偏好存在本地桌面设置，切换成功才更新记录并关闭，失败留在菜单显示原因，不自动回退其他模型。上次模型不可用导致新会话初始化失败时，明确显示清除偏好并按 pi 默认重新连接的操作，须用户主动点击。
  - 菜单从输入框向上弹出，通过 portal 放在独立浮层，避免侧栏与会话容器遮挡；高度取三者最小：触发器上方到标题栏之间（留 8px）、窗口高度的 72%、680px；可用高度不足 480px 时进入紧凑排版。浮层持续跟随触发器及视口布局变化，最大化、全屏与恢复窗口后重新定位并夹在可用视口内。
  - 回复详细程度与可视化回答各占一行：名称在左用与「思考强度」相同的标题样式，控件在右——详细程度为小号三段分段（简洁/标准/详细），可视化回答为开关；两行同高（`--ctl-h-lg`）。说明只放在标题悬停提示里，菜单内不常驻说明文字。
- **思考强度滑块** `<StepSlider>`，视觉语言是「神经脉冲」：轨道是画布绘制的五行方点阵（5px 间距、2px 方点），已点亮部分沿整条轨道取档位连续色（相邻 `--think-*` 之间插值，无硬切），未点亮为 `--bg-4` 暗点。七档色是冷→暖的温度色阶：关/轻度为中性灰与灰蓝，低为青，中为天蓝，高为鸢尾紫，极高为兰紫，最高为红；浅色主题用同一色阶压暗，文字对比 ≥4.5:1（令牌在 `motion.css`）。拖动时手柄上方不显示气泡，菜单头部的当前档位实时跟随手柄（文字淡入切换、颜色过渡），松手才真正切档。档位名：关、最低、低、中、高、极高、Max，与 pi 的 off…max 一一对应。菜单打开时，填充前沿从最左「充能」到当前档；之后亮脉冲沿点行从左向右跑过，头部最亮、拖尾渐暗，档位越高脉冲越密、越快、拖尾越长，最高两档会分叉到相邻行，「关」没有脉冲。切档时填充前沿以轻微欠阻尼的弹簧追到新档（略冲过再回落），同时从新档位向左回灌一束脉冲。它表达强度预览，不能用于表示模型正在运行。手柄是当前档位色的块光标（10×26，柔光），位置跟随画布的弹簧前沿，静止时按终端光标节拍（1.06s `step-end`）在亮与半暗之间跳四次后常亮（闪烁不超过 5 秒），悬停暂停闪烁并略放大，拖动时放大，键盘聚焦显示同色双环。档位名在轨道下方，当前档为档位色文字加同色浅底。可拖动、点击轨道或档位名跳档，方向键/Home/End 调整。画布只在菜单打开时绘制，页面隐藏时停帧，换主题即重新取色；禁用时点阵静止、不闪烁；减少动态偏好下只画静态点阵，不充能、不脉冲、不闪烁。当前模型只有「关」一档时，思考区不隐藏：头部写「不支持」，下面一句说明原因（模型配置没有声明能思考）；砚管理的自定义服务另给一个「去设置」幽灵按钮。思考当前值前保留同色小块光标，与手柄同语言。
- **上下文圆环**：上下文占用由输入框右下的圆环 `<MiniRing>` 显示百分比（≥85% 黄、≥95% 红）。点开为「上下文窗口」浮层：首行左侧标题、右侧 `已用 / 窗口 (百分比)`；下面一条 6px 分段条，按类别着色，剩余部分为底色；再下是图例行（色块 · 类别 · token · 百分比，数字右对齐等宽）。类别为系统提示与工具（含压缩摘要，取总量减去消息估算）、用户消息、回复、思考、工具调用与结果、剩余空间；pi 只报告总量，分类按当前消息文本估算并在底部注明「分类为估算」，总量缺失时只显示总条。窗口分母优先取与当前会话模型归属匹配的 pi 原生上下文快照，尚未报告时才用选中模型的声明窗口；虚拟模型路由到物理模型后不继续用虚拟声明放大可用空间。图例下是上次压缩、自动压缩开关与「压缩」按钮；正在执行或压缩时禁止重复发起手动压缩。未知用量显示未知，不把历史日志长度当作模型用量。

### 4.5 状态栏

`shell/StatusBar.tsx`：窗口底部 24px 横贯全宽，`--bg-1` 底，顶部一条 `--border-soft`，11px `--fg-mute`、表格数字（状态词与标签用界面字体，数值与花费用等宽 `--font-mono`，方向 F）。只放运行状态、连接、分支与改动、额度与本会话花费。

- 左段是**全局状态**：模式状态词 `空闲 / 运行中 / 等待批准`（宽度随语言自适应，颜色 240ms 过渡、文字交叉淡变；运行中为强调色文字，等待批准为警告色，空闲为 `--fg-mute`，不再画实底色块）· 分支与改动数 · 内核连接（状态点 + 状态词，不写 pi；点开的详情里才说明内核是 pi）· 运行中的子 Agent 数 · 手机配对。
- 右段先是**会话统计与用量**（单会话时；分屏时它回到焦点磁贴的输入框下方，见 4.4），点开是它自己的浮层、不参与状态栏的详情；接着是**额度**：当前模型各窗口的百分比与迷你条（如「5h 16% · 周 21%」），点开为额度浮层（4.7）。
- 最右是**本会话花费**「本会话 $x」：pi 没有报价的模型（订阅制、自写服务，如 Command Code 上的 DeepSeek / Kimi / GLM）按随包模型目录的公开 API 价估算，数字前带 ≈，详情浮层另列「其中估算部分」；目录里也没有标价的模型仍记 0，不猜。花费详情明确标题为「本会话用量」，输入、输出与缓存字段采用当前会话累计口径，不混入本轮值；输入区另提供会话计时与 Token 明细。流式期间不编造速度，有请求没报用量时累计值前标 `≥`；费用尚未加载时显示「—」，不能把缺失当成 0；服务返回 0 且会话已有 Token 时，注明「服务报零或未提供报价」，不把它宣称为真实免费或补造价格。
- 每一段可聚焦，可点击的段是 `role="button"` 并带 `aria-expanded`，点开为 `.ui-detail-popover` 详情，悬停或聚焦给出完整说明。没有数据时隐藏该段，不铺一排占位符。窄窗时从右往左按优先级隐藏（容器查询）：先花费（≤1100px），再手机、内核连接与会话统计（≤980px）。
- 不重复别处已有的信息：模型与思考档位留在输入框内，上下文占用是输入框里的圆环；会话统计与用量每屏只有一处（4.4）。

### 4.6 工作区磁贴与分屏

主会话、任务、日志、文件、浏览器、终端与账号额度使用同一个应用内磁贴工作区。工具首次打开在主会话右侧；主会话可以移到中间，内容区支持左右分列、上下分区，不设置固定列数上限。主会话保持独立，不可隐藏或合入工具标签。

- **磁贴外观**：主会话是主要内容，不画卡片——它的磁贴没有底色和描边，与工作区背景融为一体，只保留顶部一条拖动把手（悬停加深，键盘聚焦后 Enter 打开移动菜单）。工具磁贴是一张圆角卡片（`--r-lg`、`--bg-1` 底、柔和描边），卡片之间与工作区边缘留 8px 缝隙，缝隙本身就是分隔线，悬停或聚焦时显示强调色细线。工具磁贴只有一行 28px 标题（标签与按钮 22px）：左侧为标签（资源可新建时标签后跟 `+`），右侧只有一个「收起」；不另放移动图标，拖动从标签或标题留白开始，双击标题留白放大/还原。面板菜单（移动到左右上下、合组、放大、资源自身操作如新建或结束终端、收起）在标签或标题上右键打开，键盘用菜单键或 Shift+F10。可关闭的资源（终端）在标签上带 ×：选中标签常显，其余悬停或聚焦时显示，点 × 结束该资源而非仅收起。终端标签按顺序命名为「终端 1」「终端 2」，不带图标，shell 与目录放在悬停提示里。磁贴正文不再重复资源标题行，只保留状态提示与内容自有工具条；文件磁贴的标签就是文件名，标签上的 × 关闭文件，标题右侧的 × 只收起磁贴，正文头只放阅读/源码与文件操作，路径行只给所在目录；文件磁贴的目录列表使用全部剩余高度，仅在磁贴内部滚动。打开工具和调整排列的入口位于应用标题栏右侧，菜单统一使用 `<Menu>`，贴着触发按钮弹出。
- **项目与环境菜单**（会话头）：顶部是项目卡（文件夹图标块、项目名、等宽完整路径一行省略，右侧「打开」「复制」），其下按组以细线分隔：变更（十格方点表示改动量，已跟踪为警示色、未跟踪半亮）与分支｜拉取、推送并排一行（推送只写 `↑n`，完整说明在悬停提示）｜工作树、Pull Request、网页比较｜来源。分支名、路径、数字用等宽；菜单从触发器下方落下，各组依次落位。来源区的副本目录只在有图片时出现，「移除」说明只在有条目时出现。
- **拖动**：拖动标题留白、标签或主会话把手时实时重排：被拖磁贴保持原尺寸与抓取点，整张卡片（含内容）浮起跟随指针，带阴影与顶部把手条；其余磁贴按当前落点以约 200ms 过渡让出位置，松手后的落点显示为强调色虚线占位框；放到另一块磁贴的左右时其余磁贴实时让位，放到上方或下方时其余磁贴不动，只用强调色边框标出新磁贴将占的那一半；被拖磁贴可跟随指针移出画布，超出部分裁掉，不撑大滚动区；落下时保留它被拖起时的尺寸；松手或取消后卡片滑入落点或原位。落点判定基于「拿掉被拖面板后」的排列且整个拖动期间不变，避免磁贴移动后目标来回跳动。边缘形成分区，中央合入工具标签组。预览不写入保存的布局，松手到有效位置才提交，Esc、失焦或无效位置恢复原排列；拖动期间隐藏分隔线，终端在尺寸稳定后才调整 PTY 行列。标签可以拆分；同一资源只挂载一次，移动、合组、放大或隐藏不新建 PTY、网页或 Agent。隐藏与停止分开，停止仍由内容组件明确提供。
- **尺寸**：工作区宽高变化（左栏展开收起、窗口缩放）时，主会话旁的工具磁贴保持用户最后一次排列时的像素宽高，只有主会话伸缩；主会话到最小宽度后工具磁贴才让出空间。布局记录排列时的画布尺寸（`basis`），每次拖动、调整分隔线、打开或移动磁贴都以屏幕上的当前排列为新基准；工具与工具之间仍按比例分配。分隔线可拖动调宽高，也可聚焦后用方向键调整；移动菜单提供左右上下移动及合组选项。布局按稳定会话保存，仅保存资源引用、组、分区比例、活动标签和隐藏/放大状态。恢复默认排列只改变摆放，不清空资源。窄窗以可滚动的工作区保留最小阅读尺寸，放大当前面板可专注操作；窗口恢复后继续使用原比例。
- **过渡**：分屏新列淡入，关闭先淡出；工具磁贴打开或重新显示淡入，浮动磁贴从中心落位。原生浏览器视图不做位移；主会话磁贴与焦点换块保持即时，避免闪烁。
- **原生层**：布局调整与菜单使用现有原生浏览器遮挡协调器；浏览器坐标持续同步，PTY 按可见尺寸调整。唯一的内置浏览器绑定打开它的会话，与终端/文件预览一样留在所属列，不随焦点转移；所属会话不在当前视图时只隐藏网页，切回恢复；关闭浏览器后释放归属，下次打开绑定新的会话。
- **文件预览**：打开的文件预览标签封顶 12 个（`state/store.ts` 的 `FILE_TAB_LIMIT`）：超出时自动关掉最早打开的那一个（当前正在看的永远保留），并交还它的资源归属。
- **终端状态**：仅在程序主动上报时，在终端标签旁显示短文字徽标：运行中、等待批准/回答/登录、完成、出错、空闲；运行时可带0–100%进度，完整短标题放在标签提示中。复用统一徽标的强调/警告/完成/错误语义，文字不依赖颜色。没有上报不把存活的Shell伪装成正在运行；退出移除运行/等待但保留已报告完成或错误，关闭不留下旧状态。只取根记录，不将提示词和模型正文放进状态。
- **终端**：普通终端共用渲染配置：解析后的代码字体、13px 字号、1.15 行高、零额外字距。字体加载后才建立字符网格，避免 Canvas 测量与 DOM 字体不一致；窗口尺寸同步给真实 PTY，主题随深浅色切换。优先使用 WebGL 与连续块字符/框线绘制；GPU 不可用或上下文丢失时回退默认渲染器。提供可访问的终端文本树，屏幕阅读与运行验收不依赖画布像素反推。
- **分屏**（参考 Claude Code 的多会话布局，最多 5 块）：在左栏按住 Ctrl 点击会话，或会话菜单「在旁边分屏打开」，新会话作为一列追加到最右。每一列是一条会话自己的工作区：会话加它旁边的工具（终端、文件预览、子代理等），排布按这条会话保存，与单会话时看到的同一份；工具只能在自己那一列里挪动，不能拖到别的会话。各列等宽，每列至少是自己的会话加工具所需的宽度（会话至少 340px），放不下时整排横向滚动，不压扁。已满 5 块时再打开会挤掉离落点最近、没有焦点的一块。磁贴按从左到右的顺序各绑一条会话，位置固定、不随焦点交换。分屏时会话头从窗口标题栏移到各自磁贴上方：焦点一块是完整会话头，其余是同位置的标题（`--fg-dim`）加项目标签，每块右端都有关闭这一块；标题栏只留品牌与窗口控件。每一块都是完整的会话外观：正文加同样高度的输入框，焦点切换时版面不跳。焦点那一块是活动会话，输入框可用；其余各块的输入框显示这条会话的草稿或占位文字（运行中 / 等你回答写在底栏），外观与真输入框同尺寸。非焦点的块盖一层淡遮罩（`--split-dim`，深浅各一值，会话头不盖），悬停时变浅；遮罩不拦指针，照样能滚动、拖选文字。在非焦点块上单击（没有拖出选区）切焦点并把光标放进输入框，这一下不交给里面的按钮；焦点换块时遮罩立即换位、不做淡入淡出，只有悬停变浅有过渡。焦点切换时，失焦的那块继续显示它刚才的内容与滚动位置，新焦点那块先用已显示的内容铺上，不出现空白或旧会话内容；各块按「视口顶端所在回合 + 偏移」恢复阅读位置。非焦点那块与焦点时版面一致：同样有导航轨（正文让位量相同，不横移），内容取它在焦点时屏幕上的那份（含只推给活动会话的成果卡片），失焦后又跑过才改用运行缓存。从左栏单击会话（单会话或分屏）后同样把光标放进输入框。从左栏点别的会话替换焦点那一块。关掉焦点那一块时焦点先去右邻（没有就左邻）；关到只剩一块回到单会话。终端与文件预览属于开出它的那条会话（`state/resource-owners.ts`，没登记过的归给当时正在看的会话），只显示在它那一列；单会话时切到别的会话也不跟过去。读当前会话的工具（任务、日志、账号额度、文件树）只在焦点那一列显示；非焦点列的工具同样盖淡遮罩，点它先切焦点，这一下照常交给工具（光标留在工具里）。打开工具、整理排布的请求只由焦点那一列响应。每两列之间是一道 2px 的分隔条（`--border-str`，`.ui-splitter`，两侧各外扩 4px 好抓）：拖它只在相邻两列之间分宽度（每列不窄于 340px），左右方向键每次 24px，双击回到等宽；宽度按份额记，窗口变化时各列按比例跟着变。列与窗口右缘只留 2px，列与列之间两侧各 4px。左栏里分屏打开着的会话行铺 `--bg-2` 底色，焦点那条照常是选中行（`--bg-3`）。**从左栏拖会话**进工作区时，每块磁贴盖上左、右两个落点，指针所在的那一个高亮，松手插到那里：落在第 i 块的左半 = 插到它前面，右半 = 插到它后面；没分屏时主会话的左、右半就是最左、最右；拖的会话已在分屏里则挪到落点而不是重复开，焦点跟着会话走。长会话（虚拟列表）搬到新磁贴时，原来停在底部的仍停在底部，列表若挂载后一格都没画出来会自动重挂一次。状态在 `state/split-view.ts`（`tiles` + `live`，纯函数 `placeInSplit` / `removeSplitTile`），每列是一个 `Workspace`（`fit`），会话窗格 id 都是 `chat`，列上标 `data-split-column`（从 0 起，左起）；各列刚显示的内容与滚动位置在 `state/split-snapshots.ts`。

### 4.7 额度与长任务

- **额度浮层**（状态栏打开）：首行为标题、供应商与刷新图标，每个窗口一行「标签 … 百分比」（百分比用大号等宽字），下接 4px 进度条和一行暗色「已用 / 总额 · 重置时间」，窗口之间留白而不画分隔线，底部一行暗色「更新于」。窗口百分比取接口字段；月窗口没有官方字段时，分母由周额度反推、分子由剩余额度换回，行内标「推算」，悬停写明「本月上限由周额度反推（接口没有官方月额度字段），不是官方精确值」，不把推算值当官方值。没有旧数据时不写「下面显示的是上次成功的数据」；查询失败而有上次成功结果时显示旧数字并注明时间。查询失败（含 Promise 直接失败、supported 尚未返回）、接口未返回窗口或凭证缺失时，额度段仍要留下并写明原因，不得整段消失；只有明确不支持额度接口的自定义 API 不占位。状态栏摘要没有数字时，悬停提示写明查询失败原因，别让「—」无从解释。浮层使用 `.ui-detail-popover`，从触发处向上弹出，Esc 或点外部关闭。
- **长任务**：额度浮层底部是「长任务」一节（有当前会话才显示，只作用于当前会话、只存在本次运行内存，默认都关），每项一行「暗色标签 … `<Switch>`」：「额度用尽自动换号」只在 ChatGPT 订阅且保存了两个以上账号时出现，等同于提前点好错误行上的「换账号续跑」；「持续运行」在回合正常结束后自动发一句继续，开启时下方暗色小字写「已自动继续 N 次」。持续运行遇到以下任一情况自己关闭并用一条提示说明原因：回复最后一行是完成标记、本回合没有调用任何工具、连续自动继续达到上限、用户点停止；回合以错误结束时不发继续（额度类错误交给换号 / 等待恢复）。后台会话不生效，只看前台焦点会话。
- **账号额度磁贴**：状态栏的额度只回答「当前模型还剩多少」；「账号额度」磁贴回答「我所有账号各剩多少」，从「打开工作区工具」菜单打开。正文是账号列表，每个账号一块，块与块之间留白不画框：首行为供应商字母标识、名称（有备注显示备注，否则显示邮箱或供应商名）、`使用中` 徽标（强调色，只给正在被砚使用的 ChatGPT 账号）与行尾操作；第二行暗色写邮箱 · 套餐 · 来源（来源只在非砚账号上出现，如「Codex CLI」）。其下沿用额度浮层的窗口语言；余额类账号只写一行「标签 … 金额」。备注用行尾铅笔按钮就地编辑（单行输入框，回车保存、Esc 取消，清空即恢复默认名）。砚的 ChatGPT 账号可切换：非当前账号的行尾有「切换」按钮，切换在当前回合结束后生效，不另做确认框；「移除」只在编辑备注时出现在输入框旁（危险按钮，需确认）。列表底部一行是「添加 ChatGPT 账号」次要按钮，登录进行中显示等待与取消。本机 CLI 账号（Codex CLI、Claude Code、Gemini CLI）是可选来源，默认关闭，开关收在列表末尾的「本机 CLI 账号」折叠项里；这些账号只读，不提供切换，令牌过期时写一句暗色提示说明去哪个 CLI 刷新。查询失败就地显示一行错误，保留上次成功的数字并注明时间。磁贴标题行不放额外按钮，刷新在正文顶部一行「更新于 … · 刷新图标」。
- **任务与日志磁贴**：「任务」磁贴放目标、任务清单与待投递队列，「日志」磁贴放扩展状态与日志，二者从「打开工作区工具」菜单按需打开，状态栏的「打开任务」直接打开任务磁贴。

## 5. 弹出层：设置、对话框、引导

- 遮罩：深色 `rgba(0,0,0,.5)`、浅色 `rgba(20,20,18,.28)`，2px 模糊。面板：`--r-xl`，`--border-soft` 描边，`--shadow-pop`。
- Esc 只关闭最上层；焦点圈定只在最上层生效；关闭后焦点回到打开它的元素。弹出期间领 overlay blocker，让原生网页视图让位。
- **设置**：左导航 `--bg-1`，内容区 `--bg-0`。导航依次为模型、外观与输入、会话、能力与插件、插件市场、语音与设备、关于；旧入口映射到对应合并页。导航项 32px 高，选中为 `--bg-3` 底 + 强调色图标，不画框。内容区顶部有 18px 页标题；用 `<SettingGroup>` 组织同类设置，以 `<Disclosure>` 收纳低频与诊断项。布尔项用 `<Switch>`，说明压到一句；一眼能懂的选项不写说明，依赖其他开关的选项在前置开关开启后才出现。打开时焦点落在当前页的导航项上。
  - **页内主题切换**（2026-10-12）：长页不把多个完整表单纵向堆叠：模型分订阅/API Key/自定义服务；外观与输入分外观/输入/提醒；会话分常规/上下文；设备分语音/手机/其他电脑；能力分常规/搜索与浏览器/MCP 与技能。复用公共 Tabs，首次访问才挂载；本次页面内切换保留表单草稿与进行中操作，旧深链接直接选中主题。页面被外部切换时焦点跟到新选中项。
  - **按需加载**：可选设置页面在首次进入时加载。导航、模态遮罩与键盘焦点立即生效；内容加载期间使用公共 Spinner，不改变页面布局。
  - **模型**：服务商接入说明随界面语言显示。Claude 接入按 CC 订阅插件与按量服务明确分组，安装状态与当前会话已加载分开。
  - **能力与插件**：能力列表只显示短说明，全文按需查看。在 pi 实际提供 `/mcp` 命令时显示原生服务器状态入口，点击后留在设置页，将原生 `/mcp` 的 RPC 状态通知显示在按钮下方（保留换行）；查询中禁止重复点击，30 秒未收到状态明确提示重试，不退回主页、不自建 MCP 管理循环；既有宿主 MCP 列表标明兼容用途，不自动迁移配置或凭证。「Codemode」开关采用 SettingRow 与 Switch，默认开启；说明只表达批量调用工具与整理结果，以及下一轮对话生效；开启保留普通工具直接调用，关闭同时限制工具声明与实际执行；只读子 Agent 的限制优先；偏好只属于砚，不改写用户的 pi `settings.json`；旧 pi 或显式停用原生 Codemode 扩展时不伪造工具。外部依赖在对应功能旁提供下载、安装或版本来源；「重新检测」只检测本机，不冒充检查新版。

## 6. 动效

关键帧只在 `styles/motion.css` 定义（`npm run check:motion` 拦截模块里的 `@keyframes`、裸时长和裸曲线）。收敛为「一条曲线、三档时长、一个节拍」：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--mo-fast` | 110ms | 退场、按压、悬停、菜单 |
| `--mo-base` | 170ms | 淡入、浮层入场、图标切换、tab 内容淡入 |
| `--mo-slow` | 240ms | 展开、滑块、色阶变化、对话框与设置入场 |
| `--mo-ease` | `cubic-bezier(.22,1,.36,1)` | 所有入场与位移：快进慢停 |
| `--mo-ease-out` | `cubic-bezier(.4,0,1,1)` | 退场：干脆 |
| `--mo-loop` | `cubic-bezier(.45,0,.55,1)` | 只给运行中的循环（呼吸、脉冲） |
| `--dur` / `--ease` | 120ms / 标准曲线 | 悬停、颜色、边框过渡 |
| 错峰 | 60ms | 列表、diff 行、流式新块（上限 8） |
| 字符节奏 | 输入 30ms/字 · 流式正文 20ms/字 | 只用于演示与引导，不人为拖慢真实输出 |

规则：

- 只保留一个主要运行信号（回合活动行），其余用短过渡。
- 入场与退场成对（`usePresence` 延迟卸载），退场更快、位移更小。
- 位移不超过 4px（`--mo-shift`），缩放不小于 0.965；不做弹跳或弹性动画。
- **浮层从触发点长出**（方向 F）：菜单与弹出层以触发器所在角为 `transform-origin`，`scale(.97) → 1` + 淡入（`--mo-slow` 位移、`--mo-base` 透明度），收起反向且更快；缩放下限仍 ≥ 0.965，不回弹。锚点定位的浮层由 `useAnchoredPopover` 按实际落点写 `transformOrigin`（向上弹取底缘、向下弹取顶缘；对齐触发器哪一侧就取哪一侧）。
- **新内容整段到达**（方向 F）：流式回复中新出现的**顶层块**（段落、列表、引用、标题、代码块）整块淡入并上移 3px（复用 `mo-item-in` 的 `from`，`--mo-base`），块间错峰 60ms、上限 8（第 9 块起并入最后一档）。只在 `live` 流式消息上生效：历史回放、会话恢复、压缩重放与同一回合里已有的块都不重播；块身份取 Markdown 解析出的起始偏移，不伪造消息 id、不按时间猜。根级标记避免引用、列表内的段落重复位移；首次挂载已有块建立基线，切回正在输出的会话不补播，之后新追加的块才入场。跨 token 不重播；表格结构特殊，不动画。`prefers-reduced-motion` / 关闭动效时不位移、不错峰。
- **列表增删**（方向 F）：新增行用 `grow` 长出、删除反向收起，只对**带稳定 id** 的列表生效；排序变化与文字更新不动画（身份不变就不重播）。退场行只保留 DOM 投影：`inert` + `aria-hidden`，不可点、不进 Tab 顺序；卸载或换作用域时清计时器与退场快照（纯呈现辅助，不复制任务数据源或状态机）。首个覆盖列表是右栏任务区的**历史任务清单**（快照自带稳定 `id`）；任务本体只有 `text/done/status`、没有稳定 id，本轮不为它伪造身份、不动画。
- 会变化的都要有过渡（左栏行、分屏列、工具磁贴见第 4 节），只用透明度与 ≤4px 位移；原生浏览器视图不做位移。
- 按钮、分段、图标按钮按下时有 `mo-press` 反馈。
- 状态循环动画只挂在**真实运行**上（活动行旋转字符、运行中的工具行），结束立即停止，且不能是唯一的状态信息。思考滑块在菜单打开时的脉冲与块光标闪烁是强度预览例外，与运行状态动画分开。
- 整屏动效只有两处：主题切换（View Transition，圆心为触发按钮）与启动画面（§3.4.1）。主题切换时根元素上的令牌必须**同一刻**落：背景色（模板 / 自定义）是行内令牌、会盖过主题里的默认值，早于旧快照或晚于新快照都会让某一层带上另一个主题的底色（表现是切换瞬间闪过一块不对的浅色）。
- `prefers-reduced-motion: reduce` 下时长压到 1ms、只播一次（保留终态，不删除动画，以免延迟卸载出现空窗）；全局规则在 `tokens.css`。

基础件，关键帧与类在 `motion.css`（`.ui-grow` / `.ui-spin` / `.ui-caret` / `.ui-orbit` / `.seg.sliding` / `.md-arrive`），组件在 `components/ui`（`Grow` / `Spinner` / `Caret` / `Segmented` / `PresenceList`）：

- **展开** `grow`：新块 `grid-template-rows: 0fr → 1fr` 同步透明度，旧内容被连续推开，不跳。
- **方点阵** `spin`：10×10px、3×3 方点，亮点沿外圈转、带一格尾迹，0.8s 一圈；只用于加载占位。
- **光标** `caret`：2px 宽、1.2em 高；输入时常亮，停下后 1.06s `step-end` 闪烁。
- **环绕流光** `orbit`：`@property --ang` + `conic-gradient` 边框，经 mask 只露 1px 边。方向 E 已从输入框取消，基础件保留，新用途须先写进本节。
- **分段滑块**：选中底块 `translateX` 滑动。
- **状态交叉淡变**：状态栏模式词颜色 240ms 过渡，文字叠放交叉淡变，宽度随语言自适应（方向 F 起用中文状态词，不再画模式色块）。

**同一时钟原则**：运行中的各处（活动行、工具行、任务、上下文、改动、终端、状态栏）都从同一条运行事件流推导状态，不各自计时，因此动效始终同拍。

## 7. 手机端（Android）

手机端（`mobile/`，React Native）是同一产品的另一个入口，定位为连接电脑，不是另一套设计。它与桌面共享语义、配色和图标，差异只在触控尺寸、字号和导航方式。

- **令牌同源**：`mobile/src/theme.ts` 的色值与 `tokens.css` 同名同值（`bg0` ↔ `--bg-0` 等），`npm run check:mobile-tokens` 比对，不一致即失败。圆角 3/4/6/8。
- **尺寸**：触控目标不小于 44dp；按钮 44dp、紧凑按钮 36dp；字号 12 / 13 / 15 / 16 / 18 / 22；间距沿用桌面刻度。
- **字体**：暂不内嵌 Maple Mono CN（全量 18 MB）；正文与按钮用系统字体，活动行、元数据、字符状态、地址、配对码与代码用系统等宽。字重一律常规。分区标题为淡色等宽，不带 `## ` 前缀（与桌面 h3 一致）。
- **会话**：用户消息无框，只留强调色 `›`；一段工具调用是一行**活动行**（⠋ 运行 / ✓ 完成 / ✕ 部分失败，右侧「过程 ›」），点开为 `├─ └─` 调用树；整屏只留一个运行旋转，输入区上方的活动行只在最后一段不是过程时出现（待回答 ◆、断线 ●）；列表行首字符状态（● 运行或未读、◆ 等待）。输入框抬起为 `--bg-2`，输入区与底栏去掉顶部分隔线，错误条左侧 2px 错误色线。
- **状态用语**：没有底部状态栏；用词与桌面状态栏一致（运行中 / 等你回答 / 已连接 / 重新连接中，`STATUS_TEXT`），系统通知同样用这组词。
- **图标**：使用同一份 `catalog.json` 生成物与语义名；尺寸只用 `icon.sm/md/lg` = 16 / 20 / 24dp（随文字 16、按钮与行首 20、页面级 24），描边 1.5dp。系统通知的小图标是砚标志的单色简化字形（`ic_stat_inkstone`，为 24dp 重画），标题着浅色强调色。
- **应用图标**：与桌面同一块砖形图标（§3.4.1）——启动器普通、圆形与自适应图标，以及首页品牌角标，都是 `#151515` 底 + 浅色开口石框 + 强调色 `>_`。`mobile` 下 `npm run icons:launcher` 生成密度位图，APK 构建时同步生成。
- **动效**：沿用 `--mo-fast/base/slow` 与 `--mo-ease` 的数值，位移不超过 4dp；遵循系统「减少动画」。
- **控件**：`mobile/src/ui.tsx` 的 `Button`（含 36dp 紧凑档）/ `IconButton` / `Badge` / `EmptyState` / `Header` / `SectionTitle` / `Meta` / `Input` / `RunBar` / `StatusDot` 与桌面同名同义，`Spinner` 在 `motion.tsx`；页面不自建按钮、输入框、徽标或状态行外观。
- 深浅主题跟随系统；宽屏与折叠屏双栏时，列表与详情的层级与桌面左栏 / 中栏一致。
- 等待模型响应与真实内容分别显示，不用逐字动画模拟模型输出；没有实际能力的功能不放占位按钮。

## 9. 可访问性、键盘与可靠交互

- 所有控件可 Tab 到达；全局 `:focus-visible` 为 1px 强调色环（`--focus-ring-*` 令牌），小目标用 2px（`--focus-ring-w-strong`）。
- 禁用统一 `--ctl-disabled-opacity`（0.5）；更低的透明度只表示「过期 / 半失效」。例外：发送键的禁用态用中性底（`--bg-3` + `--fg-mute`），不用透明度，免得浅色主题里与可发送态难分。
- 图标按钮必须有无障碍名称；分段项用 `aria-pressed`，tab 用 `role="tab"` + `aria-selected`。纯图标按钮的说明用 `<Tip>`（§3.3），键盘聚焦也读得到，不只依赖原生 `title`。
- 元数据淡显不能让信息只在悬停时可得：聚焦同样让它完全显现。状态栏各段同理。
- 手机端控件提供 `accessibilityLabel` 与 `accessibilityRole`，不只靠颜色或图标传达状态。
- **可靠交互**：既有破坏性动作（删除、清空、丢弃）执行前确认；加载/保存/配对/登录的失败应就地反馈并释放 busy，成功重试清旧错误，迟到响应不得覆盖新项目/会话或新草稿。卸载、取消与失焦清理监听/计时器；可操作控件支持键盘与读屏，无动作的容器不伪装成按钮。空数据/零值图形显示空态，不产生 NaN/Infinity；错误提示沿用现有控件与语言，不增加新页面。
- **确认框**：破坏性动作的确认统一用应用内对话框（`ConfirmDialog` / `useConfirm`），不再用系统原生 `window.confirm`。标题一句话说后果，对象（路径、名称、消息片段）单独放等宽、可换行、可选中复制的正文块；危险动作的确认按钮用错误色。取消按钮在 DOM 焦点顺序首位并初始聚焦，Enter 只触发当前焦点，Esc 与点遮罩取消。多个确认请求排队串行处理；组件卸载、会话切换或整队列取消时，未决请求按「未确认」结算，不给未来留下可批准旧操作。
- **错误恢复**：发送/排队失败时保留或恢复未发送文字与附件，不重复引用，不丢等待期间新增的草稿；工作树创建失败在原菜单内反馈原因，不静默关闭。拖拽取消或卸载释放监听与指针捕获；终端暂时启动失败在恢复可用后可重新初始化，不视为模块永久不可用。附件清理遇到历史损坏、读取失败、运行中的会话或扫描期间的变化时停止删除并给出可重试原因，失败展示脱敏原因和重试说明。办公预览保留已有文字视图；超过文字预算显示截断，超过解压预算、并发上限或超时显示原因并建议稍后重试或使用系统程序。闲置历史缓存回收不改变当前/可见分屏内容、输入草稿、待答问题及滚动位置；重新打开时以持久历史和 pi 同步为准。

## 10. 升级规范的流程

1. **先改规范再改代码。** 新令牌或控件变体先在本文写清用途与边界，再改 `tokens.css` / `ui.css`（手机端同步 `theme.ts` / `ui.tsx`）。
2. **写进对应章节。** 新规则放进第 1–9 节对应位置，替换被推翻的旧说法；不在文首按日期追加，不保留两套并行的说法。界面退出默认流程时，把它的规则移到附录。
3. **新增控件先问能否复用。** 能用 `.btn` / `.seg` / `.ui-badge` / `.ui-empty` 表达的，不新建类；需要新变体时加在 `ui.css`，并补到第 3 节。
4. **模块 CSS 只管版面。** 发现模块里重写控件外观时，改成 `className="btn …"` 或组件，再删掉旧规则。新样式文件在 `styles/index.css` 登记并放进所属的层：后面的层整体压过前面的层，与特异性无关；`!important` 反过来，前层优先。间距、圆角、字号、字重有同值令牌时写令牌，不写裸值（`npm run check:css-budget` 只许散落值下降）。样式删减必须证明无引用或全属性被覆盖，部分冗余不机械删除；层叠模拟零差异不代替截图。
5. **检查。** `npm run typecheck`（含 CSS 布局检查）→ `npm run check:motion` → `npm run check:icons` → `npm run check:css-budget` → `npm run check:mobile-tokens` → `npm run measure:css` 更新 CSS 清单 → 结构性改动再用 `YAN_STYLE_DUMP=1` 跑视觉矩阵，`node scripts/css-computed-diff.mjs` 比较前后逐元素计算样式 → 视觉矩阵截图（深浅主题 × 1440×900 / 940×620 / 900×520）核对；手机端 `mobile/` 下 `npm run typecheck` 与实机截图。视觉结论以截图为准。视觉矩阵的工具组先展开正式过程入口，终端按当前工作区磁贴/页签验证；小部件使用真实 `inkstone-html` 隔离协议，不以 `data:` 或放宽 CSP 制造通过；未验证项不得表述为已支持。

### A.1 Agent Hub 工作台（外部 CLI 协作）

见[多 Agent 工作台](AGENT_HUB.md)。

「Agent 协作」磁贴是协作总览：顶部一行选择项目；其下「命令行 Agent」卡片每行一个 CLI（字母标识 · 名称 · 版本或未安装及包名），已安装的行尾是「打开终端」，一键在所选项目中启动交互终端并在侧边打开；未安装的行尾是「安装」，在一个普通终端磁贴里运行 `npm install -g <包名>`，用户可见全过程，终端结束后自动重新检测，标题行另有手动「重新检测」。再下是「带任务启动」卡片：分段控件选执行方式（交互终端 / 派出子任务 / pi 只读），Agent 选择片（未安装置灰），任务输入框与主按钮。运行列表按「进行中」「需要处理」「已结束」分组，每行为 Agent 标识、标题、方式与相对时间、状态点，点击在侧边打开该运行。没有运行时显示简短空状态。单个运行磁贴的顶部是一行状态条（状态、Agent、协作与审批入口），其下是终端或过程对话。

受管运行的磁贴是对话视图：第一条是派活指令（右对齐浅底气泡，标注来源「你」或「来自 砚主会话」，带上的未提交改动与附件以徽标、文件片显示）；其后按时间排列 Agent 叙述（复用主会话 Markdown）、工具行（可折叠，运行中展开，显示完成/失败）、改动卡片（文件名、+/− 行数、红删绿加 diff）、交接包（左侧强调色竖线，「来自 砚主会话 · 交接包」与投递徽标）、发回主会话的回报（虚线框「回报给 砚主会话」）；待答复的审批固定在末尾，黄色卡片就地批准或拒绝，问题类跳到审批与成果。路径一律显示为项目相对路径。底部是补充要求输入框，左侧「＋」添加附件，也可粘贴或拖入，待发送附件显示在输入框上方。交互终端运行仍显示原生终端。总览顶部在项目下方说明主工作区状态：有未提交改动时显示数量与「带上未提交改动」开关，非 Git 项目给出提示；运行结束后状态条提供「清理工作区」。

子 Agent 与外部 CLI 使用同一个「Agent 协作」入口。子任务是父会话/父运行的派活关系，不是另一套工作台。对话中的任务卡可打开侧边同一运行详情；旧任务保留原身份、转录、停止和补丁审阅，界面只做投影，不复制运行状态。终端运行使用一行标签栏，结构化运行展示真实过程，不模拟终端。补充要求与协作记录按需打开，正常电脑输入不常驻显示输入端。

协作关联由当前会话明确建立，同项目不等于已关联。主 Agent 可查询和联系自己的协作运行，外部运行可向其父任务或关联主会话回报；消息记录来源、目标运行及投递状态，旧运行消息不得投到新的执行尝试。终端协作消息先排队，由持有输入权的用户核对输入行后发送，不能自动粘贴并回车覆盖人工输入。协议接收与已写入终端均不表示模型已处理。成果验收与应用补丁使用不同操作。

检视器中的入口使用带 Agent 图标与进入箭头的整行按钮，与工具区对齐。工作台默认展示内嵌的真实 CLI 终端，通过统一分段切换终端/任务；「新增 Agent」展开表单，默认交互终端模式，创建后在有窗口位置时自动打开。重新进入时展示现有运行中的终端；关闭窗口只隐藏显示，不停止运行。模板和模型等可选设置按需展开，任务列表把标题与 Agent/状态分行，避免整页按钮和说明堆叠。窄栏保持单列，所有控件可用键盘操作。

终端工作窗默认用标签切换 CLI，每个标签可隐藏、重新打开；「并排」显示多个终端。终端占据剩余高度，正文不受普通按钮的固定高度约束。新增交互 Agent 只需选择项目和 CLI，初始指令可留空，直接进入原生 CLI。砚不追加受管任务说明；交互终端默认不设任务时长上限，显式指定的时限仍有效。受管执行继续要求任务内容并保留其范围与超时约束。交互终端最多四个同时运行，与受管任务的执行槽分别计数。隐藏标签保留进程，「停止」明确结束运行并释放执行槽。历史工作台兼容控件中，已安装 CLI 的打开按钮直接沿用公共 Button，不额外定义模块私有按钮或 chip 外观。

桌面工具区的「多 Agent」入口进入任务列表、派活表单与运行详情。用户选择现有项目、Agent、受管执行或交互终端以及模型；编码任务从明确的 HEAD 基线创建独立工作区，审查任务选择已冻结的交付成果。任务完成执行后显示「待审阅」，由用户验收；不自动合并。结构化执行和交互终端分别展示覆盖范围，终端静默、退出不表示任务完成。

任务详情在当前报告之后提供「运行历史」：每次运行按时间显示状态、模型、运行身份、外部会话和成果摘要，报告默认收起，由用户按需展开。恢复后的新运行保留旧运行记录；手机复用同一组事实，路径仅在桌面展示。历史内容是审阅依据，不能用旧批准直接执行新运行。派活表单提供用户模板选择、名称、保存和删除。模板仅填写任务内容、Agent、模式与模型偏好；使用模板后仍由用户选择当前项目、核对任务并点击派活，不自动执行，也不携带旧成果、运行、输入权或批准。手机仅在新派活表单显示模板控件。工作台提供「全部任务／待处理」筛选；待处理来自待答复、待审阅、失败与结果待核实的宿主事实。已开启手机待回答提醒时，Hub 待处理事项沿用现有提醒服务，锁屏只显示数量，不展示任务或批准内容；点击进入多 Agent 页面。未开启提醒不自动启用。

Agent 之间可互发**交接包**：交接包只携带参考资料（来源任务、基线、成果 SHA/ tree、摘要与请求），不授予新权限、不自动合并或推送。投递按目标能力降级——受管运行注入成新回合输入，交互终端写入 PTY（bracketed paste）；能力不适用时明确报失败，不假装成功。任务详情按**时间线**显示交接的对象、时间与投递结果（已注入／已写入终端／排队／失败）。同一项目内的活跃任务才可投递；受管运行只能把交接包发给它派出的运行，用户在电脑端可发给同项目任意活跃运行。

工作台提供「窗口」视图：用户可自行增加 agent 窗口，每个窗口一个运行（终端任务显真实画面，受管任务显说明与状态），窗口按自适应网格并排，可随时关闭；同一时刻只有一个窗口持有终端输入权，窗口头部标注当前输入端。两端共用同一套任务、时间线与投递结果，各自按屏幕布局：桌面端窗口用自适应网格并排；手机端窗口纵向堆叠，每张卡片一行头部（名称 · agent · 状态）加内容（终端或说明），最多 3 个。手机端的「窗口」与「任务」用页内切换，不新增底部导航。时间线在两端都按时间倒序，长文可展开、可复制。受管执行没有终端画面的运行卡片要直接说明，不留空白。

Agent 的执行过程以**对话**呈现（Chat View），不把终端原样缩小。对话流由四类条目组成：叙述、工具（Shell／文件／Patch；Patch 显示红删绿加的 diff，可折叠）、审批（就地批准或回答）、交接包（标注来自哪个运行）。受管运行用宿主的结构化事件；纯终端运行显示真实终端画面，不做逐帧解析。对话流底部是对话输入，可发消息或交接包。手机端任务列表用分组卡片（工作中／待处理／已完成），卡片显示标题、你发的指令、agent 与时间。

审批显示所属任务、动作与目标摘要、截止时间；答复已发送与对端已确认分别显示。资源争用显示等待，未知结果显示「待核实」，不能自动重试。桌面和 Android 复用任务事实，手机提供派活、审批、取消、报告与终端输入；终端输入和尺寸由同一控制端持有，接管后拒绝旧端迟到输入。高危 pi 确认沿用电脑确认边界。手机完整控制要求已配对且使用 Tailscale 加密通道或 HTTPS。所有按钮、输入框、下拉框沿用统一控件；任务详情可展开，错误就地显示。布局在窄窗上下排列，不新增资源锁设置管理台。手机采用同样的信息顺序，长报告和终端输出可滚动，输入操作必须显示当前控制端。手机选择任务后收起新任务表单并回到详情顶部，以「新派活」恢复表单。文本终端输入提供明确的「发送」按钮；Enter、Ctrl+C 等快捷键单独作用于终端，不承担输入框的发送语义。

### A.2 文件任务页面

文件任务曾位于「任务」磁贴内，使用现有 Button、Input、Textarea 和检查器分区。创建时显示所选输入与时间/调用预算；输入复制进独立目录，成果提供文本预览、定位与另存/应用入口。应用前在面板内列出目标与版本状态，用户明确批准后执行；冲突与部分完成分别显示。未配置模型时提供配置入口并禁用执行，恢复不明任务需用户明确核实。关闭磁贴不停止任务，关闭整个应用仍按现有退出流程停止执行。独立页面及其专属样式已于 2026-10-09 移除，历史运行详情继续通过兼容入口访问。

### A.3 手机生活助手

手机端生活助手对话与桌面配对入口曾可独立进入，模型配置返回原页面，Android 返回键与界面返回按钮语义一致。页面切换保留本次会话与草稿；请求在离开页面时取消并保留可重试记录。未配置模型时显示配置入口，不生成演示回答。没有实际持久化与调度能力时，不展示「已设置提醒」或未生效的记忆开关；附件能力未接入时不放占位按钮。

### A.4 会话地图、右栏检查器与旧仪表

- 会话地图围绕当前会话及其分支，以问答轮次为节点，提供追问、分叉、子树折叠和完整内容；会话日志与真实分叉记录为事实来源，布局偏好不替代会话状态。界面已移除。
- 右栏曾是检查器：分区之间只有一条细分隔线，标题 12px，右侧可放摘要，后跟 56px 迷你用量条（`<MiniMeter>`）；上下文展开体按工作集画进度条，清理 / 折叠 / 压缩刻度名收在刻度左下；额度每个窗口两行；分区可拖动排序、折叠或浮出为磁贴。上下文与额度采用横向仪表，工作集独立显示策略比例和阶段刻度。默认工作区已不含检查器，上下文与额度分别改到输入区圆环与状态栏。
- 编码与日常曾共用同一骨架、按场景切换默认展示内容；叠加模式已退出正常发送流程。
- 运行状态的主位置曾是输入区顶边（唯一方点阵 + 一句状态文字 + 计时），输入框外沿有环绕流光；方向 E 改为回合活动行。
- 用户消息曾是 `--bg-2` 底 + 细边的 `›` 块；方向 E 初版改为无框 `›`，随后桌面改为靠右浅底气泡（4.3）。
