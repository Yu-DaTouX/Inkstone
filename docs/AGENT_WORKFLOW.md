# 多 Agent 协作流程

[AI 协作约定](../AGENTS.md) · [文件归属与长期维护规范](REPOSITORY_GUIDE.md) · [贡献指南](CONTRIBUTING.md)

Inkstone 由维护者和多个 AI agent（Claude Code、Codex、砚内置的 pi 等）轮流或同时开发。各 agent 的会话与私有记忆互不可见，协作只能依靠仓库里的文件。本文规定这些文件的位置、读写时机和交接方式。必须遵守的规则以根目录 [AGENTS.md](../AGENTS.md) 为准，本文展开细节。

## 1. 信息放在哪里

每类信息只放一处。两处说法冲突时，以下表的位置为准，并修正另一处。

| 信息 | 位置 | 公开 | 何时更新 |
| --- | --- | --- | --- |
| 每次都要遵守的规则 | `AGENTS.md` | 是 | 规则变更 |
| 协作流程细节 | 本文 | 是 | 流程或本地资料分类变更 |
| 文件归属、命名与归档 | [REPOSITORY_GUIDE.md](REPOSITORY_GUIDE.md) | 是 | 目录职责变更 |
| 源码导航 | [PROJECT.md](PROJECT.md)、[CODE_MAP.md](CODE_MAP.md) | 是 | 能力新增或迁移 |
| 当前状态：进行中、待决定、未完成与未验证 | `.local-docs/STATUS.md` | 否 | 每次会话收尾 |
| 用户的决定与长期偏好 | `.local-docs/DECISIONS.md` | 否 | 用户做出决定时追加 |
| 交接 | `.local-docs/handoffs/` | 否 | 任务跨会话或换 agent |
| 需求稿、方案、本地计划 | `.local-docs/plans/` | 否 | 按需 |
| 审查记录、验证清单、验收报告 | `.local-docs/reviews/` | 否 | 按需 |
| 截图、日志、探针与构建产物 | `.local-docs/evidence/<日期>-<主题>/` | 否 | 产生时 |
| 已结束的主题 | `.local-docs/archive/` | 否 | 主题结束 |
| agent 私有记忆 | 各工具自己的目录 | 否 | 只放个人沟通偏好和指向上述文件的指针 |

`.local-docs/` 被 Git 忽略，只存在于维护者本机，新克隆、云端 agent 和 `git worktree` 的工作目录里都没有。在 worktree 中工作时，到主工作区（`git worktree list` 第一行）读取。没有本地资料时，依据公开文档和源码工作。

本地文件统一按 `YYYY-MM-DD-<主题>` 命名，放进对应分类；`.local-docs/` 根目录只放 `README.md`、`STATUS.md`、`DECISIONS.md` 和分类目录。`workspace-audits/` 与 `showcase-2026-09-29/` 是已跟踪脚本的固定输出位置。

`docs/plan/`、`docs/design/`、`docs/archive/` 与 `docs/dev/`（`RELEASING.md` 除外）是 2026-09-27 前的本地计划与证据体系，已冻结：只在追溯历史时读取，不再新增或回填。

## 2. 一次会话的流程

### 开工

1. 读 `AGENTS.md`，运行 `git status --short` 与 `git worktree list`。
2. 读 `STATUS.md` 与 `DECISIONS.md`。对照 `git status`：没有登记在 STATUS「进行中」的未提交改动归属不明，不要碰，必要时问用户。
3. 继续已有主题时，读 STATUS 指向的交接。交接里的「下一步」是建议，授权仍以用户当前请求为准。
4. 按任务阅读代码地图与源码。

### 登记

任务预计跨会话、跨 agent 或需要多次提交时，在 STATUS「进行中」加一行：主题、agent、开始日期、文件范围。几分钟内能做完的小改动不必登记。

### 进行中

- 只改任务范围内的文件。共享热点文件（`src/main/index.ts`、`src/shared/ipc.ts`、`src/preload/index.ts`、两份 i18n、`Settings.tsx`、`chat.css` 等）用小范围编辑，编辑前重新读取，不整文件重写，不做无关格式化。
- 遇到需要用户决定的问题，先记下，继续做不依赖它的部分，最后在回复里集中提出。
- 截图、日志等证据放 `.local-docs/evidence/<日期>-<主题>/`，不放仓库根目录或 `.local-docs/` 根目录。一次性脚本放 `.tmp/<任务>/`。

### 收尾

1. 按用户授权处理提交（第 4 节）。
2. 更新 STATUS：删除或改写自己登记的「进行中」条目；把未完成、未验证和待决定的事写进对应段落；更新「最后更新」一行。
3. 任务没做完、要换会话或换 agent 时写交接（第 5 节）。
4. 用户做了新决定时，追加到 DECISIONS。
5. 交付说明分别写：改了什么、跑了哪些检查、哪些没验证、需要用户做什么。

## 3. 并行与冲突

- 同一工作区可能同时有多个 agent。开工与提交前都看 `git status`；自己要改的文件里已有别人的改动时，先读最新内容再改。
- 不用 `reset`、`checkout --`、`clean`、`stash` 或删除处理他人改动，也不替他人提交。
- 同一文件混有两个任务的改动时，按用户决定处理：一起提交并在说明里写清，或由用户拆分。
- 大改动或长时间运行的任务可以放进 `git worktree`，分支名写明 agent 与主题（如 `claude/<主题>`）。完成后告诉用户分支名，合并与清理由用户决定；不删除其他 agent 的 worktree 与分支。
- 别的 agent 正在同一工作区改代码时，构建与测试放进临时 worktree 运行，避免构建产物和测试数据互相覆盖；需要合并时也先在临时 worktree 里合并并验证，再把 main 快进过去。`node_modules` 与 `resources/pi-runtime` 可以用目录联接指向主工作区，删除临时 worktree 前先单独拆掉联接。
- 砚的同目录并发隔离会在仓库旁的 `<仓库名>-worktrees/` 下自动创建 `yan/auto-*` 分支，由应用流程合回，不要手动处理。

## 4. 提交

- 只在用户授权后提交、推送、打包或发布。
- 逐文件暂存本任务的文件，不用 `git add .` 或 `git add -A`；提交前核对 `git diff --cached --stat`。
- 提交说明写清修改原因、检查范围与剩余限制，沿用仓库的中文风格。
- 提交后再看一次 `git status`，确认其他改动仍在。
- 公开入口（目录、命令、文档位置）变化时，同步 README、文档索引、AGENTS 与 PROJECT。

## 5. 交接

一次交接一份文件：`.local-docs/handoffs/YYYY-MM-DD-<主题>.md`，写给没有任何上下文的接手方，照着就能继续，不需要回看聊天记录。本机模板在 `.local-docs/handoffs/README.md`，必备内容如下：

| 段落 | 内容 |
| --- | --- |
| 状态行 | 进行中 / 待验证 / 已关闭；交出与接手的 agent；用户授权范围与明确未授权的事项 |
| 现状 | 分支与 HEAD；未提交改动中属于本任务的文件；与其他任务交叉的文件 |
| 已完成 | 内容、文件、验证方式与结果 |
| 未完成 | 按优先级排列；每项写现象、线索、建议做法与涉及文件 |
| 待用户决定 | 问题、选项与各自代价 |
| 验证记录 | 已跑的检查与结果；未验证项与原因（费用、设备、授权） |
| 接手顺序与参考 | 建议顺序；审查记录、证据目录、工具脚本的路径 |

写完在 STATUS 里链接它。任务结束时把状态行改为「已关闭」并注明提交，正文不再改写。

## 6. 状态板

`STATUS.md` 只写现在成立的事，按以下段落组织：

- **基线**：`main` 的提交与版本，工作区是否干净。
- **进行中**：主题、agent、开始日期、文件范围、说明。
- **待用户决定**：编号列表，写清选项。
- **未完成与未验证**：按主题分组，链接交接与审查记录。
- **工作区与分支**：worktree、未并入的分支和未提交改动数。
- **最近记录**：交接、审查、验收的索引与状态。

每条事实附来源（提交号、文件或日期）；没有核对的写「据某记录，未复核」。已完成的条目直接删掉，历史留在交接与 Git 里。

## 7. 决定日志

`DECISIONS.md` 只追加：日期、决定、影响、来源（用户原话或交接）。决定被推翻时追加新条目，并在旧条目上标「已被某日取代」。只记录用户明确做出的决定，不把 agent 的建议写成决定；已写入 AGENTS 的偏好注明位置。

## 8. 审查与验收

- 交叉审查、验证清单与验收报告放 `.local-docs/reviews/YYYY-MM-DD-<主题>.md`。
- 修复清单按处理方式分批：A 可直接改，B 需用户决定，C 清理，D 验证。执行方逐条勾选并注明提交，没做的写原因。
- 结论标明证据强度（已核实 / 静态推断），不把推断写成事实。

## 9. 私有记忆

各 agent 的私有记忆（如 Claude Code 的 memory 目录）其他 agent 读不到，只放两类内容：

- 与用户沟通的个人偏好；
- 指向 STATUS、DECISIONS 或某份交接的指针。

项目状态、交接内容和用户决定写进共享文件。任务结束后，删除私有记忆里指向旧交接的指针。

## 10. 常见问题

- 含正则、反斜杠或嵌套引号的代码不要经 `node -e` 或 heredoc 传递，反斜杠会被 shell 吃掉；用编辑工具或写成脚本文件。
- 启动 Electron 前清除 `ELECTRON_RUN_AS_NODE`。需要隔离实例时，把 `YAN_PI_DIR`、`YAN_USER_DATA`、`YAN_DATA_DIR`、`YAN_DOWNLOADS_DIR` 指向临时目录，不碰真实用户数据。
- 部分 agent 的沙箱不能运行构建、Electron 或 adb。这类检查交给能运行的 agent 或用户，交付说明里写明哪些没跑。
