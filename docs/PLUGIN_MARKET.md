# 插件市场

在 **设置 → 插件市场** 中切换「砚插件」与「pi 插件」。原来的包管理深链接继续指向市场，安装能力仍由 pi 提供。

## 砚插件

只收录为砚专门适配、由本项目维护的插件，每个条目显示源码目录链接。首批为 **Hermes × Inkstone 0.2.0**：让 Hermes 查看/控制会话，并接收用户明确作出的允许或拒绝。

点击「下载到文件夹」后选择父目录，砚导出完整的 `inkstone/` 插件文件夹。目标已存在时拒绝覆盖；不会自动安装、启用、配对或重启 Hermes。安装在 Hermes 的插件应放到其 `plugins` 目录，具体命令与配对步骤见下载内容的 `README.md` 或 [Hermes 插件说明](../integrations/hermes-inkstone/README.md)。

现有条目和可下载文件随砚版本分发，下载不依赖远程插件服务。后续专门适配的插件再收录，当前没有第三方投稿、账户、评分或独立插件运行时。

## pi 插件

页面查询 npm 中带 `pi-package` 标记的包，展示名称、版本、介绍、发布者与原链接（npm 包页，以及发布者声明的 https 仓库或主页），支持搜索和分页。原链接用系统浏览器打开；结果随页面滚动，不再套一层内部滚动框。它是 pi 原生生态入口，不表示每个包都由 pi 官方维护或经过砚兼容验证。[pi 的包目录](https://pi.dev/packages)也包含扩展、技能、提示模板和主题；部分终端 UI 插件不能直接提供图形客户端界面。

点击「选择」把来源填入下方表单，选择用户级或「仅本项目」，再点击「安装」。也可以直接输入 pi 支持的 npm、Git 或本地来源。已安装列表沿用更新、卸载与详情操作。

安装仍调用当前配置的 pi CLI，写入同一个 pi 数据目录或项目配置，不修改生成的运行时。安装结果不表示正在运行的会话已经加载；按页面说明在新会话生效。目录网络失败时显示错误，仍可按来源安装和管理已有包。

扩展可以执行代码，安装前核对发布者、来源与实际影响；没有额外沙箱或新的权限挡位。

## 维护

- 自有插件条目在 `src/shared/inkstone-plugins.ts`；增加已交付插件时同步版本、实际文件、导出白名单及 `electron-builder.yml` 的资源清单。不要只增加无法下载的占位卡片。
- pi 目录查询在 `src/main/plugin-market.ts`：固定 npm 地址，超时、响应大小限制及短时内存缓存；渲染端不传任意 URL。
- IPC 复用 `packages` bridge；已有运行中的任务保护与项目信任检查由原包管理执行。
- `node scripts/test-plugin-market.mjs --live` 检查本地夹具和实际目录，只读取网络元信息。
- 构建后 `node scripts/test-plugin-market-live.mjs` 检查实际 Electron/preload/IPC、两个页面、键盘与深浅/窄窗；不安装第三方包、不调用模型，截图保存在新的本地证据目录。
