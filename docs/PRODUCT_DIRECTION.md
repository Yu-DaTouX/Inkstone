# Inkstone 产品方向与精简边界

更新：2026-10-09。本文记录已确认的产品目标，并区分目标、当前实现与待确认的实施取舍。本日已按用户“先去精简功能，然后按需完成”实施首批精简，源码验证与未验收部分分别记录。

## 产品定位

砚是基于官方 pi 轻量 Agent 核心、适配个人使用习惯的图形客户端。优先级为简单易读的 UI、直接的权限选择、指定模型的子 Agent 协作，以及轻量和性能。会话是主要入口，不要求先建立空间、资料库或正式任务。

写作、学习、空间与资料库不作为独立产品模块。Agent 仍可在普通会话中处理文字、解释问题和读取文件；取消的是额外的业务组织与专用流程。

旧标准/计划/自主模式退出正常流程；“先计划”目前只能作为会话指令，不提供宿主强制只读计划入口。自动续跑死实现已删除，旧目标/模式/交接代码与历史兼容尚有保留。空间、资料库、专用写作/学习和复杂 CLI Hub 不列为默认产品功能。Windows 优先，其他目标平台尚未交付。

## 已确认的平台范围

| 平台 | 目标职责 | 当前证据边界 |
| --- | --- | --- |
| Windows / macOS / Linux | 同一套桌面 Agent 客户端，在电脑上执行 | 当前实现与发行主要覆盖 Windows；macOS、Linux 尚需适配和各自验收 |
| Android / iOS | 连接电脑，发送指令、查看过程和结果、回应审批 | Android 已有远程客户端；当前移动目录未见 iOS 工程，不宣称 iOS 已交付 |

当前实施优先级：先适配和验收 Windows。macOS/Linux 桌面与 Android/iOS 远程连接暂缓实施，但保留共享协议、运行身份、权限语义和平台适配边界；不把 Windows 专属路径或命令放进共享层。

手机不独立运行完整 Agent，不复制电脑的任务状态机。沿用版本化远程协议和电脑端事实源。SSH 外部 Agent 主机、云端多租户、自有账号系统不属于本次目标。

近期保留 TypeScript、React、Electron、官方 pi 与现有 React Native 移动端基础；先复用和精简，不以更换语言或应用壳作为性能结论。

## 模型与子 Agent

用户为当前会话选择主模型，并能要求它调用指定的另一个模型完成任务。子 Agent 有独立执行上下文，获得任务及必要材料，结果返回主会话。主界面只需展示模型、任务、状态、结果和停止操作。

优先复用现有 pi 子任务的模型参数、Provider 扩展加载、运行身份和结果回传；核对这些能力的端到端行为后再接线。通用委派不要求 Git；worktree 只作为代码修改时的可选隔离方式。外部 CLI 终端、受管任务、模板、补丁验收与交接不成为跨模型委派的强制步骤。

Claude Code 订阅接入先调查并验证 pi 插件。优先候选为 [pi-claude-bridge](https://github.com/elidickinson/pi-claude-bridge)：通过 Claude Agent SDK 注册模型 Provider，另提供面向 Claude 的 AskClaude 工具。它不是任意模型委派的统一实现；AskClaude 的 full 模式走 Claude Code 原生工具，必须核对权限覆盖。另一个 [pi-claude-code-provider](https://github.com/chem/pi-claude-code-provider) 已停止继续维护，作者推荐 bridge，不作为首选。

截至本次查阅，[Anthropic 官方帮助](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)说明 SDK、claude -p 与第三方应用仍可使用订阅额度；这不等于当前账户、砚打包版本或三种桌面平台已验证。插件接入需验证取消、恢复、工具事件、凭证来源和实际额度路径；不另造订阅认证协议。

## 两档权限

| 档位 | 目标行为 |
| --- | --- |
| 危险审批 | 常规操作直接执行，明确的危险操作请求批准 |
| 原生模式 | 砚不额外审批或拦截；pi、Provider、外部工具及操作系统仍按自身行为运行 |

不新增任务级权限档位、文件根授权向导或复杂策略编辑器。主会话与子 Agent 使用同一用户选择，外部执行路径必须如实说明覆盖范围，不声称具备未实现的沙箱。

主会话与普通 pi 子任务已按上述语义接线：原生模式取消砚的删除重定向；危险模式走危险清单，子运行有独立审批通道。旧工作模式、活动与越界写入审批不再参与默认会话。Claude bridge Provider 使用 pi 工具，遵循相同护栏；额外的 AskClaude 工具在 CC 内部运行，危险模式在执行前批准整次任务，显示完整任务及无法逐条检查内部操作的边界，支持插件自定义工具名；原生模式不增加这项确认。需要逐条危险审批时使用指定 claude-bridge 模型的砚子 Agent。该提醒式护栏不是沙箱。

Haiku 5.5 low 已完成真实订阅读写、主子任务与取消验收；跨 Provider 已验证本机夹具父 Provider 经真实 pi 调用真实 CC 子模型并接收结果。隔离 RPC 终止后重新加载持久会话、保留模型/低思考并继续真实 CC 回复通过。生成中进程退出会清除宿主忙碌标记，通过正式重载入口恢复同一会话，不自动重放请求；只有用户显式继续才执行新一轮。本机模型流已验证中断、正式重载和继续，真实 CC 已分别验证持久会话恢复后的回复。这不代表网络故障所有阶段或自动重试已经验收。CC 只读子任务仍明确不支持，因为它会关闭 Provider 扩展自动发现；其他收费 Provider 与跨平台运行尚未验收。

## 精简范围

| 范围 | 建议处理 | 保留的直接能力 |
| --- | --- | --- |
| 空间、资料库、专用写作/学习入口 | 退出核心界面，审计依赖后退役专用流程 | 文件夹/项目选择、附件、读取文件、普通会话 |
| 编码/日常、活动类型、标准/澄清/自主等叠加模式 | 收敛入口和设置，避免多套模式相互影响 | 会话模型、思考强度、两档权限 |
| Agent Hub 多 CLI、任务模板、固定补丁验收与交接 | 退出默认委派流程；仍在使用的功能先保留兼容 | 指定模型的子 Agent、可选终端和 Git 隔离 |
| 任务收件箱、持续关注、独立文件任务面板 | 不作为默认产品模块，检查依赖与历史数据后确定退役范围 | 会话内工具进度、子任务卡片和文件结果 |
| 独立运行服务、任务授权/预算/成果管理 | 暂停扩建，按实际调用审计，避免与会话再建一套执行管理 | 有必要的纯业务边界、运行身份与持久历史 |
| 旧上下文预算、自动续跑/交接兼容接口 | 核对消费者后清理；历史读取单独保留 | pi 原生上下文、压缩与恢复 |
| 会话地图、复杂首页与多层布局 | 默认聚焦会话，其他布局按需开放 | 搜索、历史、文件/终端/预览；分屏取舍另行确认 |

默认界面已退出空间、资料库、专用学习/写作、叠加模式、收件箱、会话地图及文件任务面板；默认 Hub 已替换为轻量委派面板，旧 Hub 详情仅在打开历史记录时加载。启动时不再导出学习记录，也不装配工作模式/活动/重复行为护栏。历史文件、兼容状态与旧服务源码保留，未做整库删除。领域模块退出不影响通用 skills、MCP 或 pi 扩展能力。

## UI 与性能原则

默认页面由会话列表、聊天区和输入区组成。模型、思考强度、权限保持容易找到；文件、终端、浏览器、预览、子 Agent 详情按需展开。手机只展示远程操作需要的功能。

先检查重复状态、无调用代码和未使用服务的常驻初始化，再按需加载可选面板。用固定场景比较启动时间、空闲内存/CPU、长会话滚动及子 Agent 并发；CC bridge 的进程与恢复开销单独记录。静态审阅不能证明性能提升，不提前承诺数值。

## 建议实施顺序

1. 审计入口、调用链和历史数据，确认精简清单；暂停旧通用执行平台路线的继续扩建。
2. 收敛 UI 与模式入口，保留会话、模型、工具和必要设置；不在同一批批量重写状态机。
3. 验证并接入 Claude 订阅 Provider，复用现有 pi 子 Agent，贯通模型选择、取消与结果回传。
4. 实现两档权限的完整语义，核对主会话、子 Agent 和 Claude 工具路径。
5. 先完成 Windows 边界验收、性能测量与独立目录包验证；macOS/Linux 桌面及移动端后续按需适配，并分别验收。

每批保留历史可读和回退路径。不重置共享工作区，不删除真实数据，不把文档更新当作实现、模型调用、发布或重启授权。
