# Inkstone 产品方向与精简边界

更新：2026-10-11。本文集中记录产品目标、当前源码能力和未交付边界；操作步骤见[使用指南](GETTING_STARTED.md)，实现入口见[代码地图](CODE_MAP.md)，检查方法见[贡献指南](CONTRIBUTING.md)。开发工作区、正在运行的窗口和已下载发行包可能处于不同版本；发行内容以对应 Release 为准。

## 产品定位

砚是基于官方 pi 的轻量图形客户端，适配个人使用习惯。优先级为简单易读的 UI、直接的权限选择、指定模型的子 Agent 协作，以及轻量和性能。会话是主要入口，不要求先建立空间、资料库或正式任务。

写作、学习、空间与资料库不作为独立产品模块。Agent 仍可在普通会话中处理文字、解释问题和读取文件；取消的是额外的业务组织与专用流程。

## 平台与验证边界

| 平台 | 目标职责 | 当前边界 |
| --- | --- | --- |
| Windows | 在电脑执行的桌面 Agent 客户端 | 当前主要开发、验证和发行平台；版本内容以发布说明为准 |
| macOS / Linux | 同一套桌面客户端 | 已确认目标，尚需适配与独立验收，不宣称支持 |
| Android | 连接电脑，发送指令、查看过程和结果 | 已有实现与局部真机检查，不能据此认为所有远程场景已验收 |
| iOS | 连接电脑的远程客户端 | 当前 mobile 目录没有已交付的 iOS 工程 |

Windows 优先；其他桌面平台与移动能力按用户需求另行推进，不提前扩建全平台空壳。共享协议、运行身份、权限语义保持平台边界，不把 Windows 专属路径或命令放进共享层。

手机不独立运行完整 Agent，不复制电脑任务状态机。SSH 外部 Agent 主机、云端多租户和自有账号系统不属于当前目标。保留 TypeScript、React、Electron、官方 pi 与 React Native 基础，不把更换语言或应用壳当作性能结论。

真实 Claude Haiku 订阅的读写、主子委派、取消和持久会话恢复已有隔离验证；跨 Provider 验证的父 Provider 使用本机夹具，不能推广为任意两个真实服务已互通。生成中 pi 进程退出后可显式重载原会话，不自动重放请求。CC 只读、真实网络故障全阶段、其他 Provider 与跨平台仍需分别验证。源码、模拟检查、真机、安装包和发布证据不能相互替代。

## 模型与权限

子 Agent 获得明确任务及必要材料，结果回到主会话；使用单一委派入口，不要求任务模板、外部 CLI 工作台或 Git。worktree 仅是代码修改时可选的隔离方式。

Claude Code 订阅复用 [pi-claude-bridge](https://github.com/elidickinson/pi-claude-bridge)，不另造订阅认证协议。Provider 路径使用 pi 工具并遵循砚的护栏；额外的 AskClaude 工具在 CC 内部执行，「自动批准」档只能在执行前批准整次委派，不能逐条检查内部操作。「不受限制」档不增加该确认；pi、Provider、外部工具和操作系统自身限制仍有效。账户资格与额度由服务商决定。

不新增任务级权限档位、文件根授权向导或复杂策略编辑器。需要逐条检查 pi 工具操作时使用指定 claude-bridge 模型的砚子 Agent；提醒式护栏不等于安全沙箱。

## 精简与历史兼容

| 范围 | 当前处理 | 保留能力 |
| --- | --- | --- |
| 空间、资料库、专用写作/学习 | 退出默认界面，不恢复为独立产品模块 | 项目/文件夹、附件、普通会话和通用技能 |
| 编码/日常、标准/计划/自主等叠加模式 | 退出正常发送流程 | 模型、思考强度、两档权限；“先计划”仅是会话指令，不是强制只读模式 |
| Agent Hub 多 CLI、模板、固定成果与交接 | 退出默认委派流程，保留旧历史后端 | 轻量子 Agent、可选终端与 Git 隔离；见[历史工作台](AGENT_HUB.md) |
| 任务收件箱、持续关注、会话地图、独立文件任务面板 | 界面已退出，不因源码尚在就列为可用入口 | 会话内工具进度、子任务卡片、文件结果 |
| 独立运行服务、授权/预算/成果管理 | 暂停扩建，按实际调用审计 | 必要纯业务与持久历史边界；见[运行服务](AGENT_SERVICE.md) |
| 旧上下文预算、自动续跑/交接、项目知识/个人记忆页面 | 旧默认流程停用；不自动注入旧资料或恢复执行 | pi 原生上下文、当前轻量裁剪扩展、历史读取与[旧记忆文件兼容](MEMORY_INTEROP.md) |

历史文件与仍有调用的兼容实现不做整库删除。领域模块退出不影响通用 skills、MCP 或 pi 扩展；源码中仍保留的领域技能不代表默认会话会加载。

## 后续取舍原则

优先补齐当前会话的可靠性、历史可读性、成果处理和性能，不恢复多套任务状态机。文件、终端、浏览器、预览、子 Agent 详情按需展开；手机只展示远程操作所需能力。

先检查重复状态、无调用代码和未使用服务的常驻初始化，再按需加载。用固定场景比较启动、空闲内存/CPU、长会话与子 Agent 并发，CC bridge 的 SDK/CLI 开销单独计入；测量方法见[贡献指南](CONTRIBUTING.md#可重复性能测量)。入口代码减少不等于整机性能提升。

未交付能力和功能建议不自动成为实施计划。每批改动保留历史可读与回退路径，不重置共享工作区，不删除真实数据，不把文档更新当作模型调用、提交、发布或重启授权。
