# 多 Agent 工作台

多 Agent 工作台让 Windows 桌面宿主管理派活、执行尝试、代码成果和审批。Android 手机通过同一个宿主服务参与。此功能属于开发中的源码版本；已发布版本是否包含入口，以实际安装版本为准。

## 从桌面派活

打开右侧的「Agent 协作」，用标签切换原生 CLI 终端、受管任务和当前会话派出的 pi 子任务。「＋」添加运行，运行列表打开已有任务，运行菜单查看协作记录、停止运行或进入审批与成果。隐藏面板或标签保留后台运行；展开按钮放大当前工作区。窄窗会收起工具列。

原生终端在面板内直接输入。受管任务显示过程事件；审批与成果按需打开。新建任务选择项目、Agent 和执行方式，沿用该 Agent 的默认模型。高级模型、模板和审查参数仍在任务详情中提供。

新任务从项目当前 `HEAD` 建立独立 worktree。主工作区有未提交改动时，可以选择「带上未提交改动」：宿主用临时 index 把这些改动冻结成起点补丁并套用到 worktree（不改用户自己的暂存区），Agent 用 `git diff HEAD` 就能看到；交付补丁只计算起点之后 Agent 自己的改动。砚主会话派出的任务默认带上，界面派活由开关决定。被 Git 忽略的 `node_modules`、`.venv`、`venv` 以目录链接接入 worktree，便于运行测试；在 worktree 里安装依赖会写回项目目录。不是 Git 仓库的项目只能在原目录打开交互终端，不能派受管任务。验收后或手动「清理工作区」时删除 worktree（先移除依赖链接，不会删到项目里的依赖），冻结的补丁与报告保留。

派活与补充要求可以附带图片和文件。附件保存在宿主数据目录的 `agent-hub/attachments/` 下、所有工作区之外，以绝对路径写进消息；Codex 另以本地图片输入接收图片，其他 Agent 按路径读取。任务应说明范围与交付要求；材料、交接和其他 Agent 的报告都是参考资料。

用户模板保存任务内容、Agent、模式与模型偏好；选择模板只填表，不执行任务，也不复用旧审批、输入权或成果。模板最多保存 50 个，桌面与已配对手机共享。任务列表可切换「全部任务／待处理」。

| Agent | 当前执行方式 | 完成判定 |
| --- | --- | --- |
| pi | 独立 RPC 执行 | `agent_end` 与助手错误状态 |
| Codex | app-server 受管执行、交互终端 | 受管模式认正式 `turn/completed`；终端退出需人工核对 |
| Claude Code | stream-json 受管执行、交互终端 | 受管模式认正式 `result`；终端退出需人工核对 |
| Gemini、Grok | 交互终端 | 退出后保留「结果待核实」 |

外部 CLI 使用各自现有的登录与额度。工作台检测命令是否可运行，不代表对应模型已登录或有可用额度。npm 的 JavaScript CLI 需要真实 Node.js；原生可执行文件直接启动。

交互终端最多同时打开 4 个，不占用受管任务的派活槽；默认没有自动停止时限。受管任务最多同时执行 3 个，其中最多 2 个发起任务，留一个执行槽给直接派活；最多保留 16 个排队任务。受管任务可派出最多 4 个直接子任务；子任务不能继续派活。停止发起任务会同步停止仍在执行或排队的子任务，子任务仍在执行时不能验收发起任务。受管任务默认 30 分钟，可通过创建请求在 1–60 分钟内设置。

## 主会话与 Agent 交互

在当前会话的项目中添加运行时，关联该主会话；已有未关联运行可从菜单加入当前会话协作。砚主 Agent 通过 `yan hub list/get/send` 查阅和联系自己的运行。受管 Codex、Claude 使用 `inkstone_reply` 回报父任务或关联主会话；pi 与终端 CLI 可使用 `yan hub reply --request-file reply.json`，文件包含 `requestId` 和 `summary`。主会话必须仍在宿主中且属于相同项目。

协议消息交给原生 Agent 处理；发给交互终端的消息先排队，用户核对输入行后显式发送，避免覆盖正在编辑的指令。每条消息绑定运行身份并按请求 ID 去重；旧运行和其他会话不能复用消息。受管任务结束后沿用「子代理完成时通知会话」设置回报主会话，终端退出需人工核对。报告属于来源 Agent，需主 Agent 或用户核实。

原有 pi 子任务与 Hub 任务共用运行列表、标签和详情入口，保留各后端的真实身份、停止与成果记录。原有只读任务继续限制工具；可写 pi 子运行采用独立原生会话目录，并交由 pi 管理上下文、技能和扩展发现。

## 固定成果和审查

受管执行正式完成后，任务进入「待审阅」。宿主用临时 Git index 收集相对于任务基线的已提交、未提交、未跟踪和二进制改动，保存补丁、报告、Git tree 和 SHA-256。这个过程保留执行工作区原有的暂存状态。

在「审查成果」中选择同项目的固定成果，新的审查任务从原基线重建补丁并核对 tree。报告与代码须一起审查；点击「验收成果」才会标记已验收。验收不会合并、提交、推送或发布代码。

工作区、报告和补丁保存在宿主数据目录的 `agent-hub/` 下。宿主重启不会自动重试旧任务。结果不明、失败或已停止的任务需要人工核对后恢复；恢复创建新的运行身份。Codex 与 Claude 有外部会话 ID 时尝试恢复其会话；pi 当前重新执行任务内容，不恢复完整旧对话。

任务详情中的「运行历史」保留每次运行的时间、模型、状态、外部会话及固定成果摘要，报告可展开查看。恢复时旧报告和成果保留在旧运行记录中，新运行从准备状态开始，不继承旧成果为本次交付。

## 共享工具和审批

受管 Codex、Claude 通过临时 MCP 配置调用砚的浏览器、已启用的 Windows 界面工具、派活和任务状态入口。pi 可使用 `yan hub start/list/get/stop`。临时能力令牌绑定本次运行与项目，精确限制可调用的宿主命令。

当前浏览器与 Windows 输入共享一个 FIFO 交互资源。等待超时意味着操作尚未开始；正在执行的动作不会因另一个请求等待超时而被释放。浏览器元素引用带目标与观察身份，并核对调用者自己的最近观察。用户接管暂停新的受管交互；超时或断连导致结果不明时，资源暂停转交，需在电脑核对旧操作后恢复。

宿主在发出受管交互前同步保存资源占用，确认返回后才释放。重启后仍占用的资源进入「结果待核实」；损坏记录会保留副本并暂停交互。记录包含资源、运行主体、操作身份与占用版本，不保存原始终端输入或网页凭证。这能识别宿主中断留下的交互，不能证明外部业务操作是否完成。

源码还增加了排队动作开始前的运行身份核对，以及内置浏览器下载的运行归属。模型只读取本运行可归属的下载；没有归属的下载仍由用户在浏览器查看，外部 Chrome 下载暂不提供运行归属。内置下载保存路径带唯一标识，避免相同建议文件名覆盖已有文件。这组最后修改尚未做运行验证。

受管 Codex 的命令、文件审批和普通文字提问显示在任务详情中。Claude 的指定写入与 shell 工具经过运行级 PreToolUse 确认。批准只针对本次请求，过期或旧运行答复不能复用。pi 原有高危确认仍要求电脑确认。

这些约束覆盖已接入的宿主工具入口。CLI 自己的 shell、原生插件和其他外部浏览器仍可能绕过协调；交互终端明确标为未协调。当前没有每任务独立浏览器登录会话、任意端口隔离、完整操作系统沙箱或自动合并保证。

## Android 参与

先按[手机接入说明](MOBILE_ACCESS.md)配对。手机工作台顶部的终端图标打开多 Agent 页面，可以派活、看报告和状态、答复受管请求、停止任务和验收成果。

完整 Hub 控制要求配对的手机身份，连接来自 Tailscale 地址或加密传输；本机回环用于受控测试和转发。普通局域网明文连接、旧环境令牌和砚对砚身份不能使用这组接口。当前内置服务是 HTTP，推荐使用 Tailscale。

手机和电脑共享同一个终端输入权。接管会推进输入版本；旧版本输入、尺寸变更和迟到请求被拒绝。手机输入权 30 秒无续期会到期，后台任务按原授权继续。终端使用随应用的本地 xterm 资源，按序回放；缺失增量时通过宿主的 xterm 屏幕状态重建颜色、光标及备用屏幕，保留有界回滚。快照附带其实际尺寸，手机接管后同步窄屏尺寸。

Android 测试包已在 USB 真机验证配对、Hub 任务列表、ANSI 显示、输入接管、输入回传、显式发送、竖屏详情和横屏双栏；停止测试应用超过 30 秒后重开，任务保持运行、手机输入权变为只读，重新接管后仍可输入。验证使用 USB 回环转发与离线终端，不代表 Tailscale、其他网络、真实 CLI 全屏界面或后台提醒已验收。新增手机流程需要桌面和手机同时使用包含该功能的源码版本。

开发时可用 `-PinkstoneHubTest` 构建独立的 `com.yudatoux.inkstone.hubtest` 测试应用，显示名称为 Inkstone Hub Test；默认构建的应用标识保持原样。构建与安装仍遵守仓库授权规则。

已开启手机待回答提醒时，原生服务同时读取 Hub 待处理事项，锁屏只显示数量；点击进入多 Agent 页面。提醒接口沿用配对和网络门禁，返回事项身份与版本。该接线已通过原生编译与离线接口检查，通知弹出、点击和后台电池行为尚未在真机验收。

## 礁石参与

[礁石](https://github.com/Yu-DaTouX/reef)（个人 Agent）可以经[中继接入](MOBILE_ACCESS.md#不用-tailscale经中继连接)配对成 `agent` 身份：只能读取 Hub 快照与提醒，执行 `create`、`cancel`、`answer`、`inspect`；验收、恢复、终端输入、模板与交接包等操作对它关闭，会话、文件、浏览器等其他远程接口也一律拒绝。`agent` 身份只能经中继隧道配对，直连请求声称 `agent` 会被拒绝；Hub 内部按手机同一层级记录操作者。

## 开发检查

基础检查使用贡献指南中的 typecheck、build 和 test:unit。以下补充检查不调用模型：

```powershell
npm run test:agent-hub
npm run test:relay
npm run test:agent-workspace
node scripts/probe-agent-hub-codex.mjs (Get-Command codex.exe).Source
npm --prefix mobile run typecheck
```

真实模型探针 `scripts/probe/agent-hub-real.js` 需要隔离的 Git 项目、独立 `YAN_*` 数据目录和用户明确指定模型及额度；不能直接在真实项目或真实用户数据目录下运行。它使用 GPT-6 Luna 低思考的一个最小文件任务，不代表其他 CLI、模型、工具或手机流程已验收。
