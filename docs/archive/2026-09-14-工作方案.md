本文把 [实施记录](../archive/2026-09-14-实施记录.md) 的实际结果与 [工作区状态](2026-09-14-状态快照.md) 的剩余事项合并为一份执行顺序。两份原文继续保留：实施记录是已完成内容和已知边界的证据，工作区状态是清理结果和当前盘点；本文是后续工作的排期，不替代它们。

## 一、已经完成并作为基线保留

- 六个功能阶段已经落地；子代理采用 Yan 自有 `pi --mode rpc` 进程适配，前端模型保持可替换。
- 文件拖放授权、链接分类、只读文件预览、工具详情分型、问题面板、额度与上下文展示、快照差异、浏览器默认拒绝策略、主窗口沙盒、密度设置和统一收尾已经实现。
- 当时的类型检查、构建、312 项单元测试、50 个实时场景、设计测量和内置 pi 检查均有通过记录；这些是历史证据，本轮重新修改后仍需按变更范围复验。
- 任务面板行为保持现状，不安排重构；登录继续保持“尚未接入”的真实状态。

## 二、第一阶段：发布前恢复性验证（最高优先级）

目标：证明当前源码可以构建、打包、启动，并且不会破坏已有便携数据。

1. 运行类型检查和构建，确认 sandbox preload 的 CJS 输出与主进程加载路径一致。
2. 执行目录打包和包内检查，确认 `out/**`、内置 pi、preload 和资源都进入最终包。
3. 启动解包版本，验证窗口显示、主进程 IPC、内置 pi 握手、浏览器面板和用户数据路径。
4. 检查 `release/砚数据/` 中现有数据在升级/换包后仍可读取；不要把发布目录中的用户数据当缓存清理。
5. 通过后再考虑生成新的安装包、便携 ZIP、SHA256 清单；代码签名仍受证书限制。

完成条件：`dist:dir`、`test:packaged` 和最小真实启动均有本轮输出；安装包内 preload 能加载，已有用户数据不被覆盖。

## 三、第二阶段：文件树交互收尾（高优先级）

目标：把“已有附件/预览能力”补成完整的项目文件树体验。

- 单击文件只选中并打开只读预览，不改变草稿；“加入上下文”作为独立动作并给出反馈。
- 使用 tree/treeitem 语义实现上下左右、Enter 和加入上下文的键盘操作；保持单一游走焦点。
- 补齐隐藏项、排序、路径显示、空目录、无权限、路径失效、读取中和结果截断等状态。
- 为异步目录读取加入 `cwd/projectId/代次` 校验；切换项目后丢弃旧请求，清缓存时同步重置 loading。
- 搜索区分“已加载节点过滤”和“整个项目检索”；项目检索需要结果上限和取消，并默认跳过大型依赖目录。
- 写入工具完成后只使相关父目录失效并局部刷新，不逐 token 刷新整棵树。

完成条件：真实项目下单击、加入上下文、键盘导航、中文空格路径、切项目竞态、无权限和大目录均有探针或原生窗口证据；窄右栏和内置浏览器同时打开时不越界。

## 四、第三阶段：子代理安全与可用性（高优先级）

目标：在保留当前自有进程适配的前提下，避免子代理与主会话争用工作区。

- 为写入型子任务创建独立 Git worktree 或等价临时工作目录；只读任务可继续使用受控 cwd。
- 明确子任务的变更预览、批准、合并或放弃流程，并记录变更归属。
- 处理并发上限、超时、停止、恢复、退出和切换 cwd 时的清理；禁止子代理嵌套起代理。
- 保持转录有界，避免将子代理用量重复计入父会话。
- 评估模型自动委派的上行协议；在没有稳定上游扩展协议前，继续保留 `/subagent` 和程序化入口，不宣称自动委派已完成。

完成条件：两个并行写入任务不会改动主工作树；用户能查看差异并决定合并/放弃；异常退出后没有残留子进程或临时工作树。

## 五、第四阶段：审阅、浏览器和数据归属

目标：把已有安全边界从“默认策略”推进到可审阅、可解释的工作流。

- 浏览器权限增加按站点的明确授权/撤销；保留默认拒绝和请求记录。
- 对本地回环、私有地址和 DNS 重绑定边界补充策略和测试；下载继续显示来源且不自动打开。
- 将 shell 或第三方工具造成的文件变化纳入会话级前后快照，或清楚标记为“无法归属”；不能把推测当证据。
- 将回复详细程度记录到每轮历史，区分全局设置和该回合实际档位。
- 对外部 Chrome 的 Cookie、页面存储和登录状态继续使用准确措辞，并安排目标网站上的人工验证。

完成条件：授权、撤销、拒绝、下载来源、写入归属和每轮档位均有可追溯记录；网站登录迁移只有在真实网站验证后才能标记通过。
