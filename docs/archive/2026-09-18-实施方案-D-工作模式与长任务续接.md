## 3. 统一状态契约
拟新增 src/shared/work-mode.ts、src/main/work-mode-service.ts、goal-controller.ts、handoff-service.ts；pi 侧新增 work-mode.js 适配层。
~~~ts
type WorkMode = 'standard' | 'clarify' | 'autonomous';
type ModeState = {
  mode: WorkMode; revision: number; pendingMode?: WorkMode;
};
type GoalState = {
  goalId: string; revision: number;
  phase: 'clarifying' | 'planning' | 'executing' | 'verifying' |
    'completed' | 'blocked' | 'stopped';
  objective: string; constraints: string[]; acceptance: string[];
  sessionId: string; segmentId: string;
  successfulAutoCompactions: number;
  continuationCount: number;
};
~~~
所有请求/推送带既有 RuntimeEnvelope；runId + generation 做迟到隔离，pending sessionId 转正式 UUID 按既有机制处理。模型不自行指定可写的会话。
模式按会话保存，首次落盘前按 runner 临时身份持有；新会话默认值在 desktop.json.defaultWorkMode。旧 autonomous=true 迁为 autonomous，否则 standard；新字段优先，迁移幂等。
入队消息保存模式版本快照；运行中切换只对下一轮生效并显示 pending。澄清就绪是专门的原子转移，可在安全边界自动继续。
默认模式、当前模式、运行中模式不能混成一个全局布尔。A 会话切模式不得改变 B 的 question 行为。
goalId 覆盖同一用户目标的多轮/多段；一般补充更新当前 goal，明确新目标才新建。任务已完成后用户新要求不复用旧 completed 状态。

## 4. 菜单与快捷键
- 原位显示“标准/澄清/自主 ▾”，菜单单选项带一句说明。
- IME 组合态最高优先；补全菜单打开且有候选时 Tab 保持填入。
- 无修饰键、普通输入框聚焦、无补全时 Tab 循环模式；长文模式保持原编辑/焦点行为。
- Shift+Tab 维持思考强度；模态/表单不抢 Tab。
- 模式菜单用方向键、Enter/Space，Esc 关闭；Tab 离开菜单。
- 设置提供关闭 Tab 快切；输入框 Esc 在无补全时可把焦点移到模式按钮，避免键盘陷阱。
- 保留草稿、选区、附件；切换不发送消息。
- 自主运行才有运行光带；澄清等回答显示真实等待状态。使用现有 tokens，新增先改 DESIGN。
- 模式提交失败恢复已确认值并显示错误，不出现 UI 已自主而扩展仍标准。

## 5. 澄清门槛与自动开工
“95%”是模型理解自评，不是成功概率。ready 条件：
confidence >= 0.95，目标/交付物/范围/约束/验收齐全，无关键未决，无未回答必要问题，modeRevision 和 goalRevision 未过期。
用户已给的信息不重复问；可从仓库查的先查；低影响事项用假设。每次 1 个关键问题，独立问题可同组。
拟建 clarification_ready 工具返回结构化理解；宿主验证字段、身份和状态，模型自评不能替代这些校验。

转移：
clarifying → ready 校验 → 原子提交 mode=standard 与 goal=executing → 显示理解摘要 → 内部 resume 一次。
内部继续使用唯一 operationId；模型调用工具成功后不能额外向用户要“是否开始”。就绪摘要不是伪造用户消息，应作为宿主控制消息留痕。

必须验证当前 pi 能否在同一工具循环刷新有效模式和工具集。不能仅改 desktop.json 就假设 before_agent_start 重跑：
- 可安全切换时，由宿主提交后确认新策略再继续。
- 不可安全切换时，在边界结束澄清轮、持久化续行记录，再启动标准轮。
两条路径都不得抢先执行实现工具或重复发用户目标。

澄清只读门禁覆盖所有工具调用入口；write/edit/bash/脚本/MCP/第三方 unknown 不得仅靠提示词限制。允许经审查的只读查询白名单，不对任意 shell 命令做脆弱的字符串“只读”判断。
question 取消/超时/无 UI/失败：保持未就绪，不沿用旧“猜一下继续”行为。用户主动切标准或自主则以新模式更新，不再等待过期答案。

## 6. 自主持续执行与停止
阶段：planning → executing → verifying → completed。可推进但未完成就按条件继续，不能一次 assistant 文本结束便默认目标完成。
拟建 goal_report 工具提交剩余步骤、证据、阻塞；宿主校验当前 goal/revision 与检查结果。任务清单勾选仅是展示材料，不足以证明完成。
默认同一无变化失败连续两次转 blocked；有新证据/新路径才重试。外部凭证或授权缺失如实报告，不能为了“不提问”扩大授权。
用户停止优先：撤销未发续行、标 stopped、取消在途可取消调用；迟到工具结果可登记事实，不能再启动下一步。取消不能保证外部操作回滚，状态未知要明说。
内部续行、用户队列和新消息由同一调度器排序，用户消息优先于尚未发送的内部续行。持久化消费点防重复；后台会话完成不抢当前视图。

## 7. 长任务预算门（先于续接）
保留 shared/context-policy 作为预算唯一公式源；默认 240k 受窗口/输出预留/余量/用户覆盖限制。
新增每次模型请求前的预算诊断：系统提示、工具 schema、Skill、项目知识、变换后历史、图片估算、输出预留。实际 input usage 用作校准；不要重复累计 cache token。
soft budget 命中：先清理旧工具结果，仍高则安排安全压缩；物理风险命中：不发送已知装不下的请求。
工具调用与结果必须成对保留；大结果摘要+可召回原文，不能静默丢约束。单条用户输入本身超预算时明确提示，不循环压缩无效历史。

D0 在隔离 pi 中证明安全点：
1. 一条用户消息引发多次工具循环，记录 context/provider 请求及 settled 时序。
2. 验证当前 hook 能否阻止下一请求、能否完整落盘并进入 compact。
3. 禁止在 before_provider_request 内递归 compact 或等待自己完成。
4. 无可用安全暂停 API 时，走支持的 pi 升级/适配；不修改 vendor 生成物。未补齐前只能交付“软预算/预警”，该硬门工程项仍未完成。

界面明确区分工作集、目标预算、模型窗口和估算/真实来源；超限等边界显示“等待安全压缩”。不得把过去请求 usage 当当前未来请求精确值。

## 8. 自动压缩计数和续接资格
当前 goal 的 segment 中，成功自动完整压缩累计到 2；下一次正常策略压缩需求触发 handoff。
手动压缩、tool sweep、state refresh、失败/取消不计。policy/native 自动事件用唯一 compactionId 去重；重启后还原计数，不能重置躲开阈值。
原生自动压缩没有事前拦截能力时，允许安全压完后接续，记录实际次序；不能宣称总是第三次之前。
紧急物理保护优先压缩，goal 已完成不续接；有未完成子代理/长命令先等待，不遗弃后台工作。
默认连续自动续接上限建议 3，可配置；到上限保留任务并报告需介入原因，不标 completed。
本策略只对自主模式默认候选；先完成真实长任务验证后再开启默认值，不能用压缩次数证明移交有益。

## 9. 交接包与事务
交接包包含：用户目标/最近补充、约束与授权、验收标准、已完成证据、未完成和失败原因、文件/Git/长进程状态、项目及 cwd、模式/模型、sourceSession/sourceHead、附件与召回来源。
TaskState 仅是带 freshness 的材料；不能把旧总结升级成事实。摘要建议 4k–8k tokens，按目标窗口收缩；约束超预算时失败降级，不静默裁掉。
不在交接包复制凭证；不把全部历史重新灌进新会话。

事务：
pending → snapshot → validated → destination-created → committed → resumed。
- 锁定 goal 调度，工具完整结束后截 sourceHead；用户新消息进入有序日志。
- 生成校验交接包；水位变化重建。
- 同项目/cwd 创建目的会话，写关系与交接包，尚不执行。
- 提交 activeSegment，旧 runner 释放 cwd 执行租约，新 runner 获取；不得绕过同 cwd 防线。
- 用 resumeId 发送一次，JSONL 消费证据确认 resumed。
- 每一步写可恢复日志；崩溃在发送后确认前，通过消费证据判断，不盲发两遍。
- 失败保留源会话；未提交回源，已提交按日志恢复目的；任何时候只允许一侧执行。

附件、相对路径、模型能力与权限重新绑定验证；源 ctx:// 引用需通过同 goal 授权的只读来源解析，不复制字符串就宣称可召回。
source 文件被删/移动则明确缺失；不得恢复 get_tree 或全局任意会话访问。
交接中用户停止废弃自动 resume；新消息按提交后的 activeSegment 只消费一次；没有消费去重支持不允许开启默认自动续接。

## 10. UI 与观测
源会话显示“已续接至…”，新会话显示“接续自…·第 N 段”与交接摘要；旧 JSONL 不重写。
用户正在看源会话时可跟随；已切走只标未读。失败显示处于哪个阶段、可继续位置。
记录 modeRevision、goalRevision、requestId、budgetSource、压缩原因/结果、handoffId、resumeId、sourceHead；不默认记录完整模型提示和凭证。
“任务继续了”要有实际新 runner 调用/消费证据，不靠提示动画。

## 12. 验收与故障用例
| 场景 | 必须取得的证据 |
|---|---|
| Tab/IME/补全/长文/弹窗 | 真 Electron 按键与焦点，不仅调用 handler |
| A 自主、B 澄清、排队后改模式 | 两会话实际工具行为与模式快照正确 |
| 模糊请求逐步澄清 | 取消不执行；条件齐全自动标准执行恰好一次 |
| 自主未完成与停止 | 能继续，停止后无新请求；blocked 不假装完成 |
| 单轮工具结果增长 | settled 前安全预算处理；诊断与真实请求相符 |
| 第三次压缩需求 | 计数准确，源/目标关系、实际工作继续可核对 |
| 崩溃/磁盘失败/用户插话/迟到结果 | 不丢原会话，不双写，不重复外部动作 |
| 深浅/窄窗/运行光带/续接卡 | 真实窗口截图与交互，截图另存 |
| 解包/便携版 | 适配层和事务状态持久化，无开发路径依赖 |

新场景名由实施时登记 CASES，真实模型场景 cost:1；在隔离数据目录运行，先 build。旧 autonomous/ask/hotkeys/slashcmd/queue/contexttakeover/sessionrunners 做关联回归，历史失败单独注明，不能借删断言通过。
每阶段把实现/自动检查/真实运行/视觉验收/应用与包/剩余限制写入 HANDOFF，全部有证据才勾选。

## 13. 回滚与文档
模式功能可回落 standard/autonomous 兼容配置，保留会话元数据；关闭 handoff 仅停止新移交，已提交事务仍需安全恢复。
不得删除旧/新会话来“回滚”；goal stopped 不重启。
更新 PROJECT、CODE-MAP、TESTING、HANDOFF 和用户快捷键说明；旧设计提案加指向本文的入口时保留原历史，不复制两个相互竞争的实现状态表。
本方案不保证模型自评准确或摘要无损；交付重点是状态可信、失败可恢复、能力受控、用量可核查。
