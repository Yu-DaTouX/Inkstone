## 4. 数据与工具契约

> **已定稿（2026-09-18，S1）**：下面这张表已落成代码与单测，细节与取值见
> [证据-02-S1 §2](../evidence/证据-02-S1-兼容性与契约.md)；实现时**直接扩 `src/shared/task-plan.ts`，不要另定义第二份**。

**第一阶段保留旧标识以减少历史兼容改动**：旧会话里的 `customType: 'left-panel-tasks'` 仍按原样读取；
新增写入走宿主日志。显示名统一为「任务计划」。

> **宿主日志的物理落点（S3 定稿，已有代码与取证）**：
> `YAN_DATA_DIR/task-plans/<sessionId>.jsonl`（**只追加**，一行一次提交）。
> **不写进会话 JSONL**：pi 的 RPC 没有「追加 custom entry」命令，而 01 §5 又明文禁止
> 外部编辑正在使用的 JSONL、也禁止用扩展 `appendEntry` 写新任务数据（
> 判定过程与代价见 [证据-02-S3 §1](../evidence/证据-02-S3-宿主任务服务.md)）。
> 行形状：`{ id, round, at, data: { schemaVersion, revision, operationId, todos } }`。

**操作**：`set` / `add` / `complete` / `uncomplete` / `remove` / `clear`。

| 规则 | 要求 |
|---|---|
| `items` | `text` 非空的数组；`done` 默认 `false` |
| `index` | **从 1 开始**的整数；越界**不得修改状态**，返回可读错误 |
| `set` 空数组 | 明确等同清空 |
| `add` 空数组 | 拒绝 |
| 上限 | 最多 **200 项**、每项 **2,000 字符**；超过返回可读错误，**不悄悄截断** |
| 串行 | 操作按会话串行；每次以**已提交的最新快照**为准；**禁止**共享模块级全局 `todos` |
| 落盘 | 仅当写入成功后返回成功；**不能照搬旧扩展「吞掉落盘失败」的处理** |
| 取消 | 提交前取消 → 不写；提交后取消 → 返回**已提交结果**，避免用户误重试 |

**数据结构**：保留兼容字段 `data.todos`；新增 `schemaVersion` / `revision` / `operationId`。
`operationId` 绑定**会话 + 工具调用**，重试**不得**重复 `add`。
历史文件**不回写、不批量转换**。

**恢复语义**：

- 恢复 / 切会话 / 分叉：从**当前有效会话条目**还原，而不是从「最近一个任意会话」的缓存还原。
- 空会话无快照 → 返回空列表。
- 分叉后只写当前分支。

**工具不代表另一台 agent，也不调额外模型。**

### S3 · 宿主任务服务 + `yan tasks apply` + 会话日志（规模 1–1.5 天）

- 宿主日志条目：`sessionId + branchHead + revision + operationId`；原子更新。
- `yan tasks apply --request-file task-update.json`：校验身份（`runId` / `generation` / 项目 / 操作 ID），
  **拒绝**模型自报任意 `sessionId` / `projectId`。
- 操作回执：包含 `operationId`、结果 revision、实际变更项，供 UI 与模型核对。
- 接入 AgentController 生命周期：两会话操作不串、停止与重启可恢复。

**出口**
- 两会话并行操作不串数据。

- 幂等：同一 `operationId` 重放只生效一次。
