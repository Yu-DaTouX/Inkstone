## 2. 三条硬约束（改动 Git 这一层时**不要拆掉**）

1. **写操作只在一个文件里**：`src/main/git-actions.ts`。
   `git-service.ts` / `git-diff.ts` 里**没有** `add` / `commit` / `switch` / `reset` / `stash` ——
   所以「哪些代码能改用户仓库」是一眼可答的问题。
   **也不要**复用 `subagent-isolation.collectDiff()`（它会 `git add -A`）。
2. **不覆盖用户改动**：不 `stash` / `reset` / `clean` / force push，**不跳过 hook**（不传 `--no-verify`）。
   脏工作区能不能切分支**由 git 自己判**。
3. **预期版本按动作分级**（`commit` 全比 / 未指定起点的新建分支只看 HEAD / 其余不比）。
   分级不是偷懒：一律全比会造出**假冲突**（连点两个文件的暂存、提交后立刻推送都会被拒），
   而假冲突的代价是用户学会无视那句提示。

## 4. 已知限制（**不改就是已知行为，不是待办**）

在决定「做」之前，这些是**有意的取舍**，不要当缺陷修：

- 审查面板是**右栏的宽档位**，不是主内容区（取舍见归档件 §16.4）；**宽度不支持拖动**。
- **没有「按行 / 按块暂存」** —— 已明确列入 **v2 backlog**（不是待办，也不是缺陷）。
- **没有「丢弃工作区改动」** —— 整个 Git 集成里**唯一不可恢复**的操作，**默认不做**。
  方案 §5.1 明确要求不覆盖用户改动；要加它**先要有**「哪些文件会被覆盖」的完整预览与二次确认。
  **「丢弃前自动导出 patch 备份」这个折中已被否**（2026-09-18 二轮咨询，见
  [二轮记录 §2.1](决策记录-二轮外部咨询-2026-09-18.md)）：
  它把「绝对不可恢复」降成「有恢复路径」，**但不是真正可逆** ——
  普通 `git diff` 不含未跟踪文件，`core.autocrlf` 的换行转换与 `submodule`（gitlink）
  都可能让补丁**应用不回去**；更糟的是「已备份」的文案会让用户放松，**反而提高误操作概率**。
  （注：`git diff --binary` 确实能表达二进制改动 —— 所以「二进制没法备份」这个理由**不成立**，
  不要写进文档。真正站不住的是上面三类。）
  真要开先补边界用例：`rename` / 未跟踪文件 / `autocrlf` / `submodule` 四种，
  其测试与确认成本远高于普通 Git action。
- 「已查看」存在渲染端 `localStorage`（本机有效、不跨设备）；
  键含仓库 / 工作树 / 范围 / 两侧内容指纹，**内容一变即失效**。
- 展开上下文**一次最多 300 行**，超出只提示还有多少行。
- 切换分支的阻断判据是「该 `cwd` 有 running 的 runner」；
  **别的进程**（终端里的 git、编辑器）不受我们控制，只能由 git 自己的 lock / 检查兜住。
- 「来源」菜单**不显示**「已读取」与「本轮已参与上下文」—— 证据不足时不显示（方案 §8）。
- 「带历史继续」的**反模式**（S2b 形态定下时明确禁止，见[决策记录](决策记录-07-S2b-工作树会话形态-2026-09-19.md)）：
  同一 session 动态换 cwd、memcpy 式复制 session JSONL（尤其复制后只改 cwd）、
  自动继承目录权限、绝对路径前缀替换。
- 工作树会话的**附件第一版不迁移**（P1）：界面要如实说「N 个附件未带入，需要时可重新授权」，
  不做自动搬运 —— 用户本机文件系统路径的授权不让它跟着走。

**测试注意**：`gitreview` 用「退出后逐字节比对 `status` / `ls-files -s` / `diff --cached --numstat` / `HEAD`」证明只读，
并做了三条反向验证；改这一层后**必须重跑它**。写操作成功后界面手里的 `expected` 要**就地更新**（用响应里带回的状态），
否则会出现假冲突（这是 G2 这一轮真实抓到的设计问题）。
