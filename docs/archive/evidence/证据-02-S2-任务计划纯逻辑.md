## 1. 本片定稿的规则（S3 的 `yan tasks apply` 照这个实现）

### 1.1 校验（严格，只用于新写入）

| 输入 | 规则 | 失败码 |
|---|---|---|
| `operationId` | 必填、非空白 | `missing_operation_id` |
| `action` | 必须是六个之一 | `unknown_action` |
| `items` | 必须是数组；每项是对象 | `bad_items` |
| 项的 `text` | 必须是字符串、去掉空白后非空 | `empty_text` |
| 项的 `text` 长度 | ≤ 2000 **code point** | `text_too_long` |
| 项的 `done` | 只能是 `true` / `false` / 省略 | `bad_done` |
| 总数 | `set` 后 / `add` 后 ≤ 200 | `too_many_items` |
| `index` | 整数、≥ 1 | `bad_index` |
| `index` 范围 | ≤ 当前清单项数（**越界不得改状态**） | `index_out_of_range` |
| `add` 的 `items` | 不能是空数组 | `empty_add` |

### 1.2 六操作语义

| 操作 | 结果 | 回执 `changed` |
|---|---|---|
| `set` | 整体替换；**`set []` = 清空**（契约明文允许） | `replaced` |
| `add` | 追加到尾部；空数组**拒绝** | `added`（带 1-based 序号与文字） |
| `complete` | 第 `index` 项 `done:true`，`status:'done'` | `completed` |
| `uncomplete` | 第 `index` 项 `done:false`，`status:'pending'` | `uncompleted` |
| `remove` | 删第 `index` 项，其余保持顺序 | `removed`（带被删文字） |
| `clear` | 清空（对空清单也成功） | `cleared` |

### 1.3 三条不变式

1. **幂等**：`operationId` 与上一次提交相同 → 原样返回上一次状态（同一对象引用）、
   `revision` 不涨、`changed` 为空、`replayed: true`。这是「重试不重复 `add`」的唯一实现点。
2. **失败即不动**：任何校验失败都返回错误，**不做部分修改**（单测逐条比对失败前后的状态快照）。
3. **`revision` 只在成功提交时 +1**；失败不涨，重放不涨。

### 1.4 历史读取

`readTaskPlanEntry(data)` 是新旧载荷的**唯一**读入口：

- 旧载荷（旧扩展）→ `schemaVersion: 0`、`revision: 0`、`operationId: null`；
- 宿主载荷 → 三个账本字段照读；
- `schemaVersion` 有值但对不上 → `undefined`（**读不了就当没有**，不按旧规则猜）；
- `todos` 不是数组 / `data` 不是对象 → `undefined`（**不**回空清单 —— 「不认识这份数据」
  与「这是一份空清单」必须能分开，否则一条坏数据会把整轮任务历史显示成「已清空」）；
- 条目里的坏项**逐条丢掉**，不因此丢掉整份历史（历史宽容、新写入严格）。

## 2. 相对前一版契约收紧的四条（都是「宁可不猜」）

| 项 | 旧行为（旧扩展 / S1 前的解析） | 现在 | 为什么 |
|---|---|---|---|
| `done` 不是 boolean | `Boolean(x)` → `"false"` 变成 **true** | `bad_done` 报错 | 静默给出相反结果是最坏的一种「成功」 |
| 长度上限 | 无 | 2000 **code point**（`👍` 算 1） | 用 `String.length` 会让 1000 个 emoji 就被判超长（CJK/emoji 场景已经在 N21-11 踩过一次同类问题） |
| 超上限 | 旧扩展不校验 | 报错，**不截断** | 截断会让模型以为写成功、用户看到另一份清单 |
| `uncomplete` 的 `status` | 旧扩展没有 status 概念；S1 的解析会保留旧 `status` | 明确置为 `pending` | 留着 `running` 会让右栏继续显示「正在进行」（`RightPanel` 以 status 优先） |

## 6. 交给 S3 的接口

1. **先校验、再落盘**：`validateTaskRequest(request, current)` 过了才动磁盘 ——
   校验失败不该留下半个 `revision`。
2. **写**：`toTaskPlanEntryData(state)`（带 `schemaVersion`；漏了会让读回来读歪）。
3. **读**：`readTaskPlanEntry(data)`；`undefined` = 「这条数据不认」，别当空清单。
4. **CAS 与幂等**：用 `state.revision` 做比较交换，用 `state.operationId` 判重放；
   两者都要**从会话文件读回来**，不能靠进程内缓存。
5. **身份**：`operationId` 由宿主生成并绑定会话（复用 01-S2 的端点身份校验），**不由模型自报**。
