## 2. 架构决定
采用“砚拥有业务逻辑 + 随包 pi 适配层”的路径。主/渲染进程不得 import pi 内部模块；resources/pi-runtime 是生成物，不修改。
建议新增（以下路径均为拟建）：
- src/shared/task-plan.ts：操作校验、纯 reducer、版本化结构。
- resources/pi-extensions/task-plan.js：仅注册模型工具、会话读写、事件桥接；不含终端布局。
- 必要的编译/资源复制入口：保证适配层能导入随包的共享逻辑，禁止只在开发 cwd 下能解析。
- src/main/builtin-capabilities.ts：内置能力身份、来源、显示名；供方案 C 复用。

“用户不作为扩展看到”是产品归属，不要求规避 pi 的正式工具注册机制。UI 来源由受信内置清单和实际加载路径决定，不能仅凭工具名字把第三方冒充为内置。诊断仍能看到真实加载路径和版本。

## 3. 数据和工具契约
第一阶段保留模型工具名 panel_todos 与 customType left-panel-tasks，减少历史兼容和调用刷新改动。用户显示名改“任务计划”；名称兼容不等于还依赖外部扩展。
操作保留 set / add / complete / uncomplete / remove / clear：
- items 为 text 非空的数组，done 默认 false；index 为从 1 开始的整数。
- set 空数组明确等同清空；add 空数组拒绝；下标越界不得修改状态。
- 建议限制最多 200 项、每项 2,000 字符；超过返回可读错误，不悄悄截断。
- 操作按会话串行；每次以已提交的最新快照为准，不能共享模块级全局 todos。
- 仅写入 appendEntry 成功后返回成功；旧扩展吞掉落盘失败的处理不能照搬。
- 支持取消，提交前取消不写；提交后取消返回已提交结果，避免用户误重试。

保留 data.todos 兼容旧读者；可增加 schemaVersion、revision、operationId。operationId 绑定会话与 toolCallId，重试不得重复 add。历史文件不回写、不批量转换。
恢复/切会话/分支：从当前有效会话条目还原，而非从最近一个任意会话缓存还原。空会话无快照时返回空列表；分叉后只写当前分支。
工具不代表另一台 agent，也不调额外模型。任务勾选不自动等于整个目标已验证完成；方案 D 的 goal 是独立执行状态。

## 4. 旧扩展共存是第一项技术门槛
不得直接同时注册两个 panel_todos，也不得删除或修改用户的 left-info-panel.ts；不能只把其 UI 隐藏后声称已迁移。
实施 agent 先验证**当前打包 pi 版本**的扩展发现、排除和工具冲突行为，写入本方案实施记录：
1. 隔离 piDir 中放置旧扩展和一个无关扩展，记录实际来源清单与工具注册结果。
2. 验证是否能在砚启动配置中只排除该旧扩展，保留其他扩展/包/技能。优先使用官方支持的资源筛选；不猜测命令行参数。
3. 若需要 no-extensions + 显式受控列表，必须验证能完整重建用户/项目/包的扩展来源、配置启用状态、顺序和相对路径；不能顺手禁用所有第三方。
4. 不能完整实现选择性排除时，内置化的“已迁移用户”验收不得通过；可先完成干净环境支持，并给已有冲突用户提供明确诊断。不能用加载顺序碰运气解决。
5. 来源匹配按规范化真实路径与可验证来源识别，不以 basename 全局过滤，防止误伤其他同名扩展。

排除仅对砚的启动生效，不改用户独立 pi 终端。旧工具和旧命令仍可在用户自己的终端使用。不通过“替用户卸载插件”解决冲突。

## 5. UI 与命令处理
- 现有任务清单、历史快照折叠和状态样式保留。
- 工具卡对受信内置来源显示“任务计划”，参数和错误仍可查看。
- /panel 从默认命令补全隐藏；手打时显示“终端面板命令不适用于砚，任务由内置任务计划维护”，不清空草稿和附件。
- 来自旧扩展的同名 runtime 命令也按**来源**排除，避免仅删除 compatibility 项后反而可执行。
- /footer 与此无直接关联；可统一改兼容命令失败反馈，不额外迁移 footer。
- 插件/资源界面将受信内置能力与用户安装包区分，内置任务工具没有卸载按钮；不能把整个旧扩展包从诊断里无条件抹去。
- 国际化、键盘焦点、深浅主题沿用现有机制；新增令牌先更新 DESIGN。

## 6. 实施步骤及每步出口
A0：复核基线、保存旧 schema/真实失败行为，完成 §4 能力探测。出口：无冲突装载策略已证明。
A1：提取 reducer 与校验、编译资源路径、工具适配层。出口：无旧扩展时工具可注册并真实写会话。
A2：接入 AgentController 生命周期与来源元数据。出口：两会话操作不串、停止与重启可恢复。
A3：命令/工具展示更新、旧用户共存。出口：没有 TUI 面板提示，其他扩展仍正常。
A4：真实模型调用、视觉与解包验收、文档同步。出口：六栏齐全才标完成。

## 7. 验证要求
纯逻辑：六操作、非法输入、不变性、revision、幂等、空列表、历史解析。
真实文件：落盘失败不得报成功；重启读取；分支快照；历史 JSONL 字节不被重写。
真实 Electron cost 0：干净 piDir、旧扩展+无关扩展、跨会话、手打 /panel 草稿不丢、工具卡来源。
真实模型 cost 1：给一个确实需要多步执行的可控任务，要求模型使用任务计划，核对工具调用、实际 JSONL、原生任务清单三者一致；不能仅造 fixture。
回归现有 todos / todonew / slashcmd / sessions / historyswitch；todos 历史红需先区分旧断言和真实回归，不能改成跳过来获绿。
包：没有本机 ~/.pi 配置的隔离解包实例仍可执行任务工具；复制资源齐全。
失败恢复：扩展冲突、RPC 重启、取消、磁盘错误、两个快速 add，均不得丢数据或误报。

## 8. 交付、回滚与限制
关闭内置工具开关即可停止新写入，历史保持可读；恢复旧装载策略时不可重复注册。回滚不触碰旧用户扩展或会话。
更新 PROJECT、CODE-MAP、TESTING、HANDOFF 的当前说明；把“扩展提供任务”改成真实的新职责。必要时将 AGENTS 的边界改成“面板保持现状，任务工具由砚内置”，不放宽其它边界。
六栏必须分别写：实现 / 自动检查 / 真实运行 / 视觉验收 / 应用与包 / 剩余限制。
本方案不承诺模型永远主动调用工具，须通过来源明确的短工具指导与真实测试验证。未解决旧扩展冲突不算完整交付。
