## A. 需要你先决定

### A1. 方案 5.1 的「紧凑 / 舒适」密度 —— 唯一没实现的功能项

方案原文：「增加"紧凑 / 舒适"密度，而不只依赖整窗缩放。」

现状：全仓没有任何 density 相关逻辑。现在只有整窗缩放（`Ctrl+=` / `Ctrl+-` / `Ctrl+0`，
对齐整数设备像素，避免中文发虚）。

要做的（如果做）：

- `AppSettings` 加 `density: 'compact' | 'standard' | 'comfortable'`，默认 `standard`
  （即当前观感，**不能改变老用户的界面**）。
- 用 CSS 变量驱动，不要散落改值：新增一组 `--d-*`（行高倍率、区块间距倍率、
  消息间距），由 `html[data-density='…']` 覆盖，各组件引用它们。
- 设置 → 外观加一档分段控件（照 `set-send-key` 的写法）。
- 验收：探针测三档下同一元素的实测尺寸确实不同 + 档位落盘 +
  **`standard` 档与历史截图一致**（用 `YAN_SHOT_DIR` 出图对比）。

风险：这是一次**全局尺寸**改动，会碰到几乎所有布局。建议单独一轮做，别和其他改动混。

### A2. 推理窗口要不要支持「用户调整尺寸 + 记忆」

方案 4.2 写的是「推理和终端默认内容自适应，并设置高度上限。**用户主动调整大小后再记忆尺寸**」。
终端两条都做了（三个拖拽把手 + 双击复位 + `localStorage` 记忆）；
推理窗口目前只有「自适应 + 上限」，**不可调整**。

已经改掉的那半：固定 `height: 25vh` → `max-height: min(25vh, 420px)`
（原来 4 行推理在 227px 的框里空 2/3）。

剩下的是「要不要让它可拖」。你说了算：

- **要**：照 `Terminal.tsx` 的把手写法加，记忆放 `localStorage`（按会话还是全局？）；
- **不要**：那这条就算结项 —— 因为「用户没调整过」时本来就该用自适应高度。

### A3. `4.4` 剩下的两个尾巴

1. **`blocked` 没有单独的 UI 样式** —— 类型和解析都支持了，界面仍显示成「未完成」。
   要不要给它一个区别于「未完成」的样子（比如黄色感叹号）？
   ⚠️ 前提是真实数据里**真的会出现**这个值 —— 写清单的是 pi 侧的扩展
   （`panel_todos`，不在这个仓库），我没法确认它会不会写 `blocked`。
2. **计数口径**：「已完成 N/M」现在就是清单自己的口径。方案问的是
   「计数是否以工具协议为准」—— 那需要**第二个来源**跟它对账，目前没有。

## B. 可以直接做（不需要你输入）

### B1. 工具详情展开 / 收起后的滚动位置

验收清单里那条「推理和工具详情展开、收起后滚动位置合理」，目前只有推理窗口有粘底断言
（`reasoning` 探针），**工具详情展开后的滚动位置没测**。

做法：在 `toolrow` 探针里展开一个终端窗口（它比推理窗口高得多），断言
「展开后当前那条仍在视口内 / 不会被顶出屏幕」，收起后同理。

### B2. UiDialog / 引导页在浅色下的表现

`light` 探针第 6 节现在扫「浅色主题下不该出现深色块」，覆盖了左栏 / 中栏 / 右栏 / **设置面板**，
但没覆盖扩展 UI 对话框（`UiDialog`）和引导页（`Onboarding`）—— 这两个都是独立的一层。

做法：把第 6 节的扫描函数复用到这两个容器上（打开方式：`UiDialog` 需要扩展发
`extension_ui_request`，可以走 `dialog` 探针里现成的注入路径；`Onboarding` 清
`localStorage` 里的 `yan.onboarded` 再 reload）。

### B3. 「全键盘可以完成设置操作」

`dialog` 探针已经覆盖了「Tab 圈定 + 焦点不逃逸 + Esc 关闭 + 焦点恢复」，
但没覆盖「**只用键盘走完**一遍设置流程」（切 tab、改一项、确认生效）。

做法：在 `dialog` 探针里加一段纯键盘操作（Tab + Enter/Space），断言没有任何一步需要鼠标。

### B4. `sound` 探针偶发失败（flaky）

第一次批量跑失败、单独跑必过、第二次批量跑又通过。
`features.js` 里有一条同类注释（「定时假设太紧，负载高时 900ms 不够」），
`sound` 大概是同一类问题，值得照那个思路把固定 `sleep` 改成轮询。

## C. 需要你指认

### C1. 4.2 的视觉微调

方案要求的「减少重复边框、收敛强调色、统一图标与文字比例」**没做** ——
因为「密度是否合适」是审美判断，靠读 CSS 不可靠。

现在**基线有了**：

```bash
YAN_SHOT_DIR=/tmp/uishot npm run shots     # 深色主界面 / 浅色 / 推理窗口 / 设置
```

（`read` 工具能直接看图。上一轮靠它抓出了两个真 bug：浅色下终端里的白底参数块、
设置页文案里的 markdown 星号。）

**已排除的**（查过，不是问题）：
- 主题令牌完整：`:root` 43 + `dark` 29 + `light` 36（`dark` 故意不重复定义 `--think-*`，继承 `:root`）；
- 8 处硬编码 `#fff` 逐个看过，都有理由（实心强调色/成功色上的白字、Windows 关闭按钮、
  浅色下的白底复选框、浏览器视口）；
- 浅色主题下没有意外的深色块（`light` 探针第 6 节）。

所以这一项要的是**你指出具体位置**：哪块觉得挤、哪条线觉得多余、哪里的图标和文字比例别扭。
指哪打哪，改完用同一套基线对比。
