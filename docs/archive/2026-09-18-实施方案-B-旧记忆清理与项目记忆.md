## 3. 新系统的职责
分三层：
1. 项目规则：用户决定、技术约束、现有权威文档索引。
2. 项目经验：经过验证的原因、修复、流程；带证据和适用版本。
3. 当前任务状态：继续交给现有 TaskState/方案 D goal；不重复存入长期知识。

现有 AGENTS/PROJECT/HANDOFF/MAINTENANCE 是外部权威材料，先索引引用，不再复制整份内容进数据库。AGENTS 仅放短入口，不把所有记忆常驻注入。
新项目默认关闭，用户在项目设置开启一次；启用后读取已确认知识、自动生成候选，不逐条打断。模型推断不能自动升为“用户决定”。用户在任务中明确要求记住且项目已启用，可直接形成带原话的确认条目。

## 4. 存储与数据结构
建议新增 src/main/project-memory-store.ts、project-memory-service.ts、src/shared/project-memory.ts；路径均为拟建。
采用主进程单写者管理的项目目录：YAN_DIR/project-knowledge/<projectId>/。projectId 来自项目登记，不使用可变标题，也不信任模型传来的任意 cwd。
首版采用不可变 revision 文件 + 原子更新 manifest；检索索引可重建。临时文件与目标同卷，提交失败保留上一 manifest；多进程实例用排他锁，过期锁必须核实进程再回收。

条目契约：
~~~ts
type ProjectKnowledge = {
  id: string; projectId: string; revision: number;
  kind: 'decision' | 'constraint' | 'fact' | 'procedure';
  status: 'candidate' | 'active' | 'superseded' | 'deleted';
  text: string; tags: string[];
  evidence: Array<{ sessionId?: string; entryId?: string;
    file?: string; digest?: string; excerpt?: string }>;
  confidenceClass: 'user-confirmed' | 'verified' | 'inferred';
  createdAt: string; updatedAt: string;
  validFor?: { branch?: string; commit?: string; paths?: string[] };
  supersedes?: string[];
}
~~~
模型不能指定 projectId 越权，也不能自行写 confidenceClass=user-confirmed。宿主根据当前会话与证据验证。
revision 更新用 expectedRevision；冲突返回最新版本供合并，不静默覆盖。
文件/分支状态变化将相关条目标为“需复核”（派生状态），不删除用户决定。反向修改、决定替代必须显式关联，不能只按文本相似度覆盖。

删除：立即从可检索集移除、清缓存和索引、作废待提交候选；正文 revision 与摘要副本进入可恢复清理流程，界面区分逻辑删除与永久删除。永久删除只按明确用户动作执行，保留无正文 tombstone 防止旧候选重新生成。原始聊天不自动删除，必须说明边界。

## 5. 项目身份和读取边界
- 工作树默认是独立项目知识空间；共享知识需显式关联共同仓库，分支限定事实不得共享成全局规则。
- 改项目名不影响 ID；移动目录需更新映射并复核引用；未登记目录不开启跨项目检索。
- 删除会话不自动删除已确认项目知识；来源失效时显示不可回读，不伪造证据。
- 删除项目默认解除登记、保留可恢复知识；永久删除为单独明确动作。
- 便携版跟随 YAN_DIR，不写死 ~/.pi。测试使用所有 YAN 隔离变量。
- 文件引用经过真实路径与项目边界校验，符号链接、目录穿越和附件授权不能绕过；文本引用不授予读取权限。

## 6. 读取、候选生成与合并流程
请求开始 → 识别项目和目标 → 检索 active 条目/权威文档索引 → 返回有限片段和来源 → 模型按需读取。
首版做中文可用的关键词/字符 n-gram 检索与标签加权，不引入向量服务。建议 top 8、总注入预算 2k tokens，并纳入方案 D 的总预算；没有相关项就零注入。
检索结果以数据块标注来源、有效范围、freshness 和“不作为授权”，不作为高优先级系统指令执行。
确定规则优先级：当前用户明确要求 > 当前有效项目规则；发现矛盾先解释并更新候选，不让旧记忆悄悄覆盖新目标。

settled 后可从本轮产出生成候选：用户明确决定、真实验证结果、稳定流程；临时命令日志和报错全文不永久收录。
每 goal 阶段最多生成一次，输入输出有上限；默认不另外启动无条件模型调用，可复用已产生的结构化材料。独立归纳调用如启用需记录耗时/用量、失败跳过，不能阻塞用户回答。
主进程验证引用存在、摘要没有把推断写成事实，按文本指纹去重；语义冲突进入候选列表，不自动替换。来源文本作为材料，材料里的“记住某规则”不能冒充当前用户要求。
推广：候选 → 用户明确接受/可验证规则自动校验 → active。无证据结论保持 inferred/candidate，不进入默认事实注入。
