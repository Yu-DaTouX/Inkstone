# Yan 工程清单收尾与 Codex 风格工作流实施方案

日期：2026-09-15  
适用版本：Windows 桌面端第一阶段  
依据：[工程清单](ENGINEERING-CHECKLIST-2026-09-15.md)。本文保留目标架构与实施依赖，模块名称可为建议名；已实现情况见 [PROJECT](../PROJECT.md)，当前任务见 [HANDOFF](HANDOFF.md)。

## 1. 方案结论

本项目不需要推翻 pi 的运行方式，也不应继续在单一“当前 Agent”上堆叠界面状态。收尾工作的核心是建立一层 Yan 会话编排：每个主会话拥有稳定的 `sessionId`、运行实例、工作目录、草稿、队列、模型能力、统计和子代理关系；界面只是订阅当前会话，切换查看对象不再等同于停止任务。

产品层级确定为：

```text
项目 Project
└── 会话 Session
    └── 回合 Turn
        ├── 推理流 Reasoning
        ├── 工具调用 Tool
        └── 子代理 Subagent
```

默认新会话保存到 Yan 自己的默认数据目录；从项目旁边创建的会话归属该项目，并且可以在项目之间移动。用户看到的是“项目内的会话”，底层文件是否物理写入仓库目录需要在实现存储适配器前确认，方案正文给出推荐实现。

本轮发布范围是 Windows。macOS、Linux 暂不适配，但共享类型、路径抽象、进程抽象和 UI 状态不能写死为 Windows-only，以便后续加入 Android 客户端或同步层。砚的账户系统暂不做；provider、模型能力、订阅套餐和用量适配保留接口。

## 2. 状态与实现边界

当前状态、验证基线和剩余任务统一维护在 [HANDOFF](HANDOFF.md)。不以目标架构、旧提交或历史测试替代实际完成度。

## 3. 编排原则

1. 会话是持久对象，运行实例是可回收资源，当前查看对象只是 UI 订阅。
2. 主会话与子任务使用稳定身份、事件和历史关联，不靠标题或数组下标识别。
3. 写入先进入隔离工作区和差异审阅，再合并、放弃或归档。
4. 每个动作携带目标身份，迟到事件不能覆盖新的会话、项目或代次。

## 4. 目标架构

### 4.1 主进程模块

新增或收敛为以下职责，名称可以按现有代码风格调整：

| 模块 | 责任 |
|---|---|
| `SessionSupervisor` | 创建、恢复、暂停订阅、切换、停止和退出时保存主会话 |
| `RunnerRegistry` | `sessionId -> AgentController` 映射；控制并发、排队、回收和运行状态 |
| `ProjectStore` | 稳定的 `projectId`、cwd、名称、分组、最近会话和归档状态 |
| `SessionLayoutStore` | 会话所属项目、存储位置、移动记录和迁移版本 |
| `CommandRegistry` | pi、扩展、技能、提示词模板和 Yan 本地命令的统一发现与路由 |
| `SubagentSupervisor` | 子代理父子关系、隔离目录、并发额度、停止/恢复和差异审阅 |
| `ExitCoordinator` | 关闭到托盘、保存后退出、中断退出、取消和进程清理 |
| `CapabilityResolver` | 模型上下文、思考档位、图像输入、压缩和 provider 元数据的权威来源 |

### 4.2 IPC 事件封套

所有异步事件和响应统一携带：

```ts
type RuntimeEnvelope = {
  sessionId: string
  runId: string
  projectId?: string
  generation: number
}
```

前端 store 按 `sessionId` 保存消息、增量、队列、草稿、模型、统计、等待输入和命令列表。`generation` 在切项目、切会话、刷新命令、切模型和取消请求时递增；响应必须匹配当前身份，否则丢弃并记录可诊断元数据，不记录敏感正文。

### 4.3 并发与同 cwd 冲突

第一版保持明确的资源预算：主会话、子代理分别计数但受一个总上限约束，超过上限时排队或提示。多个主会话指向同一 cwd 时默认标记为“共享目录风险”，不自动假定安全；写入型任务需要隔离工作区，或者明确要求用户确认共享写入。切换视图不停止原会话，停止动作必须带 `sessionId`。

## 5. 项目与会话方案

### 5.1 用户体验

- 顶部“新会话”：创建全局默认会话，使用 Yan 默认数据目录。
- 项目旁“添加会话”：创建项目归属会话，默认继承该项目 cwd、模型和必要的 UI 偏好。
- 会话菜单“移动到”：选择其他项目、默认位置或取消；移动只更新归属和存储映射，不停止正在运行的会话。
- 重新进入项目：恢复最近访问会话和草稿；项目从未有会话时才显示空状态。
- 切换项目：切换文件树、上下文和当前订阅，旧项目中的运行实例继续显示状态并继续工作。

### 5.2 存储推荐

推荐“项目语义归属 + Yan 管理物理存储”：

- 全局会话存放在 `YAN_DIR/sessions`。
- 项目会话仍存放在 Yan 数据目录，但在 `session-layout.json` 中记录 `projectId`、cwd、scope 和移动历史。
- 会话 JSONL 继续遵循 pi 的会话格式；Yan 只管理索引和扩展元数据，避免污染项目仓库、破坏 pi 读取和阻塞 Android 同步设计。
- 用户若明确需要真实文件出现在项目内，再增加可选的 `.yan/sessions` 存储后端，并自动写入 `.gitignore`、处理权限、迁移、回收站和跨平台路径；不能把“界面显示在项目下”直接等同于“把隐藏文件写进仓库”。

这也是本方案唯一需要用户在编码前确认的存储语义：这里的“创建到项目内”是否要求会话文件物理位于项目目录，还是只要求会话在产品上归属于项目。默认按推荐实现推进，除非用户明确要求物理目录。

### 5.3 迁移和删除

使用稳定 ID，不以标题、文件名或数组顺序作为身份。旧项目记录迁移到 `ProjectRecord`；旧会话扫描时按 cwd 建立候选归属，冲突保留为“待确认”，不静默移动。删除走现有回收站树机制，活动会话及其子会话拒绝直接删除；恢复操作保持父子关系。

## 6. 主要功能实施方案

### 6.1 N12/N05：后台会话和项目切换（P0）

先完成 `SessionSupervisor` 和事件封套，再接项目点击行为。

实施结果：

- A 会话运行时切到 B，A 的 pi RPC、队列和增量继续工作。
- B 拥有自己的 cwd、草稿、模型能力和命令列表。
- 切回 A 时恢复 A 的状态，不通过 `yan:setCwd` 停掉 A。
- 会话行展示运行、等待输入、失败、完成未读；项目折叠和 mini 栏只汇总状态。
- 停止、删除、换项目、改语言和退出均显式限定作用域。
- 退出后只保存可恢复信息，不宣称桌面关闭后任务仍在后台执行。

### 6.2 N04：限高省略的推理流

> ⚠️ **2026-09-15 口径变更（用户确认）**：原方案要求「内容不设固定三行高度、拖拽胶囊
> 或内部滚动；只使用聊天主容器滚动」。用户实测反馈推理占空间过大，改为 **限高省略**：
> 默认展开但钉在 `--reason-max-h`（`min(32vh,260px)`），裁掉**开头**、`scrollTop` 贴底
> 显示最新、顶部渐隐，被裁剪时提供「展开全部 / 收起」。仍不使用可滚动容器，所以
> 「没有第二条滚动条」这一条继续成立；改变的是「无限增长」→「裁掉开头」。

推理是聊天主流中的一个过程块：

- 上游没有可展示推理文本时不渲染占位。
- 推理中显示轻量“思考中”状态，并按字素增量输出。
- 内容钉在 `--reason-max-h`，超出部分裁掉开头；最新一句始终贴底可见。
- 被裁剪时才顶部渐隐并显示「展开全部」；短推理不淡化、不出现按钮。
- 推理块默认保持展开，但受 `--reason-max-h` 限高并显示最新内容；用户可用「展开全部 / 收起」控制，手动状态不被自动状态覆盖。
- 推理→工具→再次推理→回复的顺序保持真实事件顺序。
- 不使用可滚动容器（`overflow: hidden`），因此不存在「上滚被拽回底部」；
  减少动画时直接展示完整文本。

验收必须覆盖短/长文本、中英文、emoji、后台切回和工具穿插，不能只测静态 DOM 或 mock。

### 6.3 N18：命令注册表与分类菜单

命令候选统一为：

```ts
type CommandDescriptor = {
  id: string
  name: string
  description?: string
  source: 'pi' | 'extension' | 'skill' | 'prompt' | 'yan' | 'compatibility'
  module?: string
  executable: boolean
  usage?: string
  availability?: string
}
```

菜单按来源显示分类，例如“Yan 内置”“pi 内置”“扩展”“技能”“提示词模板”；同名命令显示来源和模块，不能只显示一个模糊名字。Yan 本地命令不依赖 `get_commands` 才出现。

纳入统一核对矩阵的命令包括 `/login`、`/subagent`、`/new`、`/compact`、`/model`、`/browser`、`/panel`、`/footer` 和十项 `/skill:<name>`。其中 `/panel`、`/footer` 若只有终端效果，则显示兼容性说明并从可执行候选中过滤，不制造无效果的假按钮。

补全规则：裸 `/` 即展示；完整匹配后再排序和限制数量；按光标位置替换命令名，保留参数、后文和光标；Enter/Tab 只接受候选，不顺便发送；输入法组合期间不拦截选词；切项目、切会话和扩展刷新使用代次校验。

### 6.4 N19/L02：文件树、文件标签和 `@` 引用

- 文件树单击：打开已有只读预览，并高亮当前文件；不修改输入框。
- 文件树独立动作：加入上下文，生成文件标签；不自动发送。
- 文件树拖到输入框：使用内部 MIME 携带绝对路径，输入框识别后走主进程路径校验，再转为文件标签。
- 外部资源拖入：继续沿用现有 `File` 路径和授权流程。
- `@` 补全：裸 `@` 显示当前项目根层，按需读取一层；支持中文、空格、括号、点号和 Windows 分隔符；按光标位置处理多个引用。
- 目录继续下钻，文件只替换当前引用区间；不会预读大文件或自动发送。
- 路径校验拒绝越界、符号链接/目录联接绕过和无权限访问；工作区外文件只能走显式附件入口。

### 6.5 N02/N16：模型能力、语言和 provider 适配

模型切换成功后由主进程返回权威能力快照：模型标识、provider、上下文窗口、思考档位、输入模态、压缩参数和能力未知状态。空档位必须清空旧值；未知能力和明确不支持分别显示。旧 token 使用量若不能转换，标为待更新或估计，不重新伪造计量。

界面语言的语言约束唯一由内置扩展 `resources/pi-extensions/language.js` 生成：每轮读取 `desktop.json` 的 `lang`，在 `before_provider_request` 中贴近最后一条用户消息注入独立消息，并以 `before_agent_start` 的系统提示追加作为兜底。切换语言不重建 pi 实例，下一轮生效；真实模型返回的原文始终保留，并在诊断中区分提示注入失败与模型未遵循。

provider 采用适配器接口，字段预留认证方式、模型能力、订阅套餐、用量和限制；Yan 自有账户不在本轮实现。任何“已登录”“已同步”“月度额度”都必须有真实字段或明确标注推算。

### 6.6 N09/N11/N10/N07

- 队列撤回：先核对 pi 是否支持单条删除；若只有整队清空，主进程以稳定队列 ID 串行化清空/重排并提供失败恢复，已被接收的插话标记不可撤回。
- 标题重生成：按目标 `sessionId` 请求，输入只取首条意图和最近有效用户消息；有手动标题时先生成候选，用户明确采用后替换；失败保留旧标题。
- 自主模式：低干扰边框表达“模式已开”，文字/图标另行表达“任务运行中”；减少动画时使用静态边框，不改变输入框尺寸。
- 设置清理：模型/思考统一模型菜单，上下文/压缩统一右栏；自动压缩/重试保留一个可发现入口；状态页只留诊断信息或合并移除。

### 6.7 L03：子代理

子代理记录包含 `subagentId`、`parentSessionId`、`parentRunId`、任务摘要、cwd、隔离方式、状态、开始/结束时间、结果路径和 diff 摘要。只读任务可在受控 cwd 执行；写入任务默认使用独立 worktree 或等价临时副本。

完成后显示差异、文件归属、检查结果和冲突；用户可合并、放弃或归档。合并必须保护主工作树已有修改，禁止用 reset/checkout 清理无关变更。异常退出要回收进程和临时目录；自动委派仍作为独立能力，未有稳定上游协议前只支持 `/subagent` 和程序化入口。

### 6.8 托盘和退出

- 点击窗口关闭：隐藏到托盘，不停止会话。
- 托盘菜单：显示窗口、新建会话、查看运行中的会话、退出。
- 选择退出后弹出三选一：保存后退出、中断退出、取消。
- 保存后退出：阻止新输入，写入草稿/会话布局/运行快照，先请求各实例到安全边界并等待有限时间，然后清理进程；下次启动提供恢复入口。
- 中断退出：中止主会话和子代理，写入最后可得状态，清理子进程后退出。
- 取消：继续运行。

“保存后退出”不能承诺电脑关闭后模型继续运行；它只承诺保存可恢复数据并安全结束本地进程。退出流程必须有单元测试覆盖双击关闭、托盘退出、重复退出和某个 runner 无响应。

### 6.9 像素图标与终端界面

采用现有设计令牌和终端语义，像素感通过内联 SVG/vector icon 的整数网格、单色填充和清晰状态槽实现，不引入大量不可编辑位图。

- 默认静态界面继续无装饰渐变、无阴影。
- 运行状态可使用低对比度扫光，但必须同时有文字、图标或 spinner。
- 图标只表达动作、对象或状态；选中态可以使用 filled，其余保持线性/像素化轮廓。
- 推理使用低对比度旁白样式，工具、命令、文件改动和等待输入使用不同颜色语义。
- 覆盖深浅色、正常/窄/矮窗口、100%/125% 缩放、右栏和内置浏览器同时存在的组合。

## 7. 分阶段执行与完成门槛

### 阶段 0：基线和工作区保护

确认当前提交、未提交源代码、视觉证据和历史文档的归属；不删除用户文件。重新运行 `typecheck`、构建和单元测试，记录输出。完成后才进入会话架构。

### 阶段 1：会话运行底座

实现事件封套、按 session 的 store、runner 生命周期、并发预算、同 cwd 冲突策略和退出快照。完成标准是 A/B 会话真实并行运行、切换不串事件、单独停止不影响另一会话。

### 阶段 2：项目/会话模型

实现项目归属、默认位置、项目创建、移动、最近会话、草稿恢复和迁移。先用 `SessionLayoutStore` 隔离存储策略；物理项目内存储只在语义确认后实现。

### 阶段 3：窗口生命周期与视觉过程流

实现托盘、退出三选一、自然推理流和最终终端/像素图标规范。完成标准是窗口关闭不杀任务，退出选择行为可重复验证，推理无第二滚动上下文。

### 阶段 4：模型、文件、命令和输入

按 N02/N16 → N19/L02 → N18 → N09/N11/N10/N07 的顺序完成；文件和命令共用光标、输入法、代次和错误状态基础。

### 阶段 5：子代理和审阅

实现隔离写入、差异预览、合并/放弃、异常清理和与主会话的生命周期绑定。完成标准是两个写入子任务均不能直接污染主工作树，并能留下可审阅结果。

### 阶段 6：浏览器、provider 和边界收尾

补逐站授权、撤销、私有地址/DNS 重绑定策略、下载来源、真实目标网站登录验证、真实 Chrome 下载验证和 provider 订阅字段适配。Cookie/页面存储值永不写入日志。

### 阶段 7：发布前最终验证

使用便携数据的备份副本做升级读取；重新构建最终源码，运行解包版本，执行窗口、IPC、pi 握手、浏览器、数据目录、托盘、会话恢复和退出验证；最后按发布范围生成目录包、便携 ZIP 和 SHA256。未完成全清单和测试前不安排发布。

## 9. 风险、取舍和禁止事项

- 不把“切换 cwd”复用成“停止旧 agent”的旧路径。
- 不用标题、路径后缀或数组位置代替稳定 session ID。
- 不用乐观 UI 宣称队列消息已经安全撤回。
- 不把 `get_commands` 的名称当作实际可执行能力；每个命令记录来源和执行入口。
- 不把文件树点击和输入引用混成一个动作。
- 不把静态预览或模拟登录当成真实 Chrome 登录状态。
- 不把单元测试通过当成 Electron 窗口、托盘、打包和视觉完成。
- 不重置、清理、删除或覆盖用户现有的未提交改动和视觉证据。
- 不因本清单改造任务面板整体结构，不提前宣称“日常模式”完成。
