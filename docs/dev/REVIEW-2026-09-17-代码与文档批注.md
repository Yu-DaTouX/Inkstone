## 确认的代码问题

### R01 · P2：完整 IPv6 地址被误判为非私网（**已修复 2026-09-17**）

- 批注：`src/main/browser/network-policy.ts:89`。
- 原因：合法八组、无 `::` 的 IPv6 把 expanded 设为 0，随即被 `expanded < 1` 拒绝，地址分类返回 false。
- 子代理以内存转译当前源码复现：`fc00::1 → true`；`fc00:0:0:0:0:0:0:1 → false`；`fe80::1 → true`；`fe80:0:0:0:0:0:0:1 → false`；`0:0:0:0:0:0:0:1 → false`。
- 影响：私网/loopback 地址判断函数有遗漏。URL 可能被浏览器先规范化，因此**未证明真实浏览器可绕过**。
- 修复建议：仅存在压缩段时要求 expanded 至少 1；完整形式直接验证八组。补完整/压缩/映射 IPv6 的等价性测试，再补真实网络边界验证。

### R02 · P2：新 runner 切换失败后失去进程回收入口（**已修复 2026-09-17**）

- 批注：`src/main/runners.ts:336–341`；启动失败分支同类问题在 328–334。
- 触发：新实例启动成功，但 switchSession 返回失败，例如扩展取消切换。当前仅删除 map 登记并恢复 activeId，没有调用 agent.stop。
- 子代理以内存转译加 stub 复现：start 成功、switchSession 返回 cancelled；执行 select 再 stopAll，结果 `registered=0, stopped=0`。
- 影响：已确认控制器漏调用清理；未在本轮生成实际孤儿进程。stopAll 只遍历仍登记的实例，所以后续全停也收不到该对象。
- 修复建议：在移除登记前统一清理新实例，覆盖 start/switch 返回失败及抛异常，恢复 activeId；补失败注入单测与隔离真实进程表观察。

### R03 · P2：上一轮速度被标成新一轮实时速度（**已修复 2026-09-17**）

- 批注：`src/renderer/src/components/chat/UsageBar.tsx:95`；来源选择在 68 行。
- 触发：上一轮有非零 usage 和 speed，新一轮正在流式输出但尚未报 usage。
- 原因：last 从全部历史取最近非零 usage；liveSpeed 只检查 streaming 和旧 output，直接取旧 speed。显示分支因此跳过“生成中 Ns”，并给旧速度加 live 标记。
- 同源问题：新一轮最终不报 usage 时，本轮账单可能继续呈现旧输入/输出/缓存数据。
- 证据：数据选择、条件与渲染路径静态核对；未做真实窗口复现。
- 修复建议：先确定当前回合范围，再取用量/速度；本轮缺失时显示计时或未知。补“旧轮有值、新轮无值”的零费用 UI 注入场景。

### R04 · P2：手动标题写盘失败却向 UI 返回成功（**已修复 2026-09-17**）

- 批注：`src/main/title.ts:71–73`；调用链 `src/main/index.ts:1063–1065` → `src/renderer/src/state/store.ts:1499–1505`。
- 触发：手动更名时 mkdir/writeFile 因权限、空间等条件失败。
- 原因：setManualTitle 吞掉异常，IPC 无条件返回 ok，UI 先乐观写入标题；接受标题候选还会清掉候选。
- 影响：窗口内看似保存成功，重启后更名可能丢失。自动生成标题可再生，不代表用户主动保存也应静默失败。
- 证据：完整调用路径审阅；本次未构造磁盘故障。
- 修复建议：返回明确失败，UI 回退并保留候选；用隔离数据目录模拟写入失败，不触碰真实设置。
