## 5. 新发现缺陷与修复方案（HANDOFF 未登记）

### D1 · 子代理并发槽位竞态【高】

- **现象**（`.audit-repros.cjs` A04）：同时 `start()` 三个任务，三个都通过上限检查，`runningCount = 3 > MAX_CONCURRENT(2)`。
- **根因**：`subagents.ts` 先检查 `runningCount`，再 `await prepareWorkspace(...)`，而 `this.runs.set(id, run)` 在 await **之后**才执行 —— 检查与占位之间有 await 窗口。
- **修法**：进入 `start()` 后同步登记"预备槽位"（`private pending = new Set<string>()`，`runningCount + pending.size` 参与判断），在任何失败/成功返回路径的 `finally` 里释放。
- **验收**：新增单测"三个并发 `start` 只能成功 2 个，第三个收到明确拒绝"；`test-subagent-isolation` / 真实 `/subagent` 复跑。

### D2 · 退出时已结束子代理的 worktree 不被清理【高】

- **现象**（A05）：对同一个 run 先 `finalize(run, false)`（正常结束、保留 worktree 待审阅），退出时 `stopAll()` 调 `finalize(run, true)`，`additionalCleanup = 0`，worktree 仍在。
- **根因**：`finalize()` 用 `run.finalizing` 缓存 promise，第二次调用直接返回旧 promise，`cleanupReview=true` 被忽略。而 `stopAll()` 的注释承诺"退出/重启时归档补丁后删除 worktree，避免留下孤儿目录"。
- **修法**：把目标态记在 run 上（`run.archiveRequested = true`），`finalize` 先 `await run.finalizing`，若之后发现 `review === 'pending'` 且 `archiveRequested`，再执行一次"归档 + 清理"段；或让 finalize 接受可升级的目标态并在内部循环重试。
- **验收**：单测"finalize(false) 后再 finalize(true) 必须产生 `review='archived'` 且调用过 `cleanupWorkspace`"；真实退出后 `%TEMP%\yan-subagent-*` 目录计数为 0。

### D3 · 子代理启动期上下文漂移【中】

- **现象**（A03）：`prepareWorkspace` 期间调用 `setContext()` 切换父会话，结果该 run 的 `cwd` 来自**旧**上下文、`parentSessionId` 来自**新**上下文。
- **根因**：`run.cwd` 的参数在 await 前求值，`run.parentSessionId/parentRunId/projectId` 在 await 后从 `this.opts` 重读。
- **修法**：`start()` 开头一次性快照 `const ctx = { cwd: this.opts.cwd, parentSessionId: this.opts.parentSessionId, ... }`，后续只用 `ctx`。
- **验收**：单测"准备期间 setContext 不改变本次 run 的 cwd 与 parentSessionId"。

### D4 · "只读"子代理没有只读限制【中】

- **现象**（A02）：`start(task, model, 'controlled-cwd')` 生成的 pi 启动参数里没有任何工具白名单，`controlled-cwd` 只是"不建 worktree、直接用某个目录"。
- **矛盾点**：`subagent-isolation.ts` 注释写"由上层限制为只读用途"，但上层从未限制。
- **修法**（二选一，需先确认 pi 0.85.1 的 `--tools` 语义）：
  - **推荐**：给只读子代理传只读工具白名单（如 `--tools read,grep,glob`），并在隔离模块注释里写明真实边界；
  - **保底**：如果上游不支持，则把 `/subagent --read-only` 的文案改成"不隔离工作区"而不是"只读"，不要给用户错误的安全预期。
- **验收**：单测断言只读启动参数含白名单；或探针断言 UI 不再声称"只读"。

### D5 · 复用空闲实例时 pi 进程的 cwd 不更新【高，待真机确认】

- **现象**（A01 代码层）：`runners.selectNow()` 复用空闲实例时执行 `idle.cwd = target.cwd`，但 `AgentController` 没有任何 `setCwd`/重启路径，`newSession()` 只发 `new_session` RPC —— 新会话很可能仍落在**旧项目目录**。
- **影响面**：N05 项目切换 + N12 后台会话（"切到 B 项目新建会话"这个高频动作）。
- **修法**（推荐前者）：
  1. 复用时先比较 `canonicalCwd(idle.cwd) !== canonicalCwd(target.cwd)`：不同则**不复用**，走"新建实例"或"明确拒绝并提示先停止旧实例"；
  2. 或者给 `AgentController` 增加 `restartWithCwd(cwd)`（需要真实 pi 复跑验证，成本更高）。
- **验收**：单测"空闲实例 cwd 与目标不同 → 不返回 `reuse`"；真实场景"A 项目跑完 → 切 B 项目 → 新建会话 → 会话 cwd = B"。
