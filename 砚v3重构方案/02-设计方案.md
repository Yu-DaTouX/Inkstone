## 1. 为什么整体重做

用户 2026-10-15 确认：为开发者和重度用户优化；功能**全面扩展**；只保留「砚 / Inkstone」这个名字；最不能接受**过于素淡、看不清 Agent 在做什么**。同日看过第一版预览（“发车大屏”方向）后又明确：**界面要简洁，那一版过于复杂、风格老套**，参照 Claude 新版桌面端。

因此 v3 的目标是两件事同时成立：**界面简洁**（默认只有侧栏和对话），**状态不隐身**（谁在跑、谁在等你、谁卡住，用最小的记号说清楚）。

- **保留**：产品事实与全部现有功能，pi 作为引擎，`renderer → preload 白名单 → main → pi RPC` 的边界，本地数据格式与目录，`yan` / `YAN_*` 兼容标识，安全边界（离线 HTML 预览 CSP、危险操作确认、会话归属核对）。
- **替换**：视觉、信息架构、组件体系、交互模型（本方案编写时没有读取现行设计规范）。
- **新增**：统一运行模型与停滞识别、提醒条、按需的运行总览、评审/PR、定时任务界面、MCP Apps 宿主、跨设备同步等（§20）。

## 2. 设计原则

产品原则（来自 PRODUCT.md）：

1. **状态永不隐身。** 每个运行都说清：在做什么、在等谁、卡了多久、改了什么。
2. **一个运行模型，多个视图。** 侧栏、提醒条、运行总览、托盘、手机端都从同一份运行注册表投影出来（03 §2）。
3. **pi 负责思考，砚负责看见与掌控。**
4. **强大但不铺满。** 默认视图只服务当前对话，其他能力在需要时出现，用完就收起。
5. **默认可逆。** 改动前留检查点，用分叉代替覆盖，危险操作先问。

体验目标与落点：

| 目标 | 落点 |
|---|---|
| **简洁** | 默认两块区域；会话头最多 3 个操作；输入框底部一行最多 5 个控件；工具步骤默认折叠成一行；没有常驻状态栏和常驻表格 |
| **先进** | 插话/排队、停滞识别、提醒条、运行总览、分支与检查点、评审与 PR、定时任务、MCP Apps 内联/全屏/画中画、命令面板、快速提问窗口、键盘优先 |
| **美观** | 安静的中性底色与大量留白；墨色主按钮；只用一种强调（等你确认）；每个组件状态完整 |
| **舒适** | 正文约 720px 宽、行高 1.75；暗色不用纯黑、正文不用纯白；数字等宽；动效只表达状态；三档密度；只在有事时提醒 |

## 3. 视觉方向：简洁（参照 Claude 新版桌面端）

### 3.1 一句话
**把注意力留给对话；状态用最小的记号说清楚。**

### 3.2 参照什么，不照搬什么

| 从参照借鉴 | 不照搬 |
|---|---|
| 两块区域：侧栏 + 居中的对话列 | Claude 的陶土色、Anthropic Sans/Serif 字体 |
| 控件极少；会话列表只有标题，操作悬停才出现 | Claude 的标志与星芒图形 |
| 安静的中性底色，表面靠明度区分，几乎不用描边 | 衬线标题与品牌插画 |
| 大圆角输入框、柔和阴影；用户消息是浅色气泡，回答直接铺在底色上 | 任何会让人误以为是 Claude 官方产品的元素 |

砚自己的部分：墨色主按钮（发送、允许）、墨蓝（焦点、选中、链接）、自己的标志（WP-02 另行设计）、状态点与提醒条。

### 3.3 简洁的硬规则
1. 默认只有**侧栏 + 对话**两块区域。右侧面板、运行总览都按需打开，关闭后不留痕迹。
2. 会话头最多 **3 个**操作（改动、分叉、更多）；输入框底部一行最多 **5 个**控件（＋、模型与思考、权限、上下文、发送/停止），其余收进「＋」或「更多」。
3. 不设常驻状态栏，不设常驻表格；数字只在有意义时出现（运行中显示用时，停滞显示计时）。
4. 工具步骤默认折叠成一行摘要；正在进行的那一步单独占一行。
5. 只用**一种强调**：需要你处理的事（等你确认）。其他状态都用 8px 小圆点表达。
6. 颜色克制：中性底色 + 墨色按钮；墨蓝只给焦点、选中与链接；状态色只出现在小圆点和极短的状态词上。

### 3.4 简洁之下，状态怎样不素淡
| 层次 | 做法 |
|---|---|
| 侧栏会话行 | 一个圆点表示状态（运行中会缓慢呼吸）；需要关注时在行尾显示短词：「等你确认」「停滞 1:20」 |
| 提醒条 | 有其他会话等你确认时，对话区顶部浮出一条提醒：「发布脚本 等你确认 · git push --force · 查看」 |
| 对话内 | 正在进行的那一步单独一行：圆点 + 动作 + 对象 + 用时 |
| 运行总览 | 侧栏「运行」按需打开，列出所有运行；完整页面含运行时间线 |
| 应用外 | 系统通知、托盘与任务栏状态、可选的迷你小窗、已配对手机的推送 |

### 3.5 已放弃的方向（记录）
“发车大屏”（夜屏外壳、常驻运行大屏带、多列表格、LED 状态色）在 2026-10-15 预览后被用户否决：过于复杂、风格老套。保留下来的只有两样东西：**统一的状态词汇**（§4.1）与**运行模型**（03 §2）。

### 3.6 明暗
默认跟随 Windows。浅色是近白的暖灰；深色是暖中性深灰（不用纯黑），侧栏比对话区略深一级。

## 4. 运行状态的呈现

### 4.1 状态词汇（全应用唯一的一套）

| 状态 | 记号 | 用词 | 何时显示文字 | 进入条件（数据来源） |
|---|---|---|---|---|
| 排队 | 空心圆 | 排队 / 定时 09:00 | 显示时间 | follow-up 排队、并发上限等待、定时未到 |
| 运行中 | 绿点，缓慢呼吸 | 运行中 | 侧栏显示用时 | pi `agent_start` 到 `agent_settled` 之间且有事件 |
| 等你确认 | 琥珀点 | 等你确认 | **始终显示** | 危险操作确认、`extension_ui_request` 对话类、定时任务等待授权 |
| 停滞 | 橙点 | 停滞 1:20 | **始终显示**，带计时 | 超过阈值无事件、自动重试、限流等待、重复输出被中止（§4.5） |
| 失败 | 红点 | 失败 | **始终显示** | 模型错误、pi 进程退出、工具致命错误 |
| 已停止 | 无点 | 已停止 | 悬停显示 | 用户停止、宿主回收 |
| 已完成 | 无点；未读时行尾一个小黑点 | 已完成 | 不显示 | `agent_settled` 正常结束 |

非颜色编码：需要关注的三种状态（等你确认、停滞、失败）**总是带文字**；运行中靠呼吸动画与用时区分；每个圆点都有可读名称（`aria-label`）；Windows 高对比模式下圆点换成文字。

### 4.2 侧栏会话行
`圆点 · 标题 · 行尾信息`。行尾信息只在有意义时出现：运行中显示用时（`12:40`），等你确认/停滞/失败显示状态词，定时任务显示时间，已完成不显示（未读时一个小黑点）。悬停出现置顶、归档、更多。当前会话整行浅底并加粗。

### 4.3 提醒条
- 有会话等你确认、而它不是当前会话时，对话区顶部中间浮出一条提醒：琥珀点 · 会话名 · 「等你确认」· 要做的事（一行截断）· 已等时长 · 「查看」按钮。
- 多个会话同时等待时合并为「2 个会话等你确认」，「查看」打开等得最久的那个。
- 不能关闭，处理完自动消失；不遮挡正文（正文顶部预留空间）；窄窗口下变成通栏。
- 当前会话就是等待的会话时不显示提醒条，确认卡就在对话里。

### 4.4 运行总览（按需）
- **浮层**：点侧栏「运行」或按 `Ctrl+J`，在侧栏旁打开浮层，每个运行一行：圆点 · 编号 · 标题 · 状态词 · 用时。点击跳到对应会话；底部「打开运行总览页」。
- **完整页面**（§10.1）：全部运行 + 今日历史 + 运行时间线。
- 编号：`S12`（会话）、`S12·1`（子 Agent）、`T03`（定时）、`R04`（评审），会话编号按创建顺序递增、不复用。编号只在总览、通知与手机端出现，侧栏不显示。

### 4.5 停滞识别（默认阈值，设置里可调 30 秒–5 分钟）
| 原因 | 判定 | 显示 |
|---|---|---|
| 等待模型响应 | 发出请求后超过 45s 没有任何输出事件 | 停滞 0:45 · 等待模型响应 |
| 工具无输出 | 工具执行中超过 60s 没有更新事件（可把某些命令标记为“长时间任务”豁免） | 停滞 1:00 · `npm run build` 无输出 |
| 自动重试 | 收到 `auto_retry_start` | 停滞 · 重试中（第 2 次） |
| 限流/额度 | 模型错误被归类为限流或额度 | 停滞 · 额度等待（有重试时间就倒计时） |
| 重复输出 | 流式循环防护命中（本地开发中：宿主中止，同一任务最多自动续一次） | 停滞 · 重复输出（已自动续接 / 需要你处理） |

点开停滞的会话，对话里出现一张停滞说明卡：原因、最后一个事件的时间、建议动作（继续等待 / 换模型重试 / 停止）。现有“子 Agent 连续 10 分钟无进展后请求收尾”的策略保持不变；停滞只是更早的可见信号，不会自动停止任何东西。

### 4.6 应用外
- **系统通知**：等你确认（总是）、失败、后台运行完成（窗口未聚焦且超过 30 秒）、停滞超过 3 分钟；点击只跳转，不提供“允许”按钮。
- **任务栏**：有运行时显示不确定进度条；等你确认时叠加覆盖图标并闪烁一次（进度条与覆盖图标已在 `08fd167c` 实现，v3 改由运行注册表驱动）。
- **托盘**：图标叠加状态点；菜单列出进行中的运行。
- **迷你小窗**（可选）：置顶的小窗，只列进行中的运行与状态，点击回到主窗口。
- **手机**：等你确认、失败、完成推送到已配对的 Android。

### 4.7 空与边界
- 没有运行：侧栏「运行」不显示数量；浮层显示“暂无运行”。
- pi 引擎未就绪：对话顶部一条信息条“引擎正在启动…”，侧栏圆点暂不显示。

## 5. 设计系统（令牌）

### 5.1 色彩策略
**克制。** 中性底色（带一点暖意）+ 墨色主按钮 + 墨蓝（只给焦点、选中、链接）+ 状态圆点。整个界面里，彩色只出现在三处：状态圆点与状态词、差异的增删、需要你确认的提醒。

| `font-read`（可选） | `"Source Han Serif SC", "Noto Serif CJK SC", "Songti SC", serif` | 设置里的「阅读字体」，默认关闭 |

系统字体在 Windows 小字号下最清晰，也不增加包体；以上字体在本机都已实测存在（00 §7）。所有会变化的数字用 `font-variant-numeric: tabular-nums`（WP-01 实测 Segoe UI Variable 的等宽数字）。代码字体可在设置里替换；是否继续随包 Maple Mono CN 见待定决定 D7。

### 5.4 字号与行高（固定刻度，不随窗口缩放）
| 令牌 | 字号/行高 | 用途 |
|---|---|---|
| `t-meta` | 12/16 | 行尾信息、时间、提示 |
| `t-ui` | 13.5/20 | 侧栏、按钮、菜单、默认界面文字 |
| `t-body` | 14/22 | 卡片说明、设置描述 |
| `t-prose` | 15/26 | 对话正文与用户消息（中英混排，行高约 1.75） |
| `t-title` | 14/20，600 | 会话头标题 |
| `t-h2` | 20/28，600 | 空状态、页面小标题 |
| `t-h1` | 24/32，600 | 独立页面标题 |

紧凑密度把 `t-prose` 降到 14/24，宽松提到 16/28。全部尺寸随 Windows 缩放与应用内缩放等比变化。

### 5.5 间距与尺寸
- 间距刻度（px）：`2 · 4 · 6 · 8 · 10 · 12 · 16 · 20 · 24 · 32 · 48`。
- 侧栏 264px（可收起）；会话头 48px；侧栏行高 32px（紧凑 28 / 宽松 36）；按钮 32px；发送按钮 34px 圆形。
- 对话列最大宽度 720px；输入框最大宽度 760px；右侧面板 420px。
- 手机触控目标 ≥ 44dp；桌面指针目标 ≥ 24×24 CSS px。

### 5.6 圆角与阴影
- 圆角：`6`（标签、小按钮）· `8`（按钮、侧栏行、菜单项）· `12–14`（卡片、浮层、确认卡）· `18`（消息气泡）· `20`（输入框）· `999`（提醒条、圆点、圆形按钮）。
- 阴影只给浮起来的东西：输入框 `0 1px 2px rgba(0,0,0,.04), 0 8px 28px -10px rgba(0,0,0,.12)`；浮层与提醒条 `0 0 0 1px rgba(0,0,0,.06), 0 16px 40px -10px rgba(0,0,0,.22)`（深色主题加深）；卡片只用一圈细线，不加投影。

### 5.7 动效
- 时长：悬停 90ms；展开、浮层 160–200ms；面板滑入 180ms。缓动统一 `cubic-bezier(.2,0,0,1)`，进入用 `cubic-bezier(0,0,0,1)`。
- 运行中的圆点缓慢呼吸（2.4s 一周期，透明度 1 → 0.3），这是全界面唯一的循环动画。
- 新出现的内容（插话送达、结果段落）淡入并上移 4px，180ms。
- 不做页面载入编排；流式文字不做逐字特效；“减少动态效果”时关闭全部动画（圆点改为静止）。

### 5.8 图标与状态点
- 图标以 Lucide（ISC 许可）为基础，16/18px，线宽 1.6，颜色继承文字色。
- 状态点 8px；未读点 6px（`fg` 色）；排队是 1.5px 描边的空心圆。
- 新标志：只保留名字，标志重新设计（WP-02，出 3 个方案给用户选）：单色、16px 托盘尺寸可辨、能叠加状态点；不得使用墨滴、毛笔、印章等字面联想。

### 5.9 工艺规则（对所有组件生效）
1. 所有会变化的数字都用等宽数字：用时、计时、token、费用、百分比、行号、编号。
2. 标题 `text-wrap: balance`；正文 `text-wrap: pretty`；中文正文 `line-break: strict`；启用 `text-autospace`（中英文自动间距）与 `text-spacing-trim`（标点挤压）——Electron 44.3（Chromium 152）已实测支持。
3. 长标识符（模型 ID、路径、哈希、URL）用 `overflow-wrap: anywhere; word-break: normal`；行内路径中段省略，保留文件名。
4. 行内图标基线下移 0.125em。
5. 截断阶梯：侧栏标题 1 行、摘要 2 行、说明 3 行；被截断的内容可经 tooltip 或展开看到全文。
6. 全应用只有一种焦点环：2px `accent`，外偏移 2px。
7. 能用表面明度分隔，就不用线；必须用线时用 `line`。
8. 不出现纯黑底和纯白正文。
9. 滚动条用系统原生的细化样式，悬停加粗。
10. 数字与单位：`12.4k token`、`$0.84`、`62%`；用时 `m:ss`，超过 1 小时 `h:mm:ss`。
11. “已复制”这类确认在原位显示 1.6 秒后复原，不弹 toast。
12. 操作按钮悬停才出现的地方（会话行、消息工具条），键盘聚焦时也要出现。
13. 不用粗于 1px 的彩色侧边条标记卡片、列表项或提示；需要强调时用圆点、短词或浅底。

### 5.10 令牌的单一来源
- `design/tokens.json`（建议路径）一处定义，生成 `tokens.css`（浅/深 × 三档密度的 CSS 变量）、Android 的 `theme.ts`、MCP Apps 主题变量映射（§5.11）。现有的 `check:mobile-tokens` 改为检查生成结果一致。

- 主题切换：`<html data-theme="light|dark" data-density="compact|standard|comfortable">`，颜色值用 `light-dark()` 定义。

## 8. 会话视图

### 8.1 一轮对话的结构
```
[用户消息]   右对齐浅色气泡，最大宽度 80%；悬停：时间 · 从这里分叉 · 编辑并重发 · 检查点
[思考]       一行“思考 12s ›”，默认折叠
[正文]       直接铺在底色上，宽 720px
[步骤摘要]   一行：“完成 3 步 · 改了 2 个文件 +130 −17 ›”，点开展开步骤列表
[进行中]     正在进行的那一步单独一行：圆点 · 动作 · 对象 · 用时
[子 Agent]   一行：圆点 · 子 Agent 任务名 · 模型与范围 · 用时 · 打开
[确认/提问]  需要你处理时出现卡片（§8.4、§8.5）
[成果]       图表块 / HTML / 小部件 / App 视图（§11）
[工具条]     悬停或聚焦时出现：复制 · 重新生成 · 回退代码到此轮之前 · 模型 · 用时 · 费用
```
重新生成与“编辑并重发”都通过 pi `fork` 实现，不覆盖原记录。

### 8.2 消息类型
| 类型 | 表现 |
|---|---|
| 助手正文 | Markdown（表格、任务列表、代码块、链接、图片）；代码块 `sunken` 底、12px 圆角，标题行显示语言、复制、换行切换；流式时代码块高度只增不减，结束后再高亮 |
| 思考 | 折叠行 + 时长；展开为 `fg2` 小字 |
| 错误 | 错误卡：类别标题（如“额度已用完”）、一句解释、动作（重试 / 换模型 / 查看原文，原文已脱敏）；类别来自 `shared/model-errors.ts` |
| 压缩标记 | 一行分隔：“上下文已压缩 · 150k → 32k token · 查看摘要 ›” |
| 分支摘要 | 可折叠的引用块 |
| 用户命令 | 输入框以 `!` 开头执行的 shell 命令（pi `bash`），显示为“你运行了 `ls -la`”，可选“不加入上下文” |
| 扩展通知 | `notify`：info/warning/error 三种行内提示 |

### 8.3 工具步骤
- **摘要行**（默认）：`完成 N 步 · 改了 M 个文件 +a −d`；只有命令时写 `运行了 npm test（通过）`；有失败时摘要变成红字“1 步失败”，并自动展开失败的那一步。
- **展开后**：每步一行 `动作 · 对象 · 结果`（读取 / 编辑 / 新建 / 运行 / 搜索 / 浏览 / 调用 MCP / 委派）；增删统计只取执行前后快照（拿不到就不写）；相对时间悬停才显示。
- **进行中的一步**：单独一行，圆点 + 动作 + 对象 + 用时；命令的最后一行输出悬停可见。
- **看细节**：编辑的差异在右侧面板「改动」打开；命令输出在「终端」打开；MCP 结构化结果在行内展开（JSON 树 + 文本）；带 App 的工具在下方直接渲染 App（§12）。都只读取已记录的内容，不重跑工具。
- 嵌套调用（Codemode `nestedCalls`、`parentToolCallId`）缩进在父步骤下。

### 8.4 需要你确认的卡片（危险操作确认）
```
┌──────────────────────────────────────────────────────────┐
│ ● 需要你确认                                     已等 2:14 │
│ 强制推送会覆盖远端历史，远端多出的 2 个提交会丢失。           │
│ ┌──────────────────────────────────────────────────────┐ │
│ │ git push --force origin main                         │ │
│ └──────────────────────────────────────────────────────┘ │
│ release-tool · 远端 origin · 分支 main                      │
│ Alt+Y 允许 · Alt+N 拒绝 · 2:46 后自动拒绝      [拒绝] [允许一次] │
└──────────────────────────────────────────────────────────┘
```
- 卡片 `surface` 底、14px 圆角、一圈细线；标题前一个琥珀点；“允许一次”是墨色主按钮，“拒绝”是描边按钮。
- `Enter` 永远不会触发允许；快捷键 `Alt+Y` / `Alt+N`；没有“全部允许”。
- 写到项目外的确认多一个选项“允许并记住此目录”（放在“允许一次”旁的下拉里，沿用现有能力）。
- 有超时的请求显示倒计时（pi 端到时自动处理，客户端只负责显示）。
- 决定后卡片收成一行灰字：“你允许了 git push --force · 刚刚”，作为审计痕迹留在对话里。

### 8.5 提问卡（扩展对话类请求）
`select` 选项按钮（≤6 个平铺，更多时带搜索）；`confirm` 是/否；`input` 单行输入；`editor` 多行编辑器。都显示来源与倒计时；取消 = 回传 `cancelled`。`setWidget` 的文本行显示在输入框上方的小面板里；`set_editor_text` 预填输入框；`setTitle` 作为标题建议，不强制覆盖。

### 8.6 子 Agent
对话里一行：圆点 · “子 Agent 补齐 PKCE 单元测试” · 模型与范围（只读 / 工作树）· 当前动作 · 用时 · 「打开」。点「打开」在并排视图里显示它的对话。用 worktree 隔离的子 Agent 结束后，这一行变成“完成 · 改了 3 个文件 · 查看差异 / 采纳 / 丢弃”。

### 8.7 输入框
```
┌──────────────────────────────────────────────────────────────┐
│ [图片缩略] [oauth.ts ×]                                         │ 附件（有时才出现）
│ 插话 1  顺便把 README 里的登录说明也更新一下。             撤回 │ 队列（运行中才出现）
│ 插话，或按 Alt+Enter 排队到这一轮之后…                          │ 输入区（自动增高，最高 200px）
│ ＋   Opus 5.5 · 中 ▾   自动批准 ▾                  ◔ 62%  ■   ↑  │ 底部一行
└──────────────────────────────────────────────────────────────┘
```
- **底部一行（最多 5 个）**：「＋」菜单（附件与图片、`@` 引用、`/` 命令、语音、先计划、`!` 运行 shell）· 模型与思考档（一个按钮，弹出选择器，§10.4）· 权限（“自动批准”为灰字；切到“不受限制”需要一次确认，之后显示为橙色字）· 上下文环（悬停看构成，≥80% 变琥珀色并提供“压缩”）· 停止（运行中）与发送。
- **发送语义**：空闲时 `Enter` 发送；运行中 `Enter` = **插话**（pi `steer`：当前工具调用结束、下一次模型请求之前送达），`Alt+Enter` = **排队**（pi `follow_up`：本轮结束后送达）；`Shift+Enter` 换行。**中文输入法组字期间（`isComposing`）`Enter` 一律不发送**。
- **队列**：由 pi 的 `queue_update` 驱动；可撤回、编辑、调整顺序（实现：`clear_queue` 取回全部，再按新顺序重新入队）。
- **停止**：`Ctrl+.`；输入框为空时连按两次 `Esc` 也停止。停止前先 `clear_queue`，把排队的文字放回输入框。
- **`/` 命令**：砚命令（/新会话 /分叉 /压缩 /模型 /导出 /评审 /定时）+ pi `get_commands` 返回的技能、提示词模板、扩展命令，带来源标签。
- **`@` 引用**：项目文件模糊搜索、最近文件；`@S12` 引用另一个会话的最近结果（新能力）。
- **附件**：粘贴超过 50 行的文本自动变成附件；拖放时整个对话区显示放置提示。
- **先计划**：一次性指令，让 Agent 先给出计划并等你确认；计划用 `yan-steps` 显示，带“按此执行”。
- **草稿**：按会话保存，切换会话不丢。

### 8.8 分支、检查点与回退
- **分支**：同一分叉点有兄弟分支时，用户消息旁出现“2/3 ‹ ›”在分支间切换；右侧面板「分支」页显示 `get_tree` 的完整树。会话内切换叶子使用本地进行中的 pi 原生操作批次提供的 `__inkstone_native` 的 `navigate_tree`（固定不自动摘要）；“从这里分出新会话”仍走 `fork`。
- **检查点与回退**：沿用现有影子 Git 检查点。回退对话框列出将被恢复的文件与差异预览、可能的冲突（同目录有运行时会阻止回退，沿用现有门闩规则），并提供“同时从这里分叉对话”。回退后可撤销。

### 8.9 滚动与导航
- 流式时贴底；用户上滚后停止贴底，右下出现“↓ 最新”小按钮。
- 加载更早历史时保持锚点，不跳动。
- `Ctrl+↑ / ↓` 在用户消息之间跳转；悬停对话区右缘时出现一条细的大纲轨（每轮一个刻度，沿用现有大纲数据）。

### 8.10 会话级状态
| 情形 | 表现 |
|---|---|
| 新会话（空） | 对话区中间一句问候（“今天做什么？”）+ 输入框；下面是本项目最近 3 个会话；项目、分支、模型写在输入框上方一行灰字 |
| 历史加载中 | 与最终布局一致的骨架，不用转圈 |
| 引擎启动中 / 重连中 | 对话顶部信息条“引擎正在启动…”，可以继续输入（发送会排队） |
| 引擎启动失败 | 错误条 + “查看诊断”“重新启动引擎” |
| 生成中 pi 进程退出 | 错误条：“运行中断：pi 进程退出”，提供“重新载入会话”；不自动重放请求 |
| 已归档 | 只读提示条 + “恢复” |

### 11.1 五类成果与信任等级
| 类型 | 来源 | 信任 | 渲染 |
|---|---|---|---|
| 结构化图块 | 模型输出的 `yan-chart/stats/cards/record/flow/steps`、Mermaid | 数据由模型生成 | 原生 React 渲染；解析失败退回代码块（现有规则） |

| 文件成果 | 生成的图片、文档、文件 | 本地文件 | 预览或在右侧面板打开 |

### 11.2 显示形态与尺寸
- **内联**：在对话里，宽度 = 对话列宽（可声明“宽”，放宽到 920px）；高度随内容自适应，上限 `min(70vh, 720px)`，超出时底部渐隐并显示“展开全屏”。**内联不允许嵌套纵向滚动**。
- **全屏**：占据对话区（侧栏保留），顶部是 App 名与关闭按钮；**输入框始终可见**；关闭后回到原来的滚动位置。
- **画中画**：浮在窗口右下角，可拖动、可调整大小；只属于它所在的会话。
- **面板**：右侧面板「预览」页签。
- **同一实例移动而不重建**：所有 iframe 放在一个固定的“框架层”里，按占位元素的几何位置定位；切换形态只改变它跟随的占位元素，不会重新加载、不会丢状态。跨窗口无法移动时经桥做状态转移，失败时明确提示“已在新窗口重新加载”。

### 11.3 身份与新实例接管
身份 = `(sessionId, messageId, partIndex)`，MCP App 再加 `toolCallId`；内容修改不改变身份。交互状态继续保存在现有的交互状态存储里。同一会话出现同一个小部件或 App 资源的新实例时，旧实例变暗并显示“已被新结果取代”，停用会修改模型上下文或发送消息的桥调用。

### 11.4 加载、错误与历史
骨架与最终尺寸一致；错误卡带“重新加载”“查看原始数据”；重开旧会话时 App 服务器不可用 → 显示最后一次的本地快照（仅本机保存）+ 文本回退 + “重新连接”；最多同时保持 4 个活跃框架，离开视口先冻结再卸载（卸载前保存状态）。

### 11.5 结构化图块的样式
全部改用令牌：系列用数据色；坐标轴与网格用 `line`/`fg3`；数字等宽；每张图提供“以表格查看”；Mermaid 主题从令牌生成，浅深同步。

### 11.6 `yan-widget` 桥 v2
让小部件说 MCP Apps 协议的一个子集，**一套桥实现服务两种信任等级**：支持 `ui/initialize`（下发 §5.11 主题变量）、`ui/notifications/size-changed`、`ui/request-display-mode`、`ui/message`（只填入输入框）、`host-context-changed`；砚扩展 `x-inkstone/state-save` 与 `state-restore`；不支持 `tools/call`、`resources/read` 与网络（离线 CSP 不变）。握手后改用 `MessageChannel` 端口，按 schema 校验，限速、限体积。

## 12. MCP Apps 宿主

### 12.1 范围
让 MCP 服务器提供的交互界面（`_meta.ui.resourceUri` 指向的 `ui://` 资源，`text/html;profile=mcp-app`）在砚里按标准渲染。规范以 SEP-1865 `2026-01-26` 稳定版为准，跟踪 `draft`。

### 12.2 数据通路与路线
**事实**：pi 原生 MCP 会省略 MCP Apps 资源，因为 pi 不渲染它们（pi `docs/mcp.md`）；本地方案合集 02 在 2026-10-13 的前置核对结论也是“pi 上游阻塞”，并定下原则：**砚不为此新建或扩充 MCP 连接**。

| 路线 | 做法 | 结论 |
|---|---|---|
| **A · pi 扩展桥** | 随包 pi 扩展在 MCP 工具执行后，经 pi 内部的 MCP 客户端读取 `ui://` 资源，通过扩展通道把 `{toolCallId, server, resourceUri, html, csp, structuredContent}` 交给宿主；App 发起的调用经扩展命令回到同一连接。可沿用本地已有的“宿主专用命令 + 请求/回执通道”做法（`native-session-bridge.js`） | **唯一路线**；先核实 pi 扩展 API 能否拿到 MCP 客户端与工具 `_meta`，不行就向 pi 上游提需求 |
| B · 宿主旁路连接 | 旧宿主 MCP 层对同一服务器另开连接 | **不采用**：违背上面的原则，且旧宿主客户端已按方案合集 06 收口到 pi 原生 |
| C · 替换 pi 内置 MCP | 写一个注册 `/mcp` 的砚扩展取代内置实现 | 不采用，维护量过大 |

### 12.3 协议覆盖
| 首版实现 | 之后 | 不做 / 默认拒绝 |
|---|---|---|
| `ui/initialize` → `initialized`；`hostContext`：theme、styles.variables、displayMode、availableDisplayModes（inline/fullscreen/pip）、containerDimensions、locale、timeZone、platform=`desktop`、deviceCapabilities | `ui/download-file`（draft） | `frameDomains`（嵌套 iframe） |
| `tool-input`、`tool-input-partial`、`tool-result`、`tool-cancelled` | `ui/notifications/request-teardown`（draft） | 摄像头/麦克风/定位（默认拒绝，可按服务器单独开启） |
| `host-context-changed`、`size-changed` | `sampling/createMessage` | 跨服务器工具调用 |
| `ui/request-display-mode`、`ui/open-link`（先确认）、`ui/message`（只进输入框）、`ui/update-model-context`（进上下文提示） | App 自带工具 | |
| `tools/call`（同一服务器，按可见性）、`resources/read`、`notifications/message`、`ping`、`ui/resource-teardown` | `serverResources` 列表变更 | |

### 12.4 隔离
- 每个 App 实例：`<iframe src="inkstone-app://<服务器哈希>/<实例ID>">`；每个服务器一个独立来源，靠站点隔离运行在独立进程；`sandbox="allow-scripts allow-same-origin"`；**不加载 preload**；禁止框架导航与弹窗。
- CSP 由协议处理器按 `_meta.ui.csp` 生成：只允许声明的 https 域名，再屏蔽本机、内网、`file:` 与私有协议（复用 `browser/network-boundary.ts`）；未声明时用规范规定的严格默认值。
- 现有离线 HTML 预览协议与 CSP **完全不动**。

### 12.5 宿主安全规则
1. **实例绑定**：握手后转为专用 `MessageChannel` 端口；请求身份由宿主根据端口确定；会话切换、实例销毁时关闭端口，迟到消息丢弃。
2. **可见性**：只接受 `visibility` 含 `"app"` 且属于同一服务器连接的工具调用；只有 `["app"]` 的工具不进模型工具列表。
3. **授权**：沿用现有 `danger-guard` 的 MCP 注解审批分支（方案合集 05，已提交），App 发起的调用再加一层服务器信任。所有 App 调用都记录在步骤里。“自动批准”档：带 `destructiveHint` 或注解缺失 → 出确认卡；只读工具需要用户授予“该服务器的界面可直接调用只读工具”，注解本身不构成信任。“不受限制”档不额外拦截，但仍记录。
4. **无隐式副作用**：渲染、恢复、历史重放不会自动发起写操作；`ui/message` 只填入输入框。
5. **限额**：单条消息 ≤ 1 MB；≤ 50 条/秒；`update-model-context` ≤ 16k token；`ui/message` ≤ 32k 字符；超限先节流，再标记“受限”并记录。
6. **链接**：`ui/open-link` 弹出确认，显示完整 URL（只允许 https）。
7. **凭证**：`hostContext` 不含任何令牌；日志与错误界面不回显令牌。
8. **审计**：每个服务器保留 CSP 配置、授予的权限、App 调用记录，可在设置 → 能力 → MCP 查看。
9. **销毁**：会话切换/关闭/卸载 → `ui/resource-teardown` → 最多等 500ms → 销毁框架、关闭端口。

### 12.6 界面
- **首次信任提示**：某服务器第一次要显示界面时，在步骤下方出现说明卡，列出声明的联网域名与权限；[允许并记住] [仅这次] [以文本显示]。
- **内联框**：位于产生它的步骤下方；`prefersBorder` 为 true 时加一圈细线与 14px 圆角；右上角悬停出现 [全屏] [画中画] [⋯]。
- **模型上下文**：App 的 `update-model-context` 显示为输入框上方的一行提示“已附带：图表视图状态 ×”，随下一条消息发送，可移除。
- **App 发来的消息**：只填入输入框并标注来源。

### 12.7 限制
首版只做 Windows 桌面；Android 端显示文本回退与快照。

## 16. 交互与动效细则

### 16.1 焦点
对话框、浮层关闭后焦点归还触发元素；侧栏与列表用漫游焦点（方向键在内部移动）；发送后焦点留在输入框；处理完确认卡后焦点回到输入框；流式更新不移动焦点。

### 16.2 悬停与按下
悬停只换底色（90ms）；按下再深一级，不缩放；只在指针设备上显示悬停态（`@media (hover: hover)`）；悬停才出现的操作在键盘聚焦时同样出现。

### 16.3 拖放
会话 → 对话区右半边（并排打开）；文件 → 输入框（附件或 `@`）；面板页签 → 面板边缘（拆分）/ 窗口外（弹出）。拖动中显示放置区域，`Esc` 取消。

### 16.4 流式渲染
Markdown 增量解析，只重排最后一个块；代码块先显示纯文本，结束后再高亮，高度只增不减；表格按行追加；图片占位使用已知尺寸，避免跳动；侧栏与总览的状态更新按会话合并，每秒最多 4 次。

### 16.5 动效目录
| 场景 | 动效 |
|---|---|
| 运行中的状态点 | 透明度呼吸，2.4s 一周期（唯一的循环动画） |
| 状态变化（点的颜色与行尾短词） | 160ms 渐变 |
| 提醒条出现 | 淡入 + 下移 4px，200ms |
| 浮层、菜单 | 淡入 + 2% 缩放，160ms |
| 步骤摘要展开 | 高度 160ms（`interpolate-size: allow-keywords`，Chromium 152 已支持） |
| 右侧面板 | 滑入 180ms |
| 新内容（插话送达、结果段落） | 淡入 + 上移 4px，180ms |
| 进入全屏 App | 同文档 View Transitions，从内联位置放大，240ms（Chromium 152 已支持） |

### 16.6 声音与触感
桌面只有“等你确认”默认有一声短提示音（可关）；手机在等你确认到达时一次轻触感。

## 17. 文案

- **语气**：平实、具体、短句；先说发生了什么，再说你能做什么。延续现有的白话风格（“改坏了能退回”“危险操作先问你”）。
- **状态用词**：排队 · 运行中 · 等你确认 · 停滞 · 失败 · 已停止 · 已完成。进行中的一步：正在读取 / 正在编辑 / 正在运行 / 正在搜索 / 正在压缩上下文 / 正在重试（第 n 次）/ 正在等子 Agent。
- **数字与时间**：`12.4k token` · `$0.84`（pi 以美元计价；设置里可填汇率显示人民币估算）· `62%` · `3:12` / `1:04:30` · 相对时间“3 分钟前”，悬停显示绝对时间。
- **错误**：标题说发生了什么（“额度已用完”）；一句话说原因或影响；给动作（“换模型重试”“查看用量”）；原文折叠在“查看原文”里，已脱敏。
- **空状态**：说明这里会出现什么，并给一个动作。例：运行总览为空时，“暂无运行。新建会话交代一件事，它就会出现在这里。”
- **双语**：中文为默认语言，英文完整翻译；编号、模型名、命令、路径不翻译。

## 18. 无障碍与国际化
- 目标 WCAG 2.2 AA：文字对比 ≥4.5:1（大字 ≥3:1）、非文字元素 ≥3:1、焦点可见、指针目标 ≥24×24。
- 键盘完整可达；快捷键可改。
- 屏幕阅读器：状态点有可读名称；只播报重要变化：“等你确认”（assertive）、失败与当前会话完成（polite）；流式输出不逐字播报，一轮结束后播报“回答已完成”。
- Windows 高对比（`forced-colors`）：使用系统颜色；状态点换成文字，所以依然可读。
- 尊重“减少动态效果”（圆点停止呼吸）与“减少透明度”。
- 200% 缩放下不丢内容，布局按断点重排。
- 中文排版：正文行高 1.75、`line-break: strict`、标点挤压与中英间距（Chromium 152 已支持）；输入法组字期间不触发快捷键与发送。
