## 1. 一页摘要

**问题。** 砚的主要用户同时跑多个会话与子 Agent。他们最不能接受的是“过于素淡”：长任务里看不清 Agent 在做什么、卡在哪。v2.0 方案是一份只读审计计划，没有设计内容，锚定旧设计，也没有触及这个核心问题。

**v3 的回答。**
1. **简洁的界面（参照 Claude 新版桌面端）**：默认只有侧栏和对话两块区域；会话头最多 3 个操作，输入框底部最多 5 个控件；工具步骤折叠成一行摘要；没有常驻状态栏和常驻表格。安静的中性底色、墨色主按钮，墨蓝只给焦点与选中。第一版“发车大屏”方向已被否决（过于复杂、风格老套），记录见 02 §3.5。
2. **简洁之下状态不隐身**：侧栏每个会话一个状态点（运行中缓慢呼吸），需要关注时才出现短词（“等你确认”“停滞 1:20”）；有会话等你确认时，对话区顶部浮出一条提醒，点「查看」直达；所有运行的总览按需打开；超时无进展的自动标为“停滞”并计时；应用外有通知、任务栏、托盘、可选的迷你小窗和手机推送。
3. **一个运行模型**：主进程只计算一次运行状态，所有视图（侧栏、提醒条、运行总览、托盘、手机、Hermes）只做投影；全面扩展的功能（评审/PR、定时任务、MCP Apps、同步）都接在这个模型上，不再另造状态机。
4. **完整的工作站**：重做全部现有界面，并新增代码评审与 PR、定时任务、MCP Apps 宿主（内联/全屏/画中画）、跨设备同步、运行时间线、命令面板、快速提问窗口。
5. **稳妥的迁移**：新旧外壳并存，用设置项切换，任何时候都能切回 v2；按 8 个阶段、36 个工单推进，每个阶段都可以发布。

## 3. 十个核心设计决定

1. **简洁的硬规则**：默认两块区域；会话头 ≤3 个操作；输入框底部 ≤5 个控件；步骤默认折叠；只用一种强调（等你确认）（02 §3.3）。
2. **状态词汇全应用唯一**：排队 · 运行中 · 等你确认 · 停滞 · 失败 · 已停止 · 已完成；用 8px 圆点表达，需要关注的三种状态总是带文字（02 §4.1）。
3. **色彩克制**：中性底色 + 墨色主按钮；墨蓝只给焦点、选中、链接；彩色只出现在状态点与状态词、差异增删和确认提醒上（02 §5.1）。
4. **系统字体**：Segoe UI Variable / 微软雅黑 UI / Cascadia Mono，默认零字体打包；会变化的数字一律等宽（02 §5.3）。
5. **插话与排队语义明确**：运行中 `Enter` = 插话（pi steer），`Alt+Enter` = 排队（pi follow_up）；停止前把排队文字放回输入框；中文输入法组字时不发送（02 §8.7）。
6. **确认卡防误触**：`Enter` 永远不会触发“允许”；没有“全部允许”；提醒条和通知只能“查看”，不能直接允许危险操作（02 §8.4）。
7. **成果视图统一**：图表块、HTML 成果、小部件、MCP App 共用内联 / 全屏 / 画中画 / 工作区四种形态；内联不嵌套滚动；切换形态不重建 iframe（02 §11）。
8. **MCP Apps 宿主自建**：pi 原生 MCP 不渲染 App 资源，砚通过 pi 扩展桥（首选，先做 PoC）取得资源；每个服务器独立来源、严格 CSP、宿主侧授权；离线 HTML 预览的 CSP 一点不放宽（02 §12）。
9. **运行状态在主进程计算一次**（03 §2）。
10. **新旧并存迁移**，v3 功能对等后再保留一个发布周期才删除 v2（03 §1、D12）。

## 7. 依据与尚未核实的事项

**依据**：公开仓库文档与源码目录（2026-10-15）；本机仓库 `E:\pi-desktop` 的实测核对（§8）；pi 官方文档（rpc、rpc-commands、rpc-extension-ui、json、sessions、mcp）；MCP Apps 规范（2026-01-26 与 draft）；Anthropic MCP Apps 设计指南与主题文档；第三方 Claude Storybook 复刻站（只作工艺参考）。

**已在本机实测（2026-10-15，用仓库自带 Electron 跑隐藏窗口探针）**：
- Electron 44.3.0 = **Chromium 152**。`light-dark()`、`field-sizing`、`interpolate-size`、`text-autospace`、`text-spacing-trim`、`text-wrap: balance/pretty`、锚点定位、Popover API、View Transitions、`@starting-style`、容器查询（含 scroll-state）、`text-box-trim`、CSS 嵌套**全部支持**，方案里的这些用法不需要降级。
- 字体：Segoe UI Variable、Segoe UI、Microsoft YaHei UI、Bahnschrift、Cascadia Mono/Code、Consolas 都已安装；JetBrains Mono、更纱、Maple Mono CN 不是系统字体（Maple Mono CN 由应用自带）。
- **Bahnschrift 的数字默认是比例宽度**（100px 下“1”只有 33px，其余 50–57px），开启 `font-variant-numeric: tabular-nums` 后十个数字等宽（53.23px）。简洁版不再使用 Bahnschrift，但同一结论适用于所有字体：会变化的数字**必须**带 `tabular-nums`，否则计时会抖（Segoe UI Variable 的等宽数字由 WP-01 实测）。
- 随包 pi 1.2.0 具备运行模型依赖的全部事件与命令：`agent_settled`、`queue_update`、`clear_queue`、`get_available_thinking_levels`、`get_tree`、`auto_retry_start`、`compaction_start`、`extension_ui_request`、`steer`、`follow_up`。
- 方案引用的 45 个源码/脚本路径与 25 个 `test:live` 场景名在本地全部存在。

**仍需核实，已排进对应工单**：
- 颜色对比度是按公式估算的，需要用脚本逐对复核（WP-01）。
- MCP Apps 路线 A：pi 扩展能否拿到 MCP 客户端、工具 `_meta` 和 `ui://` 资源；拿不到就需要向 pi 上游提需求（WP-52a，见 §8）。
- React Aria Virtualizer 与 virtua 在侧栏会话列表上的性能对比（WP-05）。
- 预览只在设计画布里搭建，没有做截图核对；以你在链接里看到的效果为准，显示有问题请直接指出。

本方案没有运行任何构建、测试或模型调用；所有性能目标都以 WP-00 采集的 v2 基线为准，不预设具体数字。
