# 04 · 交接指令（可直接粘贴给新会话）

> 用法：新开一个会话（Claude Code / Codex / 砚内置 pi），先粘贴 **§1 通用前言**，再粘贴对应工单的 **§3 工单指令**。
> 前提：本方案的文件已由 WP-00 放进仓库的 `.local-docs/plans/2026-10-15-v3重构方案/`（决定 D15；在此之前，它在分支 `docs/v3-redesign-plan` 的 worktree `.claude/worktrees/docs-v3-redesign-plan/砚v3重构方案/` 里）。如果放在别处，把指令里的路径替换掉即可。下文用 `<方案目录>` 指代这个位置。
> 另一个前提：主工作区「进行中」的批次已经提交或明确归属（03 §1 第 8 条），否则只启动 WP-00。

### 1.1 做界面工单时（可选：使用 impeccable 设计技能）
视觉方向已由用户钉定：**简洁，参照 Claude 新版桌面端，默认布局为侧栏 + 对话**（2026-10-15 确认；早先的「发车大屏」方向已被用户否决，原因是“过于复杂、风格老套”）。不需要重新抽签或另选世界。用 impeccable 构建界面时，把下面这段作为该界面的方向契约写进它的 surface brief（**只写进 brief，不要写进源码、注释或任何会随应用发布的文件**）：

```text
THESIS: 砚是一个安静的工作台：默认只有侧栏和对话，其余按需出现；状态用小圆点说清楚，需要你时才把你叫过去。
        简洁不等于素淡：等你确认、停滞、失败必须一眼可见。
OWN-WORLD: 暖中性底色（浅 #FAFAF8 / 侧栏 #F2F2EF；深 #1E1E1C / #191918），墨色 #1D1D1B 作为唯一主按钮色，
        墨蓝 #4057D6 只用于链接、焦点与选中；状态色只出现在 8px 圆点和少量文字上（运行绿、确认琥珀、停滞橙、失败红）。
        系统字体（Segoe UI Variable Text、Microsoft YaHei UI、Cascadia Mono）；圆角 8/12–14/18/20/999；
        不用渐变文字、不用超过 1px 的彩色侧边框、不用 Unicode 符号充当图标。
STORY: 打开砚就能看到每个会话在做什么；需要你的地方由提醒条送到眼前；处理完回到对话；随时可以插话、停止、回退、分叉。
FIRST VIEWPORT: 左侧 264px 侧栏（新会话、搜索、运行、定时任务、代码评审；按项目分组的会话行，行首是状态点；底部设置与设备状态）；
        右侧是会话：48px 会话头兼标题栏（标题、项目、最多 3 个操作、窗口按钮）；对话正文 720px 居中；
        底部 760px 输入框（＋、模型与思考、权限、上下文环、停止/发送）。右侧面板默认关闭，按需从“改动”等入口打开。
FORM: 参照 Claude 新版桌面端的布局与克制，但不用它的颜色、字体与标志（02 §3.2）。
        签名细节：运行中的状态点轻微呼吸；等你确认时会话上方出现提醒条；停滞自动计时；步骤折叠成一行摘要。
FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
```
模式规则：Operate。方向只提供色板、字体、密度和签名细节；导航与控件用标准做法。

## 2. 建议的启动顺序

| 批次 | 同时启动的会话 | 说明 |
|---|---|---|
| 第 1 批 | WP-00 | 必须最先完成：核对进行中批次、放置文档、记录决定、加开关、采集性能基线 |
| 第 2 批 | WP-01 ∥ WP-10 | 设计系统与运行模型互不相干，可以并行 |
| 第 3 批 | WP-02 ∥ WP-03 ∥ WP-12 | WP-12 依赖 WP-10 |
| 第 4 批 | WP-04 ∥ WP-05 ∥ WP-60 | 原语两份工单不碰对方文件 |
| 第 5 批 | WP-11 ∥ WP-20 | 状态点、提醒条与运行总览可以先挂在 v2 外壳里试用 |
| 第 6 批 | WP-21 ∥ WP-24 ∥ WP-25 ∥ WP-30 | 都依赖 WP-20 |
| 之后 | 按 03 §7.1 的通道推进 | 同一时间写代码的会话建议不超过 3–4 个 |
