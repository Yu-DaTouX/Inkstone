# 生图

用 `yan image generate --request-file image.json` 生成，成功后图片作为产物自动挂到回复。请求文件是 JSON，写在项目内。

## 1. 请求字段

| 字段 | 说明 |
| --- | --- |
| `prompt` | 必填。完整提示词，见第 2 节 |
| `provider` | 一般不写，按设置自动选。只在用户指定服务时填：`codex` / `openai` / `compatible` / `google` / `doubao` / `local` |
| `model` | 一般不写，用设置里的模型。用户明确指定时才填 |
| `size` | 如 `1024x1024`。**ChatGPT 登录通道（`codex`）不理这个字段**，比例必须写进提示词；其他服务按它出图 |
| `quality` | `auto`（默认）/ `low` / `medium` / `high`，只影响细节精细度 |
| `background` | `auto` / `transparent` / `opaque`，要透明底时填 `transparent` |
| `format` | `png`（默认）/ `jpeg` / `webp` |
| `mode` + `sourcePaths` | 改图：`"mode": "edit"`，`sourcePaths` 填项目内的参考图，最多 4 张、每张 ≤ 20 MB |
| `description` | 给用户看的一句话说明，可不写 |

别猜服务和模型：用户没说就别填 `provider`、`model`。想知道当前用的是哪个，看返回结果里的 `provider` 和 `model`。

## 2. 提示词要把要求写全

模型不会替你补全要求，聊天模型也不会改写提示词，写进去的才会被画出来。用户一句话「画只小猫」，你要自己补成完整描述，并把用户说过的每个要求都带上。

写进去的内容，按需包含：

- **主体与数量**：画什么、几个、什么姿态和表情。
- **场景与背景**：在哪里，背景是纯色、虚化还是具体环境。
- **风格与媒介**：摄影、水彩、扁平插画、3D 渲染、像素风等，不要只写「好看」。
- **构图与镜头**：主体居中还是偏一侧，特写还是全景，视角（平视、俯视）。
- **光线与色调**：自然光、逆光、暖色、冷色、低饱和等。
- **画面里的文字**：要出现的字**逐字写出并用引号括起来**，说明位置、字体风格和颜色。没有文字就写「不要出现任何文字」。
- **画幅比例**：见第 3 节，必须写。
- **不要什么**：用户排除的元素、不要水印、不要多余边框，直接写出来。

提示词语言跟用户要求走：画面里要中文字就用中文写那段文字，其余描述用中文或英文都行，写清楚比语言重要。用户给了完整提示词就原样使用，只补上画幅比例。

不要擅自加用户没要求的元素（品牌、人物、文字），也不要因为「更好看」改掉用户指定的风格。

## 3. 尺寸与画幅

用户提到「正方形」「竖图」「横图」「16:9」「封面」「头像」等，都要同时做两件事：

1. `size` 填对应像素：正方形 `1024x1024`，竖图 `1024x1536`，横图 `1536x1024`。
2. **在提示词末尾写出比例**，例如：`Square image, 1:1 aspect ratio, 1024x1024 pixels.` 或 `Vertical portrait, 2:3 aspect ratio.`

第 2 条是 ChatGPT 通道唯一有效的办法：实测请求 `1024x1024` 但提示词没写比例时，返回过 1199×1312 的非正方形；写了比例后返回 1254×1254。像素大小不会精确等于写的数字。

用户没提尺寸就不用强调比例，也不要自己加。

## 4. 生成后检查

- 看返回的 `path`，读一遍图，确认主体、文字、比例是否符合要求。
- 用户要求严格比例（如必须正方形）时，核对实际宽高，不符合就在提示词里加重比例要求重试一次；仍不符合就如实告诉用户，不要说成成功。
- 画面里的文字有错别字就重试，或告诉用户文字需要后期手加。
- 失败时把错误原样告诉用户，不要悄悄换服务重试。可以建议用户在「设置 → 模型 → 生图」里检查服务和 key。

## 5. 什么时候不用

- 图表、流程图、示意图、带精确数据的图：用 mermaid、yan-chart 或 HTML，不用生图。
- 需要精确文字排版的海报、名片：优先用 artifact 技能做成页面，生图只出背景或插画素材。
