# 办事模板

办事模板就是用户自己的技能：一份 `SKILL.md`，写清这件事怎么做。砚负责保存文件（`yan skill save`）并在新会话启动时加载；这个技能负责告诉你怎么写、怎么用。

用户保存过的模板会以普通技能出现（`yan capabilities search` 能找到，id 形如 `skill:<名称>`）。从旧版砚迁移来的模板名字是 `playbook-…`。

## 1. 存成模板

只在一件事**已经做成**、而且用户表示以后还要再做时才提议存模板。不要主动把每次任务都存下来。

1. 从刚做完的任务里整理出：目标、需要的输入、产出、按顺序的步骤。
2. 每一步标明影响：
   - **只读**：只看，不改任何东西；
   - **会改东西**：写文件、改成果，必须写清范围（哪些文件或目录、哪份成果）；
   - **会对外发出**：发消息、上传、调用外部服务，必须写清发给谁、发什么。
   范围随每次使用而变时，写成占位，例如 `<要整理的目录>`。
3. 把整理好的内容给用户看，确认名称和内容。用户同意后再保存。
4. 保存：写请求文件，然后 `yan skill save --request-file skill.json`：

   ```json
   {
     "name": "tidy-downloads",
     "description": "整理下载目录：按类型归档并留一份变更清单。用户要求整理下载目录或同类目录时使用。",
     "body": "# 整理下载目录\n\n## 目标\n…\n\n## 步骤\n1. 列出目录内容并分类（只读）\n2. 确认后移动文件（会改东西；范围：<要整理的目录>）\n\n## 执行约定\n- 会改东西或对外发出的步骤，执行前把具体范围告诉用户并得到确认。"
   }
   ```

   - `name`：小写字母、数字和连字符，写成简短的英文短语。
   - `description`：写清这个模板做什么、**什么时候该用**，这是以后能否被找到的关键。
   - 已有同名模板时，先问用户是否覆盖，同意后加 `"replace": true`。
5. 告诉用户：模板已保存，下一次新会话起可以直接使用。

## 2. 按模板办事

1. 用 `yan skill read --id skill:<名称>` 读模板全文。
2. 先把计划摊开给用户：会读什么、会改什么、会对外发什么，范围分别是什么。把占位 `<…>` 换成这次的实际对象；不知道的就问，不要猜。
3. 有「会改东西」或「会对外发出」的步骤时，等用户确认后再动手。只读步骤可以直接做。
4. 只做模板里列出的事，不顺手做范围外的整理。
5. 做完后说明实际改了哪里。发现模板本身有错或过时，建议用户更新模板，而不是悄悄换一种做法。
