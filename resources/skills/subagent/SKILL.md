# 子代理分工

砚负责启动、隔离、停止子代理，并在界面上显示它的状态、转录和改动。这个技能负责告诉你什么时候拆、怎么拆、结果怎么用。

## 1. 先判断该不该拆

适合拆出去并行（彼此独立、不写同一处、交回来的是一段结论）：

- 独立来源搜集：几份彼此无关的资料各查一遍。
- 长材料分段：同一份长文档按段分头读，再汇总。
- 不同方案分析：同一个问题让几个方向各给一版分析。
- 独立修改意见：对同一份代码或文档给出互不影响的意见。

不适合拆，留在主 agent：

- 短问答：派活的开销比任务本身还大。
- 连续编辑同一段内容：两边会互相覆盖。
- 需要来回确认的一步：子代理没有向用户提问的机会。
- 导师与用户的连续交流：必须保持同一个 agent 与用户对话。

拿不准时不拆。

## 2. 写任务输入

简单任务可以直接 `yan subagent start --task "任务"`。并行的子任务容易跑偏，复杂任务先写请求文件，再 `yan subagent start --request-file subagent.json`：

```json
{
  "task": "查一下这两个模块的错误处理",
  "readOnly": true,
  "brief": {
    "goal": "摸清两个模块的错误处理是否一致",
    "deliverables": ["一段结论", "不一致的具体位置"],
    "sources": ["src/main/agent.ts", "src/main/index.ts"],
    "boundary": "只读，不要改代码"
  }
}
```

- `goal`：它要达成什么，一句话。
- `deliverables`：交回什么，逐条写。
- `sources`：从哪里找，给文件、目录或资料。
- `boundary`：不许做什么（例如只读、不碰某目录）。
- 默认在独立 Git worktree 里运行，代码改动与当前目录隔离；只在当前目录做只读检查时用 `readOnly: true`。
- 多个子代理同时运行时，确保它们不写同一个文件。

## 3. 等待与汇总

- `start` 返回子代理 ID。需要进度时用 `yan subagent list`，看单个转录用 `yan subagent get --id <ID>`，不再需要时 `yan subagent stop --id <ID>`。用户在输入区上方和右侧面板能看到同样的状态。
- 子代理结束后，宿主给你的摘要是它**最后一段话**的摘录，不是经过核实的结论。汇总前自己核对关键事实。
- 未决问题需要你来判断，宿主不会替你提取。
- 汇总后由你统一回答用户，写明哪些结论来自哪个子代理。
- 不要假设子代理已经完成或改动已合并：worktree 的合并或放弃由用户在界面里确认，你只负责把结果交给用户审阅。
