# 指定模型的子 Agent

当前会话负责整体任务，子 Agent 负责一个明确子任务，结果返回当前会话。按需调用：只在任务确实可独立并行或需要隔离上下文时派子 Agent，用户没有要求时不要大量并行派发；能续派已有子 Agent 时优先续派。这里只写取舍；选项写法、续接规则、隔离与限额见 `yan subagent --help`。

1. 用户指定了模型时通过 `--model` 请求该模型，仍服从宿主的强制模型设置；没有指定时省略 `--model`，由宿主默认设置决定，不主动传当前模型覆盖用户设置。启动报错时如实告诉用户原因，不要自行省略 `--model` 或换成别的模型重试。`claude-bridge/*` 模型不支持 `--read-only`。
2. 任务说明写清目标、必要上下文、输入文件和期望结果。只传有用材料，普通子 Agent 不自动获得完整主会话历史。任务靠对话里已有的讨论、决定或读过的文件才能做、又不想让自己的上下文被过程刷满时加 `--fork`（继承当前会话的全部历史）；能用几句话讲清时用普通子 Agent。
3. 启动：`yan subagent start --task "任务" --title "短标题"`。一次派多个独立子 Agent 时，在同一条消息里并行发出。默认在当前文件夹执行，可能直接修改文件；只分析时加 `--read-only`，代码修改需要隔离时加 `--isolation worktree`。
4. 派出后不用 sleep 轮询，结束时宿主会通知；要看进度用 `yan subagent list` / `get --id <ID>`，停止用 `stop --id <ID>`。补充资料、纠正方向或追问已结束的子 Agent 用 `yan subagent send --id <ID> --message "信息"`：它记得之前的工作，优先续接而不是重派。
5. 不让多个写入任务同时修改相同文件；需要用户选择的问题留给主会话。子 Agent（包括 fork）不再派出子 Agent。
6. 汇报时以启动结果或查询结果的实际 `model` 为准，标明子 Agent 的模型、结论和未验证项；出错或部分完成不能称为任务成功。worktree 的改动由你审阅处置，不交给用户：看过补丁和结论后用 `yan subagent merge --id <ID>` 合并，或 `yan subagent discard --id <ID>` 放弃。当前文件夹任务已经直接写入，不假装有待合并补丁。
