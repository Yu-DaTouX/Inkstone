# 缺能力时怎么办

砚负责能力目录、联网检索、接入与安全检查。装、删、改都在对话里完成，不要让用户自己去设置页操作。这个技能告诉你按什么顺序找、用哪个命令装，以及常见需求通常从哪里补。

原则：**装不装由用户决定**。每次增删改砚都会弹出限时批准面板，你不需要也不能替用户批准，也不必先在对话里征求同意；认不出需求时不要猜包名。命令参数见各组的 `--help`。

## 1. 顺序

1. **先查已有的**：`yan capabilities search --query-text "<要做的事>"`，也覆盖已登记 MCP 服务的工具。查到就直接用，并告诉用户「你已经有这个能力」。
2. **本地没有再联网找**：`yan capabilities discover --query-text "<英文短词>"`；用户点名某个仓库时加 `--repo owner/name`。
3. **选一个最合适的接入**：`yan capabilities acquire --candidate <候选ID>`，等用户在面板上选。
   - 技能：装好后马上读返回的 `skillFile` 继续原任务。
   - MCP 服务：返回 `needs-config` 时按提示用 question 工具的 secret 字段要密钥，再带 `--env` 重试。
   - pi 插件（`npm:` 候选）：这一轮结束后自动装到当前项目并接着任务继续。
4. 被跳过就不要再请求同一个，按用户的话或不装东西的办法继续。被拦下（`blocked` / `failed`）时说明原因，换候选或走退路，不要绕过审查。
5. 都不行时说明缺什么，并给出不装东西的退路。

一次任务最多申请接入一两项，不要为了「可能有用」去装。

## 2. 用户点名要装或要改时

用户已经说清要什么（某个 MCP 服务、某个插件、某个仓库）时不用 discover，直接用对应命令：

| 要做的事 | 命令 |
| --- | --- |
| 加 MCP 服务 | `yan mcp add --name <名字> --command <命令> --arg … [--env 名字=$YAN_SECRET_…]`，网络服务用 `--url` |
| 看、删、启停 MCP 服务 | `yan mcp services`，再 `yan mcp remove / enable / disable --name <名字>` |
| 装、卸砚插件（如桌宠、语音输入等，以 `yan plugin list` 为准） | `yan plugin list`，再 `yan plugin install / remove --id <ID>` |
| 装、卸 pi 插件（npm 或 git 来源，可选全局或当前项目） | `yan package install --source npm:<包>@<版本>` 或 `git:github.com/<用户>/<仓库>`；`yan package list` / `remove` |
| 存用户自己的做法 | 见 `playbook` 技能（`yan skill save`） |

- 密钥、令牌一律先用 question 工具的 secret 字段向用户要，命令里用 `$YAN_SECRET_<名字>` 传；不要让用户把密钥发在对话里，也不要把值写进文件或回复。
- 启动命令、地址和包名要来自用户、服务的官方说明或 discover 的结果，不要凭印象编。
- 改动在当前会话这一轮结束后自动重启生效。告诉用户装好了什么、下一条消息起可以用；需要验证时请用户发下一条消息，或用 `yan mcp list` 看工具是否出现。

## 3. 常见缺口

| 需求 | 通常缺什么 | 从哪里补 | 不装东西的退路 |
| --- | --- | --- | --- |
| 从 PDF / 文档里取表格和结构 | 结构化解析 | 技能包；Office 文件先看 `office` 技能 | `yan office read` 或按纯文本读，表格会散成行 |
| 统计表格数据、画图 | 数据统计与画图 | 技能包，或本机 Python | 读成文本后计算；图交给 `yan image generate` |
| 打开网页读正文 | 不缺，砚自带 | `yan browser run --code -`（或 `yan browser navigate` + `yan browser text`） | — |
| 录音转写 / 朗读 | 语音能力 | 语音输入插件（`yan plugin install --id voice-input`）；朗读需要 MCP 服务 | 先用其他工具转成文本 |
| 看图片里写了什么 | 取决于当前模型是否支持看图 | 换支持视觉的模型 | 先 OCR 成文本 |
| 连数据库查数 | 数据库客户端 | 数据库 MCP 服务（连接串用 secret 字段向用户要） | 用本机命令行导出 CSV 再读 |
| 按语义搜整个代码库 | 索引式检索 | 技能包 | 先 grep 定位，再精读文件 |
| 把结果发到邮件 / 群 / 工单 | 对外发送通道（砚不内置） | 提供发送能力的 MCP 服务；每次发送前由用户确认 | 写成文件，由用户自己发出去 |
| 长视频 / 长音频做笔记 | 转写能力 | MCP 服务或本机工具 | 先拿到字幕或文稿，再分段处理（可用子代理，见 `subagent` 技能） |

## 4. 接入前后

- 申请前用一句话说明为什么需要它，面板会列出来源、命令和范围。
- 生效后先用一个小任务验证能用，再继续原来的任务。
