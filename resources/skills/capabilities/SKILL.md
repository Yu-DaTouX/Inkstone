# 缺能力时怎么办

砚负责能力目录、联网检索、接入计划与安全检查（`yan capabilities …`）。这个技能告诉你按什么顺序找，以及常见需求通常从哪里补。

原则：**装不装由用户决定**。技能用 `yan capabilities acquire` 接入，砚会弹出限时批准面板，你不需要也不能替用户批准；认不出需求时不要猜包名。

## 1. 顺序

1. **先查已有的**：`yan capabilities search --query-text "<要做的事>"`。已经有相关能力就直接用，并告诉用户「你已经有这个能力」。
2. **本地没有再联网找**：`yan capabilities discover --query-text "<英文关键词>"`。技能主要来自 GitHub 技能仓库（默认 anthropics/skills，格式与 Claude Code 的技能相同），描述是英文，检索词用英文短词（如 `pdf form`、`spreadsheet`）。用户点名某个仓库时加 `--repo owner/name`，会列出该仓库全部技能。源不可用时如实说「暂时无法搜索」。
3. **选一个最合适的技能接入**：`yan capabilities acquire --candidate <候选ID>`。命令会等用户在面板上选择：
   - 「仅本次会话使用」：只对这个会话生效（默认推荐）；
   - 「安装到我的技能」：之后所有会话都能用；
   - 跳过、写了别的话、或到时间没选：什么都不装。
4. **结果怎么用**：
   - `state=installed`：马上用 read 打开返回的 `skillFile`，按技能说明继续原来的任务；
   - `state=skipped`：不要再次请求同一个技能，改用不装东西的办法继续；有 `userReply` 时按用户的话调整；
   - `state=blocked` / `failed`：说明原因，换候选或走退路，不要绕过审查。
5. 都不行时说明缺什么，并给出不装东西的退路。

一次任务最多申请接入一两个技能，不要为了「可能有用」去装。MCP 服务目前不由这里接入：需要时告诉用户在设置 → 能力里用 `/mcp` 管理。参数细节见 `yan capabilities --help`。

## 2. 常见缺口

| 需求 | 通常缺什么 | 从哪里补 | 不装东西的退路 |
| --- | --- | --- | --- |
| 从 PDF / 文档里取表格和结构 | 结构化解析 | 技能包；Office 文件先看 `office` 技能 | `yan office read` 或按纯文本读，表格会散成行 |
| 统计表格数据、画图 | 数据统计与画图 | 技能包，或本机 Python | 读成文本后计算；图交给 `yan image generate` |
| 打开网页读正文 | 不缺，砚自带 | `yan browser navigate --url <地址>`，再 `yan browser observe` | — |
| 录音转写 / 朗读 | 语音能力 | 电脑端输入框有本地转写（设置 → 语音输入）；朗读需要 MCP 服务 | 先用其他工具转成文本 |
| 看图片里写了什么 | 取决于当前模型是否支持看图 | 换支持视觉的模型 | 先 OCR 成文本 |
| 连数据库查数 | 数据库客户端 | 数据库 MCP 服务（连接串与凭证由用户配置） | 用本机命令行导出 CSV 再读 |
| 按语义搜整个代码库 | 索引式检索 | 技能包 | 先 grep 定位，再精读文件 |
| 把结果发到邮件 / 群 / 工单 | 对外发送通道（砚不内置） | 提供发送能力的 MCP 服务；每次发送前由用户确认 | 写成文件，由用户自己发出去 |
| 长视频 / 长音频做笔记 | 转写能力 | MCP 服务或本机工具 | 先拿到字幕或文稿，再分段处理（可用子代理，见 `subagent` 技能） |
| 每隔一段时间自己做一件事 | 砚的定时任务（只在砚运行时触发，到点新开一条会话） | `yan schedule create`（见 `yan schedule --help`）；创建后需用户在「定时任务」页确认启用 | 告诉用户到时候回来让你再做一次 |

## 3. 回复用户时

- 先说结论：已经有 / 接入了什么（本次会话还是我的技能）/ 暂时做不到。
- 申请接入前用一句话说明为什么需要它，面板会列出来源和内容。
- 接入后先用一个小任务验证能用，再继续原来的任务。
