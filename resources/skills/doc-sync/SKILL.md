# 代码改完同步文档

代码改动完成后，相关文档要跟着实际行为走。这个技能说明找哪些文档、什么时候改、怎么写。

## 1. 找文档

- 改代码之前，先找出描述这块行为的文档：README、`docs/` 下的使用说明与架构文档、`AGENTS.md` / `CLAUDE.md` 一类协作约定、代码地图。
- 按改动涉及的功能名、命令名、文件名搜索，不要只看文件名猜。
- 找不到对应文档就不硬造新文档；需要新文档时先问用户。

## 2. 什么时候改

- 这一轮代码改动全部完成后，按**实际改动**统一更新一次对应章节。
- 不要边改代码边逐步小修小补文档；中途放弃的方案不写进文档。

## 3. 怎么写

- **已实现**：只写代码里真的做到的。
- **未完成 / 限制**：如实列出，不美化。
- **建议**：单独标注，和已实现分开。
- 不要借回填文档批准新的产品需求：需求稿里的待定项保持待定，只记录你实现了什么。
- 文档与代码冲突时以代码为准，并在回复里指出冲突；不要悄悄改写需求文档的原意。
- 删掉的功能，把文档里对应的入口、命令和截图说明一起删掉或改掉，不留指向不存在功能的链接。

## 4. 回复用户

- 把「代码改了什么」和「文档改了什么」分两段说明。
- 没有需要同步的文档就明说「这次没有需要同步的文档」。
