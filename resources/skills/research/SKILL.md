# 跨资料研究

砚负责保存资料的**每一个版本**，并告诉你某条引用现在是否已旧或已移除。这个技能负责告诉你怎么读、怎么对照、怎么写结论。

## 1. 读资料

- 用 `yan research read --request-file refs.json` 读片段。请求文件：

  ```json
  { "refs": [ { "sourceId": "lib_x", "version": 1, "locator": { "start": 0, "end": 400 } } ], "maxChars": 600 }
  ```

- 读的是**引用指定的那一版**，不会自动换成新版。结果里 `status` 为 `outdated` 时带 `latestVersion`：需要最新内容就另读新版本，并在回答里说明两版的差别。
- `skipped` 里的来源没有读到（已移除、找不到或没有可读正文）。**不要把它们当作证据**，也不要凭标题猜内容；如实告诉用户哪几份没读到。
- `truncated: true` 表示片段被截断，需要更多内容时缩小 `locator` 或调大 `maxChars`（上限 4000）。

## 2. 对照多份资料

- 先把每份资料对问题说了什么**逐份列出**，再比较。
- 说法不一致时**并列保留**：按立场分组（例如「支持 / 反对 / 补充条件」），写清哪几份属于哪一组。不要合并成一句「综合来看」，也不要替用户判断哪份更可信，除非用户明确要你判断；判断时写明依据。
- 只有两份资料**明确在讲同一件事且说法不同**，才算冲突。拿不准是不是同一件事时，写「可能不一致」并说明原因。
- 几份资料转述同一个原始来源时，不算多份独立证据。

## 3. 区分原文与补充

- 每条结论标明来源：**引用原文**（资料名、版本、位置）或**模型补充**（你自己的推断、背景知识）。
- 引用写成「《资料名》v2，第 120–380 字」这样的形式，让用户能回到原文核对。
- 不要把补充写成「据资料显示」。

## 4. 写进成果

- 成果里的引用保留当时的版本。资料后来更新时，用 `yan research status --artifact <成果ID>` 查看哪些引用已旧，再决定是否更新；更新前告诉用户变化在哪里，不要静默改写旧引用。
- 需要把结论交给用户时，先给并列的说法与各自出处，再给（如果有）你的判断，两部分分开写。
