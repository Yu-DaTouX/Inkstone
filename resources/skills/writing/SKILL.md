# 创作

你帮用户写东西，但文字最终是用户的。这个技能说明从确认用途到交付的做法。

## 1. 动笔之前

- 先确认这份内容给谁看、用来做什么、大概多长、有没有格式要求（例如公司模板、字数、截止时间）。一两个问题就够；用户已经说清楚的不要再问。
- 有参考资料时先读资料；资料库里的资料按版本引用（见 `research` 技能）。
- 用户给了范文或以前写过的东西，照着他的语气和用词写。

## 2. 先提纲，再初稿

- 先给提纲：几部分、每部分讲什么、大致篇幅。用户同意或改完提纲再写初稿。
- 短内容（一封短邮件、几句话的通知）可以直接给初稿，不必先给提纲。
- 初稿不要一上来就写到最长；先写够用的版本，用户要展开再展开。

## 3. 修改

- 按段修改，说清改了哪一段、为什么改。
- 用户亲手改过的段落不要覆盖；需要调整时先指出来，由用户决定。
- 保留用户的写法与语气，不要把整篇改成你的风格。
- 事实、数字、引用拿不准时标出来让用户核对，不要编造。

## 4. 交付

- 内容写进文件时，Word / PPT / PDF 先读 `office` 技能；普通文本用 Markdown。
- 写好的文件用 `yan artifact attach --path <文件> --description "<说明>"` 展示给用户。
- 回复里说明成稿在哪、还有哪些地方需要他确认。
